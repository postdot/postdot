# Herald design references

`DESIGN.md` at the repository root is the canonical, project-owned contract
for Herald's visual and interaction direction. The examples in this directory
are archived calibration evidence, not production routes, component specs, or
copy to reproduce literally.

## Archived examples

- [H-10 multi-surface holdout](examples/h-10-multisurface-holdout/) — the same
  Herald identity across Calendar, Queue, and Compose.
- [H-11 landing transfer holdout](examples/h-11-landing-holdout/) — the same
  identity transferred to two non-dashboard landing compositions.

## Using the references

Read the contract first. Use the examples to recover roles, relationships,
surface grammar, density changes, and the source-to-publications mental model;
bind the composition to current product content and states before changing
production UI. Do not copy the dashboard shell into a public surface, and do
not treat a holdout's placeholder content as a product decision.

If a rule is stable and accepted, update `DESIGN.md`. Keep unresolved visual
observations in `.autonomos/worklogs/`; keep future proof assets, audience,
proposition, and conversion decisions open until the product provides them.
