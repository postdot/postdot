## Objective

Exercise the merged media workflow through the authenticated dashboard using the
local storage adapter, without contacting a real publisher or external service.

## Verification

- Started the API on port `3001` and the Vite dashboard on port `5173` with the
  ignored local environment files.
- Confirmed `GET /health` returned HTTP `200`.
- Created a disposable project named `E2E-32 Local Media Smoke` and a manual
  channel named `E2E-32 Manual Channel` through the dashboard.
- Uploaded the local PNG fixture
  `/usr/share/devhelp/books/GXml-0.20/img/GXml.List.png` through the reserve,
  binary upload, and finalization lifecycle. The asset became verified and was
  previewed through Postbot's authenticated media route.
- Created and scheduled one mixed publication containing source text and the
  verified media asset.
- Created and scheduled one media-only publication containing the same verified
  asset.
- Reopened both publications in the editor. The mixed target preserved the body,
  asset identifier, and accessibility text; the media-only target preserved the
  asset identifier without inventing source body text.
- API logs showed only local authenticated Postbot requests. No LinkedIn request,
  external provider request, or automatic delivery occurred.
- The dashboard reload and editor inspections completed without new browser
  application errors after the local servers were ready.

## Result

The merged media route, local storage adapter, dashboard picker, publication
creation flow, persistence boundary, and editor inspection path work together in
the local development environment for both mixed and media-only publications.

The disposable records remain in the local development database only. They are
not repository artifacts and contain no provider credentials or external effects.
