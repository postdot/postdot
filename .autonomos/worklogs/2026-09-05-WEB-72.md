# WEB-72 — Start publication composition from a project calendar date

- Date: 2026-09-05
- Status: complete
- Issue: ISSUE-034
- Base: `d0f5242c583f5ff9d45f2f994b638877961a14e9`
- Branch: `web/72-calendar-compose-date`

## Objective

Allow a project owner to start a new publication from an empty calendar day with
that project's civil date carried into the compose flow, without creating or
scheduling a publication before the owner submits the form.

## Accepted scope

- Calendar creation affordances apply to empty days only.
- Scheduled publications keep their existing navigation to the publication
  detail surface.
- The compose route receives a validated `YYYY-MM-DD` project-date context.
- The first destination schedule is initialized on that project date using a
  deterministic project-local time; the owner can edit it before submission.
- Invalid, stale, or absent date context falls back to the existing compose
  default.
- Existing source, target, validation, media, and promotion boundaries remain
  unchanged.

## Plan

1. Add a small validated date-context contract for the compose route.
2. Pass empty calendar-day context through the typed TanStack Router search
   boundary and initialize the first target in the project timezone.
3. Add focused unit coverage for date-context validation and target defaults.
4. Add or update browser coverage for the calendar-to-compose interaction.
5. Run the full repository gate and record the final evidence.

## Constraints

- Do not add a new API endpoint or persistence shape.
- Do not auto-submit, auto-publish, or alter existing scheduled publications.
- Do not interpret the selected day in the browser timezone; the project
  timezone is authoritative.
- Keep the calendar and compose surfaces usable on small screens.

## Implementation

- Added a typed TanStack Router `date` search boundary for the compose route.
- Added strict civil-date validation and a project-date local schedule helper.
- Added empty-day calendar links for desktop, a date picker for the mobile
  agenda, and a project-date-aware calendar header action.
- Kept scheduled publication links on the existing publication detail route.
- Preserved the existing API, persistence, source, target, media, validation,
  and promotion contracts.
