# AUTH-636 Native session protocol qualification

Outcome: Existing signed human-session cookies pass the native HTTP protocol
qualification without server authentication changes. ADR-099 proposes that
transport for a first native adapter; mobile SDK/device acceptance remains separate.

Decisions: Preserve Bearer as the user API-key boundary. The optional Better Auth
bearer-session plugin alone would not change Postdot's domain-key dispatch.
Explicit cookie transports can omit ambient credentials and refuse redirects;
browser defaults remain unchanged. Test the initializer passed to fetch: Bun 1.4.4
reports Request.credentials as include even when initialized with omit. Origin
refusal belongs in production HTTPS acceptance because Better Auth's test default
skips it. Renewal reads explicitly process authentication Set-Cookie responses.

Validation:
- Format/lint/spelling/types and four-locale coverage → pass.
- Full unit/scripts → 1,908 passed; 11 existing opt-in skips.
- Persistent native-session scenarios → 5 pass on SQLite and PostgreSQL 18.
  Coverage includes signed-cookie integrity, raw-token/key separation, renewal,
  expiry, logout, password-change revocation, role changes, removed project grants
  and foreign-installation refusal.
- Raw HTTPS acceptance against the production bundle → pass without browser or
  automatic cookie jar: independent login, rejected origin, private binary image,
  authenticated project event, remote session revocation and stream closure.
- Existing separate-Studio production browser journey → pass, including scheduled
  worker delivery, media upload and SSE reconnection.
- Production build → all 22 packages pass. Docs export → 264 pages, 1,309 local
  targets, zero broken links.
- Footprint → API 5,763,537 bytes, anonymous JavaScript 167,828 gzip bytes and idle
  memory within unchanged budgets. No dependency or schema changes.

Open: ADR-099 is proposed, not a selected mobile framework or storage adapter.
Device TLS/storage, app/account switching, offline logout and native media/stream
lifecycle remain unqualified. Next recommended lot: trusted proxy client-IP
resolution and authentication rate-limit qualification identified in DEPLOY-635.
