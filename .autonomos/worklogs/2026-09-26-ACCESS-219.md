# ACCESS-219 — Complete the web password-reset journey

## Outcome

Implemented the browser-based password-reset journey for deployments with SMTP
configured. The login screen links to a localized request page; Better Auth sends
its one-use reset link; the localized completion page validates the token and
lets the user set a new password. The UI gives the same confirmation for known
and unknown email addresses. When SMTP is not configured, it now states truthfully
that password recovery is unavailable instead of implying an offline procedure
already exists.

The offline, operator-controlled recovery procedure remains ACCESS-220. ISSUE-062
therefore remains accepted rather than resolved.

## Decisions

- Reused Better Auth's existing reset endpoints and configured email template;
  no separate reset-token store or alternate authentication mechanism was added.
- Kept the request response non-enumerating: known and unknown accounts receive
  the same successful response and public confirmation. Only an existing account
  produces an email.
- Kept password reset unavailable when SMTP is absent and surfaced that state
  without promising an unimplemented local recovery procedure.
- Isolated Mailpit to the focused reset E2E run. The ordinary browser suite keeps
  its existing no-SMTP runtime and covers the unavailable state.
