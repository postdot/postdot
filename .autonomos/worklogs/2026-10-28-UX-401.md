# UX-401 — Detail continuity, recovery and destructive-action contrast

Status: complete
Related review: [UX-400](2026-10-28-UX-400.md)

## Delivered behaviour

- Destination editors, shared-post pages and source review use one paginated reader for a post's publications. The editor reuses its already requested first page, then follows cursors when needed. A 110-publication project no longer hides the older post's sibling destinations. No server endpoint or authorization contract changes. Completeness requires additional page reads in large projects; the first-page case adds no request.
- Shared-post review uses the management column for its source and peer-publication list. Destination editing uses the available work surface, including its comparison composer and access notices. Locked publication previews retain their readable inner measure.
- The shared-post query exposes read failures promptly instead of combining automatic query retries with the existing realtime refresh bursts. A 404 has an explicit unavailable state; technical failures retain explicit Retry. Existing source buffers and access-epoch guards remain mounted and protected.
- Publication loading failures retain the declared return: Queue by default, or Calendar with its date and reading view. Error pages have their own main landmark and update with the current locale. A transient publication failure can be retried successfully without losing calendar context.
- Rendered accessibility review found insufficient contrast on the shared destructive button: 3.5:1 in light and 4.12:1 in dark on the scheduled mobile surface. A separate semantic destructive foreground now gives its text enough contrast on the existing tinted normal/hover fills. Button geometry, confirmation and action behaviour are unchanged.

## Verification

- Detail review in English/dark and French/light: shared post, draft, scheduled and actually recorded manual publication at 1920/820/390 px; synthetic failed-provider presentation; 404 and 503 states; technical retry and calendar context.

- Existing sibling-source review, Queue to shared-post navigation and independent source saving with concurrent-change preservation.

The post keeps its declared management measure.

Seven shared-UI unit tests pass (63 assertions). Web, root and shared-UI TypeScript checks, changed-file lint/format, complete locale coverage and the repository `check:quick` gate pass. The narrow review-skill update also passes its validator; its Python YAML dependency was supplied through an isolated `uv run` environment without changing project dependencies.
