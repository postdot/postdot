# UX-402 — Invitations and access journeys

Status: complete
Related standard: [SPEC-010](../specs/SPEC-010-web-experience-standard.md)

## Scope and findings

Continue UX-401 with invitation management, invitation entry and role-based access. The project invitation destination now joins the authenticated route registry with its existing settings shell and management column. The public invitation entry remains outside that authenticated registry.

A real installation invitation with an intercepted 503 preview response rendered “Invitation unavailable”, a generic request failure and only a sign-in return. The baseline regression failed on the missing technical-error heading; its screenshot confirms the misleading terminal presentation. Under JRN-02, a missing invitation surface must explain the observed cause. A technical failure does not establish that the invitation is invalid. This also supports the completeness value by making recovery available on the affected surface. The repair separates unavailable invitations from retryable reads and reuses existing localized error/retry wording.

Source inspection also found that installation invitations swallowed session-read failures as signed-out state, while organization invitations labeled any session failure as an unavailable invitation. Both reads now offer an explicit retry. Concurrent preview/session loading and cancellation guards remain; authentication, acceptance, invitation expiry and authorization contracts are unchanged. An extra read occurs only when the person requests another attempt.

The authentication shell's unnamed decorative section also placed its visible brand text outside any accessibility landmark. Axe reproduced this on the desktop invitation error surface. It is now a named complementary landmark; visual composition and authentication controls are unchanged.

## Validation

Nine distinct focused browser scenarios pass:

- Existing project owner invitation creation/resend/acceptance, member role update and removal.
- Existing workspace invitation, group membership, access withdrawal and restoration.
- Existing viewer read-only and editor mutation boundaries.
- Existing installation administrator invitation creation/copy/revocation/acceptance.
- Existing installation administration refusal for a member.
- Two English/dark and French/light recovery journeys: project invitation management, real installation invitation preview after an intercepted 503, explicit retry, real revocation and expiry, and unknown or missing links.
- Two session-discovery recovery cases, one installation and one organization invitation. The organization case intentionally does not accept its synthetic invitation identifier; real project/workspace acceptance is covered by the existing scenarios above.

The final six-case browser run passed in 47.2 seconds. The three project/workspace/role scenarios passed in the earlier combined run, whose overall exit was nonzero because the new recovery cases still needed corrections. Intermediate collector failures included using a link locator for a Base UI return control exposed as a button, the first recovery component lacking a semantic heading, and the genuine authentication-shell landmark finding. Assertions were retained and the final recovery presentation has its own page heading, retry and sign-in return.

At 1440 and 390 px, the bilingual management and technical-error surfaces pass Axe and horizontal overflow checks. Captures were inspected for the desktop project-management page and both mobile error locales. Invitation state tests use real isolated server data: a short supported `expiresAt` is allowed to expire and its public preview is observed returning 404 before the page is inspected. No database clock, live development account or external email/provider service was modified.
