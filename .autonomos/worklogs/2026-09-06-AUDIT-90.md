## Confirmed finding and disposition

### SECURITY-91 — per-instance OAuth token requests bypassed the egress policy

**Severity:** high security boundary defect.

The provider API calls used the injected controlled fetcher, but
`exchangeAuthorizationCode` and `refreshAccessToken` in `@herald/oauth` used the
global `oauth4webapi` fetch implementation. A project-selected Mastodon instance
could therefore receive token-endpoint traffic outside the DNS pinning and
operator private-destination policy described by ADR-043.

The issue was fixed in SECURITY-91:

- OAuth now exposes an injected `OAuthFetcher` for token exchange and refresh.
- `oauth4webapi` receives it through `customFetch`.
- Mastodon callback and worker refresh paths pass the existing controlled fetcher.
- Regression tests prove both OAuth operations use the injected transport.

PR #100 was verified by CI and merged into `main`. No other direct Mastodon
per-instance transport bypass was found in the inspected API composition path.
