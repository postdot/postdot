# UX-247 — Recompose publication authoring

- Date: 2026-09-28
- Status: In progress; owner visual checkpoint pending
- Related issues: ISSUE-099, ISSUE-100
- Authority: Owner rejected the current new-publication presentation and asked for direct corrections to the redundant timezone copy, preview, and multichannel editing controls.

## Starting evidence

The authenticated French `/publications/new` view shows the project name plus
`UTC` under a breadcrumb that already identifies the project. The scheduling
surface repeats `Project time · UTC`. A visible `Preview` label sits above a
generic manual-channel card with only an avatar and skeleton lines when empty.
Destination checkbox cards, a separate `Shared content`/channel dropdown, and
an exposed `Use shared content` action compete to explain the same fan-out.
The owner supplied a screenshot and explicit feedback. The live page was
inspected without changing the owner's draft state.

## Working contract

Preserve the existing publication model and recovery data. Propose a single
editing rail with common copy and selected channels, explicit add/remove
actions, channel-specific editing on the same canvas, and a compact reset for
an adapted channel. Make the preview identify its purpose through its rendered
post shape and channel chrome. Review the implementation in the live app before
promoting any new design rule.

## Implementation and validation

The candidate now uses one navigation rail: `Common`, selected channels, and an
explicit add-channel menu. Each selected channel has a separate accessible
remove control. Selecting a channel shows its text and preview without creating
an override; the first text edit creates the override. A small reset action
appears only for an adapted channel. The shared and per-channel delivery
defaults remain independent of text and retain the existing data contract.

Removed the project/time-zone subtitle, the scheduling time-zone caption, and
the visible preview heading. The preview retains an accessible name. Manual
and custom channels now use social-post chrome with avatar, menu and reaction
icons; LinkedIn retains its recognizable action labels. An explicitly cleared
channel adaptation renders empty rather than silently falling back to common
text. The project time zone is still applied by the date/time control.

Visually inspected the authenticated French page at desktop, 820 px and 390 px. The
first narrow rendering exposed a visible rail scrollbar and a compressed add
action; revised the rail to hide its scrollbar and show the add icon at narrow
width while retaining its accessible name. The owner's existing tab/draft was
observed without editing its content, and the viewport override was reset.

Focused validation: preview model unit tests (3), X weighted-text and narrow
composer E2E tests (3), and the full mixed/media-only authoring E2E scenario
(1) pass. The latter test was updated to follow the unified editing rail and
its existing per-channel delivery details. The first full `bun run check` passed
format, lint, typecheck, unit tests, and 37/38 browser tests; its sole failure
was a stale Overview assertion expecting counters removed in UX-240. Updated
that test to assert the accepted manual-work/next-publication summary; its
focused rerun passes. Final `bun run check:quick`, the focused browser rerun,
and `bun run build` pass. The full suite has not been rerun after this isolated
test assertion correction.

Files changed for this task: `apps/web/src/components/new-publication-page.tsx`,
`publication-target-list.tsx`, `publication-draft-preview.tsx`,
`apps/web/src/lib/publication-preview.ts` and its test,

At that stage, the next action was the owner's visual checkpoint and full
gate. The owner instead requested the further refinement documented below.

## Owner refinement — visible channel movement and quieter scheduling

The owner approved the clearer editing model but rejected the remaining menu
friction and the exposed bottom form. They described a two-sided channel rail:
selected destinations on the left, muted available destinations on the right,
with direct transfer on click and motion that explains the action. They also
identified the reversed back-link placement, repeated page title, misleading
project breadcrumb, and the orphan slash on mobile.

The new-publication rail now shows both sets at once. Available channels add
with one activation, and removing a selected channel returns it to the
available group. A shared layout animation illustrates the transfer; reduced
motion disables it. Focus follows the moved channel for keyboard use. Delivery
and scheduling now live in a native disclosure summarized by the planned
date and delivery mode, so the form appears only on demand. The main heading
appears once with a correctly sized mobile back button to its left. The app
header omits the pseudo-breadcrumb on this route; it shows the project context
only when the sidebar cannot show it (collapsed or mobile).

The French live page was inspected at 390 and 820 px, including the open and
closed scheduling state. The existing browser draft was not edited, and the
temporary viewport override was reset. The focused narrow E2E scenario passed
after direct add/remove and keyboard focus checks. `bun run check:quick`
passes. The full `bun run check` completed formatting, lint, types, unit
tests, and 34/38 browser tests before the isolated Vite dev server crashed in
Node's Buffer.byteLength while serving a 41 MB transformed module
(fatal V8 optimization error, SIGILL).
The four remaining browser scenarios all passed on a fresh isolated server.
The separate production build passes across 17 packages; the two password
reset E2E scenarios also pass. The owner's visual checkpoint remains open.
Keep the task in progress and do not promote provisional styling into
`DESIGN.md` until that checkpoint.
