# AUTH-648 Implement token-gated zero-window instance bootstrap and CLI/Studio setup onboarding

- Outcome: Eliminated the unauthenticated first-user signup window on production/token-gated deployments by adding `POSTDOT_BOOTSTRAP_TOKEN` / `POSTDOT_BOOTSTRAP_TOKEN_FILE` / `POSTDOT_BOOTSTRAP_TOKEN_HASH` / `POSTDOT_BOOTSTRAP_MODE`, automatic `0600` `<dataDir>/bootstrap-token` provisioning in `NODE_ENV=production` (`token_required`), atomic `POST /api/instance/bootstrap` with optional initial user API-key minting, offline `account bootstrap` support for PostgreSQL (`--database-url` / `POSTDOT_DATABASE_URL`) and initial API-key issuance (`--issue-api-key`, `--api-key-name`, `--api-key-output`, `--json`), and Studio `/setup` token onboarding with 4-locale i18n (`en`/`fr`/`es`/`de`).
- Decisions:
  - Kept development/test default `bootstrapMode` as `'open'` when no token is configured outside `NODE_ENV=production` so existing dev/E2E workflows stay intact while `NODE_ENV=production` defaults to `'token_required'` unless `POSTDOT_BOOTSTRAP_MODE=open` is set explicitly.
  - Gated Better Auth `sign-up/email` with `runWithAuthorizedBootstrap(...)` (`AsyncLocalStorage`) inside `POST /api/instance/bootstrap` and offline `account bootstrap` instead of modifying public signup semantics globally.
  - Wrapped `account bootstrap` DB user creation, immediate session cleanup, and optional initial API-key minting in a single transaction, writing `--api-key-output` cleanly with `O_WRONLY | O_CREAT | O_EXCL | O_NOFOLLOW` and `0o600` permissions.
