# TELEGRAM-503 — Storage-to-worker media acceptance

## Outcome

Extended the existing actual SQLite worker test to cover photo and H.264 video from reserved upload through local storage, finalization, execution snapshot, multipart delivery and durable publication/media identities. All files use a unique temporary root, synthetic credentials and injected provider responses; cleanup removes only that root.

The first complete scenarios exposed a production defect: Bun returned an untyped Blob despite Response Content-Type, so the protocol rejected both media families. The adapter now constructs the Blob with the inspected pinned MIME explicitly. Byte size and checksum verification remain unchanged. This keeps the existing bounded in-memory upload policy; no streaming claim.

Assertions inspect captured requests outside the injected fetcher, because protocol uncertainty handling intentionally catches transport errors. They prove exact uploaded bytes, MIME, caption, destination, correct photo/video method, one pinned execution asset, remote media identity persistence and no subsequent send after completion or ambiguity. A definite 429 first refusal leaves a failed media delivery that retries once to success.
