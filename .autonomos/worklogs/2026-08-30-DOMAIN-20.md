## Objective

Implement the shared in-memory contracts needed by later persistence, media,
custom-channel, and editor work without changing the current database model in the
same task.

## Plan

1. Define source content, channel profile, capability, field-binding, and normalized
   validation issue contracts in `@herald/core`.
2. Implement the accepted bounded JSON Schema policy and a deterministic validation
   path with no coercion or default insertion.
3. Cover representative built-in and runtime-defined custom profiles, including
   adversarial resource and keyword limits.
4. Run all repository quality gates, record material measurements and decisions,
   and crystallize the completed task.

## Progress

- Created `feat/domain-20-content-contracts` from clean `main` at `a55b104c`.
- Confirmed that persistence migration remains scoped to DOMAIN-21.
- Added the fixed source-content vocabulary with plain-text or Markdown body,
  publishable headline, BCP 47 language, and ordered media references. Runtime
  validation preserves caller data and rejects blank semantic values.
- Added module-owned channel profile contracts for field bindings, editor-facing
  text and media capabilities, capability relationships, immutable profile/schema
  identities, and manual, built-in, or declarative HTTP execution references.
- Added one normalized validation protocol for schema, schema-policy, binding,
  capability, domain, and module checks.
- Added a lazy TypeBox JIT compiler shared by built-in TypeBox schemas and native
  runtime JSON Schemas. Compiled validators are cached by immutable profile identity,
  version, and schema hash; profile snapshots are deeply frozen, and conflicting
  cache identities fail closed.
- Added the Draft 2020-12 validation meta-schemas required before Herald policy
  validation. The custom policy rejects remote or dynamic references, custom IDs and
  vocabularies, unknown keywords, regular expressions, executable formats, open
  object shapes, unbounded strings and arrays, invalid JSON, and resource-limit
  violations. It never calls conversion, cleaning, or default insertion APIs.
- Made TypeBox 1.3.20 a direct `@herald/core` dependency. Version 1.3.22 was checked
  and exercised but produced a second resolved TypeBox copy beside the current
  Elysia v2 OpenAPI beta peer setup. The repository therefore keeps the already
  tested 1.3.20 version until that peer boundary can be upgraded without duplication.

## Implemented resource ceilings

- Schema JSON: 64 KiB, depth 16, 256 schema nodes, 64 properties per object,
  64 definitions, 16 composition branches, and 64 enum values.
- Schema-declared strings and arrays: finite maxima required, capped at 1,000,000
  characters and 10,000 items respectively.
- Target content JSON: 1 MiB, depth 64, 100,000 values, 1,024 properties per object,
  and 10,000 items per array.

These are parser and resource-safety ceilings, not provider capabilities. Immutable
channel profiles declare their smaller destination-specific constraints.
