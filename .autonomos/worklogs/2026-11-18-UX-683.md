# UX-683 Edit mode and route unification on the shared composer (SPEC-013)

Outcome: Editing a post uses the composer that creates one. `/posts/$postId` opens on "All channels"; `/publications/$publicationId` opens the same editor on that channel's tab. Channel state and actions sit above the editor, Content options, outcome, comments and activity below. The per-publication editor, the post source page and their messages are retired (about 3,100 lines). UX-684 (production composer specs and the Channels audit locator) closed with it.

Decisions:

- One "Save" applies every channel with pending changes, including a never-applied draft version. The editor is read-only while it applies. An application whose result is unknown blocks "Save" and that channel's date until the server is checked; discarding text does not settle it.
- A failed autosave for a passing reason (network, 5xx, 429) is tried again every 5 s; validation errors wait for the next edit.
- Checking the server after an unknown application keeps an unsaved local edit in place, with no recovery dialog.
- A change made elsewhere is told once: one conflict card about the post ("This post changed elsewhere"), no second status line.
- The multi-channel version update keeps going while the editor refreshes after each channel; each write is still checked against its expected revision.
- The local copy decision shows the post text once, then only the channels whose version or date differ, with real media.
- The post loader lives in its own module so route loaders do not pull the editor into the application entry (anonymous login budget).
- Auth pages subscribe to the language so a lazily loaded catalog re-renders them; found through the French setup journey.
- Kept: the Media field in Content options, because it is where image alternative text is edited; the inline media row does not offer it. Removing that duplicate needs alt text editing in the composer first.

The previous full run had 21 failures; each was fixed or explained above.
- `publication-concurrent-editing.spec.ts` migrated: 18/18. Composer production specs (UX-684): 15/15. Experience audit (opt-in): 2/2.
- `check:quick` on every commit; web unit tests 375 pass.
