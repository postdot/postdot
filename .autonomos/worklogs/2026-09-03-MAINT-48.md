# MAINT-48 — Extract publication authoring read models

- Date: 2026-09-03
- Status: completed
- Scope: `packages/db` publication authoring reads and draft mutations
- Task: MAINT-48
- Related issues: ISSUE-016, ISSUE-020

## Objective

Reduce the responsibility concentration in
`packages/db/src/manual-store/publication-authoring-store.ts` by isolating its
read-only publication authoring models: the working draft, editor state, and
publication summaries. Keep draft source synchronization, rebasing, and target
promotion transactions in the mutation store.

## Boundary and invariants

- Preserve the `createManualStore` and `createPublicationAuthoringStore`
  facades and all public types.
- Preserve project and actor scoping for every read.
- Preserve the editor state's relationship checks between publication, post,
  channel, profile, draft, and selected target revision.
- Share the working-draft loader between read and mutation paths; do not copy
  equivalent SQL into two modules.
- Preserve all draft write-conflict checks, source revision rules, target
  promotion rules, job reconciliation, and transaction boundaries.
- Keep this as a database-backed read-model extraction; do not introduce a
  generic repository or change the domain model.

## Alternatives considered

- Keep reads and mutations together: rejected because the read model has a
  separate responsibility and currently accounts for a substantial part of the
  authoring store's queries and public methods.
- Duplicate the working-draft query in a new read module: rejected because it
  would allow read and mutation paths to drift and increase maintenance cost.
- Build a generic query/repository layer: rejected because the boundary is
  specific to publication authoring and does not justify a wider abstraction.

## Verification plan

- Preserve the existing editor, draft, rebase, promotion, scheduling, and
  source-conflict tests.
- Run focused database tests and the full repository quality gate.
- Obtain an independent read-only review before opening the remote PR.

## Implementation

The publication authoring read model now lives in
`packages/db/src/manual-store/publication-read-store.ts`. It owns the working
draft, editor state, and publication summary queries, including their existing
project and actor scoping and relationship checks. The read store also exposes
one internal working-draft loader that the authoring mutation store reuses, so
the read and write paths do not carry duplicate draft SQL.

`publication-authoring-store.ts` retains source synchronization, draft save,
rebase, target promotion, job reconciliation, conflict checks, and transaction
boundaries. Its public facade still exposes the same authoring read and mutation
methods through `createManualStore`.
