# CHANNEL-479 — Profile preservation spike

## Completed

Built an isolated, unconnected prototype for targeted title/message required and
maximum edits. It uses core validation before and after edits, preserves unrelated
definition data, rejects provider-owned execution and refuses unsupported
constraint combinations. No production import, persistence or external effects.

Nine tests cover real manual/webhook presets, X-derived weighted counters,
optional presence versus empty content, semantic validation, preserved enum rules,
invalid bounds, inconsistent dual bounds, valid root composition and relations.
No-op output preserves original definitions.

## Findings and limitations

Targeted editing is feasible for direct simple fields. Preservation is not enough
to claim arbitrary profile support: schema-level conditions and relations require
explicit projection. A form cannot silently replace richer definitions.
Media mutation, transport authoring and activation/adoption are not implemented.

An initial forbidden-pattern fixture and incompletely bounded trusted-profile
copy were rejected by real policy. Corrected fixtures use a supported enum and
existing preset conversion. A root-composition test was also corrected to meet
the current bounded object policy; the final test asserts input validity before
asserting the editor's refusal. Moved the experiment under the web app because
its real preset module uses the app's TypeScript alias.
