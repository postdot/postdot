# PROVIDER-94 — DEV.to built-in channel

## Objective

Add a DEV.to built-in provider vertical slice using the Forem API v1 while
preserving project-owned publisher credentials, the shared built-in provider
contract, durable execution semantics, and the source/target content boundary.

## Session start

- Base branch: `main` after the merged X provider change.
- Branch: `feat/provider-devto`.
- Worktree: canonical checkout.
- No real DEV.to credentials or external requests will be used during implementation.

## Initial plan

1. Confirm the current Forem API v1 article contract and the existing provider
   composition conventions.
2. Implement the package-level DEV.to contract, article profile, API-key
   publisher, and deterministic tests.
3. Integrate the project connection flow, provider registry, conformance tests,
   package manifests, workspace, and Docker inputs.
4. Run the complete repository, E2E, and container gates before handoff.

## Open decisions

- Confirm whether DEV.to article title and Markdown body can be represented by
  the current source content vocabulary without weakening the shared boundary.
- Keep organization publishing out of this first provider slice unless the
  existing destination model already supports it without a new ownership
  decision.

## Implementation

- Added `@postbot/devto` with the Forem API v1 contract, article profile,
  API-key verification, article creation, bounded request timeouts, and
  provider outcome classification.
- Added the project-owned DEV.to connection route and policy. The route
  verifies `GET /api/users/me`, encrypts the API key through the existing
  publisher credential store, records the account destination, and never
  returns the key.
- Added the `devto` channel profile and web onboarding flow. Postbot maps the
  source headline and body into a DEV.to article and supports one JPEG/PNG
  main image through signed public media delivery.
- Registered the provider in the built-in execution registry, API composition,
  Docker manifest, workspace, lockfile, and shared adapter conformance suite.
- Added focused publisher, profile, route, and execution-adapter tests. The
  execution tests cover signed image delivery, authentication reconnect
  behavior, and fail-closed media validation.
- Added ADR-045 with the provider boundary and explicitly deferred
  organization publishing, tags, series, canonical URLs, and other provider
  metadata until their product semantics are decided.

## Verification

- `bun run check` passed: format, lint, typecheck, all package tests, the
  Playwright E2E suite (1/1), and the production build.
- The production image built successfully as
  `postbot-provider-devto-review:2026-09-06`.
- `bun run autonomos status` confirmed protocol v0.6.0-alpha artifacts match.
- No DEV.to credentials, real account verification, or external article
  publication was performed. The live-provider check remains a separate
  operator validation step.

## Final crystallization

- PROVIDER-94 is complete on `feat/provider-devto` and ready for PR review.
- ADR-045 remains proposed for governance review; implementation does not
  silently expand the destination model to DEV.to organizations.
