# AUDIT-125 — Post-sprint UX/UI reconciliation

- Date: 2026-09-09
- Status: internal validation recorded; independent external audit still open
- Base: `141e5447` (`origin/main`, integrated UX/IA stack)
- Integration: PR #148 (`chore(web): integrate UX and IA sprint`)
- Scope: read-only browser validation of the authenticated web client after the
  UX/IA stack was integrated. No product code or provider action was changed.

## Method

The pass used an isolated worktree with an isolated API/database and web server
(`127.0.0.1:3201` / `127.0.0.1:5175`). A synthetic account and project were
created. The following routes were visited directly and through navigation:

- Overview
- Calendar
- Queue
- Compose
- Channels
- Media
- Access

The pass also opened the notification sheet, switched English/French, and
switched dark/light themes. Accessibility trees and desktop screenshots were
checked. The existing Playwright and repository gates had already passed on the
integrated PR.

## Confirmed strengths

- The authenticated shell keeps project context visible in the breadcrumb and
  sidebar while preserving direct project URLs.
- Each inspected route exposes one primary `h1`; navigation controls and form
  fields retained accessible names in both tested locales.
- Calendar has a real date-oriented entry path even with no scheduled work.
- Queue, Calendar, and Compose now have visibly different jobs instead of one
  undifferentiated dashboard surface.
- Notifications use a non-blocking right-side sheet and preserve an explicit
  preferences action.
- The light theme preserves the same semantic role mapping as dark mode.

## Findings to carry forward

### P2 — Queue filter strip shows an unintended scrollbar affordance on desktop

At the tested wide desktop viewport, the four Queue filters fit in the available
space, but the TabsList still exposes a small vertical scrollbar/arrow affordance
at the right edge. This looks like a leftover overflow state rather than a useful
interaction. It should be confirmed at the supported desktop and tablet widths,
then fixed in the shared tabs/layout contract rather than hidden on one page.

Related work: `DESIGN-120`, `DESIGN-121`, `ISSUE-064`.

### P2 — Empty-state grammar is improved but still repetitive

Overview and Queue still use a large centered empty card with similar icon/title/
description grammar. Channels compounds this with two vertically stacked empty
surfaces for channels and publication connections. The distinction is valid, but
the visual weight remains close to the pre-sprint pattern and makes the operator
scan two explanatory blocks before taking the single available action.

Related work: `WEB-119`, `WEB-122`, `DESIGN-98`, `ISSUE-063`, `ISSUE-065`.

### P2 — Compose and Access remain information-dense for their first visit

Compose still exposes source guidance, media guidance, destination guidance,
delivery mode, schedule, timezone, and recovery copy in one long vertical task.
Access uses a title, a long explanatory paragraph, and two management surfaces.
The content is accurate and accessible, but it is not yet the calm progressive
disclosure described by the accepted design direction.

Related work: `DESIGN-98`, `DESIGN-120`, `ISSUE-063`, `ISSUE-065`.

## Not concluded by this pass

This was an orchestrator validation pass, not an independent review. It did not
close `AUDIT-125`. It also did not establish the populated multi-channel,
failed/ambiguous, media-upload, or narrow-mobile visual matrix; those states
remain required before declaring the UX sprint complete.

## Decision

No production correction is justified solely by this pass. Keep the findings in
the existing UX/IA issues, obtain the independent post-sprint audit, and use the
result to prioritize the next implementation task instead of starting another
unbounded visual rewrite.
