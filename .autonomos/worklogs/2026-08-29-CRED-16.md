# CRED-16 — Project-owned encrypted publisher credential storage

- Date: 2026-08-29
- Status: completed
- Related issue: [ISSUE-006](../ISSUES.md)
- Decision: [ADR-012](../decisions/ADR-012-own-publisher-credentials-and-use-oauth4webapi.md)

## Scope

- Add the project-owned publisher credential domain entity and SQLite schema.
- Add a focused AES-256-GCM boundary with versioned envelopes and field-bound
  authenticated data.
- Add an internal store that never returns token material from metadata methods.
- Prove encryption, tamper detection, wrong-key failure, lifecycle updates, and
  project deletion semantics.
- Do not implement OAuth authorization attempts or migrate LinkedIn routes and
  workers in this task.

## Notes

- CRED-16 is stacked on the accepted CRED-15 decision branch while PR #1 remains
  open. It will be rebased onto `main` after that PR is merged.
- The installed Bun/Drizzle skill references `references/migrations.md`, but that
  file is absent from the installed skill. Postbot's committed migration conventions
  and migration tests are used instead.

## What was done

- Added a framework-independent `PublisherCredential` entity with project ownership,
  external account metadata, normalized scopes, explicit health state, expiration,
  and connection attribution.
- Added the `publisher_credentials` table and migration `0005_fuzzy_namor.sql` with
  project-scoped uniqueness, composite actor attribution, lifecycle constraints,
  optimistic revisioning, and no Better Auth user or account reference.
- Added a focused AES-256-GCM cipher using Bun Web Crypto. Each field receives a
  fresh 96-bit nonce and authenticated data bound to the envelope version,
  credential ID, provider ID, and secret field.
- Added an internal credential store that separates metadata from secret resolution,
  serializes duplicate connection attempts, rotates tokens with an optimistic
  revision check, preserves refresh tokens when providers omit replacements, and
  fails closed on unavailable or invalid credentials.
- Revocation now clears every persisted secret field while preserving non-secret
  project metadata. Reconnection can reactivate the same project credential.

## Verification

- Proved round trips, nonce uniqueness, context binding, wrong-key failure,
  ciphertext tampering, unsupported versions, and invalid key lengths.
- Proved that plaintext access and refresh token bytes never appear in a real SQLite
  database file.
- Proved project deletion cascades credential deletion and that the credential table
  has no foreign key to Better Auth `user` or `account` tables.
- Proved incomplete envelopes, cross-project actor attribution, concurrent creation,
  concurrent rotation, refresh-token preservation/removal, reconnect-required state,
  revocation, and reactivation.
- `bun run check` passes with 97 tests across the repository.
- `git diff --check` and the Autonomos protocol status pass.

## Footprint

- No runtime dependency was added; cryptography uses Bun Web Crypto.
- The `@postbot/db` Bun bundle increased from 63,580 bytes to 67,978 bytes: a 4,398
  byte increase for the cipher and complete credential store boundary.
