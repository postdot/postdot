## Changes

- The release workflow accepts explicit alpha/beta/rc or stable version tags
  instead of hardcoding the first tag. Alias rejection, existing-tag refusal,
  main/source validation, CI and visibility acknowledgement remain intact.
- A required previous-image digest reaches native candidate acceptance. The
  release preflight refuses mutable previous tags and foreign image namespaces.
- `production-container-upgrade.py` seeds the previous immutable image through
  its real HTTP API with an account, project, manual channel, draft and PNG.
  It takes a complete backup with the previous executable, starts the candidate
  over that volume, logs in and checks retained identities/editor state and
  byte-identical media. A successful candidate write establishes normal operation.
  It then restores the pre-upgrade backup into another volume with the previous
  executable, verifies the original data, absence of later writes and recovery
  hold's HTTP 503 refusal. Containers and data are task-owned and cleaned up;
  no provider connection is created.
- Native candidate jobs now run both recovery acceptance and this upgrade/restore
  check before the publication job can run.
- Corrected two CI failures introduced in ONBOARD-582: ten help subprocesses
  previously shared one five-second test budget; each flag/command now has its
  own test and cleanup. The bilingual setup test previously registered two init
  scripts with unspecified ordering; each language now has a separate context.
  Assertions and product behavior are unchanged.
