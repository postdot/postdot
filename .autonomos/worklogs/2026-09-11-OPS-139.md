# OPS-139 — Isolate concurrent E2E runtime resources

- Status: completed
- Date: 2026-09-11
- Scope: Playwright runtime allocation, E2E API startup, test output, and teardown ownership
- Related issue: [ISSUE-025](../ISSUES.md#issue-025-isolate-concurrent-local-and-test-runtime-resources)
- Related task: [OPS-139](../TASKS.md#runtime-isolation-follow-up)

## Implementation

The Playwright configuration now obtains a per-invocation runtime from
`scripts/e2e-runtime.ts`:

- `mkdtemp` creates a unique direct child of the OS temporary directory for the
  SQLite database and local media store.
- Free loopback ports are selected independently for the API and Vite server;
  `POSTBOT_E2E_API_PORT` and `POSTBOT_E2E_WEB_PORT` remain available for explicit,
  caller-reserved debugging ports.
- Test artifacts use a run-specific `test-results` directory.
- Playwright worker configuration loads reuse the parent runtime through the
  propagated data-directory and port environment variables instead of creating
  new resources.
- The API launcher validates the database and media paths against the generated
  root, and global teardown removes only that exact safe root. The previous
  fixed `postbot-e2e-data` directory is rejected by the safety check.

The normal development runtime remains on its operator-owned configured ports
and database/media paths. This change isolates E2E invocations without silently
changing the lifecycle of the shared local development server.

## Verification

- `bun test scripts/e2e-runtime.test.ts` — 4 passed, covering concurrent
  allocation, legacy-root rejection, explicit debug ports, and worker reuse.
- Two concurrent `bunx playwright test e2e/realtime-validation.spec.ts` runs —
  3 passed in each run on distinct dynamically selected ports.
- `bun run test:e2e` — 15 passed with the default eight-worker local runner after
  extending only the realtime assertion window to tolerate concurrent API load.
- `CI=1 bun run test:e2e` — 15 passed with the repository's one-worker CI gate.
- `bun run test:unit` — all package test tasks passed.
- `bun run format` — passed.
- `bun run lint` — passed.
- `bun run typecheck` — passed.
- `bun run build` — passed.
- After the runs, no `/tmp/postbot-e2e-run-*` data directory remained. Initial
  empty roots produced by the first multi-process implementation were removed
  individually after validation; no application data was involved.

The initial default local eight-worker suite exposed an intermittent realtime
`expect.poll` timeout under concurrent API load. The assertions now use a
10-second polling window, still bounded by the test timeout, so the local gate
matches the concurrency it already permits. This is test-harness timing only;
no realtime product behavior was changed.
