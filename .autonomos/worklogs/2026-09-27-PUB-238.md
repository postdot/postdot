## Delivered

- Added a durable approval-request table tied to the exact draft revision and
  immutable target revision. Request submission and the first target snapshot
  are atomic.
- A key with `publication:manage` can submit an unscheduled draft and proposed
  delivery time. The proposal does not set `scheduledAt`, create a worker job,
  or trigger a provider call. Direct scheduling remains guarded by
  `publication:dispatch`.
- Approval, rejection, and pending-request reads require a human session with
  project editor access. Approval promotes only the requested immutable
  revision and creates executable work in one transaction. Rejection leaves
  the publication as an editable draft; a subsequent edit supersedes the
  pending request.
- An overdue proposal stays inert. Approval requires a newly chosen future
  time or an explicit `publishNow` action. The immediate run time is resolved
  inside the promotion transaction, avoiding a stale client/server timestamp
  race.
- Added a compact localized review queue to the publication queue, including
  overdue recovery actions and realtime cache invalidation. Documented the API
  key and human-session boundaries in
  [user-api-keys.md](../../docs/security/user-api-keys.md).
- No agent-specific identity or new CLI/MCP client was added.
