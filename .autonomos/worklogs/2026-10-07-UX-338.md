# UX-338 — Discord Multiline Quote and Subtext Preview

- Base: `3a064e8f2`.
- Status: complete; full validation passed.

## Rendering change

The existing remark transformer now adapts native multiline quotes and subtext in
its parsed tree. A leading `>>>` quote has its extra CommonMark containers removed
and includes the remaining message blocks. Paragraph text lines beginning with
`-# ` become smaller block-level text while adjacent ordinary lines stay normal.
Nested emphasis, underline and spoilers keep their existing rendering.

The renderer does not rewrite the body string. Source text, storage, publisher
payloads and notification suppression are unchanged. HTML is not enabled, remote
images remain disabled, and preview links do not navigate.

Subtext is identified from original source lines rather than decoded text alone:
escaped markers therefore remain literal. Code is an opaque leaf. If an opaque
multiline inline token prevents line correspondence, the paragraph is left
unchanged instead of being destructively split. This is an explicit approximation
for complex mixed-line constructs, not a complete Discord parser. No native
identity or emoji resolution, embeds, or new dependency was added.

The [official Discord formatting guide](https://support.discord.com/hc/en-us/articles/210298617-Markdown-Text-101-Chat-Formatting-Bold-Italic-Underline),
consulted on 2026-10-07, documents `>>>` for multiline quotes and `-# ` at the
beginning of a line for subtext. Native client pixel fidelity is not claimed.

## Proofs

Two new unit regressions failed before implementation: triple nested quote
containers and literal subtext. Four added tests cover one quote containing later
paragraphs, line-specific smaller text with marks, escaped/code markers, and
spoilers plus unsafe content inside the new structures. Existing underline,
strikethrough, spoiler and security tests remain intact. Ten tests passed.

The existing destination preview scenario now asserts one quote, inclusion of the
final paragraph, subtext and nested marks, smaller computed font size, no page
overflow at 1280 and 390 pixels, screenshots in both themes, and unchanged source
text on returning to the common tab. Light and dark narrow screenshots were
inspected: normal lines remain full-sized; subtext occupies one smaller line;
one border contains both quote paragraphs without nested indentation.

## Neighboring defect discovered (UX-339)

The expanded theme traversal exposed a real existing dark-theme editor contrast
failure: native HTML `mark` defaults to black text, while the Discord spoiler mark
uses a dark blue translucent background. Axe reported 1.78 contrast for the rich
editor marks, not the preview. A focused run failed at the existing accessibility
assertion. The editor now explicitly inherits mark text color. The dark theme is
kept through the spoiler check instead of restoring light to hide this defect.
No accessibility assertion was removed or weakened.

One isolated unit invocation encountered an intermittent Bun CommonJS/ESM loader
error in the existing spoiler dependency before tests ran. An unchanged rerun
passed all ten tests. No dependency or loader workaround was introduced; the full
unit gate will check the final state.
