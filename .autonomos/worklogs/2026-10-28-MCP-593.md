# MCP-593 — Hosted MCP endpoint

Owner reopened ISSUE-036 on 2026-10-28 and chose a hosted HTTP endpoint (not a local stdio relay) with
full parity with the CLI's project workflows. Decision record: ADR-096.

## Delivered

- `POST /mcp` in the API: stateless Streamable HTTP (JSON responses; 202 for notifications; 405 for GET and
  DELETE), `initialize`/`ping`/`tools/list`/`tools/call`, protocol versions 2025-06-18, 2025-03-26 and
  2024-11-05. Implemented directly (about 150 lines) rather than adding the SDK's express/hono/zod tree to the
  image; the official SDK client is a test-only dependency of `@postdot/api`.
- Authentication: Bearer user API keys only (the same verifier as the API, now shared in
  `access/user-api-key-authentication.ts`); cookies are never read; browser `Origin` must be a configured
  origin; invalid key → 401 with `WWW-Authenticate`.
- Authorization: none of its own. A call is dispatched in-process through `app.handle` with the caller's
  `Authorization` header, so roles, project scope, capabilities, lifecycle guards, revisions and attribution
  are the API's. `tools/list` and `tools/call` hide tools whose capability the key lacks.
- 72 explicit tools (`tool-catalog.ts`), inputs derived from the live OpenAPI document (path and query
  parameters plus flattened JSON body; `attachProjectChannel` and `transferProjectChannelManagement` rename
  the body `projectId`). Annotations come from method, capability and catalog flags. Confirmation: every
  `publication:dispatch` operation always requires `confirm: true`; `createPost` only when it asks for
  automatic delivery or a time; sharing, cadence, movement, archiving and provider analytics refresh too.
- Not exposed: session-only surfaces, provider connection and custom HTTP secrets, audit, binary upload and
  streaming (import from URL instead), permanent deletion.
- `POSTDOT_MCP_ENABLED` (default true). Responses above 100,000 characters are truncated with a notice.
- Docs: new "Connect an agent with MCP" page, API/CLI page, getting started, development, README, skill
  description, site MCP card and FAQ updated. Marked as available from `0.1.0-alpha.5`.

## Evidence

- `mcp.test.ts` (5 tests, official SDK client against the real app): catalog builds from live OpenAPI
  with no collisions and with dispatch tools gated; 401/403/405 and cookie-only refusal; a read-only key
  lists only read-only tools, sees only its project, cannot call a tool it lacks; write tools work for a full
  key; an unconfirmed scheduling `create_post` creates nothing, confirmed creates one, a draft needs none;
  disabled deployments return 404. API suite 558 pass; `check:quick` passes.
- Native AMD64 container acceptance: the upgrade script now also creates a read-only key on the migrated
  data and checks `tools/list`, `list_projects` and an invalid key against the container's `/mcp`; passed
  against the published alpha.3 and alpha.4 images.

## Not done

  setup; ARM64 and a real third-party assistant session are not claimed.
