# OPS-289 — Development launcher exit diagnosis and terminal hangup

## Findings

The historical shared-session exit code zero cannot establish its original cause:
the previous launcher logged neither received signals nor API exits. A deliberate
SIGTERM reproduces that silent successful launcher exit. A persistent Bun file
watcher does stay alive after its child exits, so natural watcher disposal is not
supported as the cause by the isolated probe.

Two terminal-hangup defects are reproducible. SIGHUP sent to the launcher leaves
its API child running and holding the runtime lock. Sending SIGHUP to an isolated
process group also reaches the API directly: it terminates without releasing its
lock. These findings are verified independently of the historical observation;
do not claim that historical incident was definitively caused by SIGHUP.

## Changes

The development launcher reports child starts, watched restarts, expected stops,
unexpected exits with code/PID, and received shutdown signals. It emits no
configuration or credentials. Unexpected API exit waits for an edit instead of
retrying indefinitely; an exited child is not signaled again. SIGINT, SIGTERM and
SIGHUP produce signal-specific launcher exit statuses. Launcher hangup requests
the API's graceful SIGTERM path before finishing.

The API now routes direct SIGHUP through its existing idempotent graceful shutdown,
covering group-wide terminal closure. Worker/media drain, database close and
runtime lock release remain authoritative. No forced termination, lock reclamation,
background daemon or new service is introduced. SIGKILL cannot be intercepted and
still requires the existing fail-closed operator procedure.

## Evidence

- Isolated launcher hangup: before, exit 129 with live API and held lock; after,
  exit 129 with stopped API and released lock.
- Isolated group hangup: before, stopped API but retained lock; after, both API
  termination and lock release confirmed.
- Five restart tests pass, including unexpected clean child exit, edit-triggered
  recovery, group hangup, delayed drain and cancellation. A separate test starts
  the real API with synthetic credentials, isolated ports/database/media and no
  owner environment file; direct child SIGHUP releases its runtime lock.
- Shared launcher logs demonstrate a source reload as old PID stopped then new
  PID started, and remain separate from ordinary API request logs.

Full `bun run check` passed: 64 main browser journeys, two password-reset
journeys and 17 build tasks. After the group-hangup refinement, all 17 script
tests and the final format/lint/typecheck gate also pass. Logs:
`/tmp/herald-ops289-check.log`, `/tmp/herald-ops289-scripts.log` and
`/tmp/herald-ops289-quick.log`.
