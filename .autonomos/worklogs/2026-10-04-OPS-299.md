# OPS-299 — Bun runtime and production packaging review

Status: complete; runtime correction and full integration gate passed.

## Findings

The production model already uses a single bundled Elysia/Bun process, Bun SQLite,
local/S3 storage and a compiled SPA. A Dockerfile, README deployment instructions,
contributor guide, CI recovery check and isolated local recovery script already
exist. A root project license, production Compose example and image publication
workflow were not found. The gaps are coherence and release evidence rather than
an absent deployment implementation.

The Node 25.9.0 Vite abort from UX-297 was an internal Buffer/HTTP engine failure;
its precise trigger remains unknown. Node 24 passed that gate. This review does
not claim to fix V8. It removes the accidental Node execution from Vite's normal
web development/build commands, following the owner's Bun production direction.

## Reproduced failure and correction

The current Bun production image failed its web build with
`vite-module-runner:import-meta-resolve`. Explicit Bun execution reproduced the
same configuration failure on the host. Vite's supported native configuration
loader started and built successfully under Bun 1.4.2, so web commands now use
`bun run --bun vite --configLoader native`. Keep the existing router, localization,
React and Tailwind plugins; no replacement bundler or new runtime is needed.

The Bun images expose a `node` command that delegates to Bun. Checking
`process.versions.bun` returned 1.4.2. The running production server executable
was `/usr/local/bin/bun`. Compatibility imports from `node:*` do not introduce a
Node engine. The recovery script now asserts the production process executable.

acceptance check as the first release follow-up. No retained lock was removed.
