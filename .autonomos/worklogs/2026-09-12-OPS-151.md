## What was done

The single publication worker now processes one due job per project per round,
then repeats rounds while work remains. A project with a large backlog can no
longer monopolize the worker ahead of another project whose job is already due.
External provider effects remain serial and continue to use the existing
project-scoped system actor, lease duration, claim token, and durable outcome
fencing.

No provider or MediaStore adapter change was required. The existing worker
fixture covers successful, retryable, failed, and ambiguous provider outcomes;
the local and S3-shaped MediaStore contract matrix covers atomic replacement,
size/write-limit failure, bounded reads, and absence of partial objects. The
deployment-specific behavior of a real cloud provider or bucket remains an
explicit operational verification boundary.

## Key decision

Fairness is bounded round-robin scheduling, not concurrent execution. The
quantum is deliberately one job per project so the current single-process
worker keeps its serial external-effect and SQLite assumptions while preventing
unbounded starvation.
