- Status: blocked
- Scope: opt-in live LinkedIn connection, scheduled publication, provider result,
  deletion, and Herald audit verification
- Related decision: [ADR-011](../decisions/ADR-011-select-linkedin-member-text-publisher.md)

- The operator configured `LINKEDIN_CLIENT_ID` and `LINKEDIN_CLIENT_SECRET` in
  the ignored `apps/api/.env` file. Secret values were not read or recorded.
- `HERALD_PUBLISHER_ENCRYPTION_KEY`, `BETTER_AUTH_URL`, and `HERALD_WEB_ORIGIN`

  idempotent `DELETE` operation for a returned post identifier.

## Initial browser blocker

After restarting the IDE and ChatGPT, the official browser runtime still reported
that no browser connection was available. The supported browser surface cannot
complete the interactive LinkedIn authorization without a connected browser, and
no alternate automation path was used.

Local Chromium diagnostics confirmed that Google Chrome is running, but the
ChatGPT extension is not installed in the selected profile and the required
native-host manifest is missing. Opening Chrome or Chromium alone therefore
does not create a supported browser connection.

The documented recovery is to reinstall the Browser plugin from the ChatGPT
plugin UI. The native host and extension were not modified from this workspace.

## Follow-up

The desktop ChatGPT session now exposes a supported Codex in-app browser, so the
browser connection is no longer the blocker. The local web application loaded
successfully, and opening `/dashboard` redirected to `/login` because this
browser session had no authenticated Herald user. After explicit operator
authorization, the agent created a local development account with a generated
password; the password was not recorded in the repository or this worklog.

The agent created the disposable `PUB-09 LinkedIn Smoke Test` project and its
`LinkedIn Smoke Channel` channel, then opened the LinkedIn authorization flow.
LinkedIn rejected the request before authorization because the callback URL
`http://localhost:3001/api/oauth/linkedin/callback` is not registered for the
configured LinkedIn application. No OAuth grant, token, or publication request
was created.

After the callback was registered, the retry reached LinkedIn's sign-in page
without a redirect mismatch. The browser session has no authenticated LinkedIn
member, so the operator must sign in directly in the visible browser. No
LinkedIn credentials were entered by the agent.

## Current diagnosis

The operator has authenticated the intended LinkedIn member in the visible
browser. A fresh callback returned to `/dashboard?publisher=provider_unavailable`
after the OAuth attempt was consumed, but no `publisher_connection` or
`publisher_credential` was persisted. The current route catches the post-state
exception without recording a safe diagnostic, so the next step is to add
redacted provider-flow logging and reproduce the callback. The API is configured
on port `3001`; the web application remains on port `5173`.

The callback now records only the provider, project and channel identifiers,
flow stage, error name, and a bounded redacted error message when logging is
enabled. The diagnostic change passed the API format, lint, typecheck, and test
checks. A fresh authorization request reached LinkedIn's consent screen for
the authenticated member; no permission was approved during this attempt.

The operator then approved that consent screen. LinkedIn returned to Herald,
but the authorization-code exchange failed with an OAuth response-body error
before any credential or connection was persisted. A second authorization
request is currently paused at the same consent screen so the provider error
details can be captured on a fresh callback; no publication request has been
sent.

The redacted diagnostic identified the exact provider response: the token
endpoint returned HTTP `401` with code `invalid_client` and description `Client
authentication failed`, during `exchange_authorization_code`. The configured
client identifier matches the application shown by LinkedIn, and the local
secret is present without dotenv truncation or the example placeholder; its
value was not read or recorded. LinkedIn's documented authorization-code flow
also requires sending `client_id` and `client_secret` in the form-encoded token
request, which is the behavior of the current OAuth adapter.

## Current blocker

The remaining dependency is external to Herald's OAuth flow: the LinkedIn
application credentials must be verified or re-entered in the ignored
`apps/api/.env` file, without sharing the secret. The API must then be restarted
before a new authorization attempt can confirm the connection. No code change
is justified by the observed response, and no LinkedIn publication request has
been sent.

## Resume conditions

1. Verify or replace the LinkedIn application secret locally and restart the
   API.
2. Complete a fresh LinkedIn authorization and persist one project-owned
   connection.
3. Schedule exactly one publication using the approved content, wait for the
   worker outcome, and inspect the provider identifier and audit event.
4. Delete the returned LinkedIn post through the provider API and verify the
   resulting Herald state before reviewing ADR-011 and closing PUB-09.
