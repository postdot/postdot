# QUAL-05 — Trustworthy Quality Gate and M0 Footprint

## What Was Done

- Replaced all placeholder test scripts with six Bun tests covering the Elysia app
  boundary, committed Drizzle migrations, SQLite foreign-key behavior, Better Auth
  health, email registration, and session resolution.
- Removed database and auth side effects from API module import by introducing an
  explicit application factory and runtime-only composition.
- Added injectable Better Auth runtime options and explicit database migration and
  close functions for isolated integration tests.
- Made `bun run check` execute formatting, lint, strict typechecking, tests, and
  production builds in the same order locally and in CI.
- Added Bun text and LCOV coverage reporting without an arbitrary global threshold.
- Added a Linux x64 footprint command that builds Postbot and records API artifact
  size, initial `/` JavaScript, cold start to health, and warm idle RSS.
- Updated GitHub Actions to `actions/checkout@v6.0.2` and
  `oven-sh/setup-bun@v2.2.0`, the current official releases reviewed for this task.
- Configured the GitHub repository to allow squash merges only and to delete merged
  branches automatically.

## Key Decisions and Why

- Packages without behavior (`packages/core` and the current web scaffold) expose no
  test script instead of claiming success through an empty or placeholder suite.
- Elysia tests call `app.handle(Request)` and Better Auth tests call its public
  handler, avoiding network ports and framework-specific test dependencies in the
  default suite.
- SQLite integration tests use `:memory:` databases and committed SQL migrations.
  Foreign-key enforcement is enabled on every connection so declared cascade rules
  are actual runtime behavior.
- Coverage remains informational. Bun reports only loaded modules in this suite, so
  the current 100% result must not be interpreted as whole-repository coverage.
- Better Auth 1.7.2 returns `{ "ok": true }` from `/api/auth/ok`; this differs from
  the older `{ "status": "ok" }` example in the installed skill.
- The initial web measurement includes the Vite entry and the split index route,
  resolved from the generated Vite manifest. It excludes the lazy `/about` route.
- The root and API TypeScript configs override the inherited type entry with
  `types: ["bun"]`. `@tala-tools/tsconfig@0.0.2` still names `bun-types`; the shared
  package should be reviewed separately so consumers using `@types/bun` do not need
  this override. A clean GitHub Actions install exposed the API override requirement;
  the local package directory had retained a stale `bun-types` link.
- GitHub branch protection is unavailable for this private repository on its current
  plan. Until the repository plan or visibility changes, green CI before merge is a
  documented process rule rather than an enforced required check.

## M0 Reference Measurement

Command: `bun run measure:footprint`

- Environment: Linux x64, AMD Ryzen 7 5800X, Bun 1.4.0.
- Build mode: production; API bundle minified; Vite production build.
- Fixture: one empty temporary SQLite database per process.
- Sampling: five cold processes, health polling, then a 1,000 ms idle warm-up.
- API artifact: 1,111,078 bytes (budget: 15,728,640 bytes).
- Initial `/` JavaScript: 311,761 raw bytes; 101,613 gzip bytes (budget: 184,320 bytes).
- Cold start to healthy: 149.27 ms median; samples 160.39, 147.20, 155.14,
  147.51, and 149.27 ms.
- Idle RSS: 65,444 KiB median; 65,792 KiB maximum (target: 153,600 KiB;
  hard ceiling: 256,000 KiB).

All provisional M0 budgets pass. These are local reference results, not production
or marketing claims.
