# WEB-559 — Derive workspace read contracts from Eden

- Issue: ISSUE-188 (partial implementation; issue remains open)
- Status: complete
- Scope: workspace list/detail, team-member and invitation reads

## Changes

The four web methods use Eden and the checked response extractor, with inferred
return types. Existing session credentials and ApiError normalization use the
shared client and unwrap helper already verified by WEB-558.

The client package derives workspace list/summary responses from the typed route
tree, then derives role, list item, member, team, team member and invitation types
from those responses. This replaces eight handwritten web declarations while
preserving their existing public import names through re-exports.

WorkspaceInvitation.status is now the string exposed by the server response
schema, rather than the unrelated project-invitation enumeration. Existing UI
logic filters pending invitations by value and needs no change. Workspace
mutation method bodies still use their previous transport; their shared result
types now refer to the same server-derived entities.

No dependency, server schema, permission policy or rendered component changed.
