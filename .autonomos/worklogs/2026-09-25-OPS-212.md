# OPS-212 — Secure, document, and verify opt-in Prometheus metrics

## Context

`GET /metrics` was exposed on the same HTTP listener as Herald's public API and
did not require authentication. The owner approved securing this existing
Prometheus surface and deferring any wider OpenTelemetry adoption for later
evaluation.

## Outcome

- Prometheus metrics are disabled by default; the route is not mounted unless
  `HERALD_METRICS_ENABLED=true` is explicitly configured.
- Enabling metrics requires a dedicated `HERALD_METRICS_TOKEN` with at least 32
  characters. It is separate from Herald user API keys and browser sessions.
- Scrapes use bearer authentication with a constant-time comparison for tokens
  of equal length. Missing and invalid credentials receive `401` and a Bearer
  challenge.
- Process metrics are not initialized while the feature is disabled, and the
  OpenAPI document only describes the metrics auth scheme when the endpoint is
  mounted.
- The deployment guide now covers token generation, enable/disable behavior,
  Prometheus `credentials_file`, private-network access, and the metric values
  and their limitations.
- HTTP integration coverage uses an ephemeral local listener and verifies the
  disabled route, rejected anonymous/invalid requests, authenticated scrapes,
  and changing scheduler and publication-worker data.
