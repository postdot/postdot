# REALTIME-144 — Reauthorize project event streams after revocation

- Status: completed
- Date: 2026-09-12
- Task: REALTIME-144
- Issue: ISSUE-069

## What was done

Project SSE streams now revalidate the Better Auth session and current project
membership before reading the journal and again after the journal read. A failed
or errored authorization check fails closed, emits a terminal
`project.access-revoked` event, and closes the stream. The browser consumes this
signal and closes its EventSource so the browser cannot automatically reconnect
with a revoked project stream.

The existing user-global notification stream is intentionally unchanged: it is
scoped to the authenticated user rather than one project.

## Key decision

The existing heartbeat interval is also the reauthorization bound: 15 seconds by
default. Rechecking on both sides of a journal read prevents a revoked member
from receiving a batch after a check that preceded the read, while preserving the
non-polling wait model between changes.
