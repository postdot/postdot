## Initial proposal phase

Recommend closing the ordinary approval exception first and deferring a distinct,
explicit retained-contract consent until its exact revision/assessment bindings
and execution-support checks are implemented. ADR-078 describes the alternative
of delivering both together, the preservation rules and acceptance evidence.
That proposal-only checkpoint changed no approval policy, migration, role or UI.

The built-in registry already resolves exact execution revisions at the worker
boundary. No approval-boundary support dependency or explicit security-disable
mechanism is assumed to exist merely because the accepted specification requires
it. Those are implementation prerequisites for an exception, not reasons to allow
implicit consent today.

### Next product work

The ordinary exception is closed by this tranche; explicit old-contract consent
remains deferred. The next recommended foundation is an explicit, lossless way to
adopt the active profile for an existing draft. Static tracing found that save
retains `draftRow.profileVersionId` and rebase updates source revision while
preserving target content; neither is a profile-adoption operation.

A second isolated in-memory probe moved the declared body binding from `/body`
to `/article/body` through authorized profile draft creation and activation.
Manually saving the new shape on the old draft preserved its owned profile,
returned `review_required` and refused promotion with `invalid_content`. Creating
a new draft with the same new shape used the active profile and was `compatible`.
This proves the missing adoption path for that bounded example, not universal
schema incompatibility or a complete migration audit. No field mapping, automatic
conversion or history deletion was implemented. Preserve historical snapshots and
local recovery when designing that subsequent operation.
