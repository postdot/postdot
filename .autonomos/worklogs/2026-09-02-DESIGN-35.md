# DESIGN-35 — Implement the first authenticated app-shell design slice

- Date: 2026-09-02
- Status: completed for the merged app-shell slice
- Scope: authenticated dashboard shell, publication workspace, and publication editor
- Task: DESIGN-35

## Objective

Apply the accepted direction in `DESIGN.md` to the first production-facing
authenticated surface without locking the unresolved navigation and contextual
panel decisions prematurely. The slice must preserve the existing workflow
and remain usable at desktop, tablet, and narrow mobile widths.

## What was done

- Split the dashboard route controller from its presentation into
  `DashboardShell` and `DashboardWorkspace` components.
- Replaced the centered, card-heavy dashboard composition with a full-width
  operational shell: a compact rail, project and channel context, a main
  workspace, and a focused next-actions column.
- Made the source-to-destination relationship explicit in the compose and
  queue surfaces.
- Reworked the publication editor around source content, channel target,
  explicit promotion, delivery snapshot, and channel capability feedback.
- Added the shared `Badge` primitive and aligned shared colors, radii, and
  state tokens with the current Postbot design direction.
- Replaced the changed surface's unsuitable circular Solar icon choices with
  verified Linear icons from the project's configured icon package.
- Preserved the existing API, media, manual-delivery, and publisher
  connection handlers rather than introducing presentation-only data.
- Updated the end-to-end scenario for the new navigation and visible form
  interactions.

## Revision after owner feedback

- Installed the relevant Base UI shadcn primitives in `@postbot/ui` instead of
  continuing to compose raw controls in the application: `Alert`, `Avatar`,
  `Card`, `Empty`, `Field`, `Input`, `Select`, `Textarea`, `Tooltip`, and the
  supporting menu, dialog, scroll, separator, tabs, and button-group
  primitives.
- Normalized generated primitives to use package-local imports, Base UI's
  `render` prop, and verified Solar Icons Linear imports; no Radix-only API or
  placeholder icon implementation remains in the shared package.
- Replaced the provisional Geist-only implementation with the Google Sans
  Flex direction used by the accepted calibration examples, while keeping
  system fallbacks and the final font choice provisional.
- Reworked the shell from a content-sized grid to a `h-svh` flex layout. The
  rail and context sidebar now stay viewport-bound; only the main work surface
  owns the page scroll, and the context sidebar owns its own bounded scroll.
- Replaced raw dashboard and editor inputs, selects, empty states, and error
  messages with the shared primitives. Surfaces now use a small number of
  semantic raised regions rather than borders around every section.
- Updated the media upload control to use the shared Button styling while
  preserving the native file input behavior and corrected the Base UI native
  button warning for the label render target.
- Updated the Playwright scenario to exercise the Base UI combobox and option
  semantics rather than native select APIs.

## Revision after the second owner review

- Replaced the bespoke two-part navigation with the shared shadcn/Base UI
  `Sidebar` primitive. The expanded sidebar now owns project selection,
  project creation, workspace navigation, channels, counts, and sign-out;
  the main surface receives the standard collapse trigger.
- Kept the sidebar viewport-bound and made its mobile behavior an explicit
  Base UI sheet with an accessible close control. Collapsed desktop mode hides
  labels and secondary text instead of leaving clipped fragments.
- Added the SPA theme foundation with `@wrksz/themes` and a persistent
  light/dark toggle in the authenticated and public headers. The existing
  neutral/Cobalt role mapping is shared by both themes.
- Removed default card rings and decorative content borders from the shared
  surface grammar while preserving borders for controls, focus, errors, and
  other semantic relationships.
- Reused the project's verified Linear Solar sidebar and close icons in the
  generated primitives; template `IconPlaceholder` imports and Radix-only
  `asChild` patterns remain absent.

## Revision after the third owner review

- The owner confirmed that the current shell is directionally closer but not
  visually mature. The remaining work is a system correction, not a request
  for more local overrides around shadcn defaults.
- Treat shadcn/Base UI as the accessible component source and interaction
  contract, while Postbot owns the visual defaults at the shared token and
  primitive level. Do not preserve a generic shadcn appearance by layering
  inverse utility classes in consuming pages.
- Define explicit surface levels and semantic shadow roles for canvas,
  raised content, inset regions, fields, and overlays. Use depth where it
  clarifies nesting or focus, with low-contrast dark-theme values and no
  decorative border or shadow quota.
- Revisit the authenticated header and sidebar alignment, typography roles,
  spacing rhythm, and text contrast as one composition. Keep page/form
  information architecture as a subsequent slice so the shell correction can
  be reviewed without mixing it with a full workflow redesign.
- Added a named canvas role to the shared theme contract, made the code editor
  surface theme-safe, and removed the remaining arbitrary provider color from
  the authenticated shell.

## Revision after the latest owner review

- The owner rejected the repeated overline/icon/title/description stack as a
  default heading pattern for an operational application. Section hierarchy
  now needs to begin with the task title, with supporting copy, metadata, and
  icons used only when they provide a concrete job.
- The dashboard must reduce desktop scroll by compacting secondary sections
  and repeated explanation while preserving readable authoring space for the
  primary compose and review tasks.
- Shared controls must have one coherent height in a row. Optional helper
  text must not alter the alignment of neighboring fields or actions.
- Normal field surfaces should rely on the semantic field surface and shadow;
  visible borders remain for focus, invalid state, or an actual grouping.
- Surface corners must be explicit and consistent across forms, panels, and
  cards instead of being inferred from the surrounding layout.

## Design decisions

- The authenticated app uses a dark, neutral, surface-led canvas with Cobalt
  reserved for action and orientation.
- Borders describe hierarchy and relationships; semantic surface levels and
  restrained shadows establish nesting where a boundary needs more than
  spacing. Universal rounded cards and decorative shadows are not used.
- The desktop shell is full-bleed. At tablet width, the context moves into a
  compact strip; at mobile width, the rail becomes a horizontal task switcher
  and the workspace becomes a single readable column.
- Draft editing remains explicit: source changes do not silently replace a
  selected target revision, and the editor separates autosave from promotion.
- The navigation taxonomy, the long-term value of the right-side context
  column, and font-axis/weight calibration remain provisional as stated in
  `DESIGN.md`.

## Open boundary

The owner accepted this bounded app-shell slice for merge after reviewing the
rendered result. It is not a permanent visual lock for every future surface. The
public, login, and future documentation surfaces remain separate design work and
should not inherit the dashboard layout mechanically.

After this revision, render the shell and populated workspace again, then
refine only the identified visual or interaction issues before crystallizing
the accepted shell rules. The subsequent design slice should reduce workflow
scroll and recompose the long forms, with its own information-architecture
evidence.
