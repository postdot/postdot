# UX-256 — Compact channel identity and uninterrupted creation

Status: Completed

## Plan

1. Remove redundant sidebar inventory; retain one Channels navigation entry.
2. Reuse channel creation inside the composer, preserving content and media.
3. Put profile choice first, suggest available platform names, and improve compact identities.
4. Review six destinations and repeated platforms, then run the full local gate.

## Choices

Default platform names remain editable. Letters distinguish repeated platforms without looking like notification counts. Existing names are not silently changed. The current project defines the peer set; letters describe the current ordered platform variants, not permanent domain identifiers. Custom avatars retain their deterministic colors and gain initials. No new persisted color property or database uniqueness migration is introduced.

Owner feedback also reopens UX-248: theme-aware DEV.to/Discord and native platform action symbols must replace the cheap common-icon approximation. Work will be recorded under that existing task.

## Implementation

Removed the duplicate sidebar channel inventory; the Channels navigation entry remains in expanded and compact navigation. The composer opens the existing channel creation dialog in place, with the same role checks and callback as channel management. Choosing a profile comes before naming it. Defaults use platform names and available alphabetic suffixes; explicit edits are preserved. Collision validation uses trimmed, case-insensitive names in the current project, including archived channels supplied to the dialog. Existing duplicates are preserved rather than silently renamed; this is client-side guidance, not a new database uniqueness guarantee.

The selection rail retains its two-sided movement and separate remove controls, but shows compact avatars instead of repeating every channel name. Repeated built-in platforms display A/B/C in square corner patches; custom destinations show initials over their deterministic colors. The active destination name remains visible below the rail, so mobile users do not depend on hover. Alphabetic variants are current project ordering cues, not permanent account IDs; deletion can change ordering.
