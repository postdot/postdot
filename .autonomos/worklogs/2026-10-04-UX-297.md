# UX-297 — Destination article headlines in publication previews

Status: complete; full integration gate passed.

## Finding and correction

Existing publication detail passed the internal post title to its article preview. DEV.to receives a headline from its destination document, so an article could appear untitled or display unrelated metadata even though its destination editor and payload contained the correct title.

The preview now reads the field declared with the profile's `headline` semantic, using the existing target field reader. This supports declared JSON pointers rather than guessing a property name. Missing and explicitly blank destination titles remain blank; post metadata and current source content are not substituted for the destination document. New composition already uses its shared headline and is unchanged. Editable detail reads the working target; lifecycle-locked inspection reads the selected execution target when one exists, even if a later not yet applied draft carries another headline.

This is presentation only: no source ownership, transformation, persistence, promotion, scheduling, or publisher contract changes. No dependency or UI primitive was added.

## Verification
