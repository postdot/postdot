# CRED-15 — Publisher credential and OAuth boundary

- Date: 2026-08-29
- Status: completed
- Related issue: [ISSUE-006](../ISSUES.md)
- Accepted decision:
  [ADR-012](../decisions/ADR-012-own-publisher-credentials-and-use-oauth4webapi.md)

## What was done

- Added durable decision-discipline rules to the root `AGENT.md` through the
  Autonomos adoption workflow.
- Recorded ISSUE-006 as the accepted problem separating application authentication
  from publisher credential ownership.
- Marked PUB-09 blocked while the credential boundary is unresolved.
- Searched the agent-skill ecosystem and installed the focused
  `mcollina/skills@oauth` project skill after checking its adoption and source.
- Reviewed current OAuth security guidance, LinkedIn's authorization-code behavior,
  and the current releases and maintenance state of `oauth4webapi`, `openid-client`,
  `@badgateway/oauth2-client`, and Arctic.
- Ran a temporary Bun 1.4.0 compatibility spike against `oauth4webapi` 3.8.7. PKCE,
  state generation, client-secret-post, refresh, and revocation primitives loaded
  successfully. The temporary directory was deleted after measurement.
- Accepted ADR-012 for a Herald-owned credential lifecycle using `oauth4webapi` only
  for low-level OAuth mechanics.

## Key decisions and evidence

- Better Auth remains the application-authentication system with email/password as
  its only V1 strategy. Using its user-owned account rows or social providers for
  project-owned publisher credentials is rejected.
- `oauth4webapi` is the recommended primitive because version 3.8.7 explicitly
  supports Bun, has no dependencies, is tree-shakeable ESM, implements the current
  OAuth security profiles, and imposes no user, session, or storage model.
- `openid-client` is credible but adds OIDC-oriented convenience, `jose`, and
  `oauth4webapi` itself. `@badgateway/oauth2-client` is a smaller credible fallback
  with less conformance and Bun-specific evidence. Arctic is deprecated and was
  excluded.
- The installed OAuth skill is retained for its RFC-oriented security checklist;
  its Fastify examples are not an implementation template for Herald's Elysia API.
- No runtime dependency, schema change, or publisher refactor was made in this
  decision task.
- Project governance confirmed that channel connections belong to projects. The
  connecting actor is audit attribution only, so their project departure or Herald
  account deletion leaves the connection intact. Explicit disconnect, provider
  invalidation, or project deletion ends its usability.
- Follow-up work is split into credential storage, OAuth transaction handling, and
  migration tasks so each boundary can be proved before PUB-09 resumes.
