# UX-348 — Composer presentation and profile identity

Base: `5f948a88f`. Diagnostic only; no production changes.

## Method

An isolated browser probe creates nine channels through the authenticated API:
three native controls (X, Discord, DEV.to), three manual custom profiles bearing
those exact profile IDs, and three custom templates retaining native execution
contracts but renamed alias-x, alias-discord and alias-devto. Templates use the
existing templatesFromPresets factory, including custom schema preparation.
All nine creations return 201. Every destination profile read completes before
controls are sampled. The source remains `**Bold** text`.

Raw native copies initially failed custom schema validation (missing dialect,
then insufficiently bounded strings). These were fixture preparation mistakes,
not evidence that custom native-execution templates are unsupported. The existing
factory produces accepted fixtures without bypassing those guards.

its article commands and Markdown rendering nevertheless disappear. Manual
DEV.to exposes the title via the platform-name fallback despite an optional
headline. Manual Discord renders Markdown and gains Discord commands despite a
manual execution contract. Manual X selects weighted feedback despite its generic
short-text contract; the native-execution alias loses that counter.

## Cause and implementation boundary

new-publication-page.tsx selects title fallback, weighted feedback and editor
profiles by channel.profileId. publication-draft-preview.tsx also selects preview
presentation and rendering by profileId. The probe records that same identity in
data-preview-platform. A profile identity is not an execution capability.

UX-349 should use the existing explicit native execution contract for native
presentation, preserving schema-aware headline and generic length feedback.
Accepted source formats alone do not identify a Markdown dialect. Preview callers
need inspection: the shared component currently takes Channel rather than the
richer list item; do not add an unexamined public metadata contract to fix this.

## Evidence, limits and validation

Final nine-case probe: 1/1 passed in 17.3 seconds (19.7 seconds including harness),
one worker, no retries, no provider calls. The earlier six native/manual controls
also passed in 13.0 seconds. No product code changed during browser runs.
The temporary probe is removed after diagnosis; UX-349 must retain an executable
regression while correcting the behavior. No transmission, pixel fidelity,
profile activation races or other native platforms are claimed covered.

Delivery is documentation only: static gates, no full matrix or unit rerun.
validated/full remains at 5f948a88f. UX-348 is closed; UX-349 is the bounded follow-up.
