# MAINT-46 — Extract publication media capability resolution

- Date: 2026-09-03
- Status: completed
- Scope: `packages/db` publication media validation and resolution
- Task: MAINT-46
- Related issues: ISSUE-016, ISSUE-020, ISSUE-003

## Objective

Reduce the remaining responsibility concentration in
`packages/db/src/manual-store.ts` by extracting the cohesive media capability
pipeline used by publication creation, draft assessment, and channel-profile
impact assessment. The pipeline turns profile capabilities and target content
into validation issues or resolved, ready media while retaining the database
integration boundary.

## Boundary and invariants

- Preserve the existing `createManualStore` facade and all public types.
- Keep media lifecycle access project-scoped through the existing
  `MediaAssetStore.getAsset` contract.
- Preserve fail-closed behavior for missing services, missing or non-ready
  assets and representations, invalid snapshots, incompatible media, required
  accessibility text, public URLs, and byte limits.
- Preserve stable media ordering, binding-specific limits, original-first
  representation selection, and the distinction between draft assessment and
  scheduled target resolution.
- Keep storage persistence, media lifecycle ownership, and profile orchestration
  in their current packages; this task changes code organization only.

## Alternatives considered

- Keep the helpers in the root store: rejected because the same media pipeline
  is consumed by several independent persistence use cases and currently makes
  the root module own a non-persistence concern.
- Move the pipeline to `packages/core`: deferred because it currently depends on
  the database package's project-aware media lookup and persisted snapshot row
  shape.
- Split each media check into separate modules: rejected because assessment,
  snapshot comparison, and resolution share the same capability semantics and
  would become harder to compare and test together.

- Added `packages/db/src/manual-store/publication-media.ts` for the shared

- Kept media lifecycle persistence and project-scoped access in `packages/db`;
