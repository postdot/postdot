# PROVIDER-87 — Per-instance Mastodon built-in channel

## Objective

Add a provider-specific Mastodon vertical slice without turning Mastodon into a
deployment-wide configuration or weakening Herald's project-owned publisher
credential boundary.

## Decisions applied

- Mastodon instance origins are connection data, not environment variables.
- Each connection registers an OAuth application on its own instance and uses
  authorization code flow with S256 PKCE.
- The encrypted provider session stores the instance-issued client credentials
  next to the token context; the project connection stores the normalized
  instance origin and account destination.
- Herald remains the scheduler and publishes ordinary statuses through a
  versioned built-in execution contract.
- The first profile supports plain text and up to four JPEG/PNG images with
  required accessibility text. Provider media identifiers are checkpointed
  through the existing durable media-delivery lifecycle before status creation.
- Provider failures are classified as retryable, permanent, or ambiguous. An
  ambiguous upload or status result is never silently retried.

## Implementation

- Added `@herald/mastodon` with the profile, typed HTTP publisher, response
  classification, idempotency key support, and asynchronous media processing.
- Added the project-scoped connection flow, callback, encrypted credential
  persistence, endpoint-aware publisher policy, and authenticated web dialog.
- Registered the adapter in the built-in provider registry and added Mastodon
  to the shared adapter conformance suite.
- Added `ADR-041-mastodon-per-instance-oauth.md` with the provider boundary and
  official protocol references.
- Kept the IDE workspace synchronized with the new package.

## Follow-up

- `SECURITY-88` must define the operator-controlled outbound network policy for
  user-selected Mastodon instances before Herald is exposed as a multi-user
  service. The current origin validation protects URL shape, but it does not
  yet provide the same DNS/private-address policy as custom HTTP.
- `ANALYTICS-89` is the next product foundation after this provider slice: use
  durable publication, execution, media, and notification events as the
  provider-neutral source for later analytics views.
