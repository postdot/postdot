# UX-403 — Archive navigation, restoration and removal

Status: complete
Contract: [ADR-094](../decisions/ADR-094-project-and-workspace-lifecycle.md)
Standard: [SPEC-010](../specs/SPEC-010-web-experience-standard.md)

## Findings and changes

- NAV-05/WAY-03: the archive page marked Settings as its destination. Archives now has an explicit settings-shell destination and search entry. A separate Resources group avoids implying personal ownership or installation-admin permission; the existing endpoint still filters manageable resources and readable receipts. The registry classifies this installation-wide inventory as a management column; no instance-admin guard was added.
- LAY-01/LAY-02: the archive list stretched across the settings canvas. Its header now uses the standard independent title/return composition, and its body uses the 64 rem management column. Archive rows identify their project/workspace kind and reuse the resource's generated avatar (LAY-03/WAY-02). Rows no longer link back to the archive page they already occupy.
- NAV-01/NAV-04: project configuration links previously omitted their route-owned project. Archive links and deletion returns now carry the actual route project or explicit settings context, and the archive page has one return to that context. The settings shell suppresses its duplicate return.
- COH-02/COH-03: restore confirmations incorrectly repeated the archive explanation. Project restoration now explains renewed availability without rescheduling cancelled work; workspace restoration explicitly leaves its projects archived. Destructive explanations, name confirmation, pending-work cancellation and uncertain-outcome acknowledgement remain.
- JRN-02/completeness: technical archive-list failures previously offered no retry. Explicit Retry now recovers them promptly. Failed impact refreshes retain the existing confirmation, expose Retry and prevent submission until a successful read. Existing operation errors keep their entered decisions and can be retried. The impact fingerprint and server authorization remain authoritative.
- NAV-02: returning to a project removed the settings shell before its archive child had finished leaving, briefly rendering that child without a QueryClient. The dashboard now selects its shell and context from presented route matches/search, keeping the provider until navigation commits. Both bilingual journeys explicitly reject that console error. This is a shell-selection fix, not a cache/transport replacement.
- The browser caught the router's implicit ancestor activation marking both Settings and Archives current despite only one visual selection. Exact destination matching now prevents ancestor entries claiming the current page. Object pages retain their explicit declared-parent selection.
