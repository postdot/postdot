# ISSUE-126 — X authoring and delivery text validation

- Status: Resolved by X-214; this file records the initial triage.
- Finding: The X profile schema/capabilities use a 280 raw-character/grapheme limit, but the delivery adapter uses a weighted parser. The parser also documents URL and invalid-character approximations.
- Reproduction: A 320-character URL passes the weighted parser but fails profile validation. A 200-character CJK string passes profile validation but exceeds the weighted limit and is rejected only by the adapter.
- Research: X's developer documentation recommends the official `twitter-text` library and describes weighted URL, emoji, Unicode, and NFC behavior. The published JavaScript package is 3.1.0 (six years old) and depends on `core-js` 2 and `punycode` 1.4.1. An isolated npm audit reported no known advisories on 2026-09-25; npm warns that the installed `core-js` 2.6.12 is unmaintained.
- Options: Adopt the official npm package; vendor a pinned upstream implementation and own updates; or keep Herald's parser and run upstream conformance against it.
- Decision: Use the official `twitter-text` package while viable. Reassess ownership only if a concrete maintenance or compatibility problem appears; if one does, maintain only the functions Herald needs and verify them against upstream conformance.
