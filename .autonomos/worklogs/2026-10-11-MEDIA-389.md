# MEDIA-389 — stored image previews

## Accepted scope

Generate two internal image variants and a blurred placeholder at upload
finalization. Keep one library asset, its immutable original, and its existing
publication references. No new dependency, service, schema migration or admin
configuration. Nifra is excluded by owner direction.

## Implementation

- Bun.Image generates WebP at 256 and 768 pixel bounds, quality 80, inside fit,
  without enlargement. A native ThumbHash PNG data URL is embedded in recipe
  metadata. Processor identity and version distinguish these internal variants.
- Reuse derived representations linked to the original. Register storage
  ownership before writing bytes. Decoding is serialized across imports.
- Static JPEG, PNG and WebP are eligible. Animated images and other media retain
  original display; unsupported processing preserves the verified original and
  emits a fixed diagnostic without exposing exception content.
- Authenticated content accepts thumbnail/preview presets only, preserving
  original default, byte ranges and private no-store behavior. Missing variants
  fall back to the original. No arbitrary size or remote transformation endpoint.
- Grid, compact media controls and search use previews. Placeholder backgrounds
  disappear after image load. Full viewer and downloads retain originals.
- Existing deletion, trash, restoration and complete-backup ownership include
  variants. Purging waits for in-flight preview writes. Reconciliation cannot
  let a derived preview substitute for a missing original's availability.

## Evidence

Focused store/API/backup/provider suites: 22 tests passed in about 1.8 seconds;
provider pinning additionally rechecked after replacing its header-only fixture
with a complete image. Tests prove one asset, two derivatives, source linkage,
no enlargement, original byte preservation, authorization, variant byte ranges,
backup/restore, partial write cleanup and deletion during generation.

Representative deterministic 1024 × 600 PNG: original 1,844,428 bytes,
thumbnail 12,896 bytes, preview 200,442 bytes. Savings are specific to this
fixture (about 99.3% and 89.1%), not a universal compression claim.

Focused browser library/viewer/bulk-actions scenario passed in 12.7 seconds
(16.1 seconds with harness): grid requests preview, image decodes, full viewer
requests original. Initial browser launch failed before test execution because
its configured browser path was absent; using the existing local browser cache
resolved it. No browser download, retry setting change or full matrix run.

Static format/lint/spelling/typecheck passed. A PNG chunk identifier spelling
annotation and test assumptions about response representation count were fixed:
finalize returns the original reservation, while library reads include internal
representations. Deleted assets intentionally disappear from getAsset.

## Limits and next step

Existing assets are not automatically rewritten or backfilled. Their content
route still works through original fallback. Video posters and playback policy
are unchanged. No live S3 integration was exercised; processing uses the same
MediaStore port as the local test implementation. No Sharp fallback introduced
without a demonstrated supported-upload codec gap.

Next recommended pass: explicit generation of previews for existing images,
reusing the same presets and lifecycle rather than changing originals.
