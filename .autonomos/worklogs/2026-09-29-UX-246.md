# UX-246 — Representative operational journey review

Status: Completed implementation, representative review and full local validation

## Plan

1. Inventory existing deterministic coverage and identify presentation gaps.
2. Review populated operational states across desktop/tablet/mobile and locales/themes.
3. Correct evidenced usability defects while preserving lifecycle and recovery behavior.
4. Run the complete local gate and record a concise before/after review.

## Boundaries

Use isolated E2E fixtures; no real provider dispatch or live account/data changes.
Retain existing permissions, domain states, URL context and recovery semantics.
Earlier changes in the local main checkout remain intact. Exact platform preview
fidelity stays under UX-248; synthetic outcomes do not prove provider behavior.

## Before / after findings

| Observed defect | Correction |
| --- | --- |
| Long destination names separated their state marker onto another line. | Keep marker and truncated destination name in one inline group. |
| Queue row headings skipped directly from h1 to h3. | Use h2 for publication rows. |
| Existing publication titles competed with the return link on narrow screens. | Keep controls on the first row and center the title independently below; retain a centered desktop title. |
| A mobile retry button squeezed the error into a narrow text column. | Stack lifecycle information and actions on mobile. |
| Light theme attention, queued, published and failed states were too faint. | Darken the existing semantic colors without changing dark theme tokens. |
| The sidebar creation action lost text contrast on hover in light theme. | Retain the primary surface color and use a light shadow for hover feedback. |
| Inactive tabs lost contrast on their inset surface. | Use the existing muted foreground token instead of foreground opacity. |
| The agenda's inline Queue link relied on color alone. | Keep the underline visible before hover. |
| The detail page had no main landmark and an unnamed duplicate complementary landmark. | Give the editor a main landmark and use a normal container around the already named preview section. |
| Illustrative preview engagement used an accessible name on a generic element. | Give the static illustration an image role and preserve its accessible description. |

These are applications of the accepted hierarchy and accessibility rules. No new
visible explanatory copy, API behavior, lifecycle transitions or design tokens
outside the existing semantic state palette were introduced.

## Review matrix

The new mixed operational fixture includes manual due work, failed automatic
work, uncertain outcomes, scheduled work, a draft, a published item and a
cancelled item. It uses long destination names and realistic draft text. Outcome
states are intercepted; editor content comes from actual isolated draft records.
This proves presentation and route behavior, not actual platform dispatch.

Representative pairwise combinations, not the full Cartesian product:

| Locale | Theme | Width |
| --- | --- | --- |
| English | Dark | 1280 |
| English | Light | 820 |
| English | Light | 390 |
| French | Light | 1280 |
| French | Dark | 820 |
| French | Dark | 390 |

Each combination checks the populated Queue, keyboard attention filtering and
reload, manual and failed publication details, keyboard return navigation,
centered titles, the calendar/agenda, horizontal overflow and Axe findings.
Screenshots are captured by the isolated E2E run. A real isolated approval request
also checks desktop/tablet/mobile and French before keyboard approval; the API
then confirms the exact approved schedule. No connected provider is involved.

Existing deterministic journeys retain coverage for empty work, multiple
channels, media upload/reuse/search, draft save/conflict/recovery, unavailable
provider handling, notifications and realtime feedback. The full local gate
re-runs those journeys; the new visual matrix supplements them rather than
claiming to exercise every branch in every viewport.
