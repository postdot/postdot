# UX-269 — Configuration return continuity

## Implemented slice

Configuration's shell return follows the project retained in the header rather
than navigating to `/dashboard`, whose default resolution can choose a different
project. Workspace and installation-access page headers use the same contextual
project when it belongs to the selected workspace. Project-specific access pages
retain their explicit project return. With no selected project, return includes
`projectId=none` so navigation cannot silently select the first available project.

This does not change the scope of any settings operation or its permissions.

## Still open

Changing the workspace selector inside installation settings currently navigates
to workspace administration, and selecting a project leaves Configuration for
Overview. Those are existing behaviors, not altered in this slice. Review whether
selectors should retain the current global page versus navigate into the selected
resource before changing route jobs. Administration Overview's duplicated links
also remain a design candidate, not an accepted route removal.
