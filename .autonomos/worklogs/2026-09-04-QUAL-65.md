# QUAL-65 — Verified audit boundary regressions

Date: 2026-09-04
Status: completed

## Objective

Reconcile the confirmed findings from the independent product audits with the
current Herald implementation, then add focused regression coverage without
changing intentional architecture decisions.

## Changes

- Added a fail-closed channel-profile state check to workflow wake-up, job
  claiming, target loading, and the pre-effect execution boundary. A disabled
  profile can no longer start new work, while an execution that already crossed
  the external-effect boundary remains available for reconciliation.
- Changed the publication worker to obtain a fresh processing timestamp for each
  event and effect boundary. Long-running batches no longer stamp later jobs with
  the scheduler's initial timestamp.
- Added a server-side regression test proving that an invalid scheduled media
  target is rejected before the publication, target revision, and job are
  persisted.
- Added regression tests covering disabled profiles before claiming and after a
  claim but before the external-effect boundary.

## Audit reconciliation

The disabled-profile execution gap and the worker-clock issue were confirmed and
fixed. The audit claim that scheduled media bypasses capability validation was
not reproduced: the creation path already validates scheduled media before
persisting it; the new test records that boundary.

The existing structural/profile-rule separation remains intentional. The
`validateWithRules` follow-up requires a separate decision about how provider
modules register deterministic rules and is not silently folded into this task.
