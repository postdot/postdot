# WEB-184 — Make publication detail lifecycle actions explicit

- Status: Complete
- Branch: `codex/reui-calendar-spike`
- Owner: orchestrator
- Scope: publication detail lifecycle actions and state-aware feedback
- Related task: [WEB-184](../TASKS.md)

## Objective

Give operators a clear next action on publication detail pages without
collapsing manual work, delivery recovery, and publication cancellation into a
single generic control.

## Delivered

- Added a state-aware lifecycle action surface: manual publications expose
  `Record as published`, failed publications expose `Retry delivery`, and
  scheduled publications expose `Cancel publication`.
- Added a confirmation dialog for cancellation and guarded it while local
  editor changes, saves, or recovery are in progress so an operator cannot
  silently lose draft work.
- Made worker error details visible on failed publications and kept terminal
  states read-only after a successful transition.
- Fixed the lifecycle status label so due manual publications read as manual
  work instead of appearing queued.
- Added English and French messages plus browser coverage for cancellation and
  failed-delivery recovery affordances.

## Verification

- `bun run check` — passed: format, lint, typecheck, unit/integration suites,
  browser scenarios, and package builds.
- `bunx playwright test e2e/publication-detail-actions.spec.ts e2e/realtime-validation.spec.ts --workers=1` — passed (5 tests).
- Integrated browser review — scheduled detail exposes cancellation and its
  confirmation dialog; the seeded manual detail exposes the corrected manual
  action label.

## Boundary

This task clarifies the existing publication lifecycle contract in the web
surface. It does not add provider-specific retry semantics or change the
worker state machine.

## Follow-up

Return to Queue visual refinement only after the lifecycle action contract has
been exercised with the remaining publication states and real operator flows.
