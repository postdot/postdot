# WEB-51 — Make web project context URL-authoritative

- Date: 2026-09-03
- Status: completed
- Issue: ISSUE-014

## What was done

- Registered WEB-51 on a dedicated branch from the clean `main` branch.
- Changed `DashboardShell` to receive the URL-resolved project object rather
  than deriving the selected project name from the global project collection.
- Keyed `ProjectDashboardProvider` by the resolved project id so a client-side
  project switch remounts project-scoped state and cannot retain channels,
  publications, or compose drafts from the previous project.
- Extended the browser integration scenario with a second project and direct
  project URLs to exercise client-side switching, reload-safe context, and
  project data isolation.

## Key decisions and why

- The project route parameter and its loader result are the authority for the
  active project. The root dashboard project list remains a collection of
  selectable project options, not a second source of selected-project identity.
- A keyed provider is used instead of an effect that copies loader data into
  state. React state belongs to one project session and is reset at the route
  identity boundary; this avoids a transient or partial cross-project state.
- No new ADR was required. The implementation completes the URL-authoritative
  routing direction already accepted in DESIGN-36 and the existing design
  contract.
