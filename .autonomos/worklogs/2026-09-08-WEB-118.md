# WEB-118 — Route information architecture proposal

- Date: 2026-09-08
- Status: completed
- Scope: route jobs, first actions, progressive disclosure, and alternatives
- Evidence: `DESIGN.md`, ISSUE-063, Muse-1.3 audit, Luna-max audit, and current
  route/component inspection

## Observations

- `DashboardOverview`, `PublicationCalendarPage`, and
  `PublicationQueuePage` all begin with a shared page header and summary bar.
- Calendar currently switches to `CalendarEmptyState` whenever there are no
  scheduled publications, so the desktop month grid and its date links are not
  available as an empty-project entry point.
- Queue already has a distinct filtering model, but its empty state and primary
  action remain visually close to Overview.
- The accepted design contract already assigns Calendar to time scanning and
  Queue to prioritization; the implementation has not fully expressed that
  distinction at zero data.
- Dashboard shell navigation mixes project work, project management, channels,
  and global settings in one visual system; reduced mode and global settings
  context require a shared-shell decision rather than page-local fixes.

## Proposal

ADR-057 proposes retaining separate routes with explicit jobs and first actions,
using progressive disclosure to organize complexity instead of removing it. It
compares a unified workspace, a Compose-first workspace, and a styling-only
approach before recommending the route-oriented model.

## Resolution

The owner accepted the route job table and the progressive-disclosure direction
by authorizing continuation. The exact desktop Calendar composition remains an
implementation detail as long as the empty state exposes a direct date-oriented
entry path. No production UI was changed for this task.
