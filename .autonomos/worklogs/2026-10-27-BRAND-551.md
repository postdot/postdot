# BRAND-551 — Remove the previous product names

Owner direction: remove the old "Postbot"/"Herald" names for good, including screenshots; alpha, so
no heavy precaution beyond keeping existing installations readable.

## Delivered

- **Screenshots.** Only the six full-window captures (calendar, compose, queue; light and dark) showed
  the old name in the sidebar header; the detail crops did not. The 236×56 header region was replaced with
  a fresh capture of the current header (same logo, same theme background), WebP re-encoded at quality
  92 and AVIF regenerated with `encode-product-images.ts`. The generated social cards (`public/og`,
  ignored by Git) are produced by `generate-og-images.tsx`, whose wordmark is now post/dot. The README
  screenshot is `compose-light.webp`. These are patched captures, not a full recapture of the current UI.
- **Names.** 400+ tracked files renamed mechanically (`POSTBOT_*`→`POSTDOT_*`, identifiers, file names,
  skills, Compose service/volume, `postdot.js`, metrics, `x-postdot-*` webhook headers, test fixtures,
  localStorage keys). History (migrations 0000–0025, worklogs, ADRs, specs, TASKS entries) is unchanged.
  "Herald" survives only as opaque hex authenticated-data bytes in `encrypted-secret-crypto.ts`.
- **Compatibility, bounded.** Deprecated `POSTBOT_*` variables are read when the new name is unset
  (warning once; also the CLI and the agent skill); `postbot.sqlite` (+WAL/SHM/recovery marker) is renamed
  under the runtime lock when `postdot.sqlite` is the configured name and absent; `postbot_pat_` keys
  still authenticate (new keys use `postdot_pat_`); saved custom profiles keep `postbot_webhook`
  (their stored hashes cover it) and behave identically via `isWebhookMode`; Compose keeps legacy
  volumes through `POSTDOT_DATA_VOLUME`.
- **Migration 0026.** Renames `postbot_entity_*` columns; rewrites built-in profile hash labels in
  profile JSON, target/execution revisions and adoption snapshots; media processor ids; Better Auth
  team/member/grant ids, slugs and metadata keys (deferred foreign keys). Custom profile JSON is
  deliberately untouched: rewriting its mode broke the stored-hash check during acceptance.
- **Repository variables.** Created `POSTDOT_SITE_URL`, `POSTDOT_UMAMI_ID`, `POSTDOT_UMAMI_URL`; the old
  `POSTBOT_*` variables are removed after the next docs deployment succeeds.
- Guide: "Move from the Postbot names" in the installation page.

## Evidence

- Unit/script gates: 20 turbo test tasks and 117 script tests pass; `check:quick` passes. New tests:
  migration 0026 (rewritten identities and untouched custom JSON), legacy database adoption (refuses
  existing target, custom names and a held legacy lock).
- Native AMD64 acceptance of the working-tree image (not a release candidate): upgrade from the
  published alpha.3 image with the old variable names and `postbot.sqlite` — deprecation warning, file
  adoption, preserved login/project/channel/draft/media/connection/queued work, sharing on migrated data,
  restoration with the previous image; container recovery; offline bootstrap and identity.
- Browser: 17 journeys (sharing, calendar, channel authoring, connection recovery) before the full run.
