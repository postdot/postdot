# WEB-560 — Infer workspace mutations through Eden

- Issue: ISSUE-188 (partial implementation; issue remains open)
- Status: complete
- Scope: nine workspace mutation wrappers

## Implementation

Workspace creation, member-role updates/removal, group creation/rename,
group-member addition/removal and invitation creation/cancellation now call the
typed Eden route tree and unwrap the checked response. Their public inputs are
unchanged; role updates still accept only admin or member, and invitation
creation still supplies the selected team without exposing additional options.

Removed redundant response annotations and unused entity imports. The server's
response schemas determine each wrapper result. Ten compile-time contracts cover
all nine result envelopes and the accepted member-role input. Common ApiError
normalization and the existing permission handlers retain their behavior.

No backend schema, permission rule, dependency or rendered component changed.
Better Auth invitation acceptance remains on its existing boundary.

## Validation

- Web tests: 285 passed, zero failed.
- Client and access HTTP tests: 16 passed, zero failed. Existing cases include
  workspace creation, group access, rejected member writes, role changes and
  membership removal.
- Production web build: passed.
- Four isolated Playwright scenarios passed without retries in 1.2 minutes:
  workspace invitation/group access, viewer/editor roles, settings continuity,

- It also verifies that a member's group-creation request fails as ApiError 403

- The existing invitation UI scenario covers failure recovery while retaining

  permanent E2E file or harness configuration changed.
- Focused selection: access-135-workspace-invitation, access-136-project-roles,
