## Prepared replay case

Use only the existing dedicated Postbot Test Page and unpublished test application after verifying their identity. Create a fresh private acceptance runtime, separate database/media roots and generated encryption/authentication secrets. Do not import normal projects. Bootstrap its local administrator before opening a temporary public tunnel. Use the rebuilt Studio and the actual automatic worker; synthetic webhook delivery already has separate acceptance coverage.

Configure the tunnel's exact HTTPS origin for application authentication, Studio and the trusted Facebook callback `/api/oauth/facebook/callback`. Preserve strict redirect matching and HTTPS enforcement. Register the application through Studio and use the native OAuth Page picker. An old recorded grant is not evidence of a currently usable encrypted connection. Do not substitute an arbitrary access token. Existing owner test authorization remains relevant; an actual new contractual acceptance or expanded access grant still requires confirmation at that action.

Prepare two **unscheduled** automatic text drafts in a project named `Facebook refresh acceptance`. These are the proposed texts, with a unique run suffix appended before execution:

1. `Postbot technical test — native Facebook refresh, clean editor. No action required.`
2. `Postbot technical test — native Facebook refresh, local edit protection. No action required.`

Keep both unscheduled until the connection and observation setup are ready. For each case:

1. Open the publication detail and verify its project event stream is connected. Record the initial authoritative publication state and browser document identity. Do not reload during observation.
2. In the second case, keep a clearly identified local body edit unsaved while the existing scheduled revision is delivered. If the editor saves automatically, use the focused failed-save interception already demonstrated by REALTIME-516/517; do not change production autosave behavior. The remote body must be the scheduled revision, not this local edit.
3. Schedule through Postbot, allow the actual Facebook worker delivery, and independently verify the labelled remote Page post and stored provider identity.
4. Observe the durable status event, subsequent editor response and visible transition to Published within the existing acceptance timeout of 30 seconds. Confirm no document navigation/reload occurred. For the second case, confirm local text is preserved. Record elapsed time rather than inferring instant delivery.
5. On failure, distinguish worker/provider completion, event arrival, refresh request, response state and rendered state. Do not close ISSUE-177 on the basis of a reload or remote success alone. Avoid saving raw OAuth callbacks, cookies, tokens or unfiltered network archives.

Cleanup belongs to the parent: remove only the temporary callback registered for this run, stop the exact tunnel and API gracefully, and retain any private fixture only with its location recorded privately. Do not delete the existing app, Page or unrelated grants.
