## Result

Nine proposed records describe mechanisms that are present in source and tests. Their proposed status is not itself an implementation defect: the protocol reserves acceptance for project governance. The linked implementation worklogs either explicitly keep the records proposed or record implementation approval without ratifying the complete decision. All nine remain proposed.

The accepted [SPEC-005](../specs/SPEC-005-continuous-product-scope.md) establishes continuous development, no V1/MVP boundary, and the single-process self-hosted default. ADR-010 had retained obsolete V1 wording and Bun 1.4.0 despite the repository pin and production image using Bun 1.4.2. Its wording now reflects the continuous product scope and follows the repository-pinned Bun release; its status remains proposed because SPEC-005 does not decide runtime-image versus compiled-executable packaging.

The owner's 2026-09-26 analytics clarification distinguishes publication-performance analytics (for example, views and comments) from internal Postbot operational analytics. The internal operational-analytics web-page deferral does not defer publication analytics or ratify the Bluesky collection design in ADR-052/055.

## Explicit owner choices, if these records are to become normative

These choices do not block existing behavior or the independent MAINT-226 task.

1. **Packaging (ADR-010):** Ratify the repository-pinned Bun runtime image as the current self-hosted package, or keep the runtime-image versus compiled-binary choice proposed. Recommendation: retain the runtime image; do not tie this choice to a V1 milestone or a specific Bun patch release.
2. **Provider and realtime contracts (ADR-044/045/048):** Ratify the implemented X/DEV.to adapter boundaries and authenticated SSE transport, or keep those detailed designs proposed while the features remain available. The implemented provider features themselves are not being reopened.
3. **Analytics boundary (ADR-051/052/055):** The internal operational page is deferred, while publication-performance analytics remain desired. A separate product decision is still needed before treating the bounded Bluesky observation model as a reusable provider-owned collection contract beyond this implemented slice. Recommendation: keep the Bluesky-specific records proposed until that product boundary is reviewed.
4. **Restore lock (ADR-068):** Accept fail-closed sidecar ownership, including manual verification/removal after forced termination, or first decide which native host operating systems Postbot must support and evaluate a matching lock implementation. Recommendation: keep the existing fail-closed behavior; do not redesign from Linux-only evidence.
5. **Custom path authentication (ADR-069):** Ratify the narrow path-secret mode with the acknowledged possibility that the receiver and its proxies/access logs see the URL, or keep the decision proposed. Recommendation: require explicit ratification before extending this mode to query secrets, multiple secrets, or imperative signing.
