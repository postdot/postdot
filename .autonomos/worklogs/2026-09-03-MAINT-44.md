# MAINT-44 — Extract publication outcome persistence

- Date: 2026-09-03
- Status: completed
- Scope: `packages/db` publication outcome persistence and composition
- Task: MAINT-44
- Related issues: ISSUE-016, ISSUE-020

## Objective

Reduce the remaining responsibility concentration in
`packages/db/src/manual-store.ts` by extracting the persistence boundary for
publication outcomes. The extracted unit owns manual due-publication discovery,
manual publication completion, and ambiguous-publication reconciliation while
preserving the existing public facade and state-transition semantics.

## Boundary and invariants

- Keep `createManualStore(database, options)` and its exported types stable for
  API, web, CLI, and test consumers.
- Keep manual completion and ambiguous reconciliation as separate transactions;
  each has distinct preconditions and allowed state transitions.
- Preserve project and actor authorization checks, immutable terminal states,
  conditional state updates, and audit attribution.
- Keep shared publication loading and audit insertion explicit at composition
  time instead of duplicating ownership of shared statements.
- Do not change the domain model, schema, migrations, routes, or external
  publication behavior.

## Alternatives considered

- Keep the operations in the root store: rejected because their SQL, state
  transitions, and outcome-specific audit behavior formed a cohesive boundary
  that remained difficult to discover after the authoring extraction.
- Combine publication creation, authoring, execution, and reconciliation in one
  larger module: rejected because creation, editing, manual completion, and
  ambiguous recovery have different lifecycle and transaction responsibilities.
- Introduce a generic repository or outcome abstraction: rejected because there
  is no second database backend requiring it, and it would hide Bun SQLite
  transaction behavior without improving the current test seam.

## Implementation

- Added `packages/db/src/manual-store/publication-outcome-store.ts` for due
  publication queries, manual completion, and ambiguous reconciliation.
- Composed the extracted store into `createManualStore` without changing the
  public manual-store facade.
- Kept one SQLite transaction for manual completion and one for ambiguous
  reconciliation, with the existing conditional updates and audit writes.
- Injected shared actor/publication loading and audit insertion explicitly from
  the root composition so ownership remains unambiguous.
- Added integration coverage that forces audit persistence to fail and verifies
  that both outcome transitions roll back completely.
