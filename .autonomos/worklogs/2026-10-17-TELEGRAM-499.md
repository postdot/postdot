# TELEGRAM-499 — Telegram protocol foundation

## Outcome

The owner selected text plus one media, albums later. Recorded that choice without promoting the remainder of draft SPEC-008 to an accepted specification.

Added @postbot/telegram as an isolated provider package. Verification resolves bot identity, broadcast channel identity and administrator posting rights through metadata reads only. It never sends a probe or changes incoming updates/webhooks. Numeric destinations are canonical, safe integer identities; username lookup must match the returned channel. Metadata does not expose raw or encoded bot tokens, including in channel titles.

Publishing supports plain text, one JPEG/PNG photo or one MP4 video with a caption. Uses JSON for text and multipart upload for media. Rejects invalid input before transport, applies decimal 10/50 MB byte ceilings and photo dimension/aspect constraints, and preserves literal text without adding parse mode or paid broadcasts. Media input is a Blob with dimensions and must come from inspected owned storage in the future application adapter.

The text budget currently uses a conservative UTF-16 ceiling, explicitly tested with astral emoji. This does not claim maximum Unicode parity with Telegram. Before registering the user-facing profile, verify the counting contract and align server/editor validation. Do not silently truncate content or split it into extra messages.

Successful sends record chat plus message identity. Public links require a valid returned public username; private channels have no fabricated invite URL. Typed provider error codes distinguish authentication, permissions, rate limiting, destination changes and uncertain results without relying on textual matching. Matching negative API envelopes support definite rejection; malformed/conflicting responses, server failures and transport loss during sends remain ambiguous. No internal replay occurs. Valid rate hints defer; unsupported supplied delays require inspection instead of becoming an early automatic retry. Redirects are disabled and caught exceptions/provider descriptions are never returned.

Updated the lockfile, IDE workspace and Docker manifest-only inputs for the new package. Updated ISSUE-165 continuity and recorded the unrelated observed build-context problem as ISSUE-176.
