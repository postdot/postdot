# WEB-164 — Visible adaptive anchor and persistent calendar view

## Status

Complete.

## Owner direction

Make the data-aware Week/Day opening position visibly useful in the real
browser, while keeping the complete timeline available. Persist the selected
calendar reading mode through the overview URL so a refresh or shared link
does not silently return to the responsive default. Do not widen this task to
calendar cursor, scroll-position, expanded-day, or column-width persistence.

## What changed

- Added a validated `PublicationCalendarView` union and overview search
  validation for `view=month|week|day|agenda`.
- Made the URL the source of truth for the selected ReUI view. Switching views
  uses replacement navigation, preserves the existing `calendar` query, and
  keeps the responsive fallback when no explicit view is present.
- Gave the Week/Day time grid a bounded vertical and horizontal scroll surface.
  The day-header row remains sticky inside that surface so its labels stay
  associated with the columns while the hours move.
- Delayed the adaptive anchor until layout settles and retried measurement a
  bounded number of times. The selected time slot is now placed using the
  actual contained scroller, with sticky-header compensation and safe bounds.
- Kept the page-flow behavior for Month; only Week and Day opt into the
  contained time surface. This avoids changing the established Month layout
  merely to solve a time-grid problem.
- Updated unit and browser coverage for allowed query values, empty baselines,
  populated late data, the visible scroll position, and Week/Day reload
  persistence.

## Evidence

- In the integrated Postbot browser, the authenticated `Calendar review
  workspace` opened Week/Day around its afternoon publications rather than the
  `00:00` frame; the complete time range remained available in the internal
  surface.
- The empty-project browser scenario retained `00:00` and a zero internal
  scroll position.
- Browser reload restored `?view=week` and `?view=day` respectively.
- The calendar cursor/date is not persisted by this task: reloading can still
  reopen the current calendar range. This is deliberate and remains a separate
  follow-up from reading-mode persistence.
