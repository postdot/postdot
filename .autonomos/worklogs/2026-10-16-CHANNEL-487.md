# CHANNEL-487 — Contract-aware HTTP connection controls

## Scope and findings

The next proposed delivery form already exists: endpoint, authentication, account label and secret are structured controls in CustomHttpConnectionDialog. No duplicate form or execution conversion was introduced. Inspection found a concrete mismatch: path authentication was offered for Postbot webhooks, although the domain rejects it. Mapped requests with a secret path also offered incompatible non-path methods.

## Changes

- Load the active profile on dialog opening; restrict authentication choices to its execution contract. Do not load the domain compiler in the browser.
- Keep submission disabled while loading/refetching or on profile failure; show an inline retry and preserve entered connection fields.
- Require path authentication for exactly one secret segment; hide it for webhook and secret-free mapped requests. Unsupported/incomplete shapes yield no enabled choices.
- Bound the connection dialog body while anchoring header and action footer. Preserve connection-owned secret handling, clear it on cancellation/success, and set new-password autocomplete plus existing minimum-length validation on its password input.
- Add native required constraints to endpoint and secret.
- Document the boundary in the existing channel-builder reference.

## Validation

Focused UI-projection tests compare every offered authentication kind to the real domain binding validator for webhook, mapped requests with no secret and mapped requests with one secret. Invalid/incomplete shapes remain disabled. Core transport tests run alongside them; see the recorded command output for totals.

check:quick and the web production build passed. Live visual validation is still outstanding because the local API is unavailable behind its retained runtime lock. No lock was removed, no live connection attempted, and no credential or publication changed. Dialog scrolling is an implementation change, not a claimed browser acceptance result.

## Next

Restore the local API safely and verify the connection dialog at narrow viewport heights, including profile-load failure and retry. Then tackle structured mapped-request authoring as a separate bounded task; preserve advanced contracts instead of flattening them into the webhook model.
