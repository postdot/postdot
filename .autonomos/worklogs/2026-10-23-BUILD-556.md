# BUILD-556 — Keep generated local data out of Docker contexts

- Issue: ISSUE-176
- Status: complete
- Scope: Docker context exclusions and production-image verification

## Changes and findings

The root .dockerignore now excludes data, test-results and playwright-report.
Existing output/dependency patterns are recursive: node_modules, .next, .source,
out, build, dist, coverage, .turbo and .vite. Storybook output is also excluded
recursively. A tracked-file scan finds zero tracked files under these recursive
generated-directory patterns. Required sources and fixtures remain available.

The first correction excluded the three root directories but an actual COPY of
the remaining context still occupied 1.6 GB. Workspace Next.js output and nested
dependencies were still included: the former bare patterns matched only at the
context root. After the recursive correction, the same audited copy is 47 MB.
These are measurements of the copied context, not an assertion that incremental
BuildKit transfer bytes equal the complete source size.

Docker documents the recursive ** pattern and root-relative matching in its
[context reference](https://docs.docker.com/build/concepts/context/#syntax).

## Validation

- Existing data occupied 218 MB and browser results 50 MB before validation.
  They remained present throughout; no existing runtime data or results were
  deleted.
- An external temporary audit Dockerfile performs a real COPY from the normal
  repository context, rejects the three root directories, recursively rejects
  generated outputs/dependencies, and asserts 26 workspace manifests/root
  configuration files plus three tracked fixtures. Both checks pass.
- Fixtures checked: database H.264 MP4, Instagram square JPEG and publication-job
  source fixture.
- Added isolated disposable output files of about 1 MB each under all three
  excluded root directories during the audit and normal production build.
  Removed only these owned probes and the otherwise absent report directory.
- Normal `docker build --progress=plain --tag postdot-build-556:validation .`
  passes with the final exclusions and generated local outputs present.
- `POSTBOT_CONTAINER_TEST_IMAGE=postdot-build-556:validation bun run
  test:container:recovery` passes on the freshly built Bun 1.4.2 x64 image:
  packaged decoder, authenticated HTTP, graceful shutdown, complete media backup
  and held restore, startup termination and fail-closed forced termination.
- `bun run check:quick` passes (format, lint, spelling and type checks).
- No application runtime source changed. No browser matrix or unit-suite replay
  was needed for these exclusion rules; the real context and production image
  are the affected boundary.
