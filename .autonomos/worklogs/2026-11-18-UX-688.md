# UX-688 Copy the title, text and media of a manual publication

Outcome: the post page shows, for a manual channel that is not yet published, a "Content to copy into {channel}" block with one action per part: copy title, copy text, copy each image, download each file (or all of them), copy each image description, and share everything to another app where the device supports it. Resolves [ISSUE-208](../ISSUES.md).

Record:

- `apps/web/src/components/post-composer/manual-publication-kit.tsx` reads the same channel document as the preview (`getTargetPreviewTitle`, `getTargetPreviewBody`, `getTargetMediaSelections`), so the copied content is the channel's own version, and the selected execution profile once the publication is locked.
- `apps/web/src/lib/manual-publication-media.ts`: images are converted to PNG before copying because browsers only carry PNG on the clipboard reliably; GIF, SVG and video are download only. The blob is passed to `ClipboardItem` as a promise so Safari keeps the click as the user gesture. Sharing uses the Web Share API with files and appears only where `navigator.canShare` accepts files (phones).
- Shown in `PostChannelPanel` status part for `deliveryMode === 'manual'` in draft, scheduled or ready; hidden once published.
- Checks: `e2e/manual-publication-kit.spec.ts` (clipboard text keeps line breaks, PNG on the clipboard, download filename, description copy, block hidden after marking published); related specs `manual-publish-undo`, `publication-detail-actions`, `web-124-outcome-states` (axe), `publication-media` pass against the production build. Unit test for the copyable-image rule.

Notes:

- Axe flagged the first heading level (h3 under the page h1); the block uses h2.
- The first design repeated the status label "Publish by hand" as the block title, right under it; the title now names what the block holds and the channel instead.
