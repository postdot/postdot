# UX-693 Treat a failed upload as a problem to resolve, not library media

Outcome: failed uploads leave the media grid and the composer's media picker. When there are any, a compact notice above the library lists each file with a plain reason and a Remove action; past three, the rest fold behind "Show N more". Resolves GH #52.

Record:

- `apps/web/src/components/media/media-failed-uploads-notice.tsx` (new) and `media-attachment-picker.tsx`: the library splits loaded assets into usable and failed; counts, empty states and the "load more" sentinel use usable assets.
- `apps/web/src/lib/media-errors.ts`: `mediaFailureReason` maps the backend failure codes (`unsupported_format`, `invalid_content_type`, write/read limits, `upload_expired`, `size_mismatch`, `invalid_source`, `storage_missing`, `storage_failure`) to six readable reasons; raw messages are never shown. Codes checked against the API and media packages.
- Remove uses the existing deletion request, so the item follows the normal trash and retention path.
- Messages in en, fr, es, de. Checks: unit tests for the reason mapping; `e2e/media-failed-uploads.spec.ts` (four failed and two ready uploads: grid and picker show only the ready ones, the notice folds the fourth, axe clean in light and dark, no overflow at 390 px, Remove clears the notice and survives a reload).
