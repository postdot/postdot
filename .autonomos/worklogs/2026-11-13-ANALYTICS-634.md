# ANALYTICS-634 Saved publication engagement history

Outcome: Performance exposes saved metric histories for existing Bluesky,
DEV.to and Mastodon publications with bounded API pagination and a lazy chart/table.

Decisions: Each chart describes its displayed page of at most 100 observations.
Cursor ordering uses saved time plus identifier so tied timestamps cannot skip
rows. Reads retain project authorization and never collect provider data.
Missing observations split lines; changed content or measurement identities
suppress a continuous chart. Only compatible adjacent measured snapshots establish
a signed change. Freshness is the recorded state, not a live platform check.

Validation:
- Format, lint, spelling, types and existing four-locale coverage → pass.
- Unit/scripts → 1,902 passed; 11 existing opt-in skips.
- Focused PostgreSQL store/API tests → 6 passed, including pagination and access.
- Production browser journeys → 6 passed: three native histories plus grouping,
  tag filters and CSV regression. History covers gaps, measured zero, negative
  change, revision mismatch, pagination, lazy loading, read failure/retry and
  absence of collection effects; mobile overflow, keyboard and axe pass.
- Production build → all 22 packages pass. Design detector → no findings;
  desktop/mobile screenshots inspected (SPEC-010 LAY-01/02/04).
- Footprint → API 5,763,442 bytes; anonymous JavaScript 167,809 gzip bytes;
  idle memory within the existing target. No budget changes.

Open: History represents stored observations, not continuous platform monitoring.
Existing CSV remains a latest-observation export. Next recommended lot: scope the
API-only runtime and separate Studio hosting requested in the initial review.
