# UX-251 — Queue triage hierarchy

- Date: 2026-09-29
- Status: Complete; full repository verification passed at close-out
- Related issue: ISSUE-145

## Evidence and decisions

The populated authenticated Queue contained a project/time-zone subtitle that
was already represented by the shell selectors, zero badges for inactive
filters, a published row mixed with drafts at the same visual priority, and a
long pending-draft sentence repeated on every draft. The first frame now keeps
the title and creation action, preserves filter semantics and accessible count
names, hides visible zero badges, and removes copy that only restated an
unscheduled draft. Queue order prioritizes due, failed, ambiguous, and review
required work, then scheduled work, drafts, and historical states while
preserving the order within each group.

Retry and manual-publication actions use visible labels so their consequence is
clear at a glance. The existing filters, tags, bulk schedule/cancel actions,
draft menus, links, and published lookup remain available. The queue was
checked at wide and narrow widths; targeted Queue, outcome, and bulk-action
journeys pass without horizontal overflow.

Keep the Queue as the lifecycle triage surface. Revisit row grouping only if
real projects show a need for explicit sections rather than priority ordering.
