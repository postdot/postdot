# CHANNEL-497 — Builder persistence and activation integration

## Outcome

Added a regression test connecting the actual mapped-request, JSON-body and query builder adapters to the authenticated API and a migrated in-memory SQLite database. The test creates an isolated account, project, mapped channel and existing scheduled manual publication. No listener, shared database, external endpoint or live credential is used.

The scenario creates a JSON object body, adds a content reference and a boolean, adds a fixed query parameter and changes the HTTP method. It saves the resulting draft through the API, reads it back, previews impact, rejects stale activation and activates the correct revision. Assertions cover exact execution mapping round trips, preserved dynamic path/query expressions and headers, unchanged active profile before activation, and the final active profile.

Impact includes both the existing working draft and pending selected target. Preview leaves the complete editor state unchanged. Activation preserves the historical draft profile identity/content and selected target exactly, while updating the working draft assessment identity and revision as intended. The test checks these metadata changes explicitly rather than treating reassessment as a content rewrite.

## Evidence and investigation

- 25 focused tests across lifecycle/request/query/JSON-body modules passed, 261 assertions.
- check:quick passed, covering formatting, lint, spelling and types.
- No production implementation changed, so a new production build or visual browser pass was not needed. Previous passes cover the rendered controls; this pass adds server/persistence integration, not browser click-through evidence.
- Initial fixture attempts exposed a missing custom schema dialect declaration; corrected the fixture to declare draft 2020-12. An initial full draft equality expectation also surfaced intentional activation reassessment metadata; verified the store implementation and asserted its exact expected changes while preserving all other fields.
- No product defect was demonstrated in this bounded scenario. No validation assertion was skipped, and no production fallback was added.
