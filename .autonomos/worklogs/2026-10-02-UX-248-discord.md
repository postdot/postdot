# UX-248 — Discord message formatting

## Plan and outcome

Continue destination calibration with Discord message structure, emphasis,
underline and preserved line breaks. Reuse the existing Markdown renderer, with
an AST adaptation identifying underscore-delimited strong nodes by source position
and rendering those as underline. Escaped text and code nodes are never rewritten.
No dependency was added and the actual publication payload remains unchanged.

The compact message typography supports headings, lists, quotes and code. Links
are visual only, HTML cannot execute and external image URLs never load. Attached
Postbot media retain their existing presentation.

This is bounded calibration, not full Discord parser equivalence: strikethrough,
spoilers, subtext, mentions, custom emoji, multiline quote conventions and embeds
still need destination-specific treatment. CommonMark-only syntax may still differ.
Do not label this preview faithful for every Discord input.

## Reference

https://support.discord.com/hc/en-us/articles/210298617-Markdown-Text-101-Chat-Formatting-Bold-Italic-Underline

## Verification

Three component tests cover underscore underline versus asterisk bold, nested
emphasis, code/escape preservation, message structure and safe content handling.
Extend the existing destination browser journey with rich Discord content and
1280/390px captures. Full gate passed on the final change: 50 browser journeys, two password recovery
journeys and 17 build tasks, plus all package checks. The first green run produced
a mobile capture with excessive list spacing because whitespace preservation was
applied to the container. Restrict it to paragraphs, rerun the complete gate and
inspect the fresh 390px rich-message capture: compact list spacing, distinct
underline/bold and literal code markers. Tests use isolated accounts, not the owner
account. Shared preview chunk gzip grows from 79.30 to 79.50 kB (+0.20 kB);
no dependency was added.
