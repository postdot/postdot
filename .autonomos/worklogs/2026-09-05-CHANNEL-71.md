## Objective

Add the server-owned channel lifecycle contract required before the web channel
onboarding task can safely expose rename, archive, restore, and delete actions.
Keep channel identity, profile ownership, publication history, publisher
connections, and project-scoped machine access separate.

## Accepted contract

- Channels are `active` or `archived` and carry `archivedAt` plus a monotonic
  optimistic-concurrency revision.
- Rename works in either state and is revision-guarded.
- Archive is reversible, retains existing data, and is blocked by active
  publication work or a pending OAuth authorization attempt.
- Archived channels reject new authoring, profile mutation, publisher connection,
  and OAuth authorization; restore does not reschedule anything implicitly.
- Physical deletion requires an archived channel with no publications, publisher,
  or pending OAuth attempt. The API reports blockers without changing state.
- Every mutation is project-scoped, actor-attributed, transactional, and audited.

## Scope

- `packages/core`: channel lifecycle state and invariants.
- `packages/db`: channel schema/migration, focused lifecycle persistence, and
  guards at existing authoring/publisher/OAuth boundaries.
- `apps/api`: typed project-scoped lifecycle routes and OpenAPI contracts.
- Focused unit and integration tests for state transitions, reference guards,
  project isolation, stale revisions, and archived-channel write rejection.

## Forbidden scope

- Web UI implementation; that remains `CHANNEL-67` after this task is merged.
- New generic soft-delete or authorization frameworks.
- Changes to publisher credential ownership, profile version semantics, or
  publication history retention.
- Real provider calls or shared development servers.

## Implementation

- Added the active/archived channel state, archive timestamp, and monotonic
  revision to the core model and SQLite schema.
- Added the guarded, project-scoped lifecycle store for rename, archive,
  restore, and physical deletion, including actor-attributed audit events and
  machine-readable blockers.
- Added fail-closed guards to publication authoring, channel-profile mutation,
  publisher connection, and OAuth authorization boundaries.
- Added typed Elysia/OpenAPI routes for lifecycle mutations and regenerated the
  Drizzle migration and snapshot for existing channel rows.
- Kept physical deletion restricted to empty archived channels; profile rows
  may cascade, while retained publications and project-owned publisher state
  remain explicit blockers.
