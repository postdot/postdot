# UX-349 — Execution-aware composer and preview presentation

Base: `e8a0990ef`. Owner-approved implementation of UX-348.

## Change and boundary

A shared native-presentation resolver recognizes only the six supported built-in
execution contracts. Manual, declarative HTTP, unknown built-in and absent
execution produce generic presentation. Profile IDs still own labels and avatars;
they do not grant native formatting. No public response, persisted field,
library, source ownership, validation or delivery rule changes.

The composer uses the existing active channel execution summary for the native
DEV.to title fallback, X weighted feedback and configured editor dialect. Required
headline bindings and generic character/grapheme limits still come from its
existing full-profile read. Common copy remains plain. Invalid text is preserved,
not clamped or blocked from draft persistence. Accepted source formats alone do
not identify a Markdown dialect.

The shared preview requires an explicit execution argument. Composer and stories
supply list metadata; publication detail supplies previewProfile.execution. The
latter already selects the working profile for editing or selected target profile
for locked inspection, preserving historical rendering even when the channel
changes later. It does not require adding execution to the Channel entity or
reading another profile. Native chrome, Markdown rendering, identity samples and
mosaics use the resolved native platform; labels and avatars keep channel identity.

## Evidence

Two unit cases cover all six native contracts, manual and HTTP execution, unknown
and missing execution, and editor dialect selection. Existing preview ownership
unit cases remain: 17/17 combined, 39 assertions.

The retained nine-case scenario extends editor-composer-pilot: native controls,
renamed custom templates preserving execution, and manual profiles named x,
discord and devto. All nine API creations must succeed. It checks weighted
feedback, title, commands, preview platform and actual Markdown rendering. Manual
profiles retain literal text and their eight-character limit. Narrow 390px has no
page overflow. Initial focused run: 1/1 in 16.6 seconds (19.1 with harness), one
worker, no retry. The first run used the shared Content locator after changing
scope; the actual field is Channel content. Correcting that locator preserved the
invalidity assertion and required no product change. The manual X dark screenshot
was inspected: generic preview and short-text feedback are visible.

## Validation plan

The selector requires the full 39-file matrix because native-presentation is a
new unmapped module. Respect that fallback rather than editing coverage mapping to
make this pass cheaper. One final complete control supplies static, all unit,
browser and build obligations; no container behavior is affected.

## Limits and next direction

No real provider delivery or pixel fidelity claim. The nine-case regression covers
X, Discord and DEV.to; existing preview journeys exercise Bluesky and Mastodon layouts. No new LinkedIn
visual proof is claimed.
Native contract revision compatibility remains server-owned. Profile identity
continues to choose avatars deliberately, as ADR-083 describes.

## Harness correction before the complete control

Root typecheck cannot resolve web-only path aliases when a browser spec imports
the app template factory directly. Package typecheck had passed, but the complete
control correctly caught this before unit or browser suites. The fixture now
reads the actual custom templates from the existing creation dialog and renames
their IDs before API creation. This exercises the real factory through its UI,
avoids test-only bundler imports, and does not weaken profile guards. Root
typecheck then passes. An earlier static attempt also caught a worklog spelling
error; neither attempt reached the complete browser matrix.

## Follow-up scope

resolver still compares profile.id with discord/devto. This pass changes the
shared preview caller there, not the target field controls. The next diagnosis

locked inspection controls, before changing that path.

The UI-derived template scenario passed 1/1 in 17.4 seconds (19.9 with harness).
It replaces the direct app-module import while keeping all nine required creations
and all behavioral assertions.
