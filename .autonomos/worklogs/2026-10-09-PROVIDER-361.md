## Confirmed sources

Checked on 2026-10-09:

- [Official uploading guide](https://bsky.network/docs/about-bluesky-content/video/):
  hosted accounts need verified email; account-level upload limits apply. Direct
  PDS upload is possible but exposes a post before processing finishes. Recommended
  preprocessing uses a service token scoped to uploadBlob with PDS audience,
  uploadVideo, job status, then the processed blob in the record. A blob returned
  alongside already_exists is reusable.
- [Official embed lexicon](https://raw.githubusercontent.com/bluesky-social/atproto/main/lexicons/app/bsky/embed/video.json):
  MP4, 300,000,000-byte ceiling, optional description and aspect ratio. This schema
  does not establish a duration ceiling or account eligibility.
- [Official application constants](https://raw.githubusercontent.com/bluesky-social/social-app/main/src/lib/constants.ts):
  current client uses ten minutes and 300 decimal MB. These are client constants,
  not a guarantee that every account or service accepts those limits.
- [Permission specification](https://atproto.com/specs/permission):
  blob MIME grants and scoped service RPC grants are separate permissions.
- [Upload limits lexicon](https://raw.githubusercontent.com/bluesky-social/atproto/main/lexicons/app/bsky/video/getUploadLimits.json):
  canUpload, remaining daily videos/bytes and optional reason fields. Do not hardcode
  an account quota or request email address access merely to preflight eligibility.

## Repository findings

The Bluesky profile and executor are image-only post-v1. OAuth requests only the
post-create and image-blob grants. Its durable media identifier is a serialized
completed BlobRef; unfinished image uploads without an identifier are ambiguous.
Video needs a processing-job checkpoint distinguished from a completed blob, plus
worker deferral using the existing processing mechanism. Never reinterpret job IDs
as blobs or recreate a post while media processing remains incomplete.

Existing authoritative MP4 inspection, pinned media reads, description authoring,
private playback and deferred external-effect scheduling can be reused. No new
runtime, conversion, public Herald media endpoint or storage service is required.

## Proposed contract, not implemented

One exclusive H.264 MP4, three seconds to ten minutes, at most 100 decimal MB (the
current bounded Herald video policy), with description and inspected dimensions.
Keep text/image post-v1 unchanged; add explicit post-v2. Preprocess through Bluesky
before creating the record, persist processing checkpoints and release the worker
between checks. Keep outcome ambiguity separate from known unfinished processing.

New authorization grants require consent through reconnection for video use;
existing image credentials must continue to work without forced revocation.
Permission checks must use the actual token grant, not the requested-scope metadata
currently written by the callback. Exact least-privilege RPC scopes and SDK response
parsing remain implementation checks, not claims proven by this preparation.
