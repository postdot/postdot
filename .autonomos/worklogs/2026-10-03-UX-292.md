# UX-292 — Discover concurrent changes while preserving local editing

## Scope and progress

Continued ISSUE-150. The owner authorized the next pass; the refresh mechanism remains a consequential choice, with a question sent to the owner before implementing it.

## Reproduced defect and correction

A deterministic browser journey holds the local draft PATCH request in flight. A second authenticated context saves a newer shared source and destination, then explicitly rebases a sibling draft. The existing supported rebase SSE event invalidates the first editor query, so a newer server snapshot arrives before the held autosave completes.

Before correction, the incoming snapshot incremented the request generation but preserved the `saving` state. The stale response was ignored and no further state transition occurred: the editor remained on “Saving…” instead of exposing reconciliation.

The incoming-update path now enters conflict even when a save was pending. Local source/target/scheduling buffers and expected revision remain unchanged; authoritative CAS guards remain in effect. The old request response cannot clear the conflict or overwrite the buffer. The test asserts visible reconciliation, disabled promotion, preserved local text in the recovery buffer and the newer destination in the database.

All three focused two-session journeys pass after correction. The new journey failed before correction with the editor still on “Saving…”.

## Initial refresh mechanism review (superseded by ADR-076)

- Preferred proposal: refresh the existing publication-editor query every five seconds only while its page is visible. This costs up to twelve reads per minute per visible editor, needs no new server service or journal event, and bounds discovery latency. Keep existing SSE invalidation for supported lifecycle facts. Verify hidden-page suspension, visibility return and local-edit safety before adoption.
- Alternative: extend SSE to signal normal draft changes without journaling each autosave. This could reduce repeated reads, but requires explicit transport/reconnect semantics and a fallback for lost signals. A process-local signal must never become the correctness source.
- Journaling each roughly 650ms autosave was not implemented: it creates durable history volume for transient editing activity and changes the stream allowlist.

The current query has infinite stale time and disables focus/reconnect refresh. Normal draft saves insert no journal fact. Therefore the source conflict journey still explicitly reloads; no automatic draft discovery is claimed by this correction.

## Owner-approved SSE continuation

The owner rejected periodic polling and accepted an ephemeral SSE hint on the existing project connection. ADR-076 records that accepted direction; the earlier mechanism discussion above remains historical evidence, not current policy.

Implemented post-commit route emission, scoped process-local subscription, pending-change coalescing, authorization checks and cleanup. Browser hints invalidate only the matching publication or same-post sibling editors when the source changed, with a short one-shot grouping window. Connection/reconnection and visibility return refresh active editors; hidden pages defer draft-hint reads. No normal draft-save audit fact or recurring draft timer was added.

The first real sibling-refresh test exposed an additional bug: snapshot fingerprints omitted the current Post source revision, so fetched source changes were ignored when a sibling draft was unchanged. Added that revision to the fingerprint. Actual in-flight saves now settle before incoming snapshots are reconciled, avoiding false self-conflicts while retaining server revision guards and explicit local recovery.

Added tests for scoped safe ephemeral frames, authorization, coalescing and client envelope validation. Browser coverage now verifies automatic sibling conflict discovery without reload, local-copy recovery, pending-save conflict, hidden-page return and actual offline/online SSE recovery. Initial experiments exposed both the omitted fingerprint and test connection timing; final results below supersede those experiments.

Final SSE continuation validation passed: formatting, lint/spelling, typechecks, all unit/script tests, 69 main browser journeys, two password-reset journeys and 17 builds. Both development services responded HTTP 200 after validation. No AGENT.md update: the accepted transport choice belongs in ADR-076, without duplicating policy across files.
