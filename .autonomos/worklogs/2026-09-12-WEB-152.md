# WEB-152 — Return complete Queue aggregates alongside paginated publication rows

- Status: completed
- Date: 2026-09-12
- Task: WEB-152
- Issue: ISSUE-077

## What was done

The publication summary page contract now returns `summary` with total,
manual, automatic, and scheduled counts. The database computes it from the
same authorization-scoped project, tag filter, and optional half-open
scheduled range as the paginated rows, without applying the continuation
cursor.

The dashboard keeps this aggregate separate from the bounded publication list.
Queue summary bars, tabs, accessible labels, and unfiltered section metadata
now use complete counts. Loading another page appends rows and preserves the
known aggregate; a refresh or mutation replaces both pieces from a fresh read.
Calendar range reads receive the same range-scoped contract but continue to
use their own paged collection for rendering, so the new counts do not blur
calendar-range semantics with global Queue totals.

## Key decision

Pagination remains the row-delivery mechanism. Aggregate metadata is a small
bounded read beside it, with filter and range semantics explicit at the API
boundary. No unbounded history read or second projection was introduced.
