# MEDIA-183 — Refine media Trash hierarchy and copy

- Status: Complete
- Branch: `chore/reconcile-autonomos-ledger`
- Related issue: [ISSUE-104](../ISSUES.md#issue-104-define-the-scalable-project-media-library-contract)
- Design thesis: Keep Media as the primary route and make Trash a subordinate management view reached from the existing toolbar. Keep the Trash return path explicit and preserve only content that carries distinct state or recovery value.
- Domain boundary: No change to project ownership, retention duration, deletion, purge, or restore behavior.

## Delivered

- Replaced the peer-level Media/Trash segmented tabs with a quiet Trash action in the existing toolbar. The Trash view has a compact heading and a direct return-to-Media action.
- Hid the page-level Import action while Trash is active; it returns with the Media view.
- Shortened destructive actions and confirmation titles to “Delete” / “Delete this file?” (localized in French). Retention details appear once in the confirmation as low-emphasis text; the per-file permanent-deletion deadline remains as compact, distinct recovery metadata.
- Removed explanatory retention copy from the empty Trash state and removed the extra library-specific view terminology.
- Updated the browser flow to use a stable Trash action selector. The former exact-count expectation assumed one Trash item even though that same scenario had already moved two files there.
- Reworded restore and loading feedback to avoid unnecessary library terminology.
