# UX-250 — Destination inspection

## Scope and decision

Continue the accepted publication-detail composition. Read-only destination fields
were arranged as separate cards in two columns, which fragmented reading and
constrained long content. Replace them with a semantic description list: labels
and values align on wider screens and stack on narrow screens. Preserve all
values, including unset, null, false and empty values, and retain text line breaks.

Both editable and read-only Advanced JSON disclosures now share a native keyboard
control with a right-hand chevron and a 44px minimum height. Remove the redundant
outer surface; the payload itself retains its field surface. Invalid JSON still
opens the editable disclosure automatically. Validation, payload editing,
scheduling and lifecycle behavior are unchanged.

50 browser journeys, two password recovery journeys and 17 build tasks. Browser
evidence uses isolated fixtures, not the owner account. No fresh visual capture
of the expanded read-only technical list was inspected in this pass. Both local
