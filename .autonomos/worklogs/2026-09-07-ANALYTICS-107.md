## Findings

- Herald already has the correct durable operational sources: current
  `publications`/`jobs` rows and the versioned, project-scoped `audit_events`
  journal. Notifications have their own cursor and recipient state and must not
  become analytics input.
- The existing ANALYTICS-89 read path is a narrow query-time baseline. It reports
  current publication inventory and a small set of journal counts, but the target
  contract still needed an explicit current-vs-ranged split, workload indicators,
  delivery latency, provider-dimension snapshot rules, duplicate/version
  handling, and coverage semantics.
- The workflow makes `retry_scheduled` a durable requeue outcome, while
  `effect_started` is the boundary for a real external attempt. A claim recovered
  before that boundary must not be counted as a delivery attempt; a lease expired
  after the boundary becomes an ambiguous outcome.
- Manual publication writes `publication.published`; automatic success writes
  `publication.execution.succeeded`; reconciliation writes
  `publication.reconciled`. These canonical actions must not be summed as
  independent publication successes.
- Current publisher configuration is not a safe historical provider snapshot.
  Manual delivery must remain `manual` even when a channel currently has a
  publisher, and automatic facts need a non-secret provider snapshot or an
  explicit `unknown` coverage value.

## Decision drafted

ADR-051 proposes a query-time hybrid operational read model:

1. Current publications and jobs answer current state and queue/workload
   questions.
2. Versioned journal facts answer historical lifecycle, attempts, retries,
   recovery, and latency questions.
3. The first serving contract is read-only and query-time; a future projection is
   allowed only as a versioned, replayable cache behind the same contract after
   measured performance or retention evidence.
4. Provider engagement is a separate provider-owned observation/read-model
   boundary. Likes, impressions, clicks, reactions, and similar values are
   optional, provider-specific, freshness-aware, and never inferred as zero.

The ADR also defines metric names and counting semantics, event identity and
attempt deduplication, project/channel/provider filters, UTC and project-timezone
rules, bounded half-open ranges, retention/rebuild behavior, authorization and
project isolation, API/read-model shape, indexing constraints, alternatives, and
the first implementation out-of-scope list.
