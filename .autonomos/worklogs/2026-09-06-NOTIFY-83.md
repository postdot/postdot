## Objective

Make the durable, project-scoped in-app notification projection useful to a
human operator through the authenticated dashboard. Validate the external
delivery boundary with a recording transport in tests only; do not add a real
Ntfy, Telegram, or other provider adapter in this task.

## Accepted scope

- Add typed notification response aliases to `@herald/client`.
- Add web API methods for the project inbox, read, archive, and the existing
  preference endpoints.
- Add a compact accessible notification inbox to the authenticated dashboard
  header, with unread count, loading/error/empty states, read, and archive
  actions.
- Preserve project scoping and browser-local timestamp presentation.
- Add deterministic coverage for the web API contract and the outbox handoff
  through an in-memory recording transport, without network access.

## Out of scope

- Real external notification providers or transport management UI.
- Changing the event taxonomy, notification persistence model, or delivery
  retry semantics already accepted by the notification ADRs.
- Reusing Better Auth or publisher credentials for notification recipients.

## Constraints

- Use the existing Eden Treaty client and shared Base UI components.
- Keep the notification surface operational and compact; do not introduce a
  new dashboard page or a second layout system.
- Never log or expose notification destination secrets.
- Keep all tests deterministic and free of real provider side effects.

## Plan

1. Expose the notification route types and typed client methods.
2. Integrate the project inbox into the existing dashboard header.
3. Add focused web/API and transport-boundary coverage.
4. Run the complete repository gate and perform a read-only review before PR.

## Implementation

- Added notification response aliases and route-shape coverage to
  `@herald/client`.
- Added project-scoped web API methods for listing, reading, archiving, and
  updating notification preferences.
- Added a compact header inbox using the existing Base UI dialog, button,
  badge, empty, and scroll-area primitives with Bold Solar notification icons.
- Added loading, empty, error, read, archive, unread-count, and stale-request
  protection so changing projects cannot apply an older response to the active
  project.
- Added an E2E assertion for the real dashboard inbox and a database test that
  hands a claimed external delivery to a recording transport without network
  access.
- Kept external providers, destination management UI, and real network effects
  out of scope.
