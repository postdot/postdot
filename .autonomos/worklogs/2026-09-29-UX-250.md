# UX-250 — State-led publication detail, first pass

- Date: 2026-09-29
- Status: In progress; implementation and representative lifecycle coverage complete, visual direction remains provisional for owner review
- Related issue: ISSUE-144

## Evidence and decision

We inspected the authenticated published manual item and media-only draft at
wide width, then rechecked the modified published item at 390 px. The former
showed the same body in a read-only source form and a mock post, surrounded by
revision, format, status, destination, and multiple detail strips. The latter
was called “Media · 2” in Queue but “Untitled publication” on detail and led
with a large empty text area before its actual images.

The provisional layout separates editing from inspection. Editable states keep
the source and destination preview side by side. A read-only state now leads
with one centered post representation; source body, media, revision, target
customization, and provider payload remain accessible inside Technical details,
with Activity separate. A status/date pair no longer receives a full-width
surface unless it has a lifecycle action. The read-only post uses the real
channel identity rather than the sample author or simulated engagement used in
the authoring preview. Single-destination detail does not repeat the channel
rail; multi-destination navigation remains visible. We removed redundant
channel and disclosure helper copy from the first frame.

The preview now resolves selected media directly in a locked state. This
matters because the media picker is no longer mounted until Technical details
opens; relying on its asset callback would have left a media publication blank
on first load. An isolated browser test injects a read-only publication state
over a real media-only draft and verifies the image is already present without
opening Technical details.

The media-only draft now shares Queue's “Media · N” title and opens with its
images. The empty body field is replaced by an explicit Add text action, and
content options follow the media as a compact secondary disclosure. Once
opened, the body remains editable. Source revision moved behind options while
editing and stays in Technical details when locked. No lifecycle transition or
provider contract changed. The delivery field retains the project's time-zone
calculation, but its redundant “Project time zone: UTC” helper was removed.

The published desktop and 390 px layouts were visually inspected after the
change; the reduced first frame displays the post, state/date, and two
secondary disclosures without horizontal overflow. Technical details was
opened in the browser to confirm source content, format, revision, target
snapshot, and capability information remain reachable. The media-only draft
was visually checked with both image thumbnails before the content options.
The due-manual and failed states now have focused browser assertions for
their primary actions, full error visibility, centered detail header, and
mobile return path. The complete `bun run check` passed: formatting, lint,
types, unit tests, 40 primary browser scenarios, 2 password-recovery browser
scenarios, and production builds.

## Remaining work

Inspect representative scheduled, due-manual, failed, and connected-platform
states at wide and narrow widths with the owner. Review action hierarchy,
keyboard disclosure order, and return paths. The owner should judge the
provisional content-first inspection surface before it is treated as an
accepted detail-page direction. ISSUE-144 / UX-250 stay open.
