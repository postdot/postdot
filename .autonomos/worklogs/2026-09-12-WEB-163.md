# WEB-163 — Adaptive calendar anchor edge-case verification

## Status

Complete.

## Owner direction

Validate the adaptive Week/Day initial position against real temporal edge
cases before changing the calendar reading model further. The timeline remains
complete, empty ranges remain at `00:00`, and no universal working-hours
convention is introduced.

## What changed

- Added unit coverage for an early-morning publication that still receives
  temporal context, a late-night publication that stays within the same day,
  a non-UTC display timezone, and a timed occurrence crossing into the visible
  range.
- Moved the dense populated browser fixture to six publications at 23:30 and
  asserted that their rendered time-grid slot is `23:00`, the initial scroll
  moves to useful content, and all six events remain visible in Week and Day.
- No production implementation or calendar viewport policy changed; this
  task locks the guarantees already established by WEB-162.

## Evidence

- The integrated Postbot browser project `Calendar review workspace` opened
  Week with six existing publications and reported `scrollTop: 341`, with the
  six events in the useful first viewport. Day reported `scrollTop: 164` and
  all six events visible.
- The populated Playwright scenario passed with the late-night fixture and
  retained its existing Month, responsive, resize, creation, preview, and
  dense-content assertions.

next calendar decision can return to the larger reading model for dense
