# OPS-211 — Restore authenticated local app loading and unblock the media Trash PR

## Findings

- Vite's ignored `apps/web/.env` sent `/api` traffic to `127.0.0.1:3000`, which was serving the Solar Icons documentation site. Herald's API was also configured for port 3000, so it could not serve that port.
- The previous Herald API process had no listening socket and no open handle to the SQLite database; its exact runtime-lock marker remained after the process stopped. The marker owner matched the stopped Herald process. The SQLite file size and modification time were unchanged during recovery.
- Restarted the API on port 3002 and updated the ignored local API and web env files to use that port and consistent `127.0.0.1` origins. Left the unrelated Solar Icons and Commerce servers untouched.
- Confirmed `/health` and `/api/auth/get-session` return 200 directly and through Vite. A clean browser context now redirects `/dashboard` to `/login` as expected, with no page or console errors.
- The PR's CI failure was the OpenAPI route inventory omitting `/api/projects/{projectId}/media/{assetId}/permanent`. Added the route to the expected inventory.
