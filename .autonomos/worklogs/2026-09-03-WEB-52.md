# WEB-52 — Replace raw target JSON editing with a schema-aware publication editor

- Date: 2026-09-03
- Status: completed
- Issue: ISSUE-015
- Scope: web publication target editing
- Branch: `feat/web-schema-aware-target-editor`

## What was done

- Replaced the publication editor's standalone raw target textarea with a
  schema-aware control surface while preserving Advanced JSON as an explicit
  escape hatch.
- Projected channel-schema properties and declared field bindings into stable
  controls for text, numbers, booleans, primitive enumerations, string lists,
  ordered media, and unsupported or read-only fields.
- Preserved nested and provider-specific payload fields through immutable JSON
  Pointer updates rather than reconstructing a provider payload from a fixed
  Postbot-only model.
- Applied schema and capability limits together, including text and media
  bounds, and displayed the constraints alongside the controls.
- Kept incomplete numeric input local to the control and refused to rewrite
  invalid list values automatically, preventing normal editing from silently
  destroying data that requires Advanced JSON review.
- Kept the server validation and immutable promotion boundary authoritative and
  disabled explicit promotion after the server marks a draft
  `review_required`.
- Added unit coverage for schema projection, unbound and nested fields, local
  references, ambiguous compositions, constraint intersections, JSON Pointer
  updates, optional deletion, escaped paths, and enum values.
- Updated the browser scenario to assert that persisted target content appears
  in its structured controls as well as in Advanced JSON.

## Key decisions and why

- Schema properties are projected in addition to field bindings. Bindings carry
  Postbot semantics and media ownership, while custom channels may need editable
  provider fields that do not have a shared semantic binding.
- The control set is intentionally finite. Primitive fields, primitive enums,
  string arrays, and ordered media have predictable editing semantics; composed,
  ambiguous, or otherwise unsupported shapes fall back to Advanced JSON instead
  of being guessed or flattened incorrectly.
- Schema and capability constraints are intersected. The effective editor bound
  is never looser than either source of truth, while the server still performs
  the final validation.
- Advanced JSON remains part of the durable editor contract. It preserves the
  expressiveness of runtime-defined channels without requiring a bespoke UI
  renderer for every JSON Schema feature.
- No new generic repository, schema engine, or domain abstraction was added.
  The implementation consumes the existing profile contract and leaves
  persistence, validation, and promotion semantics unchanged.
