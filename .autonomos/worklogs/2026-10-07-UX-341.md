# UX-341 — Custom-profile delivery choices in the composer

Base: `50b6019a3`. Scope: composer delivery presentation, existing active
execution summary and an extension of the existing connection-recovery journey.
No server publication rules, content bindings, migrations or provider calls.

## Demonstrated defect

The composer classified manual delivery through the `manual-message` profile
identity rather than execution. A custom manual channel therefore displayed
"Automatic delivery for this channel requires a connection" and offered an
unsupported automatic mode. The focused browser journey failed before the
correction on the unexpected connection warning (expected zero, received one).

## Correction

`PublicationChannelTabs` and `PublicationChannelSettings` consume required
`ChannelListItem` metadata. Automatic-mode availability, setup expansion and
connection status use active execution: manual does not support automatic
delivery, HTTP and native execution retain existing behavior. An absent channel
is not treated as supporting automatic delivery. The identity-only rail still
accepts the ordinary channel entity. Story fixtures carry their native execution
summaries to respect the component contract; no optional metadata fallback.

The browser journey uses real custom manual and HTTP channels. It checks manual
status, absence of the misleading warning, absence of automatic choices in
shared and destination settings, and the HTTP positive control. Mixed shared
settings remain manual even when the HTTP destination is customized to automatic.
The common draft text survives destination additions and settings changes.
No publication is submitted and no connection credentials are sent.
