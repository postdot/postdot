# AUDIT-343 — Keyboard emoji focus during composer autosave

Base: `7a7a7406f`. Follow the failed complete control in UX-341.

## Cause and deterministic reproduction

The emoji list supplied inline React component types for rows, category headers
and emoji buttons. A parent render created new types and replaced the focused
button. Composer autosave changes parent state when its response completes.
The failure is therefore a real focus preservation defect, not merely a slow
assertion. The original full-run failure is consistent with this mechanism;
the trace alone does not establish its exact ordering.

A probe held the real composer PUT response, focused the visible emoji, then
released the response and waited for the visible `Composition saved` state.
Before correction, the captured button was no longer connected to the DOM.
The assertion failed deterministically. After correction the same button stayed
connected, and keyboard insertion succeeded. The probe became an extension of
the existing `x-weighted-text` scenario, rather than a duplicate suite.

The retained scenario checks focus before and after save completion and sends
Enter through the page keyboard. It does not use a locator press to restore lost
focus. It still verifies insertion, common/destination separation, undo,
accessibility, narrow layout and French search. The temporary probe was removed.

## Correction

Move the three list component types to module scope. A small React context
supplies the current character allowance to the stable emoji component, so
limits remain reactive without changing component identity. Existing styling,
ARIA indices, callbacks, search and lazy loading remain intact. No dependency,
provider action, extra delay, retry or server rule was added.
