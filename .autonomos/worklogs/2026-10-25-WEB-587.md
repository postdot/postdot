# WEB-587 — Anonymous entry JavaScript

Resolved ISSUE-191 by separating route-critical functions from authenticated UI:

- Performance search normalization/parsing now lives independently of provider
  analytics and the eagerly constructed provider registry. Existing consumers
  retain compatibility exports and the same normalization/transport bound.
- Project-shell data loading now lives independently of dashboard contexts,
  React Query hooks and feature state. Its requests, concurrency and returned
  data are unchanged.
- The toast viewport is mounted in the dashboard and development editor lab,
  which use notifications. Anonymous authentication uses inline errors and no
  longer loads toast/tooltip/popup infrastructure. Toast content and behavior
  are unchanged on the authenticated surfaces.

Production artifact comparison, same toolchain and gzip method:

| Anonymous `/login` graph | Before | After |
| --- | ---: | ---: |
| Unique static JavaScript files | 50 | 34 |
| Raw bytes | 809,919 | 463,591 |
| Aggregate gzip bytes | 279,730 | 154,814 |
| Existing budget | 184,320 | 184,320 |

Gzip reduction: 44.66%. The baseline is the current source before this change,
not FOUND-571's historical artifact (279,720 bytes). Intermediate isolation of
search parsing and shell loading yielded 193,049 bytes; removing anonymous
notification infrastructure brought the graph below budget. No runtime-memory,
wire-transfer, startup-time or total authenticated-download improvement is claimed.

Reproduce after `bun run --cwd apps/web build`:
`bun scripts/measure-footprint.ts --web-only --check`.
The existing full Linux/x64 runtime measurement remains available. The web-only
mode needs no runtime fixture or platform restriction, reports the entry screen
and unique files, and returns failure above the unchanged target with --check.
Build CI now runs that check. Developer guidance documents both it and the new
`POSTBOT_E2E_PRODUCTION_WEB=true` browser-harness mode.
