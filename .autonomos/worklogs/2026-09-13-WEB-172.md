# WEB-172 — Retire the reviewed calendar fallback

- Status: Complete
- Branch: `codex/reui-calendar-spike`
- Owner: orchestrator
- Scope: Remove the reviewed-away legacy overview calendar and make the ReUI
  calendar implementation canonical.
- Related issue: ISSUE-097
- Related decisions: ADR-070, ADR-073

## Goal

The ReUI calendar had become the accepted product direction, but the overview
still exposed a `?calendar=legacy` switch, a second month/agenda implementation,
and tests and copy for both paths. Remove that disposable branch without
changing the established `view`/`date` URL contract or the calendar behaviors
validated in the preceding UX work.

## Changes

- Removed the legacy calendar selector from overview search state and always
  render the canonical `PublicationCalendar` implementation.
- Renamed the reviewed component and event adapter to their stable names and
  updated imports, DOM hooks, CSS, and the ReUI event-calendar README.
- Deleted the obsolete month/agenda component and the unused project-calendar
  redirect alias after confirming no live route or test depended on it.
- Pruned legacy-only calendar helpers, messages, tests, and browser branches;
  regenerated Paraglide messages and the TanStack route tree.
- Updated the canonical browser scenarios to cover overview without the legacy
  query while preserving creation, inspection, density, responsive, and URL
  state assertions.

## Decision and follow-up

The reviewed ReUI calendar is now the only overview calendar; no fallback flag
or alternate implementation should be reintroduced without a new product
decision. Composer remains a separate UX workstream. The next review should first
decide whether the sidebar page is needed in addition to the existing
“New publication” actions, then clarify “Compose” versus “Create publication”
before implementation.
