# WEB-311 — Viewer consultation coherence across calendar views

Scope: consultation only. No new role policy, no server change, no new
translations, and live-revocation presentation is deliberately untouched.

## Findings

1. **Week and day still offered a create affordance.** WEB-310 made the
   time-grid slot click inert for viewers, but
   `event-calendar-time-grid.tsx` rendered a per-slot `+` button
   (`aria-label` = `Create publication · …`) that the month view had never
   gated. For a viewer that button was a dead control that created nothing.
   The month view already honored the existing `showDayAddButton` flag; the
   time grid now honors the same flag, so one flag means "this view may offer
   a create affordance" everywhere. No new prop and no new policy.
2. **The contextual sheet named an editing action for a viewer.** The footer
   label followed the publication lifecycle only
   (`canEditPublication(publication.state)`), so a viewer opening a
   `scheduled` publication was offered `Edit publication` and landed on a
   read-only page. The label now also requires that the operator may edit;
   viewers receive the existing `View publication` translation. Editors and
   owners are unchanged, and no translation was added.

Agenda was already consistent: it exposes no create path, and its rows consult
by navigation to the publication page.

## Correction

- `apps/web/src/components/reui/event-calendar/event-calendar-time-grid.tsx`:
  the slot add button is rendered only when `showDayAddButton` is set.
- `apps/web/src/components/publication-calendar-preview-sheet.tsx`: `readOnly`
  prop; the action is named as consultation when the caller cannot edit.
- `apps/web/src/components/publication-calendar.tsx`: forwards its existing
  `readOnly` to the sheet.

## Browser evidence

`e2e/web-310-overview-viewer-actions.spec.ts` now iterates the four reading
modes for a viewer (`month`, `week`, `day`, `agenda`) and asserts, in each:

- no `New publication`, no `Select`, no `Create publication` (any variant),
  no `Reschedule`, no `Cancel`;
- `Previous period`, `Next period`, and `Today` remain enabled;
- the scheduled publication is present and, when activated, the contextual
  sheet opens with `View publication` and no `Edit publication`.

Three test-design problems were found and corrected while building this
evidence, all caused by over-broad locators rather than product behavior:

- `toHaveCount(0)` passed against a not-yet-rendered page, so each view now
  waits for the rendered calendar.
- The fixture scheduled the publication 24 hours ahead, which fell outside the
  focused civil day in Week and Day; it is now anchored inside today.
- `getByText(title)` matched the summary-bar widget above the calendar, so
  clicking it navigated away instead of inspecting in context. Event locators
  are now scoped to `[data-calendar="reui"]`.

Non-vacuity was proved twice: restoring the per-slot add button makes the
viewer `Create publication` assertion fail, and restoring the lifecycle-only
label makes the `View publication` assertion fail.

## Remaining limits

- In Week and Day a viewer clicking an empty slot expands nothing and creates
  nothing; the time grid still offers no separate read affordance beyond
  event clicks.
- Agenda rows consult by navigation rather than an in-context sheet, which is
  the existing reading contract and is left as is.
- Live-revocation presentation is unchanged and remains its own mission.
