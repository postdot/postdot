## Objective

Add a repeatable browser-level integration gate for the merged publication editor
media path. The test must exercise the real Vite dashboard, same-origin proxy,
Bun API, Better Auth, SQLite migrations, local media storage, and publication
editor persistence without contacting a real publisher.

## Decision

- Use `@playwright/test` `1.62.1` as a root development dependency. Component-only
  tests would not cover the browser, proxy, authentication, or persistence chain;
  a manual smoke test would not protect the path against regressions in CI.
- Use Playwright's Node.js runner while continuing to run the application servers
  with Bun. The runner remains development and CI tooling and does not affect the
  Herald runtime or production bundle.
- Start API and Vite as two Playwright-managed web servers on dedicated local
  ports. The API runner creates an isolated temporary SQLite database and media
  directory, resets stale data before startup, and cleans it after shutdown.
- Keep failure diagnostics in the ignored `test-results/` directory. No generated
  database, media object, credential, or provider request is committed or sent.

## Coverage

The browser test creates a disposable email/password account, project, and manual
channel; uploads a valid PNG through the dashboard; creates a mixed text-and-media
publication and a media-only publication; reloads the dashboard; reopens both
editors; and verifies their source body, target JSON, selected media, and shared
asset identity.
