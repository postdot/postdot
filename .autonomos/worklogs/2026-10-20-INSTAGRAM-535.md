## Implementation and integration

- New `@postbot/instagram` package owns fixed `graph.instagram.com/v26.0` requests, required direct-login permissions, a typed container/status/publish protocol and the versioned `image-v1` profile.
- Container creation and final publication are separate operations. Only a numeric provider media receipt can produce a published outcome; PUBLISHED container status alone cannot. No hidden polling, write retry, remote schedule or fabricated permalink is included.
- Native profile: exactly one JPEG reference, conservative 8,000,000-byte envelope, optional caption (2200 characters) and alternative text (1000 characters), semantic source bindings and public delivery requirement. Inspected MIME/byte validation belongs to the existing media capability resolver, not the content-schema validator. Width rescaling is not rejected. Aspect-ratio checks still belong in the future inspected-media dispatch integration; the profile does not currently express ratios.
- The protocol uses bounded request signals and sanitized result codes. Known structured 4xx rejections remain effect free; malformed/missing acknowledgements, network errors and 5xx writes remain uncertain. HTTP throttling may provide a bounded defer hint but the primitive performs no retry. Image URL validation rejects known local names and literal private addresses, preserves signed query strings and never fetches the image. DNS/public HTTPS reachability remains an application acceptance concern.
- The parent integrated the candidate into the canonical checkout, added the IDE workspace entry and Docker manifest-only COPY entry, and regenerated only the workspace lock entries using the offline install. No new external dependency was introduced. The Instagram package is not yet a runtime provider or Studio creation option.
- The parent recorded the owner's direct-login selection in ADR-088. Earlier META-505 research remains historical proposal context, not approval for every proposed capability.
