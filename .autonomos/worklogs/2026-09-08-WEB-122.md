# WEB-122 — Preserve calendar entry points in the empty state

- Date: 2026-09-08
- Status: in progress
- Branch: `fix/web-calendar-empty-state`
- Parent: `fix/web-ux-audit-corrections` (PR #140)
- Scope: implement the calendar portion of the accepted route/state
  direction without redesigning the whole project dashboard.

## Change

The monthly calendar grid is now rendered even when the project has no
scheduled publications. Empty days already expose a labelled link to Compose
with that day selected, so the calendar remains a useful date-oriented entry
point instead of replacing the desktop view with a generic empty panel. The
mobile agenda keeps its month-specific empty state and date picker.

## Follow-up

The Channels view no longer exposes an internal profile-version fragment in its
primary row metadata. Built-in, custom, and unknown profile identifiers now
resolve to user-facing labels at the shared display boundary, keeping provider
implementation identifiers out of the normal navigation surface while leaving
profile editing available through the row menu.

The Overview and Queue views now use view-specific empty-state titles. Overview
invites the user to start from a source post, while Queue names the absence of
attention, scheduled work, or manual work directly. The shared Empty primitive
and publication data contract remain unchanged.

The Media route now presents one attachment-library surface instead of nesting
an additional verified-media heading and description above the picker. Its
empty state receives the library-specific copy, while Compose keeps its
contextual attachment copy through the picker default.

## Deferred

Overview, Queue, Channels, and Media empty/loading/error states remain separate
parts of WEB-122 and SPEC-007. This pass does not change publication data or
the calendar domain model.
