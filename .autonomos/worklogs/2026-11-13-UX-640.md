# UX-640 Loaded Studio and API build diagnostics

Outcome: Installation diagnostics compare the loaded Studio with a fresh API
identity. Known differences warn without blocking work; incomplete metadata stays
unknown. Studio identity remains visible through API loading/error/retry states.

Decisions: Embed identity in JavaScript, not a mutable HTTP file that can change
under an old tab. The companion stamp supports archive validation; absent legacy
stamps remain supported. Hash release inputs only in the web build task and pass
Docker arguments into that stage. Compare full revisions, not shortened prefixes.
Cache restoration may retain older hashed assets: qualify the active manifest
graph rather than treating retained files as the current build. A held production
version read exposed lazy catalogs finishing without notifying stable language
context consumers; catalog readiness now changes that context value.

Validation:
- Format/lint/spelling/types; all four locale catalogs → pass.
- Final unit/scripts → 1,926 passed; 11 existing opt-in skips. Covers partial
  identities, full-hash differences, malformed metadata and mismatched archive stamps.
- Diagnostics EN/FR → 2 pass in development, 2 in production: actual loaded
  literals, ignored replacement HTTP stamp, version/revision differences,
  matching recovery, pending reads, API failure/retry and unknown metadata.
- Scoped axe checks → zero violations. Existing production account settings
  locale/theme/password journey → pass after the catalog notification fix.
- LAY-02/LAY-04: retained declared reading column; captures inspected in EN dark
  and FR light at 1440/820/390 px; measured no horizontal overflow.
- Version/revision cache variants A/B/C/A → correct stamp and active chunks
  restored. Docker build-stage extraction → matching fixture stamp and JavaScript;
  container never started, task-owned image/container removed.
- Production build → all 22 packages pass; docs 265 pages, 1,321 local targets,
  zero broken links; LLM/social exports pass.
- Footprint → API 5,765,376 bytes; initial JS 168,031 gzip bytes; sampled idle
  maximum 127,464 KiB, within budgets. Default unversioned output restored.

Open: Matching identities do not negotiate API compatibility. Legacy/unversioned
builds may remain incomparable until rebuilt with metadata; no release/deployment
was published. Next recommended lot: focused composer UX review of failure
messages and draft recovery.
