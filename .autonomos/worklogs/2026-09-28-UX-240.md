# UX-240 — Keep Overview calendar-led and improve its summary widgets

- Date: 2026-09-28
- Status: complete for the owner-selected Overview slice
- Authority: The owner explicitly retained the calendar as Overview's main
  surface, rejected a separate Calendar route and action-first landing, and
  asked for a more engaging, useful summary area in place of plain KPIs.
- Related issue: ISSUE-063
- Related decision/specification: ADR-057, SPEC-007

## Owner decision

Overview stays calendar-led. Its existing summary band should add useful
current-work context without competing with the calendar or becoming a text
wall. Queue remains the lifecycle and human-action triage surface. No
application route, navigation, API, or publication lifecycle behavior changed.

The first route-map proposal and its text-heavy static HTML prototype were
rejected by the owner and removed. The live Overview is the review artifact.

## Implementation

- Replaced the three plain KPI values with a compact, responsive band showing
  due manual publications, the next scheduled publication or the latest
  published fallback, and scheduled/published activity during the selected
  calendar week.
- Linked the featured publication to its existing detail page. When manual
  work is due, its action opens Queue's attention filter. The zero state now
  says specifically that no manual publication is due, rather than implying
  every kind of attention is clear.
- Kept activity counts and date labels in the project time zone and in the
  calendar's selected week. Added an accessible textual summary for the chart.
- Removed the unnecessary gradient and kept one restrained raised surface with
  quiet separators. At 390px, the summary reorganizes into two small top widgets
  and one full-width activity widget; the calendar remains immediately below.
- Updated DESIGN.md, ADR-057, and SPEC-007 to record the owner's calendar-led
  direction. Marked the UX-240 slice complete while preserving ISSUE-063's
  broader populated-state and route-contract follow-up scope.

## Browser review and limits

The authenticated French project currently contains one published manual
publication and no due or scheduled work. Desktop and 390px views were inspected
in the live app. The recent-publication fallback, zero-manual-work copy,
zero-activity chart, and continued calendar prominence are visible. The earlier
action link was checked against the existing Queue attention filter before the
zero-state link was hidden; no publication, schedule, or provider action was
submitted. This sparse sample cannot establish the widget hierarchy under
failed, dense, or multi-destination data; revisit that in the broader UX-246
validation pass.

## Validation

- `bun run check:quick` — passed formatting, lint/spelling, repository and
  package type checks; English and French message coverage is 100% (1454/1454).
- `git diff --check` — passed.
- No automated tests were added or run; the task is a small UI composition and

## Crystallization

The 2026-09-28 owner direction supersedes ADR-057's former action-first Overview
and separate Calendar proposal. Overview owns the calendar; the summary band
provides bounded current-work orientation, and Queue remains the triage surface.
