# CRED-18 — Migrate LinkedIn publisher connections away from Better Auth

- Date: 2026-08-29
- Status: completed
- Related issue: [ISSUE-006](../ISSUES.md)
- Decision: [ADR-012](../decisions/ADR-012-own-publisher-credentials-and-use-oauth4webapi.md)

## Scope

- Remove the publisher OAuth and account-linking path from Better Auth.
- Compose LinkedIn authorization-code, PKCE, profile, and token-refresh mechanics
  through Herald-owned publisher routes and stores.
- Make publisher connections reference project-owned encrypted credentials.
- Keep background publication execution independent from Better Auth sessions and
  user-owned account rows.
- Preserve the existing single-process, SQLite-first, low-footprint deployment path.

## What was done

- Better Auth now exposes only Herald email/password authentication and application
  sessions; no social provider or publisher account configuration is registered.
- Added a project-owned publisher runtime that composes the encrypted credential
  store, single-use authorization-attempt store, OAuth protocol package, and the
  LinkedIn adapter.
- Replaced the publisher connection foreign key from `account_id` to the composite
  project/credential relationship and removed account-based worker resolution.
- Added the LinkedIn callback flow with exact callback binding, state digest lookup,
  encrypted PKCE verifier consumption, provider token exchange, OIDC member profile
  lookup, project credential persistence, and allowlisted dashboard redirection.
- Added refresh-token execution for expired credentials, token rotation with
  refresh-token preservation, and reconnect-required transitions for failed refresh
  or provider authentication responses.
- Removed account selection and binding from the web and typed client flows. A
  project member authorizes a provider, while the resulting connection belongs to
  the project and keeps the actor only as audit attribution.
- Added the `0007` migration with a fail-closed legacy guard. Existing pre-CRED-18
  account-backed publisher connections are left intact and block migration until an
  explicit reconnect or cleanup decision is made.
- Added provider profile tests, refresh tests, API integration coverage, project
  ownership tests, token non-disclosure assertions, and legacy migration coverage.
- Updated the Docker build inputs and deployment documentation for the new package
  and encryption-key boundary.

## Migration boundary

The migration intentionally does not infer ownership or decrypt credentials from
the retired Better Auth account model. A pre-CRED-18 database containing legacy
publisher connections must be backed up and handled through an explicit reconnect
or cleanup procedure before migration is retried. No legacy token is silently
transferred or discarded.
