# NOTIFY-81 — External Notification Delivery Outbox

## Objective

Build a transport-neutral, durable external notification delivery boundary that can
support Ntfy first and additional recipient transports later without coupling any
external effect to publication or in-app inbox state.

## Plan

1. Generalize the existing fenced external-effect executor without changing publication
   behavior.
2. Add project-recipient destination, subscription, projection cursor, and immutable
   delivery outbox persistence through a committed migration.
3. Implement atomic journal projection and prove that in-app preferences remain
   independent from external subscriptions.
4. Implement claim, effect-boundary, completion, retry, ambiguity, and lease-recovery
   persistence with deterministic concurrency tests.
5. Run the complete repository gate and an independent read-only review before merge.

## Acceptance criteria

- Only project human actors can own external notification destinations.
- Destination subscriptions are explicit per notification kind and independent from
  in-app preferences.
- Projection writes and cursor advancement are atomic, restart-safe, and idempotent.
- Concurrent workers cannot claim the same delivery.
- Expired claims requeue before the external-effect boundary and become ambiguous after
  it.
- Only an outcome that explicitly asserts no effect can be retried automatically.
- No real transport request, web UI, or provider credential is introduced.
