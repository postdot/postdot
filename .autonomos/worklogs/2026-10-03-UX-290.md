# UX-290 — Destination attachment correction

## Outcome

Existing editable publications expose bound destination attachments through the
shared compact media picker. The operator can remove, reorder, describe and
select project assets inside the destination customization, without editing raw
JSON or changing the common source. Locked publications retain inspection-only
fields. No domain, permission, delivery or storage contract changed.

## Decisions

- Reuse the accepted attachment thumbnails and library instead of introducing
  another image-management interface. Keep the attachment action beside the
  media field label and the authoritative validation message beside the images.
- Scope media updates to the selected binding. Preserve nested asset paths,
  accessibility descriptions, provider-specific item metadata and other fields.
  Existing callers that intentionally update all media bindings keep that behavior.
- Scope upload recovery controllers by publication and field so destination
  pickers do not share the common-source upload controller identity.
- The light-theme accessibility review found insufficient text contrast on the
  active channel label (3.82:1). Keep the selection surface and use the semantic
  foreground for its text rather than the action accent.

## Validation

- Ten target-media unit tests pass, including nested paths, retained metadata and
  isolation between multiple media bindings.
- The focused real-browser journey passes: two common images, LinkedIn limited
  to one image, removal inside its destination field, compatible server draft,
  reload persistence and unchanged Discord adaptation.
- Both themes reviewed at 1280, 820 and 390 px with accessibility checks and
  keyboard library activation. Browser evidence uses isolated test resources.
- Read-only review of the owner's populated LinkedIn draft confirmed the
  correction controls and field-local limit. No owner content was changed; the
  temporary review tab was closed.
- Full `bun run check` passed: 65 main browser journeys, two password-reset
  journeys, unit tests, formatting, lint, spelling, typechecking and 17 builds.
  Promotion retains two source images and one destination attachment; the sibling
  draft is unchanged. The source-toolbar regression passes with scoped assertions.
- The initial full gate exposed an overly broad test-selector change, not an
  application failure. Corrected the creation/detail test scopes, verified the
  long media journey separately and reran the complete root gate successfully.
- Development API and web return HTTP 200. The existing web development process
  was no longer running during the final service review; restarted it in a managed
  terminal. Its original exit cause was not established.
