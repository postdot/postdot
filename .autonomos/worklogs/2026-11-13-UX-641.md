# UX-641 Composer failure and recovery audit

Outcome: Recovery, session renewal and concurrent choices preserved the tested content. The audit found a reproducible contrast failure and three usability improvements; product behavior is unchanged.

Decisions:
- Reviewed `/dashboard/projects/:id/publications/new`: default rich editor, EN/dark and FR/light, 1440/820/390 px. Transport failures are injected 503s; conflicts use real competing API revisions. The opt-in `e2e/experience/composer-recovery-audit.spec.ts` reproduces six states and writes captures/observations under `test-results/experience-audit/composer-recovery/`.
- First priority: failed autosave only says local recovery remains available. The failure reason is a native title, with no retry action; another edit retries. Propose explicit browser-only/server-not-updated feedback and a guarded retry, without an autosave toast.
- Accessibility: FR/light creation refusal has 14 px error text at 3.74:1 (title) and 3.60:1 (description), below axe's 4.5:1 requirement. Confirmed on repeated mobile captures, including reduced motion.
- Second priority: real Release/Maintenance tag-only conflicts render identical version bodies, each with `Tags: 1`. Propose actual tag identities before choosing a replacement. Media identity/alternative-text differences are hidden by counts in source; that case was not rendered.
- Smaller copy improvement: failed draft reads say the whole page could not load and suggest reloading; the page is mounted and Retry reads only the saved draft. Name that object instead.
- SPEC-010 review: JRN-01, NAV-04, LAY-02/04, WAY-03 and COH-02/03 had no additional finding in this bounded journey. The usability proposals refine the governing intuitiveness value; they do not invent accepted rule violations. Contrast is separate accessibility evidence.
