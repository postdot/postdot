# UX-291 — Concurrent publication editing and recovery

## Work performed

Added two isolated browser journeys using separate authenticated contexts and persisted source/destination drafts:

- A shared-source change followed by reload exposes the stale sibling source base. Explicit rebase updates that base while retaining destination text, attachment selections, selected target and publication lifecycle/delivery/schedule. Reload confirms persistence.
- A failed local autosave, newer remote destination save and explicit server reload preserve a recoverable browser copy. The blocking choice survives Escape. Restoring saves the destination text and reduced attachment selection without changing the shared source or sibling destination.

Corrected the recovery choice excerpt: when the local destination differs from the server draft, it presents that destination text rather than unchanged common text. No restore, merge or lifecycle semantics changed.

## Decisions and limits

The source conflict journey deliberately reloads the stale session. Normal draft saves do not produce an SSE invalidation fact, so claiming automatic sibling refresh would be incorrect. Recorded ISSUE-150 for a separately reviewed transport/refresh decision. Do not add durable events for every autosave without assessing journal growth and compatibility.

The recovery preview remains a short text excerpt, not a complete diff; the restored payload still includes the existing source, target and scheduling buffer. These tests do not establish a merge policy for a local source edit competing with a remote source edit.
