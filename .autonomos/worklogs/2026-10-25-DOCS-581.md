# DOCS-581 — Documentation ownership consolidation

## Scope and source discipline

Public documentation belongs to apps/docs; agent development state belongs to
Autonomos. Root docs sources are dated inputs, not current implementation policy.
Check commands/configuration against executable code and accepted decisions.
Preserve proposal/acceptance status and historical evidence; do not infer new
requirements from old plans or convert evidence into normative guidance.

## Inventory

52 files: 20 distribution notice/provenance files; 4 root references, 7 deployment
references, 7 product/planning files, 2 security files, 2 benchmark artifacts and
10 design calibration artifacts. Distribution contents must remain unchanged.
The site currently projects installation from root docs; Docker copies its notices.

## Plan

1. Publish verified user/contributor material in apps/docs with no parallel source.
2. Preserve original dated root documents under a clearly historical archive;
   keep current requirements discoverable in existing issues/specs/decisions.
3. Move notices to licenses/, repair consumers and active links, preserve pinned
   historical URLs, then validate content, packaging and removal of root docs.

## Source disposition and current authority

All 52 original files have SHA-256 preservation targets in the archive manifest.
34 documentary/provenance files remain byte-identical historical snapshots;
18 license texts moved byte-identically to root licenses/. Current license
provenance prose has separate copies with corrected paths and stale hash entries.
The archived originals are explicitly non-authoritative; original relative links
are interpreted at the recorded source commit. No file was discarded unexamined.

Current public material is authored in apps/docs, not generated from root Markdown.
The former installation projection script/input/ignore/output were removed;
Turbo dry-run verifies authored installation is a cache input, not a build output.
Root/scoped instructions and dependent links follow that ownership. Pinned source
URLs in the skills intentionally still refer to the matching published commit.

Commands and claims were checked against current scripts, configuration, route
models, UI controls and accepted decisions. Examples of rejected stale claims:
Bun 1.4.2 minimum, Next website runtime, unpublished-image status and the old
channel-builder claim that query editing is absent. Old proposals, implementation
journals and live-test claims were not copied into current public instructions.
The accepted release policy is consolidated in ADR-093 without changing its scope.
Open product scope remains in existing issues/specs; relocation closes none of it.

## Validation

- Preservation manifest verifies all 52 originals after root docs removal.
- 18 legal texts match inside the locally built distribution image; decoder
  source hash, supplementary notices and required build/base inventory pass the
  existing distribution verifier. Docker build succeeds on local AMD64.
- Complete supplied-image production recovery acceptance passes: authenticated
  project, backup/held restore, graceful stop and visible forced termination.
- 15 targeted CLI/helper tests pass, with 136 assertions.
- Site export: 212 pages, 935 local targets, zero failures. LLM and OG checks pass.
- Static formatting/lint/spelling/type checks pass. A narrow spelling override
  recognizes one preserved fixture filename in its manifest/config only.
- Source cache dry-run includes the tracked authored installation, with no removed
  root-doc input or authored-page output. No generation overwrites authored MDX.

The first site export caught an incorrect new provider-capabilities URL; the
folder-qualified link was corrected and the full export/link gate passed.
The API bundle and CSS match the released image; the complete client artifact
set is not byte-identical (chunk hashes and minified runtime symbols differ).
No blanket executable-equivalence or new ARM64 acceptance claim is made. No
application source or runtime contracts changed, no provider calls occurred,
and no versioned image was republished. Recovery validation used isolated data.

## Remaining boundary

Fresh live provider checks, new performance claims and upgrade acceptance are
outside this documentation consolidation. The next useful product task remains
real alpha operation and its concrete feedback; old plans do not authorize new
features. Root docs is absent. No new public handoff or working report was added.
