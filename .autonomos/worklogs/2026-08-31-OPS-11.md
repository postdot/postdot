# OPS-11 — Reproducible local API and web startup

- Date: 2026-08-31
- Status: completed
- Scope: Local SQLite startup, API port configuration, Vite development proxy,
  and real HTTP verification of the dashboard integration
- Related issue: [ISSUE-008](../ISSUES.md)

## What was done

- Diagnosed the local API failure as a migration-history mismatch rather than a
  Better Auth schema conflict. The active ignored database contained eight
  migration records, while the repository currently commits five migrations.
- Added fail-closed context around existing-schema migration failures. The
  migration runner does not use `IF NOT EXISTS`, silently skip statements, or
  reset a database automatically.
- Made the Vite `/api` proxy read and validate `POSTBOT_API_ORIGIN`, defaulting to
  `http://localhost:3000`.
- Added `apps/web/.env.example` and documented the paired API/web configuration
  required when the default API port is occupied.
- Removed the misleading root instruction to run migrations against a separate
  database before starting the API; the API applies committed migrations at
  startup.
- Added the migration safety rule to the database agent guidance and resolved
  ISSUE-008.

## Verification

- `bun test src/migrations.test.ts` passed with three tests.
- `bun run check` passed formatting, lint, strict typecheck, unit and integration
  tests, and all 11 workspace builds. The database suite now contains 67 passing
  tests.
- A fresh API process on port `3001` returned `200` for `/health` and
  `/openapi/json`.
- A Vite process on port `5174`, configured to proxy to the API on `3001`,
  returned the Better Auth session response and authenticated project routes.
  The smoke flow created a temporary account and project, then exercised the
  four dashboard loader requests; all returned successful responses.
- The archived pre-change database reproduced the original failure and now
  returned the actionable migration-history diagnostic.

## Local-only artifacts

- The stale database was moved to `/tmp/postbot-dev-reset-20260831/postbot.sqlite`.
- The smoke-test database was moved to `/tmp/postbot-dev-smoke-20260831/postbot.sqlite`.
- `apps/api/.env` now uses port `3001` because another local project owns port
  `3000`; `apps/web/.env` points its development proxy to `3001`. Both files are
  ignored and contain no repository changes.

## Next steps

- Restart the existing Postbot Vite process so it loads the new proxy configuration.
- Start the API and web processes from their package directories, then sign up
  through the dashboard to create a fresh local account and project.
- Keep the default `3000`/`5173` pair for environments where no port collision
  exists; the alternate origin is a local development escape hatch, not a new
  deployment topology.
