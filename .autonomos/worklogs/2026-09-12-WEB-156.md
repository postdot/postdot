# WEB-156 — Responsive calendar composition and reading modes

- Status: complete
- Date: 2026-09-12
- Task: WEB-156
- Issue: ISSUE-080
- Related task: WEB-155

## Owner direction

The calendar remains the primary project overview. A narrow screen must not
force seven cramped columns as the default. Month and agenda are different
reading modes: agenda is the automatic narrow-screen mode, while month remains
available as an intentional choice. Dense days must remain inspectable in the
calendar flow, and opening a publication preview must not discard the selected
day context.

## What changed

- Added a viewport-aware default: the experimental calendar opens in agenda
  below 48rem and in month mode at tablet and desktop widths.
- Kept the view switcher available in every size. Choosing month on a narrow
  screen preserves the month composition inside an explicit horizontal scroll
  region with a stable minimum width instead of shrinking seven columns past
  readability.
- Added a stable `data-calendar-view` boundary for the two reading modes so
  responsive behavior and browser assertions observe the rendered mode rather
  than implementation details.
- Made day-specific styling win over the shared month-cell surface, so the
  expanded-day highlight remains visible with the Herald cell treatment.
- Preserved an expanded day while its publication preview is open and after
  the preview is dismissed; context is no longer silently lost during inspect.

## Browser validation

- Restarted the local runtime on separate loopback services: API `3001`, web
  `5173`, and React Email preview `3002`.
- Created a disposable local review account, project, and manual channel after
  the development SQLite baseline was regenerated. The integrated browser is
  authenticated and left on the populated ReUI overview.
- Created six local scheduled publications for a realistic dense-day check.
  Desktop month view shows five items and `+1`; the overflow trigger expands
  all six inside the same cell and week row; event selection opens the existing
  contextual preview without changing the URL.
- Confirmed the agenda view presents all six items as a readable dated list.

## Post-checkpoint adjustment

The owner could not reach the new calendar from the normal project overview,
because it was still gated behind `?calendar=reui`. ReUI is now the default
overview calendar; the previous implementation remains available explicitly
with `?calendar=legacy` so the visual comparison stays reversible while the
owner reviews the default. The `?calendar=reui` URL remains valid as a
backwards-compatible alias.
