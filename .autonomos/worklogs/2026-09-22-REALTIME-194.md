# REALTIME-194 — Revoke user notification streams after access loss

- Date: 2026-09-22
- Status: complete
- Issue: [ISSUE-113](../ISSUES.md#issue-113-reauthorize-global-user-event-streams-after-session-or-membership-changes)

## Context

The user-wide notification stream was session-authenticated at connection time,
but a long-lived connection also needed to stop after the session became
invalid or the user lost the last project that could produce visible events.

## Accepted approach

Re-evaluate authorization during stream pulls. When the session or visible
project set is no longer valid, emit a terminal `user.access-revoked` control
event without notification payloads, close the server stream, and close the
browser event source. Keep the existing project-scoped access-revocation
contract unchanged.

## Evidence

- The user stream rechecks the session and visible project set before reading
  journal entries.
- The API test covers loss of every visible project and asserts the terminal
  control frame.
- The web test covers parsing the control event and closing the source.
- The focused API and web realtime suites pass together.
