## Store contract (database worker)

Export createPublicationFirstCommentStore(database) and PublicationFirstComment from @postbot/db. Table publication_first_comments: id, projectId, publicationId (unique within project), actorId (enabling actor), text, delaySeconds, state waiting|pending|running|suspended|sent|failed|ambiguous|cancelled, revision (optimistic integer), dueAt nullable, rootUri nullable, executionRevisionId nullable, connectionId nullable, credentialId nullable, accountId nullable, recordKey, attempts, claimToken nullable, leaseExpiresAt nullable, effectStartedAt nullable, externalId nullable, externalUrl nullable, lastError nullable, createdAt, updatedAt. FKs use same project scoping as reply store; journal state transitions transactionally. No credential material. Field names are JS camelCase and SQL snake_case.

Methods: get(projectId,publicationId,subjectId): row|null (viewer read); save({projectId,publicationId,subjectId,text,delaySeconds,expectedRevision,recordKey,now}): mutation; cancel({projectId,publicationId,subjectId,expectedRevision,now}): mutation. Mutation={kind:'saved',firstComment:row}|{kind:'conflict'}|{kind:'not_found'}. expectedRevision0 means absent; revision starts1; subsequent changes compare revision. Retry of identical save with the previous revision returns the same current row, no second object/key. save explicitly enables waiting/pending/suspended; re-enabling uses current editor attribution; edit allowed only those states before claim. Do not re-enable sent/failed/ambiguous/cancelled or create retrospectively after publication (existing suspended/waiting may be re-enabled). Preserve already pinned identity on edits/re-enabling. Creation only native Bluesky profile, automatic delivery, draft/scheduled, editor; text nonblank bounded300graphemes/3000UTF16 and delay integer0-604800.

reconcile(now): transactionally inspect waiting/pending, suspend on lost enabling-editor access (no automatic resume); waiting becomes pending only for p.state published plus native succeeded job/execution whose completedAt equals p.publishedAt, automatic execution, native Bluesky profile. Bind exact execution/root/account/connection/credential, dueAt=publishedAt+delaySeconds*1000; no snapshot. Reject wrong/replaced account; root URI DID must match account. Manual-marked/reconciled success cannot arm; failed/ambiguous parent waits visibly; cancelled parent cancels unsent work. Due after downtime stays original. pending identity mismatch/no connection -> failed with safe reason. Use existing manual/publisher/access store helpers or scoped SQL, no new provider package dependency.

Expose deliveries:ExternalEffectExecutorStore<PublicationFirstComment>; claimCurrent(row,now):boolean; getNextEventAt():number|null. Due query uses dueAt<=now, not immediate createdAt. Include eligible waiting+confirmed-parent events in next-event calculation so a parent success/startup cannot strand work; exclude suspended/terminal to avoid timer spin. Existing singleton calls reconcile before claims; failed/ambiguous parent does not create a busy timer. Fence/lease recovery follows ADR009. Before effect recheck live editor access and exact receipt/connection. Known no-effect failure with lost editor access becomes suspended; uncertain post-effect result stays ambiguous. Completion must be claim-fenced; no automatic retries. RecordKey is stable per comment even across recovery/edits. Pinning is durable; never silently rebind changed remote parent/account. Include meaningful synthetic DB tests and generated migration integrity; no full repository/browser/services.

Independent failure/ambiguous/suspended/waiting states and external link, no retry/resend or new calendar entry. No polling service, use existing query invalidation/realtime patterns.
