# UX-659 Publication and post pages without JSON or internals

- Outcome: Studio no longer shows or accepts JSON: the "Advanced JSON" editor, the read-only payload, the "Technical details" panel (delivery snapshot, profile version, schema hash) and every catalog string naming JSON are gone; fields the form cannot represent read "Set by content rules". The publication page uses a left-aligned title under a named return; a text conflict appears in place instead of folded away. The save status reads "Draft kept" while edits are not applied and "Saved" once they are, with one "Save changes" action and no revision numbers (D1–D3). Untitled headings use a word-boundary excerpt; cancel is quiet (D4). The composer tags row is chips plus one "Add tag" menu that lists, creates and manages tags (P8).
- Decisions: Owner, 2026-11-14: JSON is abolished from Studio; decide alone when one option is clearly better. D2 keeps autosave as a safety net but names it as a draft until applied — auto-applying every keystroke would reschedule jobs and trigger cadence checks. Internals stay available through API, CLI and MCP. Earlier owner-request records (GH #39) are not constraints.
- Validation: `bun run check:quick`; production-build Playwright on publication, concurrency, media, tags, provider, thread, access and undo specs (52 passed). Recovery specs now pin `timezoneId: 'UTC'` because their seeded local copies are written in UTC.
- Second pass (D5–D9): the sibling strip reads "This post on" with labelled channel chips and no unexplained dots; the schedule is one "Publish on" field instead of a fold around a picker; the move dialog says in one line what happens; published work shows its actual publication time; revision numbers are gone and about sixty strings that still said source, revision, rebase, promotion, destination or target now speak of the post, the channel, its account and its version.
- Open: `editor-composer-pilot` failures predate this work (legacy editor is dev-only; title placeholder; profile revision).
