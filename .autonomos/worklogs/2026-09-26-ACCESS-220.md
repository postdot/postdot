# ACCESS-220 — Provide local account password recovery

## Outcome

Added an offline maintenance command for resetting the password of an existing
email/password account when SMTP recovery is unavailable. The command requires an
explicit database path and an interactive confirmation of its absolute path. It
reads both password entries without terminal echo, uses Better Auth's password
hashing operation, and never accepts the password through command arguments or
environment variables.

The database operation acquires the shared runtime lock, validates and creates an
owner-only pre-change backup, then atomically updates only the selected credential,
revokes that account's sessions, and invalidates its pending password-reset links.
Tests prove that projects, API keys, encrypted publisher-credential bytes, actors,
and other users' sessions and reset links remain unchanged. The command does not
create accounts or change instance-admin roles.

## Decisions

- Implemented password reset for an existing account, not admin-role reassignment;
  the accepted ADR describes those as separate recovery operations.
- Created a fresh validated snapshot automatically before mutation instead of
  requiring operators to locate and trust an external recent backup. The snapshot
  is stored in an owner-only directory with owner-only file permissions.
- Reused Better Auth's own password-hash function through `@postbot/auth`; no second
  hash implementation or reusable bypass secret was introduced.
- Kept the offline command's password-length validation aligned with Better Auth's
  configured policy by defining both limits once in the auth package.
- Reused the existing runtime-quiescence sidecar so the command fails closed if
  Postbot is running, and shares exclusion with restore and server startup.
- Preserved user-owned API keys and historical project attribution. Revoked only
  browser sessions and outstanding email-reset tokens belonging to the recovered
  account.
