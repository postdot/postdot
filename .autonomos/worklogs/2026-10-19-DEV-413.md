## Context

DEV-412 established and corrected the API-level behavior: a termination received during the startup window now runs the same drain as a running server, releases the runtime marker through the token-checked release, and exits 0. The API-level regression lives in `scripts/dev-api.test.ts` and proves the API process alone.

What is still unverified is the developer-facing path: the development launcher (`scripts/dev-api.ts`) owns the API child, forwards the operator signal to it, and restarts it after a watched change. The SITE-410 symptom was a development watcher restart that left the API without a listener while retaining a database handle, so the launcher path deserves its own evidence.

## Delegation decision

The live catalog advertises `opencode/minimax-m3.1-flash-free` with the variants low, medium, high, xhigh and max; `max` is selected. The parent remains the orchestrator: it owns the canonical checkout, the reproduction, the real-process execution, the review and the integration.

## Implementation mission

- Owner: parent orchestrator. Worker: delegated MiniMax M3.1 Flash Free mission in a dedicated worktree.
- Base: the committed parent head. Worktree and branch: recorded after dispatch.
- Allowed writes: `scripts/dev-api.test.ts` only, in that worktree. No product code, no governance files, no configuration, no dependencies, no lockfiles.
- Forbidden: real database, media root, default or shared ports, owner credentials, the owner's `apps/api/.env`, `herald.sqlite*`, network access, installs, merges, `main` writes, further delegation, browser and E2E runs, container work, provider calls, and any weakening of the fail-closed runtime-marker policy.
- Allowed checks: the new named test in `scripts/dev-api.test.ts`, `oxfmt --check` and `oxlint --deny-warnings` on that file, and the root typecheck. The worktree dependencies are prepared offline by the parent before dispatch.
- Acceptance: an operator stop of the launcher while the API child is still starting must release the runtime marker, the API child must never have served, and the next launcher run on the same fixture must serve the API without operator action. Bounded waits; the fixture is removed only after every owned child exited.
- Stop: the scoped uncommitted diff, the exact check results, and the limitations. The parent reviews and executes the real-process test in the canonical checkout.
