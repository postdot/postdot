# PUB-631 Existing-platform depth

Outcome: Added ordered Instagram JPEG carousels, Facebook multi-photo feed posts
and explicit Bluesky link cards with an optional thumbnail. Studio previews and
guides cover the new profiles; selected historical targets keep their contracts.

Decisions: Instagram image-v1 and Facebook page-post-v1 remain registered beside
their new revisions; Bluesky keeps post-v1/post-v2 beside post-v3. Existing channels
upgrade through the shipped-template review and activation flow. The composer
still saves invalid drafts; selection refuses invalid content. 
Instagram parent containers use an additive, separate media-group ledger anchored
to the first media in an immutable execution. Item identity/indexes stay intact.
Both ledgers use the same fenced lifecycle. Lost child/parent acknowledgements
remain ambiguous; confirmed children survive parent rate-limit retries. Facebook
checkpoints unpublished photo IDs before its final feed write. Ten Facebook photos
is an application envelope, not an asserted provider maximum.

Bluesky metadata is explicit and retained, without website scraping. A thumbnail
uses the Lexicon's 1,000,000-byte limit. Clickable link/tag annotations apply to
post-v3; old revisions retain their text behavior. Preview modules load lazily to
preserve the registry's browser-independent imports and anonymous bundle budget.
