# UX-344 — Composer projection for custom field bindings

Base: `734b065e3`. Diagnosis only; no executable product change.

## Demonstrated behavior

An isolated browser journey created three real custom channels from the shipped
manual starter: a root-field control, a manual profile with all bindings below
`/article`, and an HTTP profile with the same nested bindings. Creation returned
201 for all three. HTTP delivery remained manual throughout; no connection or
provider was contacted.

Each profile was used twice in the real composer: with destination-specific text,
and with the shared text left unmodified. The request, persisted editor draft,
profile binding and validation state were inspected through the existing API.

| Profile | Destination adaptation | Persisted content | Review |
| --- | --- | --- | --- |
| Root control | Explicit text | Root body and empty media | compatible |
| Root control | Shared source | Root body and empty media | compatible |
| Nested manual | Explicit text | Root body and empty media | review_required |
| Nested manual | Shared source | Article body and empty media | compatible |
| Nested HTTP | Explicit text | Root body and empty media | review_required |
| Nested HTTP | Shared source | Article body and empty media | compatible |

For both nested explicit adaptations, validation reports missing `article`,
invalid root `/body` and `/media`, and additional properties. The text is not
lost: it survives in the wrong field, requiring repair after creation. All
creations return 201 as drafts, which legitimately preserve invalid working
content. This is not a server validation bypass or a delivery failure.
The shared source remains unchanged across the six cases.

## Cause

`dashboard-context.tsx` builds explicit target content by platform identity:
DEV.to receives `body_markdown`, LinkedIn `commentary`, Bluesky/Mastodon `text`,
and everything else `body`. Its guessed `media` field also ignores the binding.
The declared `/article/body` is never consulted in this path.

Without an explicit target override, the store calls the existing core function
`adaptSourceContentToProfile`. It projects the source through declared bindings,
which explains the successful nested positive controls. Both channels use the
same active profile version between explicit and shared cases; an activation
race is not needed to reproduce the defect.

## Recommended correction boundary

Prefer the existing `getChannelProfileState` read and the core projection over a
new request shape or an enlarged channel-list contract. For explicit destination
text, derive target content from the active profile's declared bindings using
existing source semantics. Preserve source/destination separation, the existing
shared-source fallback, the destination text and media order. Do not infer
bindings from execution summaries or add provider-name exceptions.

Credible alternative: a server-owned semantic override input. That would change
the public creation contract and introduce a second projection input. It is not
needed for this demonstrated defect, so it is not recommended for this tranche.

Before implementation, examine profile-read caching/failures and activation
between read and creation. Do not conceal an unavailable profile behind guessed
fields. A profile mismatch must remain visible through existing validation.
Do not automatically migrate profiles or change promotion rules.

## Proof and limits

The first three-case probe passed in 16.7 seconds. The six-case probe passed in
24.8 seconds including its harness, then exact persisted-content, review-state,
validation and source-preservation assertions were added. The final result is
recorded below. Temporary probes are removed after measurement; the correction
must retain its regression in an existing journey rather than preserve a
second diagnostic suite.

Nonempty media, media order, title editing, native provider contracts, scheduling,
activation concurrency and narrow layout were not exercised. Empty media proves
the wrong structural path, not loss of actual attachments. The title control's
DEV.to identity condition was observed in code only and is not a separate
confirmed user-facing finding. No faithful provider transmission is claimed.

Delivery artifacts are documentation only: static checks apply, not a repeated
complete browser matrix. The fully validated reference remains unchanged.

Final asserted six-case probe: one passed in 21.0 seconds (23.6 seconds with
harness). No locator failures or product edits were needed. UX-344 is closed
as diagnosis, and UX-345 is registered as the proposed correction.
