# UX-337 — Preserve Discord-Native Source Syntax

- Base: `0e0c61c97`.
- Status: complete; targeted validation passed.

## Change and decision

The existing unsupported-syntax guard now recognizes Discord multiline quotes,
user/role/channel references and static/animated custom emoji. Loaded text or
text entered through Source containing these constructs stays in Source mode.
Editing and restoring it therefore avoids the CommonMark conversion that changed
`>>>` into nested quote markers and encoded reference brackets as HTML entities.

This reuses the explicit Source affordance already protecting headings, lists
and masked links in Discord. Dedicated document nodes would add an editor dialect
implementation beyond source preservation; they are not needed for this repair.
No dependency, stored format, publisher behavior or notification policy changes.
The Source toggle remains disabled while unsupported syntax is present and is
available again once that syntax is removed.

Detection examines lexer tokens recursively. Code blocks, inline code and escaped
markers do not trigger the new guard; ordinary quotes and existing rich marks
remain editable. Native references inside formatting marks are protected. Plain
and article profile behavior is unchanged.

## Evidence

The new unit regression failed before the guard and passes afterward. It covers
multiline quotes, references, both custom emoji forms, nested marks, code and
escape controls, ordinary quotes and profile isolation.

The existing unsupported-source browser scenario now adds a Discord passage with
multiline quote, mention and custom emoji syntax. It requires the Source toggle to
be disabled, edits the text and checks the exact serialized value, saves and
restores it, then edits again at 390 pixels. Removing the unsupported constructs
must re-enable rich editing and render bold and underline normally. This proves
an actual update and restoration path, not just an untouched initial value.
Focused scenario: 1/1 passed, 5.8 seconds (8.2 seconds including the harness).

## Scope and limits

This is protection for loaded text and explicit Source entry, using the existing
application boundary. It does not add native reference nodes, mention resolution,
custom emoji images or multiline-quote semantics to rich editing or previews.
Entering native syntax directly into rich text is not a supported replacement for
Source entry; this pass does not change rich typing or paste conversion rules.
Other Discord constructs such as timestamps and command references were not
included. No real provider was contacted.

The [Discord formatting reference](https://docs.discord.com/developers/reference#message-formatting)
was consulted on 2026-10-07 alongside the UX-334 evidence. Installed Tiptap
`MarkdownManager.encodeTextForMarkdown` confirms that non-code text is HTML-encoded;
code contexts are deliberately excluded. The guard avoids that conversion for
native references without changing the shared serializer.
