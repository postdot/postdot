- Status: diagnostic complete; no product change, no correction proposed.

- Scope: the second entry of the shared `ChannelCreationDialog` (compact icon

## Traced path

- Entry: `apps/web/src/components/new-publication-page.tsx:715-724` mounts the
  same `ChannelCreationDialog` with `compact`, guarded by owner/editor role.
  The route itself (`apps/web/src/routes/dashboard/projects/$projectId/
  publications/new.tsx:41-49`) redirects to Channels when there is no active
  channel, so the composer entry is unreachable with zero channels.
- Callback: `handleCreateChannel`
  (`apps/web/src/lib/dashboard-context.tsx:258-296`) returns a
  `ChannelCreationOutcome`; on success it appends the channel and fills only
  the first empty composer target (`index === 0 && target.channelId === ''`),
  otherwise it leaves every target untouched. Definition failures return
  inline issues without setting the page error; all other failures keep the
  existing page banner (`publication_new_action_failed`).
- Rail: `PublicationChannelTabs.addChannel`
  (`apps/web/src/components/publication-target-list.tsx:167-178`) adds an
  explicitly picked channel as a new target and drops empty placeholders at
  pick time; selection otherwise never moves implicitly.

## Demonstrated behaviors (real isolated browser probe, since removed)

A temporary spec exercised all four journeys against the disposable harness
with distinctive values (`COMPOSER-BODY-<suffix>`, named channels, API
channel counts). No provider was contacted. Final green run: `1/1` in
`10.7 s` (`13.0 s` with harness).

- Empty project: opening `/publications/new` with zero channels redirects to
  `/dashboard/projects/<id>/channels`. There is no creation entry to diagnose
  in that state; this is established both by the route guard above and the
  redirect assertion.
- Success: with drafting (`COMPOSER-BODY-…`) and one destination (Seed)
  selected, creating `UX333 custom` returns `201`, closes the dialog, keeps
  the exact body text, keeps Seed selected, and exposes the new channel as a
  selectable `Add UX333 custom` rail button. Count `1 → 2`. No existing
  destination is replaced: with no empty slot the newcomer stays available
  rather than selected.
- Refusal: an unknown-binding definition returns `400` with
  `{/capabilities/textFields/0/bindingId, capability.binding_missing}` and no
  sentinel text in the body (path reached, not assumed). The dialog shows the
  field, path, and localized correction, keeps the exact invalid JSON, shows
  no page banner (`publication_new_action_failed` count `0`), and creates
  nothing (`2 → 2`). Correcting in the same dialog returns `201`, closes it,
  and leaves drafting and selection intact (`3` channels).
- Cancel: opening creation, typing a name, then Cancel closes the dialog with
  the channel count unchanged (`3 → 3`, so no channel was created) and body
  text and destination selection intact. Whether a request left the client is
  not established by this observation; the observed result is absence of any
  created channel and untouched work.
- Consistency: the composer entry renders the identical dialog component and
  callback as the Channels page, so definition errors and corrections behave
  identically (structured alert observed in the composer context). The only
  contextual differences are the compact trigger and the banner host, and the
  banner stays silent for definition errors on both surfaces. No divergence
  found.

Two probe-only corrections were made during diagnosis (prefilled Seed
destination instead of an add click; rich-text `toHaveText` instead of
`toHaveValue`; composer assertions moved after dialog close because the modal
makes the background inert to role queries). No product behavior was changed
to satisfy the probe.

## Defects with user consequence

None reproduced. Every journey behaved per the designed contract above.

## Intentional choices (not defects)

- The newcomer fills the first empty composer slot and otherwise stays
  available without disturbing the current selection. This is explicit code,
  not an accident, and it protects existing destinations.
- Zero channels redirect the whole composer to Channels instead of offering
  creation in place; the operator creates the first channel where the full
  management surface lives.
- Cancel resets the dialog-local draft (name and JSON) while composer state
  is untouched; the two states are separate by construction.

## Product questions (open, no proposal made here)

- Should a channel created from the composer be added as a destination
  automatically when no empty slot exists, or is available-but-unselected the
  right default? Current behavior and its utility are established above; no
  policy change is proposed in this diagnostic.
- Should the empty-project composer keep redirecting, or one day offer
  inline first-channel creation? Out of scope for this diagnostic.
