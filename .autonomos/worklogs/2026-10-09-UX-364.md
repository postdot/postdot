# UX-364 — Coherent channel connection interface

Base: `6f2b13673`. Status: completed.

The owner explicitly expanded the pass beyond Mastodon to remove repetitive,
unhelpful interface patterns across channel connections. The operator job is to
identify a destination, connect it, and recover a failed attempt without losing
entered details or searching behind an overlay.

## Changes

- Channel rows use a single flat list. Connection actions are quiet outline
  controls; disconnect is in the existing management menu rather than a prominent
  destructive action on every connected row. The menu has a shared UI tooltip.
  Missing OAuth setup is grouped once by provider instead of repeated per row.
- LinkedIn settings move from the row into a compact connection dialog. X opens
  a dialog only when multiple applications require a choice; otherwise its
  redirect stays a single action, with a row-local error.
  LinkedIn exposes an explicit personal-account/company-page choice, with an
  organization identifier only when relevant. Application selection stays in
  the dialog and appears only when there is a real choice.
- Bluesky, Mastodon, Discord, DEV.to and custom HTTP dialogs share the same
  submission behavior: local errors, preserved input after failure, clear stale
  errors on editing, one pending attempt, Enter submission and explicit retry.
  Credentials are cleared on dismissal or successful connection.
- Connection callbacks propagate their errors to the form, retaining the existing
  API requests and project refresh. The page banner no longer competes with the
  open modal. Other dashboard actions retain their existing behavior.
- Copy keeps authorization context and useful setup instructions while removing
  repeated encryption explanations and redundant descriptions. Connection dialogs
  use the same restrained dark surface and footer treatment.
