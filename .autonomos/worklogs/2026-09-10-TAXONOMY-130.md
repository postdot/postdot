# TAXONOMY-130 — Integrate taxonomy into the daily web workflow

## Objective

Expose the accepted project-category and publication-tag model at the points
where it helps orientation and daily retrieval, without turning Herald into a
second content model or adding tutorial copy.

## Delivered

- Added localized category selection to the project context. Active categories
  can be assigned or cleared; an archived category remains visible on an
  affected project but cannot be newly selected.
- Loaded project-scoped tags with project data and added a compact multi-select
  to Compose. Selected tags are assigned to each newly created destination
  publication; a failed tag assignment is reported without inviting a duplicate
  post submission.
- Added publication-detail tag loading and replacement with archived assigned
  tags retained for visibility and recovery.
- Added a compact Queue tag filter. The selection is URL-addressable, uses
  stable publication tag IDs, and applies the accepted all-selected-tags (AND)
  behavior while preserving the queue's existing lifecycle filters.
- Added the typed web wrappers for category, project-tag, publication-tag, and
  bounded publication-summary tag filtering routes. The reusable tag picker is
  built from the existing Base UI/shadcn primitives and receives localized
  labels from its caller.
- Kept category definitions instance-managed by the existing human-session
  boundary; this slice does not invent an instance-admin role or a tag manager
  UI before ACCESS-116.

## Verification

- `bun run format`
- `bun run lint`
- `bun run typecheck`
- `bun run test` — full unit/API suite and 12/12 browser scenarios
- `bun run build`
- Added Queue unit coverage for the all-selected-tags rule.

## Review notes

- The first E2E attempt exposed an unstable search-array dependency that caused
  a render loop on the Queue route. It was replaced with a stable serialized
  search key; the complete 12-scenario browser suite then passed.
- The backend tag filter is bounded to 20 raw IDs, canonicalizes repeated and
  comma-separated query values, and loads summary tag IDs in one SQL query.

## Protocol

This slice follows ADR-062 and continues the implementation sequence from
TAXONOMY-129. No provider hashtags, analytics dimensions, inferred labels, or
external-provider side effects were added.
