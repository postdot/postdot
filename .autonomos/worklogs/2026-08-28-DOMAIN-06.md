# DOMAIN-06 — Project-Scoped Domain Foundation

## What Was Done

- Added pure TypeScript entities and construction invariants for `Project`, `Actor`,
  `Channel`, `Publisher`, `Post`, `Publication`, and `Job` in `packages/core`.
- Added explicit and independent publication and job transition graphs, including
  manual publication, scheduling, retries, cancellation, and ambiguous publisher
  outcomes.
- Added the matching Drizzle schema and generated SQLite migration for all seven
  domain tables.
- Enforced same-project relationships with composite foreign keys, one optional
  publisher per channel, bounded state values, lifecycle row consistency, and
  scheduler indexes.
- Added nine pure domain tests and five domain database integration tests; the two
  existing migration tests now cover both committed migrations.
- Proposed ADR-008 for the new state graph and project-scoped integrity model. It
 remains non-normative until the project owner accepts it.

## Key Decisions and Why

- Publication state and execution state are separate because product truth must not
  be rewritten by every worker attempt.
- Actors are project-scoped attribution identities with `human`, `agent`,
  `api_token`, or `system` kinds. The domain is not coupled to Better Auth tables.
- Project identifiers are repeated on relationship rows so SQLite can reject
  cross-project references with declarative composite foreign keys. No hidden
  triggers or speculative repository abstraction were added.
- A manual channel has no publisher row. An automatic channel can have at most one
  publisher, and no generic provider configuration format exists yet.
- Approval remains outside the M1 publication lifecycle so a future policy can be
  modeled as an independent dimension.
- Redundant single-column project indexes were removed when a required composite
  index already covered the same prefix.
- The discovered external domain-modeling skill was not installed because it
  mandates `CONTEXT.md` and `docs/adr/`, which conflicts with Herald's normative
  Autonomos locations.

## Validation and Footprint

- `bun run check`: passed formatting, lint, strict typechecking, 20 repository tests,
  and all production builds.
- `bun run --cwd packages/db db:generate`: reported no schema changes after the
  migration and snapshot were reviewed.
- `bun run measure:footprint`: API artifact 1,118,839 bytes; web initial JavaScript
  101,613 gzip bytes; median idle RSS 65,800 KiB; maximum idle RSS 66,056 KiB. All M0
  budgets remain green.

Compared with M0, the domain foundation adds 7,761 bytes to the minified API
artifact and 356 KiB to median idle RSS on the local reference machine. The web
initial JavaScript is unchanged. Cold-start timing is retained as session evidence
only because the five-process local sample is noisy.
