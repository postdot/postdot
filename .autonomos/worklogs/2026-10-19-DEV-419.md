# DEV-419 — Restore the green repository gate

## Plan

1. Establish that the failure is a drifted expectation and not a product defect.
2. Register a bounded delegated mission to correct it against the server's contract.
3. Review, verify the whole gate, and integrate.

## Problem

`bun run check` failed on a clean tree, in the CLI end-to-end suite:

```
(fail) machine publication workflow > creates two destinations, saves, promotes, reschedules, inspects and cancels through a real API key
    "linkedin": "not_configured",
- Expected  - 0
+ Received  + 1
```

The assertion at `scripts/postbot.test.ts:211` compares the CLI's publisher state with a hardcoded expectation of the provider readiness shape that still lists three providers.

The CI workflow runs `bun run check` before the container acceptance, so this stale expectation kept the whole pipeline red, including the production image acceptance that follows it.

## Cause

The Facebook provider was added to the built-in registry, and the server's contract grew with it:

- `apps/api/src/modules/projects/publisher-routes.ts` builds the map as `{ connections, oauthReadiness: { linkedin, bluesky, x, facebook } }`.
- `apps/api/src/modules/projects/models.ts` declares the same four entries in the response schema.

The CLI suite's hardcoded expectation was never updated, so the suite asserted a contract the server had stopped honouring.

## Correction

One line: the expectation now lists the fourth provider, and it still compares the whole map with `toEqual`, so a missing or extra key still fails. No assertion was weakened, skipped or loosened.

The correction was delegated to MiniMax M3.1 Flash Free with the `max` variant, and the mission required the worker to establish the contract from the route, the schema, the registry and the web client's own type before touching the test, so that a product defect could not be hidden behind an updated expectation.

## Evidence

- `bun test scripts/postbot.test.ts`: 9 pass, 0 fail, 99 assertions.
- `bun test scripts`: 91 tests, 91 pass. The suite is green for the first time since the provider addition.
- `bun run check:quick`: format, lint, spelling and typechecks across the workspace pass without bypass.
- The parent confirmed the correction independently: the diff is one added line inside the existing exact `toEqual`, and the canonical checkout passes the suite.
