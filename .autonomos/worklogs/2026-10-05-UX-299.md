# UX-299 — Profile version used for historical inspection

Bounded diagnosis, no change to any contract or publication rule. The hypothesis
under test: the editor endpoint resolves its profile from the draft
(`draftRow.profileVersionId`, `publication-read-store.ts:872`) while a locked
preview reads `editor.selectedTarget.content`. If the draft had moved to a newer
profile version than the one the selected target was written under, the preview
would interpret that target with bindings it was never written against.

**Conclusion: the hypothesis did not reproduce on either direct path. The draft's
profile version does not follow a channel profile activation, so the editor's
profile and the selected target's version stay aligned.** No correction is proposed,
because no divergence was demonstrated.

## Method

An isolated Playwright probe, deleted after the investigation, drove the two most
direct existing paths with isolated data (fresh account, project, channels,
publications, promotions, publications). Nothing was imported, restored, or
simulated, and no rule was circumvented. Each run recorded the draft's profile
version id, the selected target's profile version id, both binding sets, the
stored content, and the preview's displayed text.

## Path 1 — evolve the profile while a promoted target is still pending

1. Promote a draft, so a selected target exists under profile version **v1**
   (`primary_text@/body_markdown`). Draft and selected target both on `687d6aca…`.
2. Create a channel profile draft moving `primary_text` to `/article/body`, and
   activate it. **Activation succeeded**, and the channel's active profile became
   version 2 with `primary_text@/article/body`.
3. Patch the publication draft with no new promotion.
4. Try to publish.

Observed:

| Fact | Value |
| ---- | ----- |
| Channel active profile after activation | version 2, `primary_text@/article/body` |
| Draft `profileVersionId` after activation | **unchanged, v1** |
| Selected target `profileVersionId` | unchanged, v1 |
| Draft `reviewState` | `review_required` |
| Editor bindings | v1 — `headline@/title`, `primary_text@/body_markdown`, `ordered_media@/media` |
| `POST /publish` | **refused**, 404 `Due manual publication not found` |
| Final state | `scheduled` — locked inspection never reached on this path |

Two product protections are visible here, and both are recorded as observations
rather than as findings about this mission:

- The activation **assessed the pending target** against the new profile and marked
  the draft `review_required`. That is `assessChannelProfileImpact` covering
  `pending_targets` in `channel-profile-evolution.ts`.
- The scheduled publication was then **not claimable for delivery**, so a revision
  the system could no longer validate under the active profile was not published.

Because publication was refused, this path never reached locked inspection. It is
recorded as a refusal, not worked around.

## Path 2 — publish first, then evolve the profile

Same channel profile change, applied to a second, separately created publication
that was **already `published`**, so nothing was pending at activation time.

| Fact | Value |
| ---- | ----- |
| State before evolution | `published`; draft and selected target both `22bc499d…` (v1) |
| Profile draft creation | 200 |
| Activation | 200 |
| Draft `profileVersionId` after activation | **unchanged, v1** |
| Draft `reviewState` after activation | `compatible` |
| Selected target `profileVersionId` | unchanged, v1 |
| Editor bindings | v1 — `primary_text@/body_markdown` |
| Selected target content | `{"title":"Second original headline","body_markdown":"Second selected revision body.",…}` |
| **Displayed headline** | `Second original headline` |
| **Displayed body** | `Second selected revision body.` |

Locked inspection read the selected execution revision correctly, with the bindings
that revision was written against. The editor profile and the selected target are
the same version, which is why.

## Why the versions cannot diverge here

`activateChannelProfile` does update working drafts
(`updateWorkingDraftAssessment(… profileVersionId: draftRow.id …)` in
`channel-profile-store.ts`), so the mechanism exists. It did not fire for these
publications, and in path 1 the draft was instead flagged `review_required`. Two
readings are consistent with the evidence and this diagnosis does not choose
between them: either the draft was not treated as a migratable working draft in
these states, or the assessment deliberately marked it for review instead of
rebinding it. Either way, the observed outcome is what matters for UX-299: the
editor's profile and the selected target's version did not diverge.

## Refusals encountered, recorded rather than circumvented

1. Changing the profile **identity** in a draft:
   `400 invalid_input — "A channel profile draft cannot change profile identity from devto"`.
2. Renaming **binding ids**:
   `400 invalid_content — "Channel profile is invalid: Unknown binding ID body_markdown; Unknown binding ID media"`.
   Binding ids are constrained by the profile's declared capabilities, so only the
   path may move.
3. Publishing after evolving the profile while a target was pending:
   `404 — "Due manual publication not found"`.

None of these was worked around by changing a rule, adding an import or restore
path, or editing product code. The third one ended the path rather than being
retried in a different shape.

## What was not verified

- An imported or restored publication. Building an import or restore mechanism was
  explicitly out of scope for this mission, so that path stays unexamined rather
  than assumed safe.
- A profile change that moves **capabilities** rather than binding paths.
- Concurrency: activation racing a promotion, or a promotion racing activation.
- Whether the draft is ever migrated to a newer version by some other allowed path,
  which would be the precondition for the hypothesis.

## An observation that is *not* the UX-299 question

On path 1, the draft patch was accepted with `200` carrying
`{"article":{"body":"Later draft body under v2."},"title":"Later title"}` while
`editor.profile` reported v1, whose schema requires `body_markdown` and sets
`additionalProperties: false`. The editable preview then rendered that draft with
no body, because v1 bindings look for `/body_markdown`.

That is a stale-draft-versus-stale-bindings question in the **editable** path, not
in historical inspection, and it is recorded as an observation only. This mission
does not conclude whether the draft save validates target content against the
draft's profile version, against the channel's active version, or not at all; that
is a separate question with its own evidence to collect.
