## Implementation and targeted evidence

Profile version 2 allows one exclusive MP4 with the existing accessibility
requirement and inspected duration bounds; version 1 remains exported unchanged
and both execution revisions are registered. The adapter reuses verified pinned
media and durable attachment checkpoints. The existing bounded FormData transport
materializes at most the permitted 10 MiB video; no new multipart infrastructure
or asynchronous processing loop was added.

Provider tests cover exact bytes, MP4 MIME, description, disabled mention parsing,
oversized/mixed rejection before dispatch and secret-safe 413 classification.
413 now joins the definitive payload rejection statuses. Three real SQLite worker
scenarios cover publication with attachment identifiers, definitive rejection and
an uncertain network outcome, with a second scheduler turn proving no replay of
terminal outcomes. Historical-profile rejection and multiple-video rejection use
the existing media assessor. The final focused run passed 36 tests.

The existing native-video composer scenario also covers Discord: selection,
playback, seeking, layout at 1280 and 390 pixels, accessibility default and draft
persistence under message-v2. The targeted scenario passed in 12.8 seconds including
the harness; both screenshots were inspected. No web component changed.

All external-provider responses are simulated. General 20 MiB user limits were
not asserted as Bot entitlement. Existing image transport behavior is preserved,
apart from the justified definitive classification of 413. New video is exclusive
of image batches. Existing channels require an explicit profile upgrade. No real
Discord server, Bot token or message was used.
