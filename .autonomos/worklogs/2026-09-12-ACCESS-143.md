# ACCESS-143 — Enforce the accepted project role matrix

- Status: completed
- Date: 2026-09-12
- Task: ACCESS-143
- Issue: ISSUE-068

## What was done

Added one route-facing role guard backed by the current Better Auth project
membership. Project content, channel, profile, media, taxonomy, delivery, and
provider-analytics mutations now require an active editor or owner. Viewer reads
remain available. Membership administration, project settings, and project API
key management retain their stricter owner or human-session boundaries.

The guard runs before any manual-store write, credential operation, provider
request, or scheduler wakeup. Project API keys remain project-scoped machine
principals for ordinary project operations and cannot cross the owner-only
surfaces.

## Key decision

Authorization is enforced at the HTTP mutation boundary while the domain stores
continue to receive an actor id for attribution. This keeps denial side-effect
free without making lower-level stores guess the caller's role.
