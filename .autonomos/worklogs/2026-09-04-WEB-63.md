# WEB-63 — Restrict web entry points to the authenticated application

- Date: 2026-09-04
- Status: completed
- Scope: `apps/web` route boundary and entry-point navigation
- Task: WEB-63
- Issue: ISSUE-030
- Related direction: `DESIGN.md` authenticated application contract

## Objective

Remove the temporary marketing-style public pages from the current SPA without
changing the authenticated dashboard or the email/password authentication
boundary. The root entry point must resolve the current session to the correct
application surface.

## Acceptance criteria

- `/` redirects to `/login` without a session and to `/dashboard` with a
  session.
- `/about` and public marketing navigation no longer exist.
- `/login` remains directly reachable and does not link to a removed page.
- Authenticated dashboard routes continue to use the existing shell and
  project-authoritative routing.
- TanStack Router generated route types contain only authentication and
  operational application surfaces.
- The focused browser path and the repository quality gate pass.

## Boundaries

This task does not redesign the dashboard, add a public website, change
authentication policy, or alter API/domain behavior. META-62 remains a separate
methodology track and is not folded into this implementation.

## Implementation

- Replaced the marketing root with a session-aware redirect to `/login` or
  `/dashboard`.
- Removed the temporary `/about` route and its public navigation surface.
- Reduced the root layout to shared providers and the application outlet.
- Removed the obsolete return-to-home link from the login surface.
- Regenerated TanStack Router route types after the route inventory changed.
- Updated the end-to-end browser contract to exercise both root redirects and
  the authenticated dashboard entry point. The authenticated assertion waits
  for the dashboard shell before starting the second navigation so an in-flight
  loader request is not cancelled by the test itself.
