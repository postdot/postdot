# WEB-157 — Week and day calendar views

- Status: complete
- Date: 2026-09-12
- Task: WEB-157
- Issue: ISSUE-081
- Related task: WEB-156

## Owner direction

The calendar should not be limited to a month grid. Operators need shorter
temporal windows for precise reading as publication density grows, while the
existing month, agenda, preview, and explicit creation behavior remain intact.

## What changed

- Added Month, Week, Day, and Agenda to the ReUI view switcher.
- Added a local vendored read-only time-grid view built on ReUI's headless
  navigation, visible ranges, per-day segments, overlap packing, time-zone
  formatting, and event primitive.
- Added a deliberate minimum visual height for Herald's zero-duration scheduled
  publications so point-in-time posts remain visible in Week and Day.
- Anchored a Month-to-Week or Month-to-Day transition on the selected day when
  one exists, otherwise on today, instead of opening an arbitrary first week.
- Kept seven-column Week layouts readable with an intentional minimum width and
  horizontal scrolling when the viewport cannot accommodate them. Day uses the
  available width and hides an empty all-day lane to keep the operational view
  quiet.
- Kept event clicks on the calendar preview surface; the page-level “New
  publication” action remains the only creation entry point in these read-only
  views.
- Updated the local ReUI README and the populated calendar browser scenario.

## Follow-up

The initial density gap and missing slot creation were reviewed and completed
as WEB-158 / ISSUE-082: Week and Day now use content-driven stacked slots and
delegate creation to Composer. Drag-to-create, event movement, resizing, and
