# AUTH-637 Verified client addresses for authentication quotas

Outcome: Authentication quotas and session IP metadata now use the actual socket
peer, optionally resolved through an explicitly approved proxy chain. ADR-100
records the policy; operator documentation explains configuration and limits.

Decisions: Default to no trusted proxies, including loopback. Read forwarded hops
from the verified peer toward the first untrusted address; attacker prefixes
cannot select another quota identity. Reject malformed closest hops rather than
switching buckets. Overwrite the internal IP header before mounted authentication.
Carry socket provenance through HEAD redispatch using request metadata, because
a cloned Request has no Bun socket association. Preserve Better Auth's existing
production quotas and IPv6 /64 normalization. Counters remain process-local.

  malformed chains, independent IPv4 clients, IPv6 /64 grouping and shared
