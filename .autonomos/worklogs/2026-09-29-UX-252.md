# UX-252 — Performance no-data hierarchy

- Date: 2026-09-29
- Status: First implementation complete; navigation prominence remains a product review question
- Related issue: ISSUE-146

## Evidence and decisions

The inspected project had only a manual publication, so Performance rendered a
wide row whose only message was that statistics were unavailable. The page now
renders published publications only when their channel maps to a supported
analytics provider. Unsupported and manual publications stay truthful and
quietly remain available through Queue and publication detail. The first frame
uses a compact, useful no-statistics state instead of a provider capability
paragraph and a dead row. Provider names are not repeated beside a channel
when the destination identity already establishes the context.

The implementation does not invent metrics and preserves populated Bluesky and
DEV.to observations, refresh actions, pagination, and error handling. The
outcome-state browser journey covers the unsupported-only frame in French and
at 390 px without overflow.

## Files

Changed `apps/web/src/components/publication-performance-page.tsx` and the
English/French performance messages. The persistent navigation entry is left
in place until the product decides whether an empty analytics surface should
remain discoverable.

## Next steps

Review the route's navigation prominence with real provider-connected projects
before hiding or demoting it.
