# UX-346 — Composer controls versus custom capabilities

Base: `d568ba8be`. Diagnosis only; no application change or provider call.

## Measured journeys

Two isolated browser runs use the shipped custom starter through the creation
API, with an eight-character primary body limit and required headline. One uses
root bindings; the other wraps the schema and bindings under `/article`. Both
creation requests return 201. A native DEV.to channel provides a positive control
on the same page: its title input and Bold action are visible before switching
to the custom destination.

For both custom profiles, the title input is absent and Bold is absent. The
custom editor accepts `Long custom beyond eight` in full, without aria-invalid.
Creation as a draft succeeds (201), preserving content; the returned editor
reports review_required, a required-headline error and a body maxLength error.
Root paths are empty and `/body`; nested paths are `/article` and `/article/body`.
The server therefore enforces the definition; this is preparation feedback and
input availability, not an authorization or validation bypass.

Root: 1/1 passed, 8.6 seconds (14.3 including harness). Nested: 1/1 passed,
8.2 seconds (10.5 including harness). One worker, no retries or assertion changes.
The populated desktop screenshot was inspected: the custom workspace has text,
media and emoji actions, no title control or length warning. Narrow, light,
profile activation races and read failures were not exercised in this diagnosis.
Temporary probe removed; no redundant durable test is added before a correction.

## Code trace and interpretation

`new-publication-page.tsx` selects title visibility using profileId devto,
editor dialect using discord/devto identities, and weighted validation using x.
It does not read active custom text capabilities during preparation. UX-345
reads active profiles at submission and correctly projects custom text, but
cannot provide earlier controls or warnings.

Two demonstrated gaps merit a bounded correction: a declared headline has no
custom input, and an over-limit body has no preparation warning. The native title
is shared source state, not a destination-owned title; retain that ownership.
Allowing an invalid draft is intentional and must remain possible. A warning is
not a reason to truncate text or block draft persistence.

Markdown acceptance is a separate question. acceptedSourceFormats describes
source adaptation, not a complete editor dialect or a guarantee of native
rendering. Missing Bold on the custom profile is observed, but not classified as
a proven format-support defect. Do not silently choose Discord or article syntax
from markdown acceptance, or add provider-specific editing semantics in this pass.

## Validation and next step

with explicit loading/read-failure behavior and preserved native controls.
No public contract, promotion rule or migration is proposed here.
