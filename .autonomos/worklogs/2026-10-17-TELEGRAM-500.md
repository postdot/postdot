# TELEGRAM-500 — Telegram profile and connection API

## Outcome

Added the versioned built-in Telegram profile and native validation adapter. Plain text and media captions use separate budgets; a media-only publication is valid, an empty text-only publication is not. Schema and capability controls reject more than one media and restrict supported formats and family byte bounds. The native adapter applies the protocol's conservative UTF-16 limits without truncation.

Registered Telegram in the server profile catalog and creation schema. Added a session-only project-editor connection endpoint through the existing chained Elysia composition. Uses the isolated provider's metadata-only verification and existing encrypted project-owned credential store. Active duplicates are rejected before provider calls; reconnect-required credentials need fresh verification. Resolved destination identity and safe display metadata are stored through an explicit Telegram connection policy.

Threaded the injected transport through application/project route composition. No real provider credential or shared database was used. No Studio control has been added yet. Execution adapter registration is the immediately following task; the profile alone is not an end-to-end publishing claim.
