# NOTIFY-85 — Worker outcome projection verification

## Objective

Prove that outcomes produced by the real publication worker, including a
definitive failure and an ambiguous provider response, reach the persistent
project notification inbox through the durable event journal and notification
projection runtime.

## Decisions

- Extend the existing local LinkedIn worker scenario instead of creating a
  second fixture. The scenario already exercises success, retryable failure,
  ambiguous outcome, and definitive failure through a controlled provider
  transport.
- Keep the provider transport fully local to the test. The fake fetcher targets
  no real LinkedIn endpoint and no external notification destination is used.
- Verify the persisted inbox kinds and titles after invoking the actual
  notification projection runtime, rather than asserting only raw audit rows.

## Implementation

- Added `NOTIFY-85` to the Autonomos task board.
- Extended `apps/api/src/modules/workflow/worker.test.ts` to create the
  notification store and projection runtime after worker execution.
- Asserted that the worker-generated success, failed, and ambiguous outcomes
  produce the corresponding project inbox notifications.
