# CHANNEL-222 — Complete X publisher connection in the web workflow

- Status: complete
- Date: 2026-09-26
- Base: `docs/capability-evidence-matrix` at `09b0e200e`
- Issue: ISSUE-130
- Scope: Expose the existing X OAuth lifecycle from channel creation through connect, callback feedback, and reconnect

## Changes

- Added X as a built-in channel profile and connected its existing API OAuth
  start operation to the publisher connection panel.
- Added an X application selector for instance administrators. Non-admin
  project editors do not call the admin-only provider-application endpoint and
  instead use the instance's configured default application.
- Exposed the server-computed X callback URI on the admin-only provider
  application list endpoint. The X setup form displays it with concise OAuth 2.0
  Authorization Code + PKCE registration guidance.
- Kept callback outcomes in the existing connection feedback and recovery
  interaction; connect, reconnect, and disconnect remain consistent with the
  other built-in providers.
- Fixed typed-client error decoding: Treaty responses carry the server payload
  in `error.value`. Herald now preserves known API error codes so a missing X
  configuration produces its localized provider-unavailable message instead of
  a generic failure. Updated the notification error-state test to assert the
  localized `not_found` response.
- Added a browser scenario for channel creation, callback setup guidance,
  configuration failure, OAuth cancellation and denial, success, and reconnect.
  The browser test intercepts provider and callback traffic; it uses no live X
  account or credentials. Existing API tests exercise the OAuth protocol with
  mocked provider transport.
- Updated the capability matrix and resolved ISSUE-130 with verification limits.
