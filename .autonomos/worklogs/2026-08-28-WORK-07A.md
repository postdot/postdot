# WORK-07A — Atomic Job Claims and External-Effect Boundary

## What Was Done

- Split the M2 durable workflow proof into three reviewable tasks under `WORK-07`.
- Proposed ADR-009 for claim fencing, lease recovery, the durable external-effect
  boundary, and conservative ambiguity handling.
- Extended the pure `Job` model with claim token, claiming actor, claim time, lease
  expiry, and effect-start metadata.
- Required publication execution jobs to reference the publisher for the same
  channel, preserving manual channels outside the automatic worker.
- Added a concrete SQLite workflow store that atomically claims the earliest due
  job, fences state changes by claim token, commits the effect boundary with the
  publication transition, and recovers expired claims in an immediate transaction.
- Added and reviewed the generated migration, including safe conversion of legacy
  `running` jobs that have no claim metadata.

## Key Decisions and Why

- A claim that expires before `effect_started_at` is safely requeued because the
  external operation could not have begun.
- A claim that expires after `effect_started_at` fails the job and marks the
  publication `ambiguous` atomically. It is never retried blindly.
- Only project-scoped `system` actors can claim execution jobs. Their identifier is
  retained for publication attribution during recovery.
- Claim tokens fence stale workers. Lease expiry does not turn Herald into a
  multi-instance system; it makes singleton recovery explicit and observable.
- The claim query joins `publishers`, so a manual channel can be scheduled as product
  work but cannot enter the external-effect worker.
- No WAL mode, external queue, polling loop, generic repository, or provider
  contract was introduced in this slice.

## Migration Finding

Drizzle Kit 0.31.10 generated an invalid SQLite table-rebuild copy statement: it
selected the five newly added columns from the old `jobs` table. The committed SQL
was corrected to copy only legacy columns. A migration test now proves that pending
jobs survive and legacy running jobs become explicit failures instead of becoming
silently retryable.

`bun run --cwd packages/db db:generate` reports no remaining schema changes after
the reviewed migration and snapshot.

  <https://www.sqlite.org/lang_transaction.html> and
  <https://www.sqlite.org/isolation.html>.

  <https://orm.drizzle.team/docs/transactions> and
