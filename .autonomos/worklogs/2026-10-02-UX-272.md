# UX-272 — Access management reading and action hierarchy

## Problem

The owner rejected the prior member/key compositions despite reduced nesting and
normalized width. Flat rows alone did not resolve the mixture of identity,
permissions, invitation entry and group management. UX-270 records implementation
and validation, not visual acceptance of those rejected compositions.

## Changes

Workspace administration uses the same compact configuration body with independent
page header. Members and Groups are separate accessible tab panels, retaining
existing workspace authorization. Member invitation remains an explicit dialog.
Groups read in one column rather than competing grid cards. Their titles,
people and project grants remain visible; adding a member is disclosed on demand
within the chosen group. Repeated panel titles are visually removed while keeping
accessible section headings. Pending invitations have their own spacing.

Installation access now leads with a member list and its Invite action. Email
entry opens a focused dialog instead of appearing as an unexplained form below
the list. Successful invitation closes that dialog and reveals the one-time link
in the pending row. Failed submission keeps the email and error inside the dialog.
Current-account role/state remain readable; other-member controls retain the
original permission and self-protection behavior.

API-key identity has a compact key marker; project and action limits use a
semantic definition list with stable labels. Commands follow the permissions.
Expiration wraps on narrow screens rather than being silently truncated. Existing
secret reveal, scope selection, capability editing and revocation are unchanged.
English and French labels were added; the identical French/English word Actions
is explicitly recorded in the localization allowlist.

## Evidence

Native focused journeys cover group creation, invitation, acceptance, membership
removal/restoration and bounded API-key operations. Workspace tabs are exercised
in both themes at 1280, 820 and 390 pixels with Axe and overflow assertions;
installation member and key surfaces retain the same responsive checks.
Rendered review exposed redundant tab/section titles and permanently visible
per-group forms; both were corrected before final validation.

Earlier test adaptation accidentally inserted an invitation action in account
setup; corrected the fixture rather than altering product behavior. The previous
Herald-users heading assertion was updated to the new Members heading. No access
or recovery assertion was removed. An intermediate full gate was deliberately
stopped for the per-group disclosure correction.

Final full `bun run check` passed: format, lint/spelling, types/localization,
unit checks, 48 main browser scenarios, two password-reset scenarios and all
17 build tasks. Log: `/tmp/herald-ux272-check-final.log`. Final rendered evidence is in the isolated browser output under `test-results/`. API readiness and web HTTP both return 200;
the shared development services remain active.

## Durable guidance and continuation

No new global palette, domain ownership or universal component rule is adopted.
The composition is a reviewed implementation candidate, not a claim of owner
visual acceptance. Existing DESIGN.md hierarchy and necessity rules apply;
AGENT.md needs no operational change. Keep future resource-management review
focused on reading order and action intent rather than wrapper removal alone.
