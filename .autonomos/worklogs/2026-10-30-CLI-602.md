The owner explicitly asks for project-interest decisions rather than automatic agreement. Keep Bun-first tooling and shared source, but prioritize the small installed-runtime npm artifact for the first public alpha. The measured standalone proof works; it does not establish demand for maintaining native distributions. Retain optional compilation without making the native platform/release matrix a prerequisite. This corrects the earlier conflation of Bun-first development with mandatory embedded-runtime delivery. Continue the current slice with profiles, credential isolation and remote validation.

## Profiles and API-key credentials

Added named profiles with server origin and default project, selection/removal, explicit environment/flag precedence and a separate credential file. Remote handlers resolve their server, project and credential from one snapshot. An origin override cannot inherit the active profile's saved key or default project. A login checks the submitted key through Treaty before changing stored credentials; failed verification preserves the previous key, and an origin change during verification prevents persistence. Configuration writes use private files, atomic replacement and a short exclusive lock. Corrupt files and unsafe secret-file permissions fail explicitly instead of being silently replaced.

Implemented `config add/list/use/remove/set-project` and `auth login/status/logout`. Login accepts hidden terminal input or bounded stdin; JSON/noninteractive calls never prompt. Status reports only credential source, server and project. Logout removes the selected local credential and accurately reports whether environment authentication is still set; it does not claim server revocation. POSIX file persistence is implemented; Windows persistence remains unqualified and uses an explicit environment-key alternative. The public README documents these behaviors and the unencrypted-file storage boundary, without claiming an npm release.

The installed tarball works with saved profiles under Bun 1.4.4, the existing Node 25.9.0 and Node 26.12.1. Remote acceptance covers scoped discovery, byte-for-byte upload, profile defaults, successful/failed/oversized/noninteractive login, key preservation, no credential output, logout and environment use. A second HTTP listener receives no request when an origin override has no explicit credential. Focused configuration checks cover precedence, private modes, symlink refusal, malformed-file preservation and mutation locking. Real terminal probes verify hidden input and Ctrl-C cancellation under Bun and both available Node runtimes. Node 24 and other operating systems still require release qualification. Standalone compilation is now an opt-in acceptance option rather than a mandatory npm-release burden.
