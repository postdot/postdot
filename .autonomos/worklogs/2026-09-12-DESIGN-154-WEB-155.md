## Owner direction

The publication preview should not explain its own context with a visible
“Preview” heading, a footer “Close” button, or a second status marker. Clicking
an existing event inspects it without leaving the calendar. Clicking the day
background or `+N` inspects the date in the calendar itself; only the explicit
`+` control creates a publication for that date.

## What changed

- Added the project-local `herald-operational-ux` skill with reusable rules for
  hierarchy, progressive disclosure, one-fact/one-marker, one-dismissal, and
  inspect/create/navigate intent.
- Removed the publication preview eyebrow, footer dismissal action, and
  decorative status dot. The primitive close button, outside-click behavior,
  and Escape behavior remain available.
- Replaced the date drawer and nested overflow popover with an inline selected
  date section below the month grid. It lists every scheduled publication for
  the date, including items previously hidden behind `+N`, and each item opens
  the existing publication preview.
- Kept the day add button as the only date-oriented create entry point. A day
  background selects the date; clicking the same date again collapses its inline
  context.
- Updated the calendar contract and issue/task ledger to make the interaction
  meaning explicit. The seven-column responsive recompose is intentionally not
  claimed complete and remains WEB-156.
