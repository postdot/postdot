# CLI-372 — File and URL media import

Base: `805b970e5`. Local main, no push or real provider side effects.

## Delivered workflow

CLI commands: media policy, list/show, upload, import-url, and finalize. File upload
uses the existing typed Treaty routes for policy, reservation, raw PUT, and
finalization. The installed Treaty fetch override supports streaming a body while
the positional body is undefined; the byte-equality test protects against JSON or
multipart serialization. No second HTTP implementation, storage abstraction,
dependency, server schema, or format converter was introduced.

The server supplies allowed types and size limits. CLI hints do not bypass
inspection. Per-request timeout is configurable, default 30 seconds. Failed
verification exits nonzero. Pending responses are returned once, without polling.
File transfer errors after reservation retain asset/intent IDs; the CLI never
repeats a write, removes an asset, or assumes that an interrupted write failed.
URL import uses the server's downloaded-copy workflow and existing network policy,
not external article-image hosting.

## Evidence and validation

Extended the existing real-process CLI journey using an owned temporary local
store and in-memory database. A PNG is uploaded, recovered byte-for-byte, inspected,
and attached to two destinations. URL import passes through the real importer with
simulated network transport. Invalid PNG bytes fail verification and repeat
finalization remains failed. Additional focused cases prove one pending response
without polling and interrupted transfer retaining IDs with only GET/POST/PUT.

Targeted CLI suite: 9 tests, 69 assertions, approximately 1.3 seconds. Typecheck
passed. No live network source, video-provider delivery, or S3 acceptance is claimed.
Server image/video/storage behavior was reused rather than reimplemented.

Selector still falls back to the full matrix for unmapped CLI script paths. A
single final `bun run check` passed: 105 browser scenarios in 23.1 minutes, four
Mailpit scenarios in 16.7 seconds, static checks, unit suites, and 17 builds. The
known installed browser cache was used. No
container recovery is required because no container/serving behavior changed.
