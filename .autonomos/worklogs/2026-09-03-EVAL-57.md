## Preparation and first attempt

The local dashboard draft was created through the normal compose flow with one
generated PNG derived from the tracked Herald mark. The draft was queued for
automatic delivery to the existing connected organization channel. The worker
later attempted the due job before this session resumed because the local API
runtime remained active while the draft was waiting.

The attempt failed while starting the provider media delivery: the delivery
store used its wall clock for `created_at`, while the worker used the logical
workflow processing timestamp for `last_attempt_at`. A millisecond skew violated
the SQLite timestamp invariant before the media representation was opened or a
provider upload request was invoked. The durable row remains `pending` without
a remote media identifier, so this attempt provides no evidence of an external
LinkedIn media effect. The publication itself is conservatively classified as
ambiguous by the external-effect boundary and must not be retried blindly.

## Current blocker

FIX-58 must align provider media reservation timestamps with the workflow
processing clock and add a skewed-clock regression test before a new live attempt
is safe. No new provider request will be triggered until that fix is verified.
