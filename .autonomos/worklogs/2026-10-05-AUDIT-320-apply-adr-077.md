## What changed to make the policy usable with Autonomos

`.autonomos/**` used to be a transversal pattern, which meant an ordinary evidence
record forced the whole matrix by itself. Documentation is now classified
separately:

- `DOCUMENTATION_PATHS` covers `.autonomos/**`, `docs/**`, and Markdown;
- a change set made only of those resolves to a new `documentation` mode, which
  states that no scenario is required and that this is a policy classification
  rather than a coverage claim;
- the `documentation` mode is produced **only** when every changed path is
  documentation. Any code path alongside it re-engages the ordinary rules, so the
  full fallback for unknown and transversal code is untouched;
- the resolver still never produces a *targeted* selection with zero scenarios, so
  the old "never announce an unreliable empty selection" invariant still holds. The
  documentation mode is a distinct outcome, not an empty one.

Six tests cover this, including that a worklog beside transversal code, beside
unknown code, or beside a spec change does not suppress the relevant verdict.
`e2e/**` remains transversal: the suite files change the matrix itself.

## Correction: the validation trace

An earlier draft of ADR-077 stated that `9c1c669f9` and every commit after it were
documentation-only. That was wrong. Four of the five commits after `d70108840`
carry code or test changes, and the selector reports the full matrix for all four
because `e2e/**` is transversal, while the work actually performed was a targeted
spec run.

`d70108840` remains the last fully validated commit and is not moved by this
mission, which changes policy rather than code behaviour. The divergence between
the selector's verdict and the level actually run is recorded in ADR-077 as the
first thing the measurement phase should quantify.
