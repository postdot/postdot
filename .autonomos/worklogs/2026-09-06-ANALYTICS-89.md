# ANALYTICS-89 — Provider-neutral analytics foundation

## Objective

Define the first analytics boundary without adding a second fact stream,
external telemetry service, or web dashboard.

## Decision applied

`audit_events` remains the durable source of publication lifecycle and
automatic execution facts. Analytics are exposed as a rebuildable read model
over that journal and the current publication inventory. The initial contract
uses an optional half-open UTC range for historical events and groups daily
results in the project's IANA timezone. It returns aggregate counts only and
does not expose source content, media bytes, credentials, external identifiers,
or provider-specific payloads.

The rationale is recorded in
`ADR-042-derive-analytics-from-the-fact-journal.md`.

## Implementation

- Added `@herald/db`'s `createAnalyticsStore` with current publication
  inventory by state, delivery mode, channel, and provider dimension.
- Added event counts for publication creation, publication outcomes, automatic
  claims, effect attempts, retries, failures, ambiguity, recovery, and
  cancellation.
- Added project-local daily buckets derived from UTC event timestamps.
- Added authenticated `GET /api/projects/:projectId/analytics` with OpenAPI
  schemas and optional `from`/`to` query parameters.
- Added database and API regression coverage for access control, half-open
  ranges, project timezone bucketing, OpenAPI registration, and event-derived
  output.
- Kept `SECURITY-88` open: provider endpoint egress policy remains a separate
  operator-safety task.
