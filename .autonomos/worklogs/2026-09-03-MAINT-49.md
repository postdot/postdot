# MAINT-49 — Extract immutable publication target promotion

- Date: 2026-09-03
- Status: completed
- Scope: `packages/db` publication target promotion and execution-job reconciliation
- Task: MAINT-49
- Related issues: ISSUE-016, ISSUE-020

## Objective

Reduce the responsibility concentration in
`packages/db/src/manual-store/publication-authoring-store.ts` by isolating the
workflow that validates a working draft, materializes an immutable target
revision, promotes it, and reconciles its execution job. Keep source editing
and source rebasing in the publication authoring mutation store.

## Boundary and invariants

- Preserve the `createManualStore` and `createPublicationAuthoringStore`
  facades and all public types.
- Keep target promotion as one database transaction.
- Preserve project and actor scoping, publication state checks, source revision
  checks, profile validation, media resolution, and schedule validation.
- Preserve immutable target revision creation and media snapshot persistence.
- Preserve pending-job rescheduling, automatic-job creation, cancellation, and
  audit persistence semantics.
- Preserve draft save and rebase behavior in the authoring mutation store.
- Do not introduce a generic repository or change the domain model.

## Alternatives considered

- Keep promotion with draft save and rebase: rejected because immutable target
  materialization and execution reconciliation form a separate lifecycle from
  editable source synchronization.
- Split target revision insertion from job reconciliation: rejected because the
  promotion transaction must retain the external execution scheduling invariant
  as one cohesive operation.
- Move the workflow into a generic publication repository: rejected because this
  boundary is specific to Herald's publication lifecycle and does not justify a
  wider abstraction.

## Verification plan

- Preserve the existing promotion, scheduling, media, conflict, and rollback
  tests.
- Run focused database tests and the full repository quality gate.
- Obtain an independent read-only review before opening the remote PR.

## Implementation

The immutable target-promotion workflow now lives in
`packages/db/src/manual-store/publication-promotion-store.ts`. It owns target
content validation, media resolution, target revision and media snapshot
insertion, publication promotion, schedule validation, execution-job
reconciliation, and promotion audit persistence inside the existing transaction.
It reuses the working-draft and source-post loaders supplied by the authoring
composition, so no equivalent draft SQL was duplicated.

`publication-authoring-store.ts` retains editable draft save and source rebase
transactions, while the existing manual-store facade continues to expose
`promotePublicationDraft` with the same public behavior.
