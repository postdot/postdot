# MAINT-47 — Extract channel-profile impact assessment

- Date: 2026-09-03
- Status: completed
- Scope: `packages/db` channel-profile lifecycle and impact assessment
- Task: MAINT-47
- Related issues: ISSUE-016, ISSUE-020

## Objective

Reduce the responsibility concentration in
`packages/db/src/manual-store/channel-profile-store.ts` by isolating the
read-and-assess pipeline that determines how a proposed channel profile affects
working drafts and pending target revisions. Keep profile draft persistence and
activation orchestration in the existing store.

## Boundary and invariants

- Preserve the `createChannelProfileStore` facade and all public types.
- Preserve the activation transaction boundary: profile state changes,
  publication re-assessment, job cancellation or creation, and audit persistence
  must remain atomic.
- Preserve project-scoped queries for affected publications and target media.
- Preserve the distinction between working-draft and pending-target assessment,
  including pinned media validation and deterministic issue reporting.
- Keep profile compilation and domain assessment semantics in `packages/core`;
  the extracted module owns only database-backed orchestration around them.
- Do not introduce a generic repository or query abstraction for this extraction.

## Alternatives considered

- Keep impact assessment in the profile store: rejected because the store would
  continue to combine profile lifecycle persistence with a separate, query-heavy
  impact read model.
- Split every SQL statement into separate files: rejected because the affected
  publication queries and their media snapshot loading form one cohesive
  assessment pipeline.
- Move the assessment into `packages/core`: rejected because it currently needs
  project-scoped SQLite rows and the database media-validation callbacks.

## Verification plan

- Preserve the existing profile creation, preview, activation, and media-impact
  tests.
- Run focused database tests and the full repository quality gate.
- Obtain an independent read-only review before opening the remote PR.

## Implementation

- Added `packages/db/src/manual-store/channel-profile-impact.ts` for the
  project-scoped queries, target-media loading, and profile-impact assessment
  pipeline.
- Composed the assessor into the existing profile lifecycle store while keeping
  draft creation and activation persistence in the original transaction.
- Reused the shared content parsing and profile error helpers instead of keeping
  duplicate local implementations.
