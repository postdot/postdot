# MEDIA-393 — Optional background video posters

## Delivered

Video finalization makes the original ready before decoding. Startup scans missing posters and uploads enqueue work through an explicit callback, without polling. The queue deduplicates and serializes jobs. The optional decoder is interrupted and reaped before SQLite shutdown; an interrupted asset remains eligible at the next startup. Decoder failures retain the ready original and record a versioned failed attempt rather than retrying forever.

The extractor streams the original into a private temporary file, restricts input to MOV/H.264 and file/pipe protocols, bounds the operation to ten seconds and JPEG output to 2 MiB, and removes its temporary directory. The existing native image pipeline creates the same internal 256/768 WebP representations and ThumbHash used for images. Ownership is registered before storage writes and physical deletion waits for generation. No new library assets or publication defaults are introduced.

The existing project stream carries a payload-free completion event. Mounted media collections refresh loaded video entries without disturbing pagination or selection. Video cards use the poster or a neutral placeholder, with no video element in the grid. A player opened for inspection uses the original with metadata preload.

## Packaging and decisions

The independent Docker stage builds FFmpeg 9.0.2 from the official checksum-pinned source, with automatic dependencies, assembly and unrelated codecs/protocols disabled. It copies only the decoder and LGPL notice into the runtime. README records source/configuration and redistribution responsibilities. Development may use `herald-poster` or `ffmpeg` from PATH; absence leaves previews optional and uploads usable.

The owner accepted a small server decoder after MEDIA-391/392, with optional nonblocking posters and placeholders. This supersedes the earlier no-production-FFmpeg direction only for poster extraction; no transcoding is added. Platform-specific production builds remain a release acceptance responsibility.

## Scope and limits

Changed Docker/README, API composition/extractor/runtime/realtime projection, database preview processing/store, web media cards/collection/realtime listener, their focused tests and existing native-video browser assertion. Stable drain and original-preservation guidance is captured in the API/database AGENT files.

No live private library was modified by acceptance tests. Startup processing covers existing eligible videos when the application runs with a decoder. Rotation and ARM builds are not claimed tested. Failed extraction is not automatically retried for the same processor version. Video search rows and already-open inspection snapshots are not subscribed separately to poster completion. The original still downloads for actual playback; streaming delivery behavior is unchanged.
