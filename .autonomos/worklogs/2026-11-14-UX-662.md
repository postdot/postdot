# UX-662 Queue history, undo and density

- Outcome: A mistaken "Mark published" can be undone everywhere: Studio toast and publication page, history rows, `POST …/publish/undo` (publication:dispatch), MCP `undo_manual_publication`, CLI `publications undo-publish`; audited as `publication.publish_undone`. The queue gains a "Published" history tab (newest first, server-filtered with `state=published` and a `published` summary count; CLI `publications list --state`). An empty queue shows no tabs or filters. Rows are one line on desktop and two on a phone with actions beside; group headers drop the "N channels in these results" count and excerpts drop links.
- Decisions: Undo is a dedicated domain operation, not a general `published → scheduled` transition: it only applies to manual delivery, where nothing was sent by Postdot, and leaves the destination untouched.
- Validation: `bun run check:quick`; db (379) and API (693) tests; production-build Playwright on queue, overview, outcome, approval, media, publication and undo specs.
- Open: none.
