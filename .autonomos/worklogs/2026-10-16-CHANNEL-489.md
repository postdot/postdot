# CHANNEL-489 — Lossless mapped request editing foundation

## Completed

Read the domain execution mapping and validation rules before exposing a form. Mapped HTTP requests include dynamic and secret path segments, nested value expressions, query/header maps, form and multipart bodies, response classifications and extraction pointers. Rebuilding them from a flat form would lose semantics.

Added a browser-only projection and targeted-edit module for existing custom mapped HTTP profiles. It supports POST/PUT/PATCH changes, existing static path segment edits and outcome code-list updates. Dynamic and secret path objects are locked. Other profile and execution fields are retained by targeted immutable edits. Manual, built-in, webhook and incomplete execution shapes are not converted into mapped HTTP.

Tests cover nested map/object JSON bodies, form and multipart bodies, preservation of every unrelated field and the input object, locked expression segments, invalid indices and paths, bounded response codes and overlap rejection. Each supported edit is also checked with the real domain execution validator; the compiler is imported only by tests.

Updated the existing builder reference to describe this module's limited scope and correct its obsolete destination-editor preview description.
