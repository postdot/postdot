# UX-414 — Session refusals from media picker library actions

Status: complete
Related: UX-413 (upload refusal), UX-409 (session pause)

## Investigation

A library read refused by an ended session was probed first (composer, Add media dialog, session revoked, search typed). It already showed the sign-in pause, through the project data refresh, so no defect was reproduced for reads; the journey is kept as regression coverage.

UX-413 routed only failed uploads to the composer. The picker's other error paths (library edit-save, single and bulk deletion, URL import, listing, recovery actions) still ended in a local message without reaching the composer's session classifier.

## Changes and decisions

- `onUploadError` becomes the general `onError` on `MediaAttachmentPicker`: every error the picker describes for display (`describeError`) is also reported to the caller. The picker still does not interpret it; the composer's existing `pauseForSessionError` decides.
- The explicit call added in UX-413 is replaced by this single path, which includes upload failures.
- Other picker consumers pass no `onError` and are unchanged.

## Validation

- Four journeys in `composer-upload-session.spec.ts` pass; with the pending-media, upload-recovery and publication-media specs, 22 journeys pass.
- `bun run check:quick` passes.

## Limits and next scope

- URL import, deletion and library edit-save are routed by the shared path but have no browser journey: the import UI is an Uppy Dashboard flow that this pass did not drive. A refusal there is covered only by code inspection.
- Revocation uses the real sign-out endpoint, not wall-clock expiry. No full matrix, physical-device or screen-reader acceptance claimed.

Recommended next task: add a browser journey for a session refusal during URL import or library deletion, and then verify the standalone media page's own session handling.
