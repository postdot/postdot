# UX-248 — Article text rendering

## Plan and outcome

Resume destination preview calibration with DEV.to article formatting. The previous
preview printed Markdown punctuation as ordinary text, weakening its usefulness
for reviewing an article. Render headings, paragraphs, emphasis, lists, quotes and
code through react-markdown 10.1.0 rather than introducing a custom parser. Other
platforms retain their existing text treatment; Discord syntax differs and requires
its own bounded pass.

Keep parsing local and safe: HTML is not executed, links have visual treatment
without navigation and embedded remote images do not load. Image alternative text
remains visible; attached Herald media retain their existing preview. This is a
limited simulation, not a claim of full Forem HTML, Liquid or embed compatibility.
No source text, payload, validation or delivery semantics changed.

## References

- https://dev.to/p/editor_guide — article Markdown, HTML and Liquid capabilities.
- https://support.discord.com/hc/en-us/articles/210298617-Markdown-Text-101-Chat-Formatting-Bold-Italic-Underline — differences from article syntax, including underline.

## Verification

Server-rendered component tests cover article structure and safe handling of HTML,
image URLs and unsafe links. Full repository validation passed: 50 browser journeys, two password recovery
journeys, all package checks and 17 build tasks. Inspected the fresh 390px DEV.to
capture (ordinary text/title); rich Markdown structure is covered by component
tests, not a fresh rich-content browser capture. Browser tests use isolated
fixtures rather than the owner account.

Production bundle compared with the preceding gate: the shared publication-target
chunk grows from 43.92 to 79.30 kB gzip (+35.38 kB), explained by the CommonMark
parser and React rendering pipeline. The entry chunk stays effectively unchanged
(102.39 to 102.40 kB gzip). No runtime service was added. This bounded dependency
cost buys established parsing rather than a custom Markdown implementation.

## Remaining scope

Calibrate Discord separately, then destination media layouts and long-text
presentation. Forem embeds and remote media are deliberately not simulated by this
pass. UX-248 remains in progress; no AGENT.md rule is promoted.
