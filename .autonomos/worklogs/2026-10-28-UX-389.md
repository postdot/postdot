# UX-389 — Web experience standard and baseline audit

- Task: UX-389; issue: ISSUE-192; specification: SPEC-010 (draft)
- Date: 2026-10-28

## Request

The owner asked for high, enforceable quality standards so that agents can see the defects the owner perceives in menu sequence, hierarchy, intuitiveness and coherence between actions, without the owner listing each one. The owner supplied examples (empty first project, Workspace channels transition, project directory layout, mixed page widths, colour by category) and noted that this was a quick first reaction. The communications agent's COMM-016 review of alpha.3 supplied six further points.

## Delivered

- `SPEC-010` (draft): five rule families (JRN, NAV, LAY, WAY, COH) with a verification method each. WAY-01 (colour per scope) is a `candidate` pending an owner decision because it touches the colour direction in `DESIGN.md`.
- `e2e/experience/route-registry.ts`: 17 routes with scope, shell, width class and job. Declarations are a draft; see its header.
- `e2e/experience/experience-audit.spec.ts`: evidence collector, opt-in through `POSTDOT_EXPERIENCE_AUDIT=true` (excluded from the default matrix in `playwright.config.ts`). It records full-page captures and `observations.json` under `test-results/experience-audit/` (untracked).
- `.agents/skills/postdot-experience-review/SKILL.md`: the audit procedure.
- No application behaviour changed and no existing test changed.

## Baseline audit

Scope examined: English, dark theme, an administrator account with one new workspace and three empty projects, 1440 x 900 and 390 x 844, every registered route (empty state only), plus the empty-project journey and the sidebar scope transition. Not examined: light theme, French, populated data, shared channels, reload behaviour after selecting a context, and anything on a touch device. At 390 px only horizontal overflow (none on any route) and the Overview capture were checked.

The first owner example needed a correction after reading the code: the empty-project action does work. `New publication` opens the composer, which accepts text and offers `Add channel` inline (UX-256). What fails is the explanation and consistency around it.

## Limits of this audit

- Dark theme, English, empty states, one account. A populated, light or French pass can change findings 1, 8, 9 and 12.
- The collector's measures are coarse. They support review; they do not replace it.
- No rule is accepted. Findings 1-13 are candidates for repair only after the owner accepts the cited rules.

## Open owner decisions

1. Accept, rewrite or reject each SPEC-010 rule; decide WAY-01 (colour per scope).
2. Finding 1: should Overview keep the calendar before any channel exists (SPEC-007) or is the empty state the intended first frame? `web-122-empty-states.spec.ts` follows the answer.
3. Finding 3 and 11: should Workspace channels live in the product shell with the project retained, or in the settings shell with a return that names the project?
4. Finding 8: which width class governs project-scope pages in the settings shell.

## Owner decisions and first repairs (same day)

The owner found the WAY rules sensible but wanted to judge a rendered implementation, chose a guided channel-first start for an empty project, delegated the width decision and authorized initiative motivated by intuitiveness, modernity, performance and completeness. SPEC-010 is therefore accepted except WAY-01; the values and decisions are recorded in the specification. The owner did not answer decision 3 (shell of Workspace channels); it was decided from the owner's earlier stated wish not to leave the page in use.

- UX-390 (finding 3): the sidebar link carries the selected project, `dashboard.tsx` resolves it for `/dashboard/workspace/channels`, and the page now renders in the product shell with "Back to project". The extended `workspace-channels.spec.ts` asserts project retention, the product navigation and the return. Focused specs (workspace channels, channel sharing, navigation matrix, settings continuity) pass.
- UX-391 (finding 1): empty Overview now says why the calendar is absent and offers `Add channel`, which opens channel creation on the Channels page via a one-shot `add` search parameter. Channels empty copy follows the same story. Updated deliberately: `web-122-empty-states`, `design-121-shell`, `channel-authoring-identity` (first-destination test reaches the composer by address); related specs (project roles, narrow composition, publication detail, viewer actions, live revocation, ambiguous recovery, populated states, project feature data) pass unchanged. SPEC-007 amended.
- Width classes decided by job (LAY-02) and recorded in the registry; implementation is UX-392.
- Not run: the complete repository matrix; only the affected scenarios, per the proportionate-validation rule. Dark theme and English were the only states rendered after the change in the focused specs.
- Follow-ups UX-392 to UX-398 hold the remaining findings (4, 5, 6, 7, 8, 9, 10, 12 and the COMM-016 points).
