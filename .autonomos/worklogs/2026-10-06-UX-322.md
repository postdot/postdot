# UX-322 — Block ordinary promotion on an active-profile mismatch

- Status: complete; final full validation passed
- Task: [UX-322](../TASKS.md)
- Mission base: `28b5ee197`
- Sources: [ADR-020](../decisions/ADR-020-version-and-assess-channel-profile-changes.md), [SPEC-004](../specs/SPEC-004-publication-content-boundary.md), [UX-321](2026-10-05-UX-321.md)

## Proposed rule

Ordinary promotion must validate persisted draft content against both:

1. the profile version owned by the working draft, preserving historical profiles and zero-loss editing; and
2. the channel's currently active profile, including its media requirements.

An old-profile success must not clear an active-profile incompatibility. The promotion transaction must fail before creating a target revision, changing publication assessment, touching jobs, or writing audit events. Approval-request submission and approval retain their existing behavior in this mission; an active-profile-aware explicit re-approval remains a separate follow-up.

For automatic delivery, an execution-contract change between the owned and active profiles is also an ordinary-promotion blocker. A genuinely compatible old target remains eligible for automatic execution when its content satisfies the active constraints and its execution contract is unchanged.

## Implementation

- `packages/db/src/manual-store/publication-promotion-store.ts`
  - Loads both the draft-owned and channel-active profile rows.
  - Compiles and validates content against the active profile when it differs from the owned profile.
  - Reuses the existing working-draft media assessment against the active profile.
  - Adds an execution-contract comparison for automatic delivery.
  - Returns a distinguishable `invalid_content` message without adding a new error code:
    - `Publication target content is incompatible with the active channel profile ...`
- `packages/db/src/manual-store.ts`
  - Supplies the same existing media assessment to the promotion store as active-profile media evaluation.
- Web presentation:
  - Added `editor_promotion_active_profile_mismatch` in English and French.
  - `isActiveChannelProfilePromotionError` recognizes the server result.
  - The editor shows that localized refusal instead of an unknown promotion failure and refreshes publication queries.

No automatic migration, mandatory adoption, new approval mechanism, database migration, or provider contact was added.

## Deterministic regression

`packages/db/src/manual-store.test.ts` now covers:

- an incompatible activation producing a cancelled automatic job for the invalid target while a compatible target keeps a pending job;
- an old-profile save that remains valid under the superseded profile;
- ordinary promotion of that rescued content remaining blocked;
- preservation of the rescued bytes, draft-owned and assessed profile references, selected target revision, profile-version history, and job states;
- ordinary promotion of another draft whose content satisfies both the old and active profiles;
- retention of the pre-existing compatible selected target and its pending automatic job.

`apps/web/src/lib/publication-promotion.test.ts` covers recognition of the new server refusal and rejection of unrelated invalid-content failures.

## Explicit re-approval follow-up

No active-profile-aware approval or re-approval path was added. UX-323 is reserved for defining explicit re-approval of a superseded contract where execution remains supported, without replacing it with ordinary promotion.
