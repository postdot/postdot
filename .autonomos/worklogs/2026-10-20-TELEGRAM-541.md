## Integration contract

Base 591aa92f8. Preserve TELEGRAM_EXECUTION_REVISION = message-v1 and expose unchanged old profile as telegramMessageChannelProfile. Add TELEGRAM_POLL_EXECUTION_REVISION = message-v2; telegramChannelProfile becomes version2, with optional poll object and otherwise unchanged text/media behavior. Parent retains historical profile resolution and registers both execution revisions. No database migration or shared poll abstraction.

Text is the poll question when poll exists, not a separately sent caption. Poll shape: { options: readonly string[], multiple?: boolean, openPeriod?: number }. Missing poll means an ordinary message. The poll excludes media; validation reports a conflict without silently deleting attachments or text. Anonymous regular poll is fixed, not a hidden setting. Multiple defaults false. Absent openPeriod means no automatic closing; supplied duration is relative seconds after actual provider creation.

Shared package exports from poll.ts: TelegramPollInput, TELEGRAM_POLL_LIMITS { minOptions:1, maxOptions:12, maxQuestionLength:300, maxOptionLength:100, minOpenPeriod:5, maxOpenPeriod:2628000 }, readTelegramPoll(value):TelegramPollInput|null and telegramPollError(question,poll):string|null. Use conservative UTF-16 bounds as existing Telegram text validation does. Syntactic reader must allow editable blank answers; semantic validator rejects blank question/answers, malformed option counts/types, unknown fields, invalid flags/durations. Never coerce or truncate payloads. Default UI starts with two answers; protocol permits the documented 1-12.

Official source checked 2026-10-20: https://core.telegram.org/bots/api#sendpoll and InputPollOption. Question 1-300 characters, options 1-12, answer text 1-100; optional open_period integer5-2628000, mutually exclusive with close_date. Postbot exposes only relative duration. Do not copy obsolete 600-second or Mastodon bounds. No results collection, voting, closing action, updates/webhooks or polling service.
