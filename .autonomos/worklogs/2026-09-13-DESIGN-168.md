# DESIGN-168 — Make Calendar Affordances Discoverable

- Status: Complete
- Branch: `codex/reui-calendar-spike`
- Owner: orchestrator
- Scope: ReUI calendar toolbar state and shortcut disclosure
- Related issue: ISSUE-093
- Related decision: ADR-071

## Goal

Make the selected reading mode immediately legible and disclose the small
calendar keyboard pilot where the operator can act on it, without turning the
calendar into a tutorial or adding a global shortcut legend.

## Evidence and direction

- The selected `Semaine` button currently reads as a tonal/shadow variation
  inside the same muted group, so the active mode is not sufficiently obvious.
- Shortcut metadata is available to assistive technology, but no visible
  affordance teaches pointer users that the controls also accept keys.
- The accepted operational UX contract favors progressive disclosure and
  rejects redundant explanatory copy.

## Plan

1. Add a reusable Base UI-compatible `Kbd` primitive to `@herald/ui`.
2. Apply a clear filled active state to the view group and add compact keycaps
   to the controls that own the existing calendar shortcuts.
3. Keep the layout responsive and preserve the current focus, URL, and scoped
   hotkey behavior.

## Changes

- Added the shared `Kbd`/`KbdGroup` primitives to `@herald/ui` using the
  Base UI project's existing token vocabulary.
- Reworked the calendar toolbar so the selected view uses a filled
  `surface-raised` surface without relying on a shadow, while `T`, `[`, `]`,
  and the view keys are shown beside their owning controls.
- Kept the existing `aria-keyshortcuts`, local target registration, input
  exclusion, and preview suspension intact.
