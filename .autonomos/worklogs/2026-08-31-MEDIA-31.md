# MEDIA-31 — Connect durable media to the web publication editor

- Date: 2026-08-31
- Status: complete
- Scope: authenticated media selection and upload from the dashboard and zero-loss publication editor
- Related task: [MEDIA-31](../TASKS.md)
- Related specification: [SPEC-004](../specs/SPEC-004-publication-content-boundary.md)
- Related decisions: [ADR-014](../decisions/ADR-014-separate-autosaved-drafts-from-execution-revisions.md), [ADR-019](../decisions/ADR-019-separate-media-assets-representations-and-deliveries.md)

## Objective

Connect the existing project-owned media lifecycle to the web authoring surface
without introducing a second attachment model, weakening server-side validation,
or replacing provider-specific target content with a page-local representation.

## Delivered

- Kept the media routes in the typed Elysia route tree even when media storage is
  not configured. Authenticated callers receive a stable `503 media_unavailable`
  response instead of a missing Eden route or an opaque failure.
- Exported the media route response contracts through `@postbot/api` and
  `@postbot/client`, and added web API helpers for listing, reserving, raw binary
  upload, finalization, polling, and authenticated content URLs.
- Added a reusable web media picker that lists verified project assets, uploads
  one or more files through the reserve/upload/finalize lifecycle, waits for
  asynchronous inspection, previews image representations through the private
  Postbot route, and preserves accessibility text.
- Added media selection to the dashboard creation flow. A source post may now be
  text-only, media-only, or contain both, while the existing server remains the
  authority for source and target validation.
- Added the same picker to the zero-loss publication editor. Source media changes
  update ordered-media bindings in the current target JSON while preserving
  unrelated provider-specific fields already present on matching media items.
- Added focused tests for target binding updates, preservation of target-specific
  fields, disabled media storage behavior, OpenAPI route exposure, and the typed
  client route tree.

## Deliberate limits

- The editor does not add a browser-side media deletion action; the existing
  project media lifecycle remains the authority for deletion and retention.
- The picker does not transform media or invent provider capabilities. It displays
  verified representations and leaves profile-specific compatibility decisions to
  the server and channel profile.
- No real provider publication was performed as part of this task. Provider media
  delivery remains covered by deterministic worker tests and its explicit live-test
  boundary.
