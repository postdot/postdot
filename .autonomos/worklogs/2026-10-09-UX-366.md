# UX-366 — Shell, menus and transient feedback

Base: `243b6ab0a`. Status: complete.

Owner-authorized shared interface correction. The scroll region currently owns an
inset shadow that can be painted behind children. Menu and Select popups use the
anchor width even when the trigger is an icon. Screenshots of the populated live
calendar confirm that the top structural edge disappears under scrolled content.

Plan: separate structural frame and scrolling content; use intrinsic popup width
with anchor minimum and available-space maximum; integrate the existing Base UI
Toast primitive using the official shadcn base-nova component as the starting
point. Use transient confirmations for clipboard success and channel lifecycle
success. Keep form errors inline, autosave quiet and durable outcome notifications
unchanged. No automatic duplication between feedback systems.

Sources: https://ui.shadcn.com/docs/components/base/toast and
https://base-ui.com/react/components/toast (checked 2026-10-09).

## Implementation and targeted evidence

The frame clips its child scroller and owns a non-interactive fixed edge overlay.
The existing header and one main scroll region remain; no document-scroll redesign
or scroll hijacking. Select and menu panels use maximum-content width, trigger
minimum and available-space maximum. Select labels may wrap only at that bound.

The shared toast renderer adapts the official base-nova registry component to
Postbot tokens and Solar icons, without a new dependency. It retains primitive
stacking, timeout, swipe and keyboard behavior; close tooltip and region/close
labels are localized. First uses are API-key clipboard success (deduplicated,
no secret in the message) and successful channel lifecycle actions. Existing
inline clipboard failure and lifecycle errors are unchanged.

Two targeted scenarios passed in 28.8 seconds: populated shell clipping, menus
at 1280/768/390 pixels and F6/dismiss; API-key copying and transient feedback.
The first shell fixture did not scroll because it was empty; replaced it with 12
real manual channels. A test used an incorrect menu label; corrected to the actual
label. Toasts have the primitive's non-modal dialog semantics, so modal assertions
must identify their subject; the lifecycle test now names its dialogs. No primitive
accessibility behavior was overridden to satisfy tests.

Full validation is required by the shared shell/root/UI scope. Freeze executable
files during that single run. No external provider call or live data mutation was
needed for review. Live French calendar and account menu screenshots confirm the
fixed edge and readable menu on the user's project.

The upstream MIT notice is retained in `packages/ui/LICENSE.shadcn.md`; this is a third-party notice, not a choice of Postbot project license.
