# CLI-585 — Deployed feedback and global help

The owner reports a successful real alpha.1-to-alpha.2 upgrade, preserving session,
project, channel, draft and media. Deployed checks confirm GitHub #5, #6, #7 and
#9; those reports are now closed. #11 was independently verified and already
closed. #6's direct setup navigation was an optional suggestion, not the missing
administrator-role explanation. #7 does not claim live S3 compatibility testing.
#8 (secure bootstrap) and #10 (project/workspace removal) remain open and were
not implemented or claimed by alpha.2.

Confirmed a separate global-help defect: unknown top-level arguments reach server
startup, so `--help` previously attempted configuration/startup. Both global help
flags now return command usage before configuration or storage access. Existing
command-specific help and ordinary server startup remain unchanged.

Validation: 13 isolated subprocess cases pass (54 assertions), covering both
flags globally and for all five maintenance commands with invalid configuration,
zero stderr and no created files. The built production bundle's global help also
exits successfully with invalid storage configuration. No full container/E2E
rerun is warranted by this early argument-only branch.

This fix is source-only, pending a future image version; the immutable alpha.2
image is unchanged. Its publication must not be confused with this later fix.

The OpenAPI `0.1.0` value is API schema metadata. `/health` is liveness, not an
application release identifier. The published image already carries OCI version
and source labels; a runtime/Studio identification feature should derive from
reliable build metadata rather than substitute the API schema version.

Next recommended scope: secure first-administrator provisioning (#8) and reliable
runtime release identification, then a separately approved project/workspace
retirement policy (#10). No new agent rule or archival batch was needed.
