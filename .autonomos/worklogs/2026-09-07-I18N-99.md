# I18N-99 — Authenticated web copy migration

## Objective

Migrate Herald's authenticated web interface to the accepted Paraglide
localization boundary from ADR-046, keeping English as the base locale and
French as the second locale while preserving publication content, provider
payloads, API error codes, and server behavior.

## Mission contract

- Base commit: `aa2c9977b5a9312b23d5d04963b0da05af25ac69` (origin/main, PR #107)
- Branch: `feat/i18n-copy-migration`
- Scope: `apps/web/src`, `apps/web/messages`, web-localized tests/tooling, and
  this Autonomos worklog/task state.
- Forbidden scope: API/server prose, API error-code changes, publication or
  user-authored content, provider payloads, Paraglide strategy/locales/ADR,
  generated `apps/web/src/paraglide` output, and UI redesign.
- Required gates: format, lint, typecheck, i18n coverage, tests, build, and
  `autonomos status`, plus isolated browser language-switch verification.

## Initial state

- The Paraglide foundation from I18N-95 and the catalog coverage gate from
  I18N-100 are present on the base commit.
- `en` and `fr` catalogs currently cover the foundation messages, but the
  authenticated application still contains embedded interface copy.
- The requested `.autonomos/workflows/` files are absent in this checkout; the
  installed `.agent/workflows/` session, task, and crystallize procedures are
  the available workflow sources.

## Progress

The inventory and classification are complete. The authenticated interface copy
was migrated across these categories:

- authentication, app shell, workspace/project navigation, account actions,
  language and theme controls;
- overview, queue, calendar, empty/loading states, filters, summaries, and
  accessible labels;
- channel creation, profile editing, lifecycle actions, and provider connection
  dialogs for built-in and custom HTTP channels;
- publisher connections, media library/attachment flows, project access tokens,
  notifications/preferences, and all retry/error surfaces;
- publication composition and the editor, including source/target fields,
  capability/review states, recovery/conflict actions, promotion, scheduling,
  date/time/number formatting, and pluralized counts.

API errors are rendered in the web client from stable error codes and parameters
through `formatApiError`; API codes, server prose, and provider payloads were not
changed. The coverage script now understands Paraglide variant/plural messages
and compares structured messages precisely.

Intentional exceptions preserved at the localization boundary:

- user-authored publication titles, source/target bodies, media content, and
  accessibility text;
- provider names, brands, external account names/handles/IDs/URLs, and runtime
  schema field labels/descriptions supplied as external metadata;
- raw profile/schema JSON, accepted provider formats, and stable technical
  identifiers/codes;
- generated `apps/web/src/paraglide` output, which remains ignored and is not
  committed.

No redesign, new i18n library, locale/strategy change, ADR change, API code
change, or server-side translated prose was introduced. English remains the
base locale and French the second locale. Both catalogs contain 655 messages and
report 100% coverage.
