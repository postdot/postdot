## Production defect found and fixed

The first fresh-container probe created the administrator but GET
/api/auth/get-session returned 404. This reproduced before and after restart,
with and without a JSON content-type header: not a cookie persistence failure.
The dashboard's GET /* fallback outranked the root ALL wildcard used by the
Better Auth mount. A narrow GET /api/auth/* forwarding route now precedes that
fallback; the original mount continues handling the other methods. Requests
reach the existing auth handler unchanged, with parsing disabled; no auth rules
or permissions were changed. createAuthRoutes only requires the handler member
of its argument to support the bounded composition test.

The retained web-assets composition regression failed with 404 before the fix
and passes after it. It verifies GET path, POST path/body and SPA rendering.
The existing real Better Auth session-cookie test also passes.
