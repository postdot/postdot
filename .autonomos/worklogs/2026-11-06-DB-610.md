# DB-610 — Isolate dialect fragments and regenerate the SQLite baseline (phase 1 of ISSUE-194)

Status: in progress (2026-11-06), branch `feat/postgres-storage-profiles`.
Decision record: [ADR-097](../decisions/ADR-097-selectable-storage-profiles.md) (proposed).
Previous phase: [DB-609](2026-11-06-DB-609.md).

## Scope

1. **Dialect module (`packages/db/src/sql/dialect.ts`) and portable SQL audit**:
   - Parameter binding normalization (`?N` and unnumbered `?` -> `$N` for PostgreSQL, keeping `?N` / `?` for SQLite).
   - Engine-specific SQL fragments and helpers isolated in one module:
     - Current millisecond epoch expression (`unixepoch('now') * 1000` vs PostgreSQL `floor(extract(epoch from clock_timestamp()) * 1000)::bigint`).
     - JSON extraction and array iteration (`json_extract`, `json_each`, JSON object/array checks).
     - Pattern matching (`glob` vs portable/engine-specific pattern match).
     - Conflict handling (`insert or ignore` audited per call site and converted to explicit `on conflict (...) do nothing` with target columns).
     - Scalar two-argument `max(a, b)` replaced with portable `case when ... end` or dialect helper (avoiding PostgreSQL aggregate `max()` vs `greatest()` NULL difference).
     - Physical `rowid` tie-breaker in `publication-profile-adoption-store.ts` replaced with a deterministic portable ordering guarantee.
     - Sequence high-water mark in `event-journal-store.ts` (`sqlite_sequence` vs PostgreSQL sequence introspection).
     - Deferred foreign-key constraint handling in `resource-lifecycle-store.ts` (`pragma defer_foreign_keys = on` vs `set constraints all deferred`).
     - Quoted camelCase result aliases (`as "camelCase"`) and quoted `"user"` table references across runtime SQL so PostgreSQL does not fold column names to lowercase or reject reserved words.
     - Engine-neutral constraint/database error classification replacing direct `SQLiteError` imports in `apps/api/src/plugins/error-handler.ts` and stores.
2. **Regenerated SQLite baseline + explicit reviewed extras**:
   - Reconcile `domain-schema.ts` with live schema (`instance_state.default_workspace_id` FK action and `projects_workspace_id_id_uidx` composite unique index).
   - Keep `publications_channel_planning_at_idx` expression index in explicit extras (since `drizzle-kit generate` misquotes comma-separated SQL expressions in `.on(sql\`...\`)`).
   - Extract all 48 live triggers, 6 live views, the expression index, and the initial singleton `instance_state` seed row into explicit reviewed SQLite extras.
   - Verify 100% schema/table/column/index/FK/check/trigger/view parity between the 27-file historical chain and the regenerated baseline + extras before replacing the 27-file chain and retiring historical-only migration tests.

## Checkpoint 1 — placeholder validation and portable statements (2026-11-06)

- `normalizeStatementSql` now runs for every SQLite statement, so PostgreSQL's
  placeholder rules are enforced on the active engine. It rejected four real
  statements: three channel-lifecycle queries bound an unused `projectId` and
  referenced only `?2` (shared channels intentionally consider every attached
  project), and one cadence query mixed `?` with `?2`/`?3`. They now bind only
  `channelId` as `?1`, and the cadence query is fully numbered.
- Validation errors include a truncated statement excerpt for diagnosis.
- `publication-reply-store` and `publication-first-comment-store` no longer use
  the synchronous Drizzle builder through `runSync`; they use port statements.
- Validation: db 349 tests, API 565, core 109, auth 15 pass; root
  `bun run check:quick` passes (`schemaname`/`sequencename` added to cspell for
  the PostgreSQL sequence introspection fragment).

Remaining in DB-610: the rest of the dialect fragment audit (JSON, epoch, glob,
`rowid`, `max(a, b)`, deferred constraints, quoted aliases, error
classification) and the regenerated SQLite baseline with explicit extras and a
parity check against the historical chain.
