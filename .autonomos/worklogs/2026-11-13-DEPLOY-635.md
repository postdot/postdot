# DEPLOY-635 Optional Studio and multi-client boundary

Outcome: The production API can run without Studio assets. A separately served
production Studio passes the local HTTPS proxy journey. ADR-098 records the
approved direction and the future native-session requirements.

Decisions: Keep the integrated default and one public browser origin. File serving
does not change backend topology, human-only operations or API-key ceilings.
Studio/API versions remain paired. Native transport selection and hosted-ingress
qualification are separate from this delivery. For deterministic reconnection,
the test proxy closes actual SSE sockets: Chromium's simulated offline mode left
existing streams open. The worker proof uses a controlled automatic destination;
manual publications remain scheduled until the operator acts.

Validation:
- Format, lint, spelling, types and four-locale coverage → pass.
- Full unit/scripts → 1,903 passed; 11 existing opt-in skips.
- Production build → all 22 packages pass. Final docs export → 264 pages,
  1,308 local targets, zero broken links.
- Separate Studio HTTPS journey → pass, including production bundle startup with
  absent assets, session/key provisioning, rejected auth origin, key ceilings,
  browser login, private avatar and 2 MiB media transfer, invalid OAuth return,
  actual stream interruption/reconnection, scheduled worker publication to a local
  receiver, and revoked-session refusal. Final focused run also passes.
- Existing TLS automatic-publication journeys → 2 passed, preserving both clean
  editor reconciliation and unsaved local destination content.
- Footprint → API 5,763,537 bytes; anonymous JS 167,809 gzip bytes; idle memory
  within existing budgets. No dependencies or database migration added.

Open: Native human-session transport and Cloudflare/Vercel ingress remain
unqualified. Better Auth logged its existing shared per-path rate-limit fallback
when it could not resolve a trusted client IP; file serving does not change that
policy. Qualify client-IP trust/per-client ingress limits before claiming them.
Next recommended lot: native-session transport qualification with Better Auth.
