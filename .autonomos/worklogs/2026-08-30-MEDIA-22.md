# MEDIA-22 — MediaStore Contract and Bun Adapters

Date: 2026-08-30
Status: completed
Task: Implement the Postbot MediaStore contract with local and Bun S3 adapters

## Context

ADR-019 and SPEC-004 require a Postbot-owned storage boundary for immutable media
representations. The storage layer must remain separate from media assets,
representation metadata, format inspection, retention, publication references, and
provider delivery. Local self-hosting and S3-compatible deployment must use the same
object semantics without exposing Bun-specific file objects outside the adapter.

## Implementation

- Added the `@postbot/media` package and synchronized `postbot.code-workspace` and
  `bun.lock`.
- Defined a framework-independent `MediaStore` contract with:
  - opaque validated object keys;
  - bounded streaming writes with optional expected-size and content-type hints;
  - normalized object metadata;
  - complete and exclusive-end byte-range reads;
  - bounded reads and idempotent deletion.
- Added typed `MediaStoreError` codes for invalid keys and limits, source failures,
  size mismatches, read/write limits, and storage failures.
- Implemented `LocalMediaStore` with Bun file primitives, private directory/file
  permissions, temporary streaming writes, and atomic rename publication.
- Implemented `S3MediaStore` with `Bun.S3Client`, S3-compatible prefixes, native
  streaming writers, lazy range reads, and backend-specific details kept private to
  the adapter.
- Kept the store's `put` operation as a replace-at-key infrastructure primitive so
  both backends have the same semantics. Higher-level media services must allocate
  a fresh application-generated key for every immutable representation; the store
  does not allocate domain identities.
- Added one contract suite executed against both the local adapter and an in-memory
  S3-shaped test double. It covers round trips, ranges, replacement, missing-object
  behavior, idempotent deletion, size ceilings, failed-write preservation, unsafe
  keys, and invalid ranges.

## Implementation evidence

- Bun 1.4.0's `Bun.write(path, Response(stream))` did not complete for an arbitrary
  web stream in a direct runtime probe. The local adapter therefore uses
  `Bun.file(path).writer()` with the same bounded stream consumer as S3, then commits
  with `rename`. This preserves streaming and atomicity without buffering media or
  weakening the test.
- The public S3 adapter accepts `Bun.S3Client`; its internal structural seam exists
  only to test the adapter without requiring live cloud credentials.
- Content inspection and MIME verification remain outside this package. The local
  filesystem cannot persist a backend-independent content-type header, so the
  content type is deliberately only a backend hint; authoritative detected media
  metadata belongs to `MediaRepresentation` in MEDIA-23.
