# SITE-425 — Grain scale, header continuity and recovery surfaces

Owner liked the flowing material but reported uncovered header area and grain
that changed scale between wide/mobile screens. Authorized calibration followed
by the previously proposed public recovery-page extension.

Original grain was shader noise sampled per drawing pixel. The canvas width cap
scaled those pixels on larger screens. Removed grain from the shader and created
an original deterministic 128x128 grayscale PNG tile, rendered at 128 CSS pixels
without sizing it to viewport or device pixel ratio. Shared overlay uses low
soft-light opacity and progressive masking: least noticeable behind introductory
text, stronger towards colored material. No SVG filter, generated AI picture,
external asset or new package. Animated color fields still use capped WebGL.

Hero compensates its top offset with equal negative margin/positive padding, so
its background covers the sticky header without changing content positions. Safe
text region now accounts for that padding. Header remains transparent at the top.

Shared recovery component gains calm material; full-width background retains the
previous constrained content alignment and covers behind its header. 404 and
route-error content/retry behavior unchanged. Footer uses the same calibrated
texture, continuing SITE-424.

Docs formatting, typecheck, static export. Focused isolated probe: background top
at zero, reload heading position stable, same grain background-size at 1920 and
390 px, no horizontal overflow, 404 material ready and recovery button usable,
no page errors. Desktop light hero/404 and mobile hero visually inspected. Generic
route error shares implementation but was not induced as a real runtime failure.
No full app E2E matrix or repeated resource benchmarks.

Next: assess the calibrated texture and recovery-page continuity; keep marketing
sections deferred. Current material is owner-liked but exact calibration remains
an iteration, not immutable brand policy.
