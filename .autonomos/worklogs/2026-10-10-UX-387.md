# UX-387 — recognize media before inspecting metadata

## Owner feedback and direction

The previous quick review was too shallow: obvious icon/tooltip corrections did
not supply a useful hierarchy. Apply interface-design and frontend-design to the
actual task: recognize an image, view it, then inspect its metadata. Different
search sources need different row treatments. Preserve Herald's tokens and avoid
extra explanatory copy or decorative separators.

## Changes

- Search returns the ready original representation's content type, without
  exposing storage locators. Image rows show a 48px cropped preview via the
  existing authenticated media content endpoint; other kinds retain icons.
- Media results open the existing viewer rather than the information dialog.
  Closing consumes the route inspection parameter, retaining repeat selection.
- Information dialog uses the darker raised surface, wider image column,
  quieter metadata spacing and no separator lines or redundant footer. Usage
  remains available. No metadata or existing operation removed.
- Search project-page icons match existing sidebar icons.
- Shared tooltips added for theme, sidebar, compact back, information close and
  media action menu. Native language title removed to avoid duplicate hints.
  Viewer zoom/fullscreen/close controls already use shared tooltips. This is a
  bounded surface pass, not a claim that every action across Herald is audited.

## Verification

Real API search regression passed (24 assertions). Existing search scenario
checks an actually loaded image preview and two viewer open/close cycles, along
with previous keyboard/scope/loading/error checks: passed in 19.2s. Static
checks passed; final commit hook checks cover the last media-menu tooltip. Existing media-library scenario exercises information, viewer
and menus; passed in 16.5s; wide screenshot inspected. No full repository suite.

An initial concurrent browser/static invocation collided on generated Paraglide
files. This was a harness execution error; rerun media after static completion,
without changing application behavior or assertions.

## Scope and next

No thumbnail-generation pipeline introduced: preview uses the existing image
content route. No search mutation, authorization change or storage URL exposed.
Next recommendation: review the composer and destination controls as one user
journey, with explicit hierarchy and interaction feedback rather than another
catalog of cosmetic details. Keep it a bounded visual pass.
