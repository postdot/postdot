# MEDIA-180 — Make the Media route a first-class library and introduce a headless Uppy intake boundary

- Status: Complete (first integration slice)
- Branch: `codex/reui-calendar-spike`
- Owner: orchestrator
- Related issue: [ISSUE-102](../ISSUES.md#issue-102-make-the-media-route-a-first-class-library-and-introduce-a-headless-uppy-intake-boundary)
- Predecessor: MEDIA-179

## Objective

Make the standalone Media route read as a reusable project library rather than
an attachment picker, and evaluate Uppy where it has a clear technical role:
file intake and upload orchestration without importing its Dashboard UI.

## Decisions

- `@uppy/core` owns the browser file queue and custom uploader boundary.
- `@uppy/react` supplies the headless file-input, dropzone, context, and state
  hooks; no Uppy Dashboard markup or stylesheet is used.
- Herald remains authoritative for `reserve → raw upload → finalize`, pending
  verification polling, and `MediaVerificationError` diagnostics.
- Publication forms keep selection, accessibility text, and ordering behavior.
  The Media route opts into explicit `manage` mode and does not expose
  selection toggles or a fake publication-selection count.
- The existing Herald-owned viewer/editor is intentionally unchanged. A future
  Uppy Image Editor comparison must prove its standalone integration before it
  can replace the current editor.

## Delivered

- Added `apps/web/src/lib/herald-media-upload.ts`, a client-injected Uppy
  adapter that maps successful files back to verified `MediaReference` values
  and preserves ready, pending, and failed finalization behavior.
- Added unit coverage in
  `apps/web/src/lib/herald-media-upload.test.ts` for lifecycle ordering,
  verification polling, typed failures, and controller success state.
- Replaced the picker’s direct file-input upload loop with official headless
  Uppy React hooks while retaining Herald's existing API client and domain
  lifecycle.
- Added a separate non-selectable asset-card rendering path for the library.
- Reframed the Media route as a manage-only project library with preview/edit
  actions and a direct New publication action.
- Added a browser contract proving the Media route has no attachment-selection
  toggles and can return to the canonical authoring route.
