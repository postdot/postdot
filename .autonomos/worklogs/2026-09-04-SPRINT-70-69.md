## Delegated control experiment outcome

The two read-only workers were deliberately dispatched through the explicit
worktree fallback with separate worktrees, but the current multi-agent control
surface did not provide a usable terminal lifecycle:

- both agents remained reported as `running` after several bounded waits;
- a follow-up request to conclude produced no report;
- an interruption request produced no terminal status or report;
- `close_agent` returned the previous status `running` for both agents, after
  which the control plane emitted shutdown notifications;
- both dedicated worktrees remained clean, with no file changes or commits.

No worker output is accepted as evidence. The result reproduces the
visibility and cancellation limitation already recorded for `META-62` and
does not change the explicit-worktree policy. The orchestrator completed the
two reviews locally and recorded only verified evidence in:

- [TIME-70 report](../archive/calendar-queue-delivery/worklogs/2026-09-04-TIME-70.md)
- [PROVIDER-69 report](../archive/foundations-first-deliveries/worklogs/2026-09-04-PROVIDER-69.md)

Both tasks remained in progress until the owner decisions were made. The owner
then accepted both recommendations; provider implementation is now proceeding
on a dedicated branch while timezone implementation remains separate.

## Review outcome

TIME-70 confirms that persisted scheduling values are epoch-millisecond
instants, while the editor and calendar implicitly use the browser timezone.
The recommended direction is a project IANA timezone with unchanged instant
storage, subject to owner approval and explicit DST and existing-data rules.

PROVIDER-69 confirms that LinkedIn already has a typed provider package and a
versioned channel profile, but the workflow worker still centralizes provider
selection, credential refresh, destination handling, content extraction, and
provider media sequencing. The recommended direction is a small versioned
built-in-provider adapter/registry while keeping custom HTTP separate and
leaving project credential ownership in Postbot.

## Accepted direction

The owner accepted the project timezone policy and the versioned built-in
provider adapter boundary. ADR-032 and ADR-033 were merged through PR #69
(`f60e97a7`). The provider implementation is tracked in the
`PROVIDER-69` worklog; the timezone implementation must remain a separate
change because it affects project persistence, API contracts, and web calendar
semantics.
