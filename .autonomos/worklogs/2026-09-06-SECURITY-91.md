# SECURITY-91 — Route per-instance Mastodon OAuth token requests through controlled egress

## Objective

Close the gap found during AUDIT-90: Mastodon API calls used the operator-controlled
fetcher, but authorization-code exchange and refresh-token requests still fell back
to the global `oauth4webapi` fetch implementation.

## Finding

ADR-043 requires every runtime request to a project-selected Mastodon instance to
use the shared network policy. The Mastodon publisher and connection routes already
injected the controlled fetcher for instance API calls, while `@postbot/oauth`
exposed no way to inject one into token endpoint requests.

## Implementation

- Added an optional `OAuthFetcher` to authorization-code exchange and refresh-token
  inputs.
- Passed the injected fetcher to `oauth4webapi` through its `customFetch` hook.
- Injected the controlled Mastodon fetcher into the callback token exchange and
  worker credential refresh paths.
- Added regression tests proving both OAuth token operations use the injected
  fetcher, preserve POST/manual-redirect semantics, and do not require a real
  provider.
