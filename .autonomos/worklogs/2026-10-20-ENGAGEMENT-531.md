## Validation and outcome

Implemented and verified the public Mastodon slice.

The provider reader performs anonymous status and context GETs against the instance identified by the delivered permalink. It excludes ancestors and restricted descendants, orders replies by their parent relationship, bounds traversal to 60 replies and depth 6, and enforces a 10-second deadline even for a transport ignoring cancellation. Missing/restricted roots are explicit unavailable snapshots. Rate limits, malformed responses and transient failures preserve the previous snapshot with a warning.

No current channel connection or credential is used. The existing production Mastodon network-controlled fetcher is injected into the reader, preserving configured outbound private-destination policy and pinned DNS resolution. Redirects are not followed. Both the retained URL and external ID are rechecked before saving an asynchronous result. Snapshot identity includes the original instance, so equal local status IDs on different servers cannot share data. Incompatible or missing retained permalinks do not trigger collection.

Mastodon HTML is parsed with Bun's HTMLRewriter and decoded with the existing locked entities 4.5.0 package, promoted to a direct Mastodon dependency. Paragraph breaks and content warnings survive; script/style/comment content is removed. Studio renders plain text. Reply links use the original instance's status route rather than arbitrary response URLs. The legacy /web/statuses route is supported by upstream routing (redirect into /statuses).

The existing snapshot table is reused without a migration. Its store now distinguishes the provider's external ID from the instance-qualified snapshot root and rechecks the retained URL for Mastodon. Bluesky roots and existing stored snapshots remain compatible. The response provider union and existing English/French messages now support both platforms. Project roles, explicit refresh, retained failure state, disclosure reads and API-key action ceilings remain unchanged.
