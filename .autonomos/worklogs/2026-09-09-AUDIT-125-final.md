## Reconciled findings

### Closed or materially improved

- The composer no longer presents the former tutorial paragraphs as the main
  task. The live surface exposes title, content, media, destination, delivery,
  schedule, and recovery controls with progressive disclosure.
- Media is integrated into the composition flow through the picker and compact
  previews. The full library remains the management surface for metadata and
  accessibility details; this is intentional separation, not a missing
  composer feature.
- A publication cannot select the same channel twice. The live composer exposes
  one destination tab and disables the add-destination action when all active
  channels are selected.
- Shared delivery and schedule defaults are visible once, while channel-level
  overrides remain available on demand.
- Calendar keeps its date-oriented month grid with a direct creation path even
  when there are no scheduled publications.
- The Queue filter strip no longer exposes the previously observed desktop
  vertical overflow affordance. Horizontal behavior remains covered by the
  responsive contract.
- The notification surface is a non-blocking right-side sheet, with an explicit
  preferences action and an accessible empty state. It is no longer the
  centered blocking dialog identified in the early comparison.
- Ambiguous publication recovery is now exposed in the editor through explicit
  published/failed reconciliation actions; it does not retry a provider.
- Provider applications load as an instance-scoped settings route and clearly
  report that no project is selected. This is consistent with the decision that
  provider applications are not project-owned.

### Still confirmed and worth implementing

#### P2 — Reduce repeated empty-state weight

Overview and Queue still use large, visually similar empty surfaces. The
wording is now route-specific, so this is no longer a correctness problem, but
the repeated card/icon/title/description grammar still makes an empty project
feel like a dashboard of explanations rather than a quiet work surface. The
next pass should compare a compact inline state, a single first-action row, and
the existing card before choosing one shared pattern.

Related work: `DESIGN-98`, `WEB-119`, `WEB-122`, `ISSUE-063`, `ISSUE-065`.

#### P2 — Make global settings scope more explicit in the shell

The provider-applications page correctly has no selected project, but it still
shares the project-oriented shell. The breadcrumb and project selector convey
the scope only indirectly. The next shell pass should make the transition to
instance settings unmistakable without duplicating navigation or pretending
that provider applications belong to a project.

Related work: `DESIGN-121`, `ISSUE-064`.

#### P2 — Continue progressive disclosure on Access and configuration surfaces

Access is safe and understandable, but its long introductory paragraph and
the empty token surface still make the first visit read like documentation.
Provider applications likewise expose a full creation form beside the existing
application list. The next change should keep security/recovery explanations
available while moving them into concise context, disclosure, or help affordances
near the relevant action.

Related work: `DESIGN-98`, `DESIGN-120`, `ISSUE-063`, `ISSUE-065`.

#### P3 — Keep the media-library distinction deliberate

The standalone Media route still shows filename and technical metadata rather
than behaving like the visual composer. This is acceptable because it is an
asset-management surface, while the composer now shows the image itself. Do not
merge the two surfaces merely to make screenshots look alike; revisit only when
search, bulk management, accessibility editing, or richer media operations
justify a library redesign.

## Explicit non-findings

- No evidence justifies replacing SSE, TanStack Query, or the current route
  model as part of this UX pass.
- No evidence justifies adding a WebSocket/WebRTC layer, a second persistence
  model, or a provider-specific preview system here.
- The remaining whitespace on empty routes is not itself a defect. Postbot's
  quiet dispatch-desk direction allows breathing room; the actionable hierarchy
  matters more than filling the viewport.
- The old composer terminology and detached media presentation must not be
  reopened as findings: the current implementation already addresses those
  observations within the agreed scope.

## Decision and next concrete step

`AUDIT-125` is complete. `WEB-124` validation is complete after the browser
matrix and ambiguous recovery surface. The broader UX/IA work remains open in
`DESIGN-98`, `DESIGN-120`, `DESIGN-121`, `WEB-119`, and `WEB-122`.

The next implementation should be a bounded shell/configuration pass: first
make instance settings scope explicit, then simplify the Access and provider
application first-visit surfaces, and finally compare the compact empty-state
alternative on Overview and Queue. It should be reviewed against the existing
browser matrix before any further global visual changes.
