# WEB-174 — Replace the Composer Entry Point with a Canonical New-Publication Action

- Status: Done
- Branch: `codex/reui-calendar-spike`
- Owner: orchestrator
- Scope: Route, creation entry points, and the project-sidebar slice defined by
  ISSUE-098 and DESIGN-173.
- Related issue: ISSUE-098
- Related design task: DESIGN-173

## Accepted contract

- The canonical authenticated project route is
  `/dashboard/projects/$projectId/publications/new`.
- The visible product noun is `publication`; the primary action is
  `New publication` / `Nouvelle publication`.
- The old `/compose` route and the persistent `Composer` Work-navigation peer
  are removed. This is a private development application, so no compatibility
  alias is required.
- A project’s creation action is exposed as a prominent sidebar action only
  when a project is active. Project creation itself is reached from the project
  selector, not from a persistent standalone disclosure; the selector is labeled
  `Project` / `Projet` because it changes the active project context.
- The multi-destination authoring behavior and form structure remain unchanged
  in this slice. Source/Destinations hierarchy, preview, and the broader sidebar
  redesign remain follow-up work.

## Implementation checklist

- [x] Rename the route and authoring page module without changing the API
  contract or calendar date/time search behavior.
- [x] Update navigation helpers, all application links, copy, and browser
  scenarios so no `/compose` or visible `Composer` reference remains.
- [x] Put project creation behind a project-selector action with an accessible
  inline form and preserve the existing pending/error behavior.
- [x] Add the single primary new-publication action to the project sidebar and
  keep instance-settings/no-project states coherent.
- [x] Regenerate route/i18n artifacts, run focused checks, then the full

## Verification

- Focused Playwright coverage passed for the shell, narrow new-publication flow,
  empty states, and publication/media entry points.
- The authenticated integrated browser shows `Projet`, one `Nouvelle publication`
  action, two Work links (`Vue d’ensemble`, `File d’attente`), and project
  creation in the selector.
- `bun run check` passed format, lint, typecheck, unit tests, 17 Playwright
  scenarios, and the production build. English and French i18n coverage is 100%.

## Resolution

The Composer route and presentation have been removed as a peer concept. Herald
now has one canonical `/publications/new` entry point, a publication-oriented
user vocabulary, a primary project-sidebar action, and a selector-owned project
creation flow. The Source/Destinations hierarchy and the remaining sidebar
recomposition are intentionally left for the next authoring UX slice.
