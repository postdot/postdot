# OPS-692 Say which step of the SMTP test failed

Outcome: the SMTP test in Settings > System reports which step failed (server name, connection refused, no answer, TLS, login, sender or recipient refused) and repeats the server's reply line when there is one. Resolves GH #49; context in ISSUE-216.

Record:

- `apps/api/src/modules/email/smtp-failure.ts` maps Nodemailer errors (`code`, `command`, `responseCode`, `response`) to a reason; the reply is kept to one line of at most 300 characters. A timeout is reported separately from a refused connection because a blocked port (firewall, Kubernetes network policy) shows as a timeout.
- `POST /api/settings/email/test` returns `reason` and optional `serverReply` with `email_test_failed`, and logs `[postdot-email] SMTP test failed` with reason, code, command and response code. The password is never in either.
- Studio shows one sentence per reason plus the reply, in en, fr, es, de. Self-hosting docs explain the reasons and where to look for a blocked port.
- Checks: unit tests for the mapping (login, blocked port, refused, unknown host, certificate, wrong TLS mode, sender and recipient refused, bounded reply); the API SMTP test now also covers a rejected login and asserts the password is absent.

Notes:

- The owner's production failure (Stalwart on 465 behind Kubernetes) is likely an egress rule; this change will show it as "no answer" if so.
