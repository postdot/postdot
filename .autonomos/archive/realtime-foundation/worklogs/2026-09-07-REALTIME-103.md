# REALTIME-103 — Integrate the authenticated SSE transport into the production web Query boundary

## Objective

Move the reactive client work from the isolated REALTIME-96 prototype into the
authenticated dashboard without introducing a second source of truth. Use
TanStack Query for server-backed cache state, consume the project-scoped SSE
endpoint as an invalidation signal, and keep the server read models authoritative.

## Scope and boundary

- Start from the merged REALTIME-102 transport on `main` at `b0857953`.
- Own the initial production web boundary in `apps/web/src` and the related
  Autonomos evidence.
- Keep TanStack DB, WebSocket/WebRTC, polling loops, provider actions, database
  schema changes, and notification redesign out of scope.
- Keep the SSE envelope payload-free: the browser refetches project and
  notification read models rather than trusting event data.

## Implementation

- Added a project-scoped `QueryClient` provider and one browser SSE connection
  for each authenticated project dashboard.
- Added strict client validation for project update envelopes, project identity,
  event version, entity shape, and the empty payload contract.
- Added bounded invalidation retries to account for the durable notification
  projection being allowed to lag the journal event.
- Added reconnect/resynchronization invalidation for project data and the
  notification inbox.
- Migrated project dashboard data from local `DashboardContext` state to a
  project-scoped TanStack Query cache while preserving existing mutation flows.
- Migrated notification inbox and preferences reads to Query, retaining
  server mutations and safe cache updates for read/archive/preferences actions.
- Kept the existing notification presentation unchanged; its contextual UX is
  still governed by DESIGN-97.

## Limits and follow-up

- The current stream is intentionally an invalidation channel. It does not
  replicate rows into the browser and does not change the notification API.
- Browser-level coverage proves the existing dashboard still works with the
  provider mounted; a deterministic test of a real worker outcome arriving over
  SSE should be added once the E2E harness can create a durable event and wait
  for the resulting projection.
- Queue, overview, calendar, and dashboard sidebar now receive project-query
  invalidations through the shared project data cache; a later pass may split
  those broad reads into narrower query keys if measurements justify it.
- TanStack DB remains an isolated reference prototype and is not a production
  dependency boundary.
