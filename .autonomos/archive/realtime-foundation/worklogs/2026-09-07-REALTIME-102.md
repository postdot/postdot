# REALTIME-102 — Establish the authenticated SSE project event stream

## Objective

Implement the server transport contract needed for real project reactivity while
keeping the PR #109 client prototype isolated. Reuse the durable `audit_events`
journal and the existing notification projection, expose no provider-sensitive
data, and leave dashboard wiring for a later client task.

## Implementation

- Started branch `feat/realtime-transport-foundation` from clean `main` at
  `ffe67b21`.
- Inspected ADR-037's append-only journal and ADR-038's recipient-owned
  notification projection. Confirmed that the journal is the correctness source,
  the notification projection has its own cursor and may lag, and process-local
  callbacks are not sufficient for reconnects.
- Added ADR-048 with the selected SSE endpoint, authentication, project scope,
  cursor, envelope, safe payload, liveness, error, projection-lag, and client
  catch-up contracts.
- Extended the event journal store with a high-water cursor lookup and a typed
  cursor sequence decoder. No database schema or migration was added.
- Added `GET /api/projects/:projectId/events`:
    - Better Auth session only; project bearer tokens are forbidden.
    - Human project membership is checked through the existing notification access
      boundary, with cross-project access returning `404`.
    - `Last-Event-ID` is parsed as the opaque `event-sequence:<AUTOINCREMENT>`
      cursor and replayed through the ordered journal reader.
    - Malformed cursors return `400 invalid_cursor`; cursors above the journal
      high-water mark return `409 cursor_ahead`; valid historical cursors remain
      replayable because the current journal has no retention floor.
    - Only version-one, allowlisted project-view events are emitted. The envelope
      contains the durable event id, cursor, project, type, entity, version, and
      timestamp, with an empty payload used as an invalidation signal.
    - Actor/correlation/causation context, raw audit metadata, credentials, tokens,
      provider responses, and provider-specific content are excluded.
    - Bounded SQLite polling, comment heartbeats, request abort handling, reader
      cancellation, terminal `project.resync-required` events, and timer/listener
      cleanup are implemented without a broker or process-local source of truth.
- Kept the PR #109 prototype, `DashboardContext`, publication adapters, and UI
  unchanged.
- Added HTTP, stream, journal, and OpenAPI coverage for authentication, project
  isolation, replay/reconnect, invalid and ahead cursors, non-monotonic or
  foreign journal responses, heartbeat, cancellation, and sensitive-payload
  exclusion. Tests use in-memory SQLite and fake events only.

## Limits and next steps

- The endpoint is an invalidation transport; the client must refetch authoritative
  project and notification read models and retry when notification projection is
  behind. The Query coordinator is not wired into production in this mission.
- The default stream performs a bounded journal read every 250 ms and emits a
  heartbeat every 15 s. Connection counts and SQLite read cost need measurement
  before broad dashboard rollout.
- A future journal retention policy must add an explicit retention-floor contract;
  until then, an old valid cursor is replayable. Global sequence jumps are normal
  for project-filtered reads and are not treated as loss.
- ADR-048 remains proposed for review. The next implementation task can add the
  narrow TanStack Query production boundary and browser-level reconnect coverage
  without rewriting `DashboardContext` or adopting TanStack DB.
