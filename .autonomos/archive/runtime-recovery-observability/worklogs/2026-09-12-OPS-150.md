# OPS-150 — Prove graceful runtime shutdown and durable restart recovery

- Status: completed
- Date: 2026-09-12

- Issue: ISSUE-075

## What was done

The next-event scheduler now exposes an asynchronous stop barrier. It cancels
future timers, marks the scheduler stopped so no new work is planned, and waits
for the current due-work cycle to settle. The publication worker forwards that
barrier, and the production entrypoint awaits the worker and media-maintenance
drain before stopping the remaining runtimes, closing SQLite, and releasing the
runtime quiescence lock.

Media reconciliation now tracks its in-flight operation and returns the same
drain guarantee from `stop()`. Notification projection remains synchronous and
already rejects queued startup work after an immediate stop. Existing restart
and stale-runtime-lock behavior remains explicit: a forced process termination
leaves a marker that an operator must verify before removing.

## Key decision

Graceful shutdown waits for durable completion rather than cancelling an
external effect whose outcome may already be unknown. A forced termination is
therefore treated as an ambiguous recovery boundary and handled by the existing
lease recovery and operator-verified runtime-lock procedure; no supervisor or
provider-specific cancellation protocol was introduced.
