# OPS-216 — Production HTTP failure logging

- Status: complete
- Date: 2026-09-25
- Base: `docs/autonomos-diagnostic-backlog` at `b0e79831`
- Issue: ISSUE-128
- Scope: Log unexpected server failures without enabling routine production request logs

## Changes

- Production now defaults to `LOG_LEVEL=error`; successful-request records and
  expected 4xx warnings remain below that threshold. `LOG_LEVEL=silent` still
  explicitly disables logging.
- The global Elysia error handler logs thrown and returned 5xx failures once,
  while preserving generic client-facing 500 responses and existing 4xx behavior.
- Error records include method, registered route template, status, a generated
  `X-Request-ID`, error type, and up to twelve stack frames. Raw exception
  messages, request headers, bodies, and dynamic route values are excluded; this
  keeps signed media URL tokens out of logs while retaining code-location clues.
- Updated the deployment example and API logging guidance to match the new
  production default and correlation header.
