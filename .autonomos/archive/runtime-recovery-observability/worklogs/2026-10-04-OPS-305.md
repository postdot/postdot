## Review evidence

The bounded detached refused-restart probe corrects the previously unbounded
foreground execution. Its finally block removes the named probe. The shutdown
entrypoint now catches exceptions from database close and lock release and uses
distinct exit codes. All five diagnostic tests pass. The fresh production image
acceptance passes: source and restored containers serve 25 assets, stop in 0.2s
with exit 0 and release their lock; SIGKILL reports 137, retains the marker and
causes a refused restart. The complete gate reported by the other agent was not
independently rerun in this audit.

The normal-path correction is validated, but the exit-code contract is not yet
complete. RuntimeQuiescenceLock.release() calls removeLockIfOwned(), which catches
unlink failures and returns normally. A temporary directory probe acquired a lock,
changed parent permissions to 0500, and called release(): it returned without
throwing while the marker remained (EACCES). Permissions were restored and only
the probe directory was removed. The entrypoint therefore cannot reliably infer
successful release from the absence of an exception. See ISSUE-151 / OPS-306.

An additional diagnostic boundary deserves investigation: executor.ts copies an
unexpected callback Error.message into an ambiguous outcome, and workflow-store

leak. Verify callers, API exposure and existing sanitization before choosing a
correction. See ISSUE-152 / AUDIT-307.
