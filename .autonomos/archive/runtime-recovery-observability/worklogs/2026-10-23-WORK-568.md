# WORK-568 — Bounded effects and renewable claims

## Authorization and plan

The owner approved the complete ISSUE-186 recommendation: two internal effects at most, one per project, fair admission across publications, replies and first comments, renewable fenced claims, cooperative deadlines, newly arriving work and shutdown/recovery verification. No additional process, external provider action or remote publication is authorized.

1. Record execution policy and add fenced renewal.
2. Share bounded project admission across the three work families.
3. Propagate cooperative cancellation and preserve uncertain outcomes and draining.
4. Run focused regressions and the integration milestone checks.

## Diagnostic baseline

Two disposable SQLite reproductions established that an overdue completion is accepted until recovery revokes its token; after recovery the result is fenced out and the publication remains ambiguous. A blocked project prevented another project from starting. Fourteen existing claim/fairness tests passed. The reproduction used synthetic providers only.

## Implementation

- One publication worker owns two physical slots, with one active effect per project across publications, replies and first comments. Project rotation and a separate family cursor per project prevent starvation under concurrent publication backlogs.
- Each family claims at most one item per admission. Reply and first-comment claims accept an optional project filter. Existing standalone service processing remains available for focused tests.
- The running batch is coalesced across overlapping callers. It refreshes project discovery while effects run, polls at most one second apart when waiting, and responds to explicit replanning. Stop closes admission and drains every actual operation, including direct batch calls outside a scheduler wake.
- SQLite renewals condition on running state, matching token, strictly live expiry and a deadline that never moves earlier. No migration is needed. Renewal does not generate publication status/audit events because it changes no domain outcome.
- The shared core executor accepts an explicit active-effect policy. It renews, requests cooperative cancellation on deadline/lost ownership, checks ownership again before completion and keeps timers/physical ownership until the actual effect settles. Exceptions after the durable boundary remain uncertain; expired/recovered tokens cannot commit.
- Publication defaults: five-minute lease, renewal every thirty seconds, fifteen-minute cooperative attempt budget. Comment defaults: two-minute lease, renewal every thirty seconds, existing sixty-second attempt budget. Shorter provider request deadlines and durable processing deferrals remain intact.
- Provider HTTP requests combine their own cancellation with the attempt signal. Bluesky OAuth restoration and LinkedIn/Mastodon/X refresh fetches are included. Instagram token refresh keeps its existing provider request timeout; cancellation prevents subsequent publishing and retains the slot while the call settles. Production Mastodon and Instagram retain the existing network-controlled fetcher. Publication credential/media mutations check active ownership, preventing a stale attempt from writing checkpoints or changing credential state.
- ADR-090 records the owner-approved execution direction and implementation defaults; ADR-009 links its replaced renewal deferral. Narrow API/core guidance records the shared admission and drain requirements.

## Focused investigation and corrections

- The initial admission loop repeatedly retried empty asynchronous candidates instead of reaching idle. The focused run was stopped, empty candidates were remembered until actual progress/new work/poll wake, and the dispatcher was simplified to avoid relying on a fixed number of microtask turns.
- Existing first-comment tests configured a changed account or lost response after parent processing. The new coherent drain may deliver a zero-delay comment in the parent's batch. Move those fault injections before parent execution; preserve their existing failed/ambiguous/no-repeat assertions.
- New fixtures initially used a past schedule and an assumed 202 response. Correct them to the actual scheduling invariant and established 200 reply contract.
- Saturation testing demonstrated that one global flattened cursor could still favor publications in a busy project. The regression failed before the correction. Independent per-project family rotation fixes this while preserving project fairness and both concurrency bounds.
- Publications created in the same millisecond are not ordered by their test labels. The blocked-project test now queues the second item after the first effect actually starts; the fairness test checks family order without inventing a publication-label order.
- The Bluesky OAuth fetch type includes Bun's static preconnect property. Preserve that property with Object.assign rather than casting an incompatible function.
