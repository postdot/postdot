# MAINT-50 — Extract channel-profile read models

- Date: 2026-09-03
- Status: completed
- Scope: `packages/db` channel-profile reads and profile mutations
- Task: MAINT-50
- Related issues: ISSUE-016, ISSUE-020

## Objective

Reduce the responsibility concentration in
`packages/db/src/manual-store/channel-profile-store.ts` by isolating the
channel-profile state read and activation-preview model. Keep profile draft
creation and activation, including their transactionally coupled impact
assessment and job reconciliation, in the mutation store.

## Boundary and invariants

- Preserve the `createManualStore` and `createChannelProfileStore` facades and
  all public types.
- Preserve project and actor scoping and channel/profile relationship checks.
- Share the draft-profile loader and profile-impact assessor between read and
  mutation paths; do not duplicate their SQL or assessment work.
- Preserve profile draft revision checks and profile identity/version rules.
- Preserve activation transaction boundaries, impact assessment persistence,
  job cancellation/creation, audit events, and rollback behavior.
- Keep this as a cohesive database-backed read-model extraction; do not add a
  generic repository or change the domain model.

## Alternatives considered

- Keep reads and mutations together: rejected because profile state and preview
  are a distinct read model from draft creation and activation writes.
- Duplicate the draft-profile query or impact assessor: rejected because read
  and activation behavior could drift and duplicate database work.
- Extract the activation transaction: rejected because profile activation,
  impact persistence, job reconciliation, and its audit event must remain one
  cohesive transaction.

## Verification plan

- Preserve the existing profile state, preview, creation, activation, impact,
  media, job, and rollback tests.
- Run focused database tests and the full repository quality gate.
- Obtain an independent read-only review before opening the remote PR.

## Implementation

The channel-profile read model now lives in
`packages/db/src/manual-store/channel-profile-read-store.ts`. It owns the
channel/profile state query and activation-impact preview, together with the
shared draft-profile loader and impact assessor. The public manual-store facade
continues to expose the same read methods.

`channel-profile-store.ts` retains profile draft creation and activation. The
activation transaction still performs profile state changes, impact persistence,
job cancellation or creation, and audit persistence as one atomic workflow.
