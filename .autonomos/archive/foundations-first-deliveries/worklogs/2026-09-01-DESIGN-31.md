# DESIGN-31 — Harden dashboard navigation and narrow-screen header behavior

- Date: 2026-09-01
- Status: completed
- Scope: authenticated dashboard shell and responsive main navigation
- Task: [DESIGN-31](../../../TASKS.md)

## Objective

Resolve the objective defects found during a browser review of the authenticated
dashboard without starting a visual redesign:

- the authenticated dashboard must not present a second `Sign in` action beside
  its existing `Sign out` action;
- the main navigation must remain usable at a narrow mobile viewport;
- the behavior must be protected by a reproducible browser assertion.

## Decisions

- The root shell derives whether it is inside the protected dashboard area from
  the TanStack Router pathname. This avoids adding a session request to every
  public page and avoids duplicating the dashboard loader's session request.
- Navigation labels remain in the accessibility tree through screen-reader-only
  spans below the small-screen breakpoint. Icons provide the compact visual
  affordance, while full labels return at the regular breakpoint.
- No broader color, typography, spacing, or component redesign is included. That
  requires an explicit design direction and is outside this objective hardening
  task.

## Files modified

- `apps/web/src/routes/__root.tsx` — hide `Sign in` in dashboard routes and make
  the header navigation compact and non-wrapping on small screens.
- `e2e/publication-media.spec.ts` — assert the public and authenticated navigation
  states and verify one-line navigation at a 390 px viewport.
