# MAINT-45 — Extract atomic post and publication creation persistence

- Date: 2026-09-03
- Status: completed
- Scope: `packages/db` post and publication creation persistence
- Task: MAINT-45
- Related issues: ISSUE-016, ISSUE-020

## Objective

Reduce the remaining responsibility concentration in
`packages/db/src/manual-store.ts` by extracting the atomic creation use case for
a post and its publications. The extracted unit owns initial content validation,
initial working-draft and target-revision persistence, automatic-job creation,
and creation audits while preserving the existing public manual-store facade.

## Boundary and invariants

- Keep `createManualStore(database, options)` and the exported creation types
  stable for API, web, CLI, and test consumers.
- Preserve one immediate SQLite transaction for the complete post and
  publication creation operation.
- Preserve project and actor authorization checks, channel/profile ownership
  checks, source and target validation, and manual-versus-automatic execution
  constraints.
- Preserve the distinction between unscheduled drafts and scheduled target
  revisions, including media snapshots and automatic jobs.
- Preserve creation audit attribution and rollback when any persistence step
  fails.
- Keep shared loaders and audit/job composition explicit; do not introduce a
  generic repository abstraction.

## Alternatives under review

- Keep creation in the root store: rejected if the complete creation use case
  remains the last large orchestration boundary after the previous extractions.
- Split validation, revision inserts, jobs, and audits into unrelated helpers:
  rejected because that would obscure the single transaction and scatter one
  cohesive use case.
- Move media capability resolution into the new module: not assumed; the
  existing media validation helpers remain shared until a separate media
  lifecycle boundary is demonstrated.

## Verification plan

- Preserve the existing manual-store creation and rollback coverage.
- Add or strengthen an integration assertion that creation rolls back across
  posts, publications, revisions, media snapshots, jobs, and audits.
- Run focused database checks, then the full repository quality gate.
- Obtain an independent read-only review before opening the remote PR.

## Implementation

- Added `packages/db/src/manual-store/publication-creation-store.ts` for the
  complete post and publication creation use case, including its insert
  statements and immediate transaction.
- Composed the new store from `createManualStore` while keeping shared actor,
  channel, profile, job, audit, and media boundaries explicit.
- Preserved the existing public `createPost` facade and all creation behavior.
- Added integration coverage that forces a publication-creation audit failure
  and verifies rollback of the post, publications, working drafts, target
  revisions, revision media, jobs, and creation audits.
