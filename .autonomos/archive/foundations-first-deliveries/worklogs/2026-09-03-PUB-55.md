# PUB-55 — Add explicit LinkedIn member and organization-page destinations

- Date: 2026-09-03
- Status: completed
- Issue: ISSUE-022
- Scope: LinkedIn provider contract, project publisher connections, OAuth flow, worker delivery, and the connection UI
- Branch: `feat/linkedin-organization-destinations`

## Objective

Represent the LinkedIn member who authorizes Postbot separately from the member or
organization page that a channel publishes to. Preserve existing member
connections while adding an explicit organization-page path.

## Plan

1. Record the accepted destination boundary and verify the current LinkedIn API
   requirements.
2. Add typed LinkedIn destinations, organization verification, and destination-
   aware text and image payloads.
3. Persist the destination on the project publisher connection and route it
   through the worker without moving secrets into the destination model.
4. Expose the explicit organization-page setup in the API and dashboard, then
   cover member regression, organization validation, and failure boundaries.
5. Run the repository quality gate, review the diff, and hand off through a
   remote PR. Do not perform a real publication in this implementation task.

## Decision record

The owner approved implementing the explicit LinkedIn organization/page option.
ADR-031 records the boundary: credentials represent the OAuth member principal;
connections represent the publication destination. Organization IDs are verified
after OAuth before a connection is created. Existing member connections remain
member destinations.

## Safety boundary

- Better Auth remains email/password-only for Postbot.
- OAuth access and refresh tokens, provider identifiers tied to a real account,
  session cookies, and organization details from a real account do not belong in
  repository artifacts, logs, commits, or test snapshots.
- No real LinkedIn post is created, scheduled, sent, or deleted by this task.

## Current evidence

- LinkedIn Posts API accepts a person or organization author and requires
  `w_member_social` or `w_organization_social` respectively.
- Organization Lookup verifies a requested organization for an administrator and
  uses `rw_organization_admin`; the connection path therefore treats organization
  setup as an explicit permissioned flow.
- The current Postbot code stores only the member ID and always emits a person URN,
  which is the defect being addressed.

## Completed

- Added typed member and organization destinations to the LinkedIn contract.
- Added organization lookup and permission verification after OAuth.
- Persisted destination data separately from the encrypted OAuth credential.
- Routed destination author and media-owner URNs through the worker.
- Added explicit page setup to the dashboard while preserving member setup.
- Added migration, unit, integration, E2E, lint, format, typecheck, and build
  coverage. No real LinkedIn publication was performed.
