# PROVIDER-86 — Built-in provider adapter conformance

## Objective

Add a shared conformance suite for the built-in LinkedIn and Bluesky provider adapters so their common execution boundary is verified before another adapter is added.

## Decisions

- Exercise the actual application adapters with injected provider primitives rather than testing a substitute adapter.
- Keep the suite deterministic and network-free by using provider fakes at the package boundary.
- Cover registry identity, published/retryable/permanent/ambiguous outcomes, unavailable credentials, invalid destinations, and the media lifecycle boundary.
- Keep provider-specific OAuth, HTTP, payload, and media behavior in the provider package test suites.

## Implementation

- Added `apps/api/src/modules/workflow/providers/conformance.test.ts`.
- Recorded and completed `PROVIDER-86` in `.autonomos/TASKS.md`.
- No production behavior, provider credentials, or external integrations were changed.

## Verification

- `bun test apps/api/src/modules/workflow/providers/conformance.test.ts --timeout 30000`

## Next steps
