# OPS-12 — Revalidate the current single-process distribution

- Date: 2026-09-01
- Status: completed
- Scope: production image inputs, SQLite media restore, runtime routes, and footprint
- Related issue: [ISSUE-001](../ISSUES.md#issue-001-validate-the-complete-production-distribution-path)
- Related decision: [ADR-010](../../../decisions/ADR-010-use-bun-runtime-image-for-v1-packaging.md)

## Objective

Revalidate the current production distribution after the shared UI package, media
workflow, and publication editor were integrated. The validation covers a fresh
Docker build, the single-process runtime, the documented backup and restore path,
and the existing resource budgets.

## Findings and fixes

The first fresh Docker build failed before dependency installation because the
manifest-only build stage did not copy `packages/ui/package.json`, even though
`@postbot/web` depends on `@postbot/ui`. The Dockerfile now includes that workspace
manifest, and the root guidance records the rule for future workspace changes.

The first real media restore into an existing Docker volume also exposed a latent
SQLite lifecycle defect. `restoreWithMedia` atomically replaces the database path
while the media-backup fence still holds a connection to the previous inode. Bun
reports `SQLITE_READONLY_DBMOVED` when that connection is released. Fence release
now ignores only that expected moved-database code and still propagates unrelated
release failures. The SQLite regression test now restores over an existing target,
checks that pre-restore state is replaced, and verifies that no fence remains.

## Verification

- `docker build --tag postbot:ops12 .` passed after the Dockerfile correction.
- A fresh volume started as the non-root runtime user (UID 1000), applied the
  committed migrations, passed its healthcheck, and served `/health`,
  `/openapi/json`, `/`, and `/dashboard` with HTTP 200.
- A complete media backup bundle was created from the running volume. After the
  container stopped, a sentinel table was added, then the bundle was restored over
  the existing database. The sentinel was removed, the fence table was empty, and
  the restored volume started successfully again.
- The test image measured 166,540,239 uncompressed bytes and 68,653,290 compressed
  bytes. The temporary image, volume, container, and backup bundle were removed
  after validation.
- `bun run measure:footprint` passed on Linux x64 with Bun 1.4.0: API artifact
  1,835,836 bytes, initial web JavaScript 108,902 gzip bytes, median cold start
  268.01 ms, maximum sampled idle RSS 92,844 KiB, and median publication-job RSS
  increase 2,668 KiB. All configured budgets remain satisfied.
- `bun run check` passed formatting, warning-free lint, strict TypeScript, all unit
  and integration tests, the Playwright browser test, and all package builds.
- `git diff --check` passed.
