# MEDIA-24 — Revision media, provider delivery, and complete recovery

- Date: 2026-08-31
- Status: completed
- Task: [MEDIA-24](../../../TASKS.md)
- Related specification: [SPEC-004](../../../specs/SPEC-004-publication-content-boundary.md)
- Related decision: [ADR-019](../../../decisions/ADR-019-separate-media-assets-representations-and-deliveries.md)

## Objective

Implement the durable media boundary through publication target revisions,
execution revisions, provider-specific media delivery, and complete media-aware
backup and restore. Preserve the accepted rule that an external effect uses the
exact validated content and representation selected before the effect boundary.

## Delivered

- Added ordered `PublicationRevisionMedia` relations that bind target-content JSON
  locations to project-owned immutable media representations.
- Added `PublicationExecutionRevisionMedia` snapshots copied before the durable
  external-effect boundary. The workflow fails closed when the persisted media
  index disagrees with the target content or reference count.
- Added media capability enforcement during target promotion, including ownership,
  readiness, MIME family, byte, dimension, duration, count, total-size, and
  accessibility checks. Representation selection is persisted rather than repeated
  during retry.
- Added `ProviderMediaDelivery` state and idempotency storage for provider-specific
  media uploads. Failed deliveries can be retried; ambiguous deliveries remain
  blocked from automatic retry and require explicit reconciliation.
- Added a singleton backup fence that prevents physical media deletion while a
  complete backup or restore is active.
- Added complete backup bundles containing a SQLite snapshot, a strict manifest,
  and streamed representation bytes. Every database and object checksum is verified;
  restore never overwrites a destination object with different bytes and replaces
  the database only after validation.
- Kept database-only backup and restore available as explicitly separate low-level
  operations and documented the complete `--media` commands.
- Added the required Drizzle migration and corrected generated legacy-column copy
  expressions so the migration initializes cleanly from the current development
  schema.
