# META-62 — Recheck app-managed worktree control

- Status: blocked by the current harness control surface
- Date: 2026-09-05
- Base commit: `01380379f7e7c7d7891689975f9bcb78aa025624`
- Scope: orchestration evidence only; no Postbot product code

## Objective

Recheck whether the current Codex app worktree creation route now provides the
durable identity, operator visibility, lifecycle status, interruption, and
cleanup controls required by Postbot's orchestrator policy.

## Controlled experiment

The canonical checkout was clean and aligned with `origin/main`. A single
read-only worktree mission was requested for project `postbot` with these
constraints:

- inspect only `AGENT.md`, `.autonomos/TASKS.md`, and the META-62 worklog;
- do not edit, commit, push, start servers, use browsers or credentials, or
  perform external effects;
- return the worktree path, branch, HEAD, task identity, inspected files, and
  clean-tree confirmation.

The app returned only the preparation identifier
`client-new-thread:db63b127-7fe6-433d-9380-6655571e5d36`. The identifier could
not be passed to task inspection or control operations. Repeated task-list
snapshots over approximately 50 seconds did not show a new Postbot task, and
`git worktree list --porcelain` remained limited to the canonical checkout and
three pre-existing detached Codex worktrees. No corresponding new worktree,
worker report, terminal status, interruption acknowledgement, or cleanup
handle was available.

## Assessment

The recheck does not satisfy any stronger acceptance claim than the previous
experiment. A preparation identifier is not a durable operator-facing mission
handle. Because the mission never became inspectable, the orchestrator cannot
prove its progress, worker attribution, cancellation, or cleanup. The app-managed
path remains unsuitable as the default for Postbot implementation work.

The explicit-worktree fallback remains the operational default. It records the
worker identity, base commit, worktree path, branch, semantic scope, checks,
result, and cleanup evidence; the orchestrator retains shared servers, browser
validation, credentials, external effects, integration, pull requests, merges,
and branch cleanup.

## Repository impact

- No Postbot product file, server, browser session, credential, database, media
  root, branch, or existing worktree was changed by the experiment.
- `.autonomos/ISSUES.md` records the recheck evidence for ISSUE-029.
- `.autonomos/TASKS.md` keeps META-62 blocked.

## Next steps

1. Keep using the explicit-worktree fallback for implementation and review
   missions.
2. Reopen META-62 only after the app route returns a durable task ID that is
   visible in the Codex task list and supports status, interruption, and
   cleanup verification.
3. Continue Postbot product work independently of this harness limitation.
