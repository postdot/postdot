# CRED-17 — OAuth authorization-attempt lifecycle

- Date: 2026-08-29
- Status: completed
- Related issue: [ISSUE-006](../../../ISSUES.md)
- Decision: [ADR-012](../../../decisions/ADR-012-own-publisher-credentials-and-use-oauth4webapi.md)

## Scope

- Add a focused `@postbot/oauth` package for standards-oriented protocol mechanics.
- Generate authorization code requests with PKCE S256 and high-entropy state.
- Persist only a state digest and an encrypted PKCE verifier in an expiring,
  single-use, project-scoped authorization-attempt record.
- Bind attempts to actor, project, channel, provider, exact callback URI, scopes,
  and an allowlisted application return path.
- Consume attempts atomically before token exchange and reject missing, mismatched,
  expired, or replayed callbacks.
- Do not migrate the LinkedIn HTTP routes or worker in this task.

## What was done

- Added `@postbot/oauth` and synchronized `postbot.code-workspace` with the new package.
- Added `oauth4webapi` 3.8.7 as the package's only runtime dependency. It has no
  transitive runtime dependencies and explicitly supports Bun.
- Added authorization URL construction with high-entropy state, PKCE S256, exact
  callback binding, normalized scopes, protected-parameter rejection, HTTPS by
  default, and loopback HTTP only for local development and tests.
- Added standards-library validation of state and authorization-server issuer, plus
  authorization-code exchange with provider-selected client authentication.
- Added strict local return-path allowlisting that rejects external, sibling-prefix,
  encoded-separator, fragment, backslash, and control-character redirects.
- Added migration `0006_quick_silver_centurion.sql` and an
  `oauth_authorization_attempts` table containing only a SHA-256 state digest and an
  encrypted PKCE verifier.
- Added a ten-minute attempt lifetime, capped at fifteen minutes, exact actor/provider/
  callback binding, atomic single-use consumption, replay classification, and expiry
  cleanup. Consumption and expiration both erase the persisted verifier envelope.
- Generalized the CRED-16 cipher context from credential IDs to record IDs so the same
  reviewed envelope primitive can protect short-lived PKCE verifiers without another
  cryptographic implementation.

## Verification

- Proved PKCE request construction, protected parameter rejection, exact issuer and
  state validation, opaque-value preservation, and a real code exchange against a
  local fake provider using `client_secret_post`.
- Proved state-digest stability, raw-state absence, verifier encryption, callback
  binding mismatches, expiration, replay races, digest collisions, invalid PKCE
  verifiers, and fail-closed wrong-key behavior.
- Proved database constraints reject incomplete or contradictory attempts and unsafe
  return paths.
- Detected an invalid 202-byte Bun re-export artifact during footprint review, changed
  the package barrel to a build-safe export, and added a bundle import smoke check to
  the package build.
- `bun run check` passes with 110 tests across the repository.
- `git diff --check` and the Autonomos protocol status pass.
