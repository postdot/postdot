# CHANNEL-26 — Custom HTTP delivery and restricted egress

- Date: 2026-08-31
- Status: completed
- Task: [CHANNEL-26](../../../TASKS.md)
- Related specification: [SPEC-004](../../../specs/SPEC-004-publication-content-boundary.md)
- Related decisions: [ADR-017](../../../decisions/ADR-017-use-versioned-webhooks-and-mapped-http-for-custom-channels.md), [ADR-018](../../../decisions/ADR-018-restrict-custom-channel-network-egress.md)

## Objective

Implement automatic delivery for runtime-defined custom channels without adding a
script execution boundary, while preserving project-owned connection credentials,
immutable execution targets, bounded resource usage, and the accepted outbound
network policy.

## Delivered

- Added a framework-independent declarative HTTP contract to `@postbot/core`.
  It supports the versioned Postbot webhook and a bounded one-request mapping for
  path segments, query parameters, headers, JSON, URL-encoded form, multipart,
  bounded arrays, media URLs, response classifications, and remote identity
  extraction.
- Rejected arbitrary scripts, functions, process state, filesystem access,
  environment access, unbounded expressions, reserved headers, and unbounded
  mapping structures at profile validation time.
- Added `@postbot/custom-http` with HMAC-signed webhook delivery, structural mapped
  HTTP delivery, streamed multipart media, bounded request and response handling,
  cancellation, redacted errors, and no redirect following.
- Added DNS resolution and address pinning for every attempt. Public HTTPS is
  allowed by default; public HTTP, private destinations, metadata endpoints, and
  mixed public/private answers require or fail the operator-owned policy described
  by ADR-018.
- Added project/channel-owned custom HTTP connection metadata while keeping the
  secret in the existing encrypted publisher credential store. Better Auth remains
  outside this connection model.
- Passed the immutable execution profile, content, attempt, publication timing,
  channel identity, and complete media facts from the worker to the transport.
  Missing ready media representations now fail closed instead of producing a
  partial payload.
- Added the authenticated custom HTTP connection route and OpenAPI inventory
  coverage without returning the connection secret.
- Added the schema migration, package workspace entry, Docker build context, and
  public package documentation.

## Deliberate follow-up

Multipart media delivery is available through the application-owned media reader.
The default single-process composition does not yet expose public signed media URLs
for `media_urls` mappings. This remains explicit so local paths and S3/R2 object
locators are not leaked to receivers. [MEDIA-28](../../../TASKS.md) tracks that separate
delivery-authority capability; it does not block webhook or multipart delivery.
