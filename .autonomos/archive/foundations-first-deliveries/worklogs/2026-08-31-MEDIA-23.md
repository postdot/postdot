# MEDIA-23 — Project Media Lifecycle

Date: 2026-08-31
Status: completed
Task: Implement project media upload, inspection, representation, and cleanup lifecycles

## Context

ADR-019 and SPEC-004 require project-owned media to remain separate from storage
objects, publication snapshots, and provider delivery state. MEDIA-22 supplied the
bounded local and S3-compatible `MediaStore` contract; this task adds the durable
application lifecycle above it.

## Implementation

- Added framework-independent media lifecycle concepts and transition guards in
  `@postbot/core`: project assets, immutable representations, expiring upload
  intents, verified format inspections, family metadata, and derived-representation
  fields.
- Added `media_assets`, `media_representations`, and `media_upload_intents` with
  project-scoped composite foreign keys and SQLite checks for lifecycle states,
  verified facts, failure envelopes, derivation metadata, upload timestamps, and
  deletion timestamps. A representation source is constrained to the same asset.
- Added `MediaAssetStore` persistence and orchestration. Reservation allocates an
  opaque key and an expiring intent; upload streams through `MediaStore`; finalization
  stats and streams the stored bytes, computes SHA-256, inspects bounded headers, and
  marks the asset ready only in a transaction after successful verification.
- Kept client MIME types and filenames as hints. The built-in registry currently
  recognizes PNG, JPEG, and WebP image headers with bounded dimension inspection;
  unsupported or malformed inspection results remain failed rather than ready.
- Added authenticated API routes for reservation, raw streaming upload, server-side
  finalization, metadata listing, verified content download, and two-phase deletion.
  Public responses omit internal object keys. The binary download uses a native
  `Response`; its exact binary and error responses are documented separately in
  OpenAPI so Elysia does not attempt to validate a stream as JSON.
- Added startup and periodic reconciliation for expired intents, missing objects,
  failed lifecycle rows, and grace-period deletion. Deletion archives normal
  selection first, checks retained publication and audit references, removes storage
  objects idempotently, and retains terminal metadata.
- Added declarative environment configuration for local media defaults and complete
  S3/R2 credentials, endpoint, prefix, size, expiry, and deletion-grace settings.
  The configured store is constructed once at runtime and the local `data/` tree
  remains ignored.
- Updated the narrow `AGENT.md` guidance for API media transport, database media
  lifecycle ownership, and the root package map.
