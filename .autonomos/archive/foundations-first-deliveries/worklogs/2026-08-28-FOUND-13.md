# FOUND-13 — Add Elysia 2 request logging and declarative environment configuration

- Date: 2026-08-28
- Status: completed
- Scope: `apps/api` runtime configuration and request observability

## What was done

- Added a TypeBox-backed environment declaration and parser with typed strings,
  secrets, integers, booleans, URLs, enums, defaults, and aggregated startup
  errors.
- Replaced scattered runtime configuration values with one structured
  `PostbotConfig` object.
- Added `apps/api/.env.example` and kept the local `apps/api/.env` ignored by Git.
- Added Pino 10.3.1 and a native Elysia 2 request logger with readable development
  output and JSON-compatible production output.
- Disabled request logging by default in production and made `LOG_LEVEL=silent` an
  explicit opt-out in any environment.
- Added unit tests for environment parsing and logger success, failure, and disabled
  paths.
- Documented the distinction between the API origin and the Vite web origin.

## Key decisions

- `@bogeychan/elysia-logger` was not added because its current published integration
  uses Elysia 1 lifecycle names (`onRequest`, `onAfterResponse`, and `onError`),
  while this project runs Elysia 2 beta with `request`, `afterResponse`, and `error`.
  The project keeps the small native adapter until an Elysia 2-compatible upstream
  release is available.
- Environment declarations live beside the API composition root and produce one
  structured config. This keeps secret validation centralized without introducing a
  universal configuration framework or a second source of truth.
- `BETTER_AUTH_URL` identifies the API/auth server origin, while
  `POSTBOT_WEB_ORIGIN` identifies the browser application origin. They use ports
  `3000` and `5173` respectively during local development because the API and Vite
  dev server are separate processes. A single-origin production deployment can use
  one value for both.
- The logger uses Pino directly and a small local pretty stream instead of adding a
  pretty-print transport dependency. This preserves structured logs while limiting
  development-only footprint.

  returned 200 and the process emitted no request log.

  budgets; the API artifact and idle RSS increased from the M0 reference after the
  Pino runtime dependency was introduced.
