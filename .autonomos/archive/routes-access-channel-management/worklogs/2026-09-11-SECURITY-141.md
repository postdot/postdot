# SECURITY-141 — Support path-authenticated custom HTTP receivers safely

- Status: completed
- Date: 2026-09-11
- Scope: custom HTTP profile contract, encrypted connection binding, API/UI surface, and transport redaction
- Related issue: [ISSUE-031](../ISSUES.md#issue-031-support-path-authenticated-custom-http-receivers-safely)
- Related task: [SECURITY-141](../../../TASKS.md#custom-http-authentication-follow-up)
- Related decision: [ADR-069](../../../decisions/ADR-069-custom-http-path-authentication.md) (proposed)

## Implementation

- Added `path` custom HTTP authentication and the dedicated `{ kind: "secret" }`
  path segment to the shared declarative contract.
- Enforced exactly one secret segment for mapped HTTP path authentication and
  rejected secret segments with other authentication modes or Postbot webhooks.
- Kept the endpoint origin-only and resolved the secret only from the encrypted
  connection credential at request construction, with one-component URL encoding.
- Applied the binding check at API connection creation, publisher-store
  compatibility validation, and the transport's pre-dispatch fail-closed path.
- Added the API response schema and web connection selector/help text for the new
  authentication mode.
- Redacted raw and encoded credentials from transport diagnostics and rejected
  response identifiers/URLs that echo the credential before they can be persisted.
