# DESIGN-36 — Recompose publication workflows for calm, low-scroll authoring

- Date: 2026-09-02
- Status: completed
- Scope: authenticated web workspace navigation and task composition
- Task: DESIGN-36

## Objective

Recompose the authenticated publication workspace so that the dashboard does
not present overview, authoring, queue management, channels, and media as one
continuous page. Each operational task should have a clear route, a bounded
information hierarchy, and a responsive composition that preserves the source
to destination relationship.

## Owner-accepted direction

- Keep the shared authenticated shell and its project context.
- Make the project part of the route context so refresh, browser history, and
  deep links preserve the active workspace.
- Provide separate task surfaces for overview, compose, queue, channels, and
  media under the selected project.
- Keep the publication editor as a dedicated nested route.
- Treat the queue as the first planning surface; add a calendar only after its
  interaction and data contract are designed.
- Preserve the existing API, domain contracts, media lifecycle, and
  multi-destination authoring semantics.

## Evidence

The live authenticated workspace was inspected with representative data at
1440 × 900, 1024 × 800, and 390 × 844. The current single-page dashboard had a
document scroll height of approximately 1908 px, 2697 px, and 3389 px
respectively. Its compose section alone measured approximately 974 px on the
wide desktop, 1494 px at the intermediate width, and 1782 px on mobile. This
confirmed that the primary problem is task composition and navigation, not
only local spacing or component styling.

## Alternatives considered

- A single page with collapsible sections would minimize code movement but
  would retain competing task hierarchies, weak deep links, and a long
  operational flow.
- A hybrid with only compose and queue as routes would reduce the largest
  surface but leave management tasks in an uneven navigation model.
- The accepted route-oriented workspace gives each task a stable URL and
  viewport while retaining shared shell primitives and domain components.

## Implementation boundary

This task changes the web route composition and state ownership only. It does
not introduce a calendar, change publication persistence, redesign the
publisher protocol, or replace the existing target authoring contract.

## Implementation

- Reduced the dashboard route to authentication, project discovery, and the
  global project-management actions.
- Added a project-scoped route layout that owns the selected project, its
  loaded operational data, and the in-progress compose state.
- Added dedicated Overview, Compose, Queue, Channels, and Media routes under
  the project context. The existing publication editor now inherits the same
  project layout and returns to that project's Queue.
- Replaced local anchor navigation with typed TanStack Router links and made
  the project route authoritative for shell context and deep links.
- Split the former 709-line dashboard workspace into focused page and
  presentation components. The source and destination authoring component,
  media lifecycle, publisher connection actions, and API contracts remain
  unchanged.
- Added route-aware browser assertions for project redirects, overview
  viewport containment, and the existing publication/media journey.

## Validation

- Live browser checks covered the authenticated Overview, Compose, Queue,
  Channels, and Media routes at 1440 × 900, 1024 × 800, and 390 × 844. No
  horizontal overflow was observed. Overview, Queue, Channels, and Media fit
  their viewport with the representative fixture; Compose scrolls only for
  its actual authoring form.
- `bun run check` passed: repository formatting, strict lint, strict typecheck,
  10 package unit-test suites, the Playwright integration scenario, and all
  package builds.
- The Playwright scenario passed with project creation, `/dashboard` redirect,
  channel creation, mixed and media-only publication creation, queue routing,
  reload persistence, and publication editor navigation.

## Follow-up observations

- The exact amount of overview content must be validated against real data.
- The project route shape and redirects must remain compatible with the
  existing publication editor links.
- The calendar composition remains an explicitly separate design task rather
  than an implied part of this route migration.
