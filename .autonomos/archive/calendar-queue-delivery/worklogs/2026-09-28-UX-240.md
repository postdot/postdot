# UX-240 — Keep Overview calendar-led and improve its summary widgets

- Date: 2026-09-28
- Status: complete for the owner-selected Overview slice
- Authority: The owner explicitly retained the calendar as Overview's main
  surface, rejected a separate Calendar route and action-first landing, and
  asked for a more engaging, useful summary area in place of plain KPIs.
- Related issue: ISSUE-063
- Related decision/specification: ADR-057, SPEC-007

## Owner decision

Overview stays calendar-led. Its summary band should stay silent when there is
nothing useful to surface; show only real, current work without zero counters,
empty-state copy, or stale activity. Queue remains the lifecycle and
human-action triage surface. No application route, navigation, API, or
publication lifecycle behavior changed.

The first route-map proposal and its text-heavy static HTML prototype were
rejected by the owner and removed. The live Overview is the review artifact.

## Implementation

- Replaced plain KPI values with a compact band that renders only when manual
  work is due or a scheduled publication is coming up. The manual widget shows
  its positive count and a direct Queue action; the scheduled widget links to
  the publication and shows its channel and time.
- Removed the zero-count states, reassurance copy, weekly chart, and old
  published-item fallback. When the project has no current item to surface,
  the entire band is absent.
- Kept a quiet raised surface with no gradient or shadow. On narrow screens,
  one item uses only the space it needs and two items form a compact row.
- Updated DESIGN.md, ADR-057, and SPEC-007 to record the owner's calendar-led
  direction. Marked the UX-240 slice complete while preserving ISSUE-063's
  broader populated-state and route-contract follow-up scope.

## Browser review and limits

The authenticated French project currently contains one old published manual
publication and no due or scheduled work. Desktop and 390px views were inspected
in the live app. The summary band is absent, leaving the calendar as the first
content below the page heading. The due action's Queue destination was checked
before hiding its zero state; no publication, schedule, or provider action was
submitted. Positive due and upcoming states still need review with realistic
data in the broader UX-246 validation pass.

## Validation

- `bun run check:quick` — passed formatting, lint/spelling, repository and
  package type checks; English and French message coverage remains 100%.
- `git diff --check` — passed.
- No automated tests were added or run; the task is a small UI composition and
  owner-directed contract update. Rendered desktop/mobile behavior was checked
  manually in the running app.

## Crystallization

The 2026-09-28 owner direction supersedes ADR-057's former action-first Overview
and separate Calendar proposal. Overview owns the calendar; the summary band
provides bounded current-work orientation, and Queue remains the triage surface.
