# WEB-145 — Complete Queue and calendar publication reads

- Status: completed
- Date: 2026-09-12
- Task: WEB-145
- Issue: ISSUE-070

## What was done

Publication summaries now expose a versioned keyset cursor and a bounded page
size. Queue keeps the first page responsive and offers an explicit Load more
action, de-duplicating appended rows. Calendar reads use a half-open `[from, to)`
UTC range derived from the selected project-local month and drain each bounded
page, so a month with more than 100 publications is not silently truncated.

The calendar query has a dedicated cache key and is invalidated by project
realtime updates. API/client models, filters, ranges, and the old internal full
list helper all use the same stable ordering.

## Key decision

The cursor follows the existing publication ordering: scheduled rows first,
then scheduled time ascending, updated time descending, and id ascending. The
calendar range excludes unscheduled publications by construction; Queue remains
the complete continuation surface for those rows.

## Follow-up

Queue counters currently describe the rows loaded into the context until the
user follows the visible continuation. If product requirements later demand
exact all-history counters before loading, add aggregate count metadata as a
separate bounded read rather than removing pagination.
