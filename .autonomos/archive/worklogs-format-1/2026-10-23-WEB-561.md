# WEB-561 — Derive project access grants through Eden

- Issue: ISSUE-188 (partial implementation; issue remains open)
- Status: complete
- Scope: user/group grant lists, creation, role updates and removal

## Changes

Eight grant wrappers now use the typed Eden route tree and checked unwrap
helper, with inferred responses. The two shared entity types are derived from
the server's grant list responses in the client package and re-exported under
the web module's existing names. No handwritten entity declaration remains for
these two grant types.

Existing inputs remain intact. Creation and role updates accept editor or
viewer; returned grants can also contain the owner role established by the
server. Error normalization and single-request behavior use the existing client.
No backend schema, access rule, dependency or rendered component changed.

- Web typecheck, production web build and check:quick passed, including format,

- Web tests: 285 passed, zero failed.

- Five isolated Playwright scenarios passed without retries in 54 seconds:

  scenarios and one disposable acceptance exercising the migrated wrappers.
- The disposable acceptance invokes the actual web API module with owner/member

  - a foreign workspace's group receives ApiError 409 invalid_project_grant and

  - removing the group grant preserves direct editor access;
  - removing the direct grant preserves group editor access;
  - removing the remaining group grant removes project visibility.
