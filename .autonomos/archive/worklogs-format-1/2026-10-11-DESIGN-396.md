# DESIGN-396 — Three public identity candidates

Owner-authorized exploration; not an amendment to DESIGN.md or the app.
Scope: three complete local landing directions, typography/palette/materials,
product presentation, image treatment, documentation entry and mobile behavior.
No runtime, provider, publication or deployment changes.

## Plan before implementation

Prism: Manrope, white #f7faff, ink #14223b, cobalt #2a55ee, pale blue
#dae6ff, lavender #b9b7ff. Centered opening, broad product stage under glass-like
light, crisp indigo documentation surface. Product depth, not a feature tile grid.

Studio: Bricolage Grotesque, white #fbfcf8, black #20251f, grass #31634b,
lemon #e2ef88, pale lilac #e8def5. Left-aligned oversized type, asymmetric
image-led composition, publication specimen and open editorial sections.

Signal: Space Grotesk, dark ink #11131b, paper #f2f4ff, periwinkle #aaa8ff,
blue #5684ff, muted #a7aec3, ember #ecb98a. Split composition, a procedural
broadcast field, dark application stage, luminous documentation surface.

All: truthful illustrative content, local working navigation, one source with
independent destinations, no pretend testimonials/stars/pricing or claims of AI
writing. Original campaign image and native vector work; actual HTML product
specimens remain labeled as examples. Motion responds to interactions and honors
reduced motion. Multiple sections must carry each direction, not just its hero.

Self-critique before build: avoid merely recoloring the previous two-column hero.
Prism uses centered depth, Studio image-led editorial asymmetry, Signal asymmetric
technical density. Avoid warm-serif/clay, neon-on-black and repeated boxed grids.
Verify all three at desktop/mobile; owner chooses before promoting any identity.

## Delivery and critique

Implemented the three static candidates at `/directions/prism/`,
`/directions/studio/`, `/directions/signal/`, with a local comparison gallery at
`/`. Each includes opening, workflow, interactive product specimen, self-hosting,
documentation entry, closing and footer. Existing documentation routes remain
unchanged; the themed documentation entry is a specimen, not three duplicated
content systems. Actual docs theming follows the owner's selected direction.

Created two original campaign photographs with the image-generation tool; encoded
as WebP with Bun.Image (209 KiB + 510 KiB). Originals remain in the image tool's
output, not in the repository. These are fictional campaign media, not user assets
or screenshots of an already released UI. The HTML product specimen is labeled
as a workflow example. No provider logos, external image service or invented
social proof. Added three self-hosted font packages only in the docs workspace.

Review preference: Studio has the strongest departure from the operational app,
with expressive type, an asymmetric photographic opening and lemon/lilac/green
materials across multiple sections. Prism is the safer product-oriented option,
but less distinctive. Signal is a coherent dark technical option, but closest to
familiar developer-product vocabulary. None is declared accepted. Keep the owner
choice separate from app-wide token promotion; the procedural signal artwork is
static, while product changes use Motion and respect reduced motion.

Corrections during review: moved the static route list out of a client component
so server static generation can consume it; hid decorative channel initials from
accessible button names; removed redundant campaign photography from the docs
specimen. One screenshot attempt failed at the browser capture layer; rerun
completed. An initial locator included a decorative initial in its name; the
accessible-name correction and focused run passed.

Validation: `check:quick` passed; static export includes the gallery, all three
candidates, search and eight documentation pages. Inspected complete desktop
1440px and mobile 390px captures for all three. Focused browser probe confirms
LinkedIn adaptation changes, History/Access/Media switching, no horizontal
mobile overflow and no page errors. No application unit or E2E matrix, container
rebuild, external-provider action, publication or push. Container workspace list
is unchanged; docs builds remain excluded from the application image.

Next: owner selects a whole direction, or identifies which elements work, before

visual tasks are silently started and DESIGN.md is unchanged.
