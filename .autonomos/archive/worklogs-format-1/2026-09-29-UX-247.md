# UX-247 — Composer visual refinement

- Date: 2026-09-29
- Status: In progress; latest visual treatment awaits owner review
- Related issues: ISSUE-099, ISSUE-100
- Previous evidence: [2026-09-28 UX-247](2026-09-28-UX-247.md)

## Owner direction

The owner accepted the visible selected/available channel groups, collapsed
delivery settings, and restrained transfer motion. They asked for a centered
new-publication heading, stronger visual identity and boundaries for channel
controls, a compact vertical channel tile with a corner remove action on
mobile, and a substantially more credible LinkedIn post preview. They also
asked us to inspect other interface choices at the same level of care.

## Decisions and implementation

- Centered the single page heading within the composer width using a three-
  column header; the back action remains on the left with a square icon control
  on mobile.
- Gave shared copy a layer icon and the restrained primary accent. Selected
  channel tiles now have a defined surface and selection boundary; available
  channels keep a muted, dashed mobile outline. On narrow screens the avatar
  and channel name stack, while the separate round remove action occupies the
  upper corner. A visual pass found the selected tile's label was clipped by
  the default button height, so the button was made full-height.
- The LinkedIn preview now uses a local fictional profile portrait only when
  no account identity is available; connected destinations show their actual
  account/destination name with an initial rather than an invented photograph.
  Other built-in account-based networks use the same identity rule. LinkedIn's
  light post surface includes post metadata, content, illustrative reaction
  totals, and recognizable actions. Illustrative figures appear only with
  draft content or media and are identified as examples to assistive technology
  and on hover. These numbers are not analytics or persisted publication data.
- LinkedIn's own [post-interaction help](https://www.linkedin.com/help/linkedin/answer/a522684)
  and [Page-post FAQ](https://www.linkedin.com/help/linkedin/answer/a567075)
  were used to check the reaction, comment, and repost vocabulary. This is a
  visual approximation rather than a provider-rendered post.
- Promoted only the owner-accepted two-group selector and collapsed scheduling
  contract into `DESIGN.md`. The new visual details and simulation treatment
  remain provisional pending review.

The fictional portrait was generated with the built-in image-generation tool
using this prompt: "A believable, fictional adult professional's centered
head-and-shoulders portrait for a small social-post avatar, natural expression,
casual-professional clothing, warm neutral background, soft daylight, realistic
skin texture; no text, logo, watermark, or recognizable real person." The
selected image was optimized to a 256 px WebP project asset.

## Owner correction and second pass

The owner rejected the outlined, large-radius channel tiles and the generated
portrait. Their preferred grammar is compact controls differentiated by raised
or inset surfaces and short shadows, with lines only where they carry actual
information. They also asked for the channel image to occupy the full control
height without left padding, a separate remove button, a conventional stock
mockup identity in the LinkedIn preview, and workspace/project context across
the dashboard whenever the sidebar hides its selectors.

The channel rail now uses one-height compact controls. A selected destination
groups its edit and remove actions as adjacent buttons, with a flush-left
avatar. Available destinations remain muted on the right and transfer into the
selected group through the existing layout motion. The schedule disclosure is
now one subdued surface without its prior full-width rules. The preview uses
the owner's supplied Unsplash portrait as a local JPEG and a fictional sample
name, even when a real destination is connected. Its LinkedIn example is
denser and uses restrained illustrative engagement. The dashboard header no
longer repeats page titles or a pseudo-breadcrumb; a collapsed or mobile
sidebar exposes direct workspace and project menus with their existing visual
identities across project pages. Full sidebar selectors remain available when
expanded, including search and creation.

The stock source is
`https://images.unsplash.com/photo-1568602471122-7832951cc4c5` with the
owner's provided crop parameters. The portrait is illustrative and never
derived from a connected account. `bun run check:quick` and the focused narrow
publication journey pass after these changes. The focused browser test also
opens and dismisses both compact scope menus. The production web build passes.
Storybook's 390-pixel composition and the authenticated page were visually
inspected. The owner's next visual checkpoint remains open; this pass is not
yet marked accepted.

## Owner correction: scope controls and media reordering

The owner accepted the composer direction but found that the header's newly
introduced scope menus had lost the original selectors' search, creation, and
configuration actions. They asked for a single persistent location for both
selectors, full-height flush-left identity images, desktop tooltips when labels
collapse, and a simpler media attachment interaction. They reported that
dragging one selected thumbnail onto another created duplicate attachments.

The header now mounts the original searchable workspace and project selectors
on all dashboard routes. Their full panels retain search, creation, workspace
administration, and project configuration. The sidebar no longer duplicates
the selectors; its project category control remains available there. Each
compact trigger uses the resource image as its left edge, with a desktop
tooltip and an accessible name containing the current selection. Mobile
tooltips are disabled. At 320 px, the workspace trigger becomes an image-only
square while the project trigger retains a truncated label.

Selected-media reorder now uses pointer/touch dragging from a small handle and
Motion's reorder list. The old directional overlay buttons and the thumbnail's
native HTML drag behavior were removed. Keyboard users can focus the same
handle and press Left or Right. The selected asset IDs are accepted only when
the resulting order is a complete permutation of the existing selection, so
reordering cannot add or lose a selection. The remove control is smaller and
offset slightly beyond the thumbnail's top-right corner. The local Uppy
dropzone implementation reads native dropped files; this explains the reported
duplication when a thumbnail was dragged as a native image into that dropzone.

The focused media E2E moves one of two images and asserts that the count stays
at two, then tests keyboard reordering. The narrow composer E2E verifies the
full selector actions, non-overlap at 320 px, and the project-configuration
header at that width. A screenshot of the isolated narrow fixture was visually
reviewed. `bun run check:quick`, the focused E2E scenarios, the media ordering
unit test, and the production web build pass. The first Vite request in the
isolated E2E process can log a transient API fetch error during startup; the
journeys then pass. No draft was changed in the owner's live browser session.

The first full repository run found four E2E failures. The workspace selector
keeps a stable action name and exposes its selected value as an accessible
description; the instance-scope test now selects the global header control
unambiguously from the page-specific workspace administration control. The
media thumbnail item reserves 6 px for its deliberately protruding remove
button, eliminating a narrow-screen scroll-width overflow. Two calendar
failures came from an old fixture that clamped every date to the 28th, making
its events yesterday on September 29; the fixture now uses the current UTC
date. The three affected E2E files reran with 8 of 9 scenarios passing, and
the remaining instance-scope scenario passed after scoping its locator. The
second full `bun run check` passed, including all 38 browser scenarios, unit
tests, formatting, spelling, linting, and typechecking.
