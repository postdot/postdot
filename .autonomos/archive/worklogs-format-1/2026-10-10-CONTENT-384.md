# CONTENT-384 — media in header search

## Delivered

Search ready, non-archived media by original filename and default accessibility
text. Existing session authentication, live project access and scope are unchanged.
Rows expose metadata only and use the existing gallery icon. Selecting a result
opens the existing media information dialog through the media route's assetId
parameter, independently of library pagination. Closing consumes that parameter,
so selecting the same asset again opens its information again.

## Quick design review requested by owner

Applied interface-design and frontend-design to search captures and header/media
components, keeping Postbot's established tokens and restrained copy. This was a
short review, not exhaustive coverage or a claim of native-platform fidelity.

Two actionable inconsistencies remain:

1. Search local page entries all use SettingsIcon, including overview, queue,
   channels and media. This weakens recognition; reuse their navigation icons.
2. ThemeToggle uses a native title instead of the shared tooltip primitive.
   Bring it into the same tooltip pattern as adjacent header actions.

Recommend one bounded follow-up for these two items, without a broad redesign or
new full-suite gate. No new design system, provider call or media processing.
