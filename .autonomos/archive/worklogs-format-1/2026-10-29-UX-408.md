# UX-408 — Keep composer reads and pending recovery with their author

Status: complete
Related: UX-406 (browser recovery isolation), UX-407 (post creation guard)

## Changes and evidence

The composer draft GET now accepts the same optional `expectedUserId` guard as its writes. After the existing project authorization check, a mismatch returns 409 `account_changed` before reading the current account's draft. All Studio composer reads supply the rendered author, including initial recovery, comparison, refresh, and the reread after a refused replacement. Legacy clients can omit the guard. Authentication and project permissions remain authoritative; the parameter grants no access.

A browser regression creates a genuine same-author conflict, changes the shared browser cookie to another account, and asks to compare versions. The stale tab shows the reload notice without displaying the second account's private draft. An API regression checks that the refused read contains no draft content; the OpenAPI export checks the optional query parameter and 409 response.

The previous validation's six failures came from request matchers that assumed a query-free GET URL. Matchers now compare URL pathnames and route interception includes query parameters. The same failure, recovery and navigation assertions remain. The corrected focused run passed all 25 journeys.

A further regression reproduced actual local data loss: while a newer browser-only recovery awaited a choice over an older server copy, the account changed, and Discard was refused. Closing the recovery dialog triggered persistence of the still-empty form, removing both original-author browser copies. The baseline failed with null in both storage locations. A paused account now leaves browser recovery untouched and makes the form inert until reload. Reconnection as the original author must offer and restore the latest browser-only text.

The saved and unsaved stale-tab cases now both require exactly 409 and the reload notice; the former conditional status assertion is removed. The isolation spec is also included in the affected-authoring selector, with its exact selection fixture updated.

## Limits and next scope

The optional guard protects clients that send it; older clients remain compatible. Legacy unscoped browser bytes are retained but never assigned to an account. This pass does not introduce proactive session checks on focus, a new authentication mechanism, or automatic ownership migration. No live provider, physical-device, screen-reader or complete browser-matrix acceptance is claimed.

Recommended next task: verify session revalidation when returning to an already open dashboard, including in-memory composer and query cache lifetimes, before deciding whether focus-time session detection is needed.
