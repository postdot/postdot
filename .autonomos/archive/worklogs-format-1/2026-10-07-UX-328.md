## Operator outcome

The profile editor now exposes only editable definition fields. Identity, origin,
version and the two fingerprints are grouped in a read-only technical disclosure.
The operator can save successive constraint changes without inventing hash values.
Pasting managed fields back into the editable JSON produces a localized explanation
before sending a request. Saving and reloading synchronize both the editable
text and authoritative metadata.

The advanced JSON editor remains; no generic schema form builder, new styling
system or migration workflow was introduced. Existing preview, explicit activation,
conflict recovery and publication adoption interactions continue to work.

## Authoritative save boundary

Core defines deterministic fingerprint inputs using its existing canonical profile
JSON representation and an injected hash function. The persistence save boundary
normalizes the channel-owned identity, origin and next version, and supplies the
existing Bun-compatible SHA-256 implementation from `node:crypto`.

The schema fingerprint covers canonical contentSchema before runtime-only provider
preparation. The complete fingerprint covers the entire normalized definition,
including derived schema fingerprint and version, excluding its own fingerprint.
Object-key order is irrelevant; array order and string contents are preserved.
No package dependency or production runtime was added.

API callers can keep sending complete legacy definitions or omit managed metadata.
Supplied identity/origin still cannot change the active profile's identity/origin;
supplied fingerprints are always replaced. Returned metadata remains authoritative
in the existing response shape. An unchanged existing draft retains identical
fingerprints while its record revision advances as before; stale expected revisions
remain conflicts. Version record IDs and audit semantics are unchanged.

No existing profile is rewritten merely by loading it. An explicitly saved mutable
draft receives new fingerprints, while active/superseded definitions, selected
targets, publication drafts, source content, approvals and execution snapshots are
preserved. Activation and adoption remain explicit. The creation endpoint for new
custom channels remains unchanged; this task concerns subsequent draft editing.
