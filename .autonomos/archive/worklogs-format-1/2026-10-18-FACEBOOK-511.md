## Delivered in this commit

Added the Facebook provider-adapter factory and tests against the existing publication worker. It handles text, link-only, photo-only and text with one inspected JPEG/PNG photo. A link plus photo remains deliberately rejected. Page destination and credential identity must agree. The frozen asset reference, storage metadata, file size, MIME and checksum are checked before sending; a same-size mutation between verification and reading is rejected. The pinned accessibility text and inspected MIME accompany multipart uploads.

The adapter uses the established media-delivery ledger. A definite rejection can be retried according to the executor's existing policy. An uploading, uploaded or ambiguous photo cannot be sent again by this adapter. The remote photo ID is a media checkpoint, while the returned post ID is the publication identity. Missing post identity, transport loss, server uncertainty and failed durable completion remain ambiguous. Invalid credentials are marked for reconnection. There are no internal network retries or provider-error/secret logging.

No production registry, channel-creation preset or content capability was activated. The factory is exercised through injected worker registries against real isolated SQLite and local media storage. No actual Meta connection, file or publication was used.

## Unresolved shared contract

`TextFieldCapability.maxLength` in `packages/core/src/channel-profile.ts` requires a non-negative numeric maximum. The isolated Facebook profile currently has no text capability, which is a holding boundary, not a claim of unlimited text. The official Page Feed reference returned HTTP 429 during this pass; no verified current Meta text ceiling was obtained. Third-party numbers were not adopted as authoritative.

Two credible directions were presented to the owner through a pending question:

1. Represent an unknown maximum explicitly and display a count without a denominator. This is recommended because it preserves the distinction between a known provider limit and missing information, but requires reviewing all consumers of the shared contract. Known limits and validation must remain unchanged.
2. Choose a clearly identified Postbot text ceiling. This fits the current numeric contract but imposes a product restriction that must not be presented as a Meta limit.

A verified native maximum could later be recorded through the normal versioned-profile lifecycle. Neither direction has been silently accepted. Root AGENT.md requires explicit governance approval for consequential domain decisions. The task therefore remains in progress; production activation and the shared text-capability change await the owner's answer.
