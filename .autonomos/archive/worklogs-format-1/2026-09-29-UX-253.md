# UX-253 — Project route context normalization

- Date: 2026-09-29
- Status: Complete
- Related tasks: UX-240, UX-250, UX-251, UX-252

## Evidence and decisions

Project-scoped Overview, Queue, Channels, and Performance no longer repeat the
selected project or `UTC` below their titles because the shell header already
owns that context. The publication detail header now uses the same centered
title pattern as New publication: one semantic back link sits on the left and
the save indicator occupies the right when editing. The mobile authoring path
keeps the same route continuity and no longer relies on a button role for
navigation.

Queue, Channels, Performance, and Media now share the same page-level geometry:
one centered title, a left return link to Overview, and an optional right-side
action. The link collapses to an icon-only control on narrow screens while
keeping its full accessible name. `DashboardPageHeader` owns the three-column
layout so the title remains centered even when one side has no action. On
narrow screens, the controls occupy one row and the title moves below them;
this avoids compressing the title beside New publication. The accepted rule
is recorded in `DESIGN.md`.

The sidebar footer's always-present publication and attention counters were
removed. Those values were either zero or duplicated Queue's filters and added
weight without a decision. Actionable states remain visible in Queue and in
the shell's notification affordance. Channels keeps connection identity and
the next connection action visible, while the optional LinkedIn organization
path is disclosed only when requested.

## Files

Changed the shared shell/sidebar, project page headers, publication detail and
new-publication headers, channel connection presentation, and related browser
assertions.

## Verification

Desktop and narrow browser journeys, accessibility smoke, channel connection
recovery, publication detail lifecycle states, the Queue return affordance, and
the full local gate cover the updated surfaces.
