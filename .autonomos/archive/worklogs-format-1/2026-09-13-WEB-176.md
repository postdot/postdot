## Accepted contract

- The page leads with its content section; the editor receives the dominant
  column on wide layouts.
- The destination section is explicit, and selected channel
  tabs appear before shared delivery settings.
- Shared settings explicitly apply to all selected channels; channel-specific
  content and delivery remain available as deliberate overrides.
- The multi-channel API, draft behavior, scheduling context, and existing
  selection/customization actions remain unchanged.
- Preview, rich editing, and new scheduling semantics are outside this slice.

## Implementation checklist

- [x] Adjust the responsive layout to give the content editor more space.
- [x] Replace the user-facing Source/Destinations hierarchy with
  Content/Publish to vocabulary.
- [x] Put channel selection before shared settings and remove redundant
  destination framing.
- [x] Keep no-channel projects actionable and preserve the calendar date/time
  context in the shared schedule control.
- [x] Remove persistent ring/shadow-only surfaces from the editor and target
  cards while retaining intentional contrast through shared surface tokens.
- [x] Update English/French copy and browser assertions.

## Resolution

Postbot now presents publication authoring in the operator’s sequence: write the
content, choose channels, confirm shared delivery, then customize only when
needed. The internal fan-out model remains available in behavior and domain
code without defining the first visual reading of the page.

## Next step

Evaluate a contextual multi-channel preview as the next authoring slice, using
the new hierarchy as the stable shell and keeping preview behavior separate from
the editor and scheduling contracts.
