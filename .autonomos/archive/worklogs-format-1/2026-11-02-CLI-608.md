# CLI-608 — Offline shell completion

Status: completed (2026-11-02). Owner accepted the completion slice deferred from the initial
CLI release. Implement one Commander-derived candidate engine, thin Bash/Zsh/Fish
adapters, explicit installation instructions and an independent CLI Changeset.
No server enumeration, credential reads, backend writes or shell startup edits.

Plan: implement completion from the registered grammar; qualify candidate edge
cases and actual shell adapters under Node/Bun; document and integrate the package.
Shell scripts bind to the runtime and installed entry point used to generate them,
so explicit Bun execution also works with Node absent from PATH. Regenerate after
moving that runtime/package. This trades path independence for reliable runtime
selection without adding wrapper configuration or network-dependent bunx calls.

Primary references: GNU Bash programmable completion manual, Zsh Completion
System manual, Fish commandline/complete manuals, and installed Commander 15
public Help/Argument/Option declarations. No third-party completion dependency.

## Implementation and acceptance

Added `completion <bash|zsh|fish>` plus a hidden candidate command. Public
Commander Help/Argument/Option metadata supplies visible commands, inherited
options, aliases and enum choices; business handlers are never parsed/executed.
Arguments after the cursor are ignored, option values and --option=value retain
their context, and the option terminator stops candidate generation. Bash URL
word breaks are handled without changing the shell's global word-break settings.

Scripts invoke the generating runtime and installed entry path as quoted argv,
including explicit Bun with no Node dependency at completion time. Fish uses the
supported token-expansion interface and requires version 4+. Setup is explicit:
no startup files are written and the public --json mode returns shell/script.
No new runtime dependency or second API client was added.

Acceptance uses real interactive Bash 5.3.20, Zsh 5.9.2 and Fish 4.9.3 PTYs.
Nine Tab cases per shell cover subcommands, mid-line completion before existing
options, options, enum values, URL arguments, quoted spaces, literal command
substitution and shell choice. The installed candidate passed all 54 cases across
Bun and Node, with the entry copied into a path containing spaces and an
apostrophe. A malformed profile file did not block completion and a configured
HTTP tripwire received zero requests. The same installed artifact still passed
remote publication/media/profile acceptance.

The package-validation workflow installs the acceptance shells and enables this
suite. Existing published-server compatibility continues without completion (the
published alpha.1 has no such command). A minor CLI Changeset was created with the
shared npm Changesets tool under Node 24; status lists only @postdot/cli. Public
README instructions describe the next package artifact; online reference marks
completion unreleased until that package is published.
