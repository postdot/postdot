## Delivered native package

Standalone @postdot/n8n-nodes-postdot 0.1.0-alpha.1 under integrations/n8n uses the official n8n node CLI 0.54.5, TypeScript 5.9.3 and n8n-workflow 2.16.0 development contracts. Its runtime peer is n8n-workflow, as required by n8n's package conventions. The application Bun lockfile, runtime registry and Dockerfile are unchanged.

The declarative node exposes Project/Get Many, Channel/Get Many, Post/Create Draft and Publication/Get. Project and channel options are loaded from the user's authenticated Postdot resources. The create operation sends canonical plain-text source content and one destination, with no scheduledAt field. The server owns profile adaptation. Publication/Get reads the complete editor state rather than inventing a delivery result. Headers use an encrypted Postdot API credential; credential testing only reads projects. Requests disable redirects and keep a bounded timeout.

The package includes the actual Postdot logo in light/dark variants, authored node metadata, AGPL license and an importable manual-trigger example that creates and reads one draft. No npm publication or n8n Cloud verification was performed. The package is private until a separately authorized release.

The official starter's strict verification preset requires MIT and a public author email. Retained AGPL and the project's name/public URL instead, with only those two metadata-rule exemptions and strict Cloud-verification mode disabled. All remaining node/credential lint checks pass. Do not present this as verified Cloud compatibility or silently change licensing for verification.

## Actual n8n acceptance

Installed the packed archive into a task-owned n8n 2.45.6 Docker user directory using npm. Imported credentials and workflows through n8n's normal CLI and executed the actual node through its runtime:

- Project discovery returns only the permitted project. Channel discovery returns its two channels, each as a separate output item.
- The shipped example creates a native Bluesky draft and reads back that same publication. Text, accents, quotes, emoji and newline survive.
- The same example works for a manual destination with the manual mode.
- An excluded project returns a NodeApiError with HTTP 404; an invalid key returns HTTP 401.
- A task-owned proxy forwards one create request, waits for upstream HTTP 201, then destroys the response socket. n8n reports ECONNRESET; the proxy records exactly one forwarded write and the database contains one saved draft for it. No automatic replay.
- Through the actual n8n editor-backend endpoints, the credential test returns OK, project options return one allowed project, and channel options return its two channels. These are backend interaction checks, not a visual browser review.
- Final Postdot evidence contains five unscheduled drafts: two earlier direct-contract probes, two successful native workflows and one uncertain native write. The job table is empty; no provider identity or live delivery exists.

Two initial negative attempts stopped at a task-broker port collision because the CLI and editor server were started together. They were not accepted as permission or uncertain-write evidence. Corrected the harness to run them separately, asserted actual execution error codes, and used an IPv4 proxy URL matching its bind address. The first empty-data credential-test request also failed as an invalid fixture; supplying the configured credential values passed. No product behavior was weakened or changed for these harness fixes.
