# UX-252 — Performance collection recovery and state review

## Findings and scope

Reviewed the current Performance source and the earlier UX-252 implementation.
The October 2 review incorrectly stated that unsupported publications still
occupied the main list: the September 29 correction already filters them out.
Retain that correction and the current discoverable route. No navigation hiding
or demotion is adopted in this pass.

The remaining concrete interaction problem was a page-level refresh failure that
could not be attributed to one publication. The mutation's last result also could
not represent independent failures retained across several rows.

## Changes and decisions

- Keep refresh failure state keyed by publication. Starting a retry clears only
  that publication's error; failing another publication preserves the first error.
- Display the existing localized failure message beside the affected publication.
  Store error presence rather than translated text, so switching language updates
  an existing alert correctly.
- Preserve collected metric values after a failed refresh. Continue distinguishing
  measured zero from unavailable or uncollected data, which remains a dash.
- Use a 44-pixel square refresh target when its text is hidden on mobile. Preserve
  the compact desktop text button and existing role-based refresh authorization.
- Do not change provider collection semantics, introduce automatic external calls,
  aggregate unrelated provider metrics or invent totals.
