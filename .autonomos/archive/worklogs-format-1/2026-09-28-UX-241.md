# UX-241 — Separate composer selection, editing, and persistence

- Date: 2026-09-28
- Status: Implemented; owner approved the interaction contract.
- Related issue: ISSUE-099
- Related evidence: UX-239 browser audit

## Browser audit

The initial visit covered one and multiple destinations, shared and channel
copy, destination removal, route-away-and-back recovery, and a 390 × 844
viewport. `Publish to` selection also activated the editor, while removal lived
inside delivery settings. Long channel names truncated on mobile, and recovery
restored text and selections but could reopen a different editing scope.
Autosave and persistent draft creation were visually adjacent, with similar
outcome language. The final actions followed the long mobile editor and
preview.

The interface was also checked for manual and automatic delivery, shared and
target-specific content, media, tags, keyboard access, and empty selection. No
real provider dispatch was performed.

## Accepted interaction contract

- `Publish to` only includes or removes a destination; it does not switch the
  editor or rewrite delivery defaults.
- A separate editor control selects shared or destination-specific copy. The
  preview follows that scope, and removing its destination returns to shared
  copy without dropping remaining work.
- Browser and server composition recovery restore the selected editor scope
  together with text and destination state.
- Quiet recovery/autosave feedback stays distinct from creating a persistent
  draft. The scheduling action names how many publications it schedules.
- Selection and scope remain accessible and usable with narrow, wrapping
  destination labels.

The owner approved this contract before structural implementation.

## Implementation

Destination chips now represent inclusion only and expose their pressed state.
The editor has its own accessible scope selector; changing it switches the
effective content and preview without changing destination inclusion. The
active scope is stored in browser recovery and the optional server composer
draft field, with legacy drafts supported. Removing the active target falls
back to shared content. Draft and schedule actions now name their distinct
outcomes, and final actions are hidden when no destination is selected.
