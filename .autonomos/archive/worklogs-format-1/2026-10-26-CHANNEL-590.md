# CHANNEL-590 — Retained work after built-in constraint changes

Completed ISSUE-174's accepted synthetic retained-work proof. The fixture uses
the actual LinkedIn profile identity/execution revision with illustrative limits
of 500 and 300 characters; these are not claims about LinkedIn's current limits.
No provider request or real publication occurred.

## Findings and corrections

The baseline preserved working drafts, selected targets and historical execution
snapshots. Three gaps reproduced before correction:

- Activation excluded every running claim, including a claim that had not crossed
  the durable effect boundary. That claim could still execute incompatible text.
- An already-started attempt could finish with a known no-effect failure and queue
  an incompatible retry after activation had deliberately excluded that execution.
- Explicit retry of a failed retained target could bypass the newer requirements.

Activation now includes claimed-but-not-started targets in its impact. A shared
internal assessor evaluates the immutable selected target against the active
profile in the same transactions that start an effect, queue an automatic retry
or authorize a manual retry. It reuses core profile assessment and pinned-media
validation, including execution-contract changes and disabled profiles. It does
not validate a retry using the mutable working draft or replace target content.

An incompatible pre-effect claim is cancelled before an execution revision is
created. A known failed attempt that cannot satisfy current requirements remains
failed/review-required rather than reporting a scheduled retry. Manual retry is
refused through its existing not-retryable contract. Compatible retained targets
continue without forced profile adoption. Already-started successful attempts
finish under their original immutable execution snapshot.

Pinned media is read as project-owned system data, independently of the original
author's current membership; no new public media access is exposed. Current
public-URL availability is passed from the existing runtime/configuration boundary.
Assessment changes append a publication.profile_assessed fact, supported by the
existing project SSE channel and client refresh path. No table/migration, provider
adapter, credential ownership or consent policy was added.

## Validation

- Final targeted proof: eight cases, 58 assertions, all pass. Covers new compatible
  and invalid drafts, refusal of invalid scheduling, retained draft/target bytes,
  compatible/incompatible pending work, pre-effect activation race, immutable
  historical/in-flight snapshots, automatic/manual retry, compatible old-profile
  retries, changed execution contracts and pinned-media requirements.
- Broader persistence/worker/profile regression pass: 79 tests, 776 assertions.
  The existing disabled-profile case now asserts cancellation, review-required
  state and no execution snapshot rather than expecting an exception with a
  still-running claim; fail-closed behavior is stronger, not waived.
- Full unit/script integration suite: 1,612 tests pass, zero failures. The eighth
  metadata-only media case was added afterward and passes with the seven others.
  It verifies pinned metadata, not byte upload or real provider delivery.
- Repository format/lint/spelling/typecheck gates pass.
- Built-production browser: four cases pass for shipped-template loading, impact
  and explicit activation, active-profile promotion refusal, and explicit draft
  adaptation without changing source or selecting a target.
- Production web and API/container build pass. The local Linux/x64 candidate

  passes production startup, authenticated project operations, static assets,

## Boundaries

The channel guide explains manual shipped-template loading, explicit activation,
retained work and retries. Automatic upstream discovery remains unimplemented;
upgrading Postdot does not silently replace a channel's active profile. The
unaccepted retained-incompatible-profile consent proposal in ADR-078 remains
unimplemented. Existing runtime adapter support checks still apply.

No image publication, production change or operator feedback gate. Source work
is ready for a later grouped release; alpha.2 remains deployed. Local test
resources were isolated and the task image tag was removed. No AGENT.md update:
ADR-020 already defines the durable ownership/assessment rule; this work closes
its execution gaps instead of adding another policy.
