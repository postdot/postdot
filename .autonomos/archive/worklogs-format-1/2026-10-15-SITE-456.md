# SITE-456 — Static OpenAPI reference

Implemented an isolated Bun exporter using the existing createApp composition,
a migrated in-memory SQLite database, deterministic dummy configuration and a
fresh temporary media adapter. It starts no HTTP listener, worker or scheduler,
and does not import the production entry point or inspect shared instance state.
The fixture includes signed media routes. Database and temporary directory are
cleaned after export; unique operation IDs and tags are checked.

Added the official fumadocs-openapi 12.4.2 integration, compatible with the pinned
Fumadocs/Base UI 16.17.1, plus required schema/highlighting dependencies. Generated
160 operation pages in 16 tag domains, native method badges and a downloadable
schema. Each page preloads only its operation fragment (largest about 23 KB), not
the 1.9 MB formatted document. The reference uses the accepted Notebook layout,
with full-width API pages and a responsive example-code column. Request execution
is disabled; no credential form, proxy or public OAuth handler was installed.

Authored introductions remain separate. The default Elysia bearer/session security
and explicit session-only/public overrides are preserved. Better Auth dynamic
routes and optional metrics are not invented. One avatar DELETE operation lacks a
response contract: export marks that absence explicitly rather than adding a
fictional status/schema. Escaped the root bearer-token description with Markdown
code so the token placeholder survives rendering.

Generation uses multiple local schema fragments. Fumadocs meta generation emits
duplicate metadata paths across these inputs and corrupted JSON under concurrent
writes. Metadata is instead written once per folder; duplicate page paths and
operation coverage are validated. One failed build left a bad loader cache; the
generated .next cache was cleared, then clean and incremental static builds passed.
Generated installation output was also moved to its correct ignore path after the
previous hierarchy change; the canonical operational Markdown remains unchanged.

Validation: focused isolated export test passes (two identical exports, zero fetch
calls, representative routes/security). Static docs export and repository quick
format/lint/spelling/type gates pass. Browser verifies POST createPost parameters,
request and response UI, method badges, sample code, stable placeholder origin,
mobile no-overflow and absence of execution forms/buttons. Generation covers all
160 exported operations. Screenshot: /tmp/postbot-site456-openapi.png. No live
provider, publication, API key, default database or service lifecycle was changed.

Notebook owner acceptance is recorded. DOCUMENTATION.md now explains the actual
pipeline, and apps/docs/AGENT.md protects generated content and the static boundary.
ISSUE-164 is resolved within its stated route-coverage boundary.

Next recommended task: improve selected server contract examples and response
annotations, starting with createPost and the avatar DELETE response, then split
