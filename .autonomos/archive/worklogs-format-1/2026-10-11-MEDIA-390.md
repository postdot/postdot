# MEDIA-390 — Existing image previews

## Scope and outcome

Added the explicit offline `media-previews` maintenance command, with `--dry-run`
and optional `--project`. It reuses the upload processor and creates only missing
256/768 WebP variants. Missing stored previews are repaired; originals, publication
references and library asset identity are preserved. No migration, dependency,
background scan or additional user-visible media entry was introduced.

The command requires an existing database, configured media storage and exclusive
runtime lock. It never reclaims an existing lock automatically. Partial completion
is retained and failures produce a nonzero exit. README documents source and
container invocation with the server stopped.

## Validation

- Store, maintenance, media routes, backup and provider delivery: 24 tests passed,
  1,378 assertions, approximately 2 seconds.
- Final changed store/maintenance suites: 17 tests passed, 1,245 assertions.
- `check:quick` passed; API build passed. Compiled CLI dry run against an isolated
  existing database returned zero eligible images and exit 0.
- Store regression covers dry run, project scope, repeat execution, partial missing
  variants, missing stored file, deletion exclusion and unchanged original bytes.
- Maintenance regression covers missing database, competing lock, invalid project
  option and release after successful execution.
- No full browser matrix: this pass adds an offline maintenance path and shares the
  already tested upload processor; it does not change dashboard rendering.

## Local application

After explicit owner authorization, verified the residual lock process was absent
and no process held the database or its WAL/SHM files; removed only that residual
marker. Dry run found 17 eligible images. Application generated previews for all
17, with zero failures. Repeat execution generated zero and reported all 17 ready.
There are 34 ready derived previews. All 18 ready original files were checked
against their persisted SHA-256 and byte sizes; original representation metadata
also matched the snapshot taken before application. Maintenance released its lock.

## Limits and next step

Static JPEG, PNG and WebP images only; other formats and animated images retain
original delivery. Native generation failures preserve the original. Video posters
remain separate: the recommended next task is a stored poster for video cards,
with playback loading only when requested.
