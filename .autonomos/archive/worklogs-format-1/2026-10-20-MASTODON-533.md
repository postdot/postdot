# MASTODON-533 — Native polls

## Scope and plan

Owner accepted the recommended native Mastodon poll slice. Work directly without delegation.

1. Verify status poll parameters and instance-advertised limits.
2. Preserve status-v1/v2 and add status-v3 with an optional structured poll.
3. Add native destination controls and a truthful non-voting draft preview.
4. Verify provider payloads, validation, worker integration and the affected browser workflow; integrate locally.

## Boundaries

- Destination-specific poll authoring belongs to the publication target editor, not shared source content.
- Initial application envelope: 2–4 distinct nonblank options, 50 graphemes each, 5 minutes through the standard maximum duration; optional multiple selections and hidden totals.
- Polls are mutually exclusive with attachments. Check the original connected instance's advertised limits before dispatch; missing or malformed configuration is not proof of support.
- Poll duration starts at actual provider publication, not draft creation or schedule time.
- Existing profile targets remain immutable. Existing channels explicitly load/adopt the shipped profile through the existing workflow.
- No voting, results collector, edits to live polls, external publishing, new OAuth scope or schema migration.

## Verification and outcome

- Added `status-v3` while retaining unchanged image-only v1 and video v2 definitions and execution registrations. Existing channel/profile adoption remains explicit.
- Added a browser-safe poll contract, grapheme validation, schema constraints and the Mastodon validation adapter in API composition. The worker rejects attachments and checks the original instance's advertised limits before any upload or status effect. Status delivery retains the execution revision's idempotency key and treats missing poll acknowledgement as ambiguous.
- Added destination-specific option, duration, multiple-selection and hidden-total controls, EN/FR text, read-only inspection and a non-voting preview. No migration or new external dependency.
- Static checks: `bun run check:quick` passed, including workspace types, formatting, lint, spelling and EN/FR coverage (1953/1953 each).
- Focused unit/integration checks: `bun test packages/mastodon/src apps/api/src/modules/workflow/providers/conformance.test.ts apps/api/src/modules/workflow/worker.test.ts scripts/production-bundle-dependency.test.ts` passed: 80 tests, 710 assertions. Covers protocol payloads, advertised limits, historical revisions, no-effect rejection, ambiguous acknowledgement and the production bundle dependency guard.
- Focused isolated browser checks passed: the poll's authoring, persistence/reload, duplicate-option rejection/recovery, mobile French layout and immutable selection without publication; existing native Mastodon MP4 import/playback and draft persistence also passed (2 scenarios, 19.2 seconds).
- Browser investigation: a root schema composition hid all normal fields in the generic editor. Removed it and retained poll/media exclusivity in the native validation adapter and worker. The duplicate-option assertion was corrected to the schema's `schema.uniqueItems` error: schema validation precedes provider validation. Earlier strict summary selector was narrowed to the customization section's direct summary. No product assertions were weakened.
- The mobile capture showed existing unset-value markers and untranslated generic field labels above the new poll controls. These are outside the native-poll slice and remain a UI finding for later triage.
- No real provider request or external publication was performed. Live Mastodon acceptance remains unverified.
