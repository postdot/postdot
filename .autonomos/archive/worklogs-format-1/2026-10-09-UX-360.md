# UX-360 — Video description authoring

Status: complete. Base: `cbe7128e8`.

Plan: trace compact media field visibility, expose the existing description input
for videos without changing image density or explicit visibility overrides, and
extend the native Discord browser case to create and edit the description through
normal controls. Run static checks, unit suites and the affected browser coverage.

## Implementation

Compact attachment rendering suppressed description inputs by default. Reused the
existing field for video representations in both inline attachment layouts; image
density and explicit visibility overrides are unchanged. Each compact description
field now uses a React instance ID so source and destination selections of the same
asset cannot share an HTML label target. No new field, translation or persistence
contract was introduced.

Extended the existing native Discord browser scenario: reserve a video without a
default description, enter its description in the composer, verify persisted
destination content, then edit it through the publication target control. Native
LinkedIn and Mastodon playback cases continue to pass. Mobile screenshot inspected
at 390 pixels: description below the compact thumbnail, readable and no overflow.

Initial browser launch failed before running the scenario because the inherited
browser path did not contain the installed executable. Used the existing browser
installation at the user cache path. The first executing regression exposed
duplicate source/destination label IDs, corrected with useId; subsequent three
native-video cases passed in 24.1 seconds.

Static gate, all unit suites and web build passed. The selector was run against
explicit mission paths because an unrelated pre-existing quoted cache directory
would otherwise cause full fallback. It retained ten scenario files (media library
and publication authoring); that coverage ran on the final code. No provider
credentials or external calls used. No full validation reference advanced.

## Final validation and limits

The affected lot finished with 50 passes and one failure in 16.6 minutes.
The failed native-presentation scenario showed a white page after reload;
its trace recorded Chromium ERR_INSUFFICIENT_RESOURCES while loading Vite modules.
Its API writes and editor read had succeeded. The unchanged scenario passed alone
in 38.7 seconds. This supports a browser resource incident, but does not establish
its root cause or claim the original lot was green. Assertions, retries and
budgets were not weakened. No complete matrix was run.

The code is locally validated only; the full-validation reference is unchanged.
No AGENT.md change: existing authoring and validation rules suffice.
