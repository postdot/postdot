# CONTENT-379 — Shared post navigation from Queue

Base: `873612739`. Owner approved the recommended product slice.

Plan: establish existing queue and source navigation, add an explicit post route
without replacing publication actions, reuse source review, then verify navigation,
complete destination visibility and responsive reading.

The route is an inspection surface, not a second publication editor. It reads the
shared source and every destination across project pagination. It preserves
individual editing and lifecycle actions in their existing pages. Explicit draft
review remains governed by ADR-084. No grouping, batch publication or source
migration is introduced.

## Implementation

Added `/dashboard/projects/:projectId/posts/:postId`. Queue rows expose a separate
`View post` link in every lifecycle state; their publication links and actions are
unchanged. The post surface leads with its source revision, text and ordered media,
then lists destination publications with their existing inspection/edit links.
The existing explicit source-review dialog is reused for editors and owners.
Readers have no review action. Source editing still belongs to the existing editor;
this pass does not create a second writing contract.

The post query uses the project-data invalidation prefix already refreshed by SSE,
loads every publication page and filters by post identity. Source media use the
existing read-only comparison component, with its existing missing-media fallback.
The source inspection is URL-addressable and survives reload. Back to Queue uses
its existing default route rather than creating a new grouping or filter contract.

The page requires a current membership read. A revocation signal suspends the
surface and advances its epoch; explicit retry rereads the authorized data before
resuming. Query errors hide the loaded surface. The explicit parent callback ignores an older access generation. Existing
review query invalidation can still initiate reads; the suspended surface remains
hidden until an authorized explicit retry. Already sent writes are not cancelled. Server authorization and
ADR-084 source/draft revision guards remain authoritative. There is no new polling,
provider call or mutation endpoint.
