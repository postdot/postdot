## Recommended first sprint: CLI-369

Use the existing `@postbot/client` and HTTP domain contracts. A JSON file or stdin can carry source content and per-destination payloads without inventing platform-specific editor flags. Preserve the existing manual `publications publish` meaning; do not silently repurpose it as automatic dispatch.

First tranche acceptance: one isolated text-only journey creates a source with destinations, schedules it, inspects status, and cancels scheduled work through an appropriately scoped API key. Retry should expose existing server semantics, not create its own retry policy. Human-readable and JSON output must distinguish validation, access, and lifecycle failures. Provider credentials remain project-owned and never become required CLI inputs. No MCP service or new domain model is needed.

Media file/URL import is a following tranche of the same machine workflow, using existing reserve/upload/finalize and URL-import endpoints. Do not combine it with rich editor work or provider expansion merely to call the CLI complete.
