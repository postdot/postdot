# WEB-565 — Provider-application contracts

## Outcome and decisions

Derived six types from Eden: provider application, provider id, state, OAuth mode,
creation input and update input. Request types retain readonly properties. The
web re-exports preserve existing imports. Migrated list/create/update wrappers
to Eden with inferred results, retaining omitted fields, explicit null values
and normalized ApiError handling. The update contract is derived directly from
its server route rather than maintained as a second handwritten request shape.
No server, dependency, shared client factory or rendered component changes.

Twelve compile-time assertions cover response envelopes and three callback URIs,
the provider/state/mode unions, secret absence in responses, nullable mode,
hasClientSecret and unchanged request input shapes.

## Validation

- Static gates passed: formatting, lint, spelling and types.
- Production web build passed.
- 285 web tests, 17 client/access-route tests and 3 selected application API tests
  passed: 305 total, zero failures. The application selection covers LinkedIn and
  Instagram secret-safe management and local Bluesky configuration; 46 unrelated
  application tests were filtered out.
- Five isolated browser scenarios passed without retries in 36.9 seconds:
  both provider-application-settings cases, both access-132-instance-access
  cases and a temporary provider wrapper acceptance.
- The temporary acceptance exercised all three wrappers through the actual web
  module against the isolated API. It verified creation and rename, retention of
  an omitted secret, absence of the secret in response data, disabled/non-default
  state, Bluesky loopback mode and all three callback paths.
- Explicit null for a required provider secret returned normalized ApiError 400
  invalid_provider_application, preserving the stored secret; a missing id
  returned 404 not_found. Bearer API-key GET/POST/PATCH administration attempts
  each returned 403. The permanent access scenario also excludes non-admin users
  from instance administration. All credentials were synthetic; no external
  provider authorization or publication was attempted.
- Removed the temporary acceptance file after verification. Permanent browser
  scenarios and configuration remain unchanged.
- Focused validation is proportionate to these three known wrappers. No full
  matrix/container replay: existing transport factories, dependencies and server
  runtime remain unchanged.
