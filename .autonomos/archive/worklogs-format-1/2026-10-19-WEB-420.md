# WEB-420 — Repair the two stale web end-to-end specs

## Plan

1. Diagnose both Playwright failures against the current interface, with the product source as evidence.
2. Register a bounded delegated mission to repair the two specs without weakening the property each one protects.
3. Review the candidate, run the two specs and then the whole matrix, and integrate.

## Diagnosis

Both failures are stale specs, not product regressions. The parent established each one on a clean tree, in isolation, with the cause read from the product source.

### `web-122-populated-states.spec.ts:323`, "keeps calendar titles readable across intermediate workspace widths"

```
Error: locator.click: Test timeout of 90000ms exceeded.
Call log:
  - waiting for locator('[data-slot="sidebar-trigger"]')
```

The spec sweeps nineteen widths in the month and week views, in a collapsed and an expanded sidebar state, and clicks `[data-slot="sidebar-trigger"]` to collapse the navigation. The current authenticated shell has no such control: the parent searched the whole web application and found no `sidebar-trigger` in the source. The spec therefore never reaches the width sweep that is the substance of the test.

### `web-124-ambiguous-recovery.spec.ts:5`, "resolves an ambiguous publication without retrying the provider"

```
Error: locator.click: Test timeout of 45000ms exceeded.
Call log:
  - waiting for getByRole('button', { name: 'Create channel', exact: true })
```

The channel creation became a multi-step wizard. `apps/web/src/components/channel-creation-dialog.tsx` renders its primary button with a label that depends on the step and the choice: on the identity step, a manual-message or a custom choice shows "Configure channel", and the other steps show "Create channel". The spec opens the dialog, fills "Channel name" and clicks a "Create channel" button that the current dialog does not offer at that point.

## The candidate

The worker repaired both specs against the current interface, and the parent reviewed the diff:

- `e2e/web-122-populated-states.spec.ts`: the current shell collapses the workspace navigation from `[data-sidebar="trigger"]` (`packages/ui/src/components/sidebar.tsx`), not from a `[data-slot="sidebar-trigger"]` control that the application no longer has. The spec now clicks the current control AND asserts that the navigation really is in the expected state before the sweep, so the collapsed dimension is verified instead of assumed. The whole width sweep and every layout assertion are untouched.
- `e2e/web-124-ambiguous-recovery.spec.ts`: the channel wizard offers "Configure content" on the identity step before the channel can be created, so the spec now takes that step. Every later assertion, including the whole ambiguous-publication property, is untouched.
