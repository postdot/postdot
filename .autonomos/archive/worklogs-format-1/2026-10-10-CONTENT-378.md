# CONTENT-378 — Shared-source updates across destination drafts

Base: `780c99ad0`. Owner approved the next product pass.

## Current behavior established

Source editing already exists in the publication editor. Saving a changed source
advances the shared post revision and leaves sibling working drafts based on the
older snapshot. The explicit rebase operation advances a working draft's source
base, increments its revision and supersedes pending approval, while preserving
its destination content, validation state, selected target, schedule and delivery.
It rejects immutable lifecycle states and inactive channels, and checks the
expected draft revision. See accepted ADR-027 and
`packages/db/src/manual-store/publication-authoring-store.ts`.

The existing UI exposes source comparison and rebase inside technical details;
it does not provide one post-level review of affected destinations. A source-base
acknowledgement must not be described as copying updated source text into a target.

## Accepted implementation

Owner approved explicit review and a per-destination keep/copy choice. ADR-084
complements ADR-027: ordinary rebase keeps the previous contract; explicit copying
updates only declared primary text, headline and ordered-media fields. Other
provider fields are preserved. The server applies source-base and content changes
in one transaction, checks both reviewed revisions, revalidates the draft and
retains immutable execution, scheduling and lifecycle state. A stale source view
or draft edit is refused without partial changes.

The editor now offers a source review dialog. It reads every page of project
publications to enumerate destinations for this post, then reads their current
editors and referenced media. Closed or immutable destinations are listed without
mutation controls. Each editable row opens its comparison, defaults to retaining
adaptation and requires an explicit choice and application to copy. Media previews
are read-only. Refused changes remain inline; a refresh action reloads the review.
Unsaved local edits and access suspension disable the entry; access epochs prevent
late responses from applying to the editor after loss of authorization.

There is no new post-wide mutation, profile migration, automatic promotion or
provider call. The existing Eden client and profile bindings are reused. Reading
all project pages is bounded by pagination but can cost more in a large project;
a dedicated source-destination read can replace it when that cost is demonstrated.

## Local environment

Both development services had stopped. The old runtime marker named a process
that no longer existed; process and file-user checks found no runtime using the
SQLite files. Its exact marker was copied to a private temporary file and removed
after verification. The API launcher and web server were restarted. API responses
and the authenticated composer were observed working again. No database content,
provider configuration or user draft was changed.

working draft; both selected targets and lifecycle records remain unchanged.
