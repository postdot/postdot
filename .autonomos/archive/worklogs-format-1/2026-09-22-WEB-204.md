# WEB-204 — First bounded component-debt extraction

## Objective

Reduce the maintenance risk of the media intake surface by extracting one
coherent management-mode rendering boundary without preserving obsolete
internal structure solely to avoid import updates.

## Change

`MediaAttachmentPicker` remains the domain entrypoint, but its management-mode
library surface now lives in
`apps/web/src/components/media/media-library-management-surface.tsx`.

The extracted surface owns the management toolbar, bulk actions, collection
states, pagination sentinel, and drop hint. The parent continues to own Uppy
upload lifecycle, attachment selection, source dialogs, viewer/editor dialogs,
deletion dialogs, and mode-specific orchestration. The new component receives
an explicit `canManageLibrary` capability rather than inferring authorization
from optional callbacks.

No compatibility facade was added for the old internal structure. Existing
behavior and data contracts were preserved where they are user-facing, while
internal imports and ownership were changed directly.

## Verification

- `bun run --cwd apps/web typecheck`
- `bun run --cwd apps/web lint`
- `bun run --cwd apps/web build`
- `bunx playwright test e2e/publication-media.spec.ts --workers=1`

All checks passed. The browser scenario passed after correcting the bulk
selection state handoff to the extracted collection.

## Remaining scope

The calendar, access, and publication editor modules remain separate future
extraction candidates. They are not being split speculatively in this pass.
