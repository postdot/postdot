# UX-244 — Channel readiness and administration scope, bounded pass

- Date: 2026-09-29
- Status: In progress; unified row candidate validated, owner visual review pending
- Related issue: ISSUE-063

## Evidence and decisions

The Channels route currently has two useful but adjacent jobs: identify the
project's channels and repair the credentials needed by built-in destinations.
The channel list remains the identity surface; the connection list remains the
repair surface. The pass removes the zero-connection counter and explanatory
paragraph that added no decision, keeps a single visible connection action per
row, and puts the optional LinkedIn organization/page path behind disclosure so
the common member flow stays quiet. Archived and revoked states remain visible
and actionable.

The project and workspace selectors in the persistent header already own the
selected context and retain search, configuration, and creation actions in the
opened menu. This avoids reintroducing project or workspace labels into each
route. The bulk scheduling dialog also no longer repeats the project time zone;
the picker still receives the project zone for correct parsing and formatting.

A narrow-screen review exposed one remaining redundant sentence beneath an
unconnected LinkedIn destination. The connection badge and action already make
the state and next step clear, so the sentence is suppressed there. The channel
identity and connection-repair rows are still adjacent and repeat the channel
name; their wider information architecture remains an open part of this task.

No permission, route, provider, or connection contract changed. The remaining
question is the durable relationship between project channel identity,
publisher readiness, and workspace/instance administration. That requires a
reviewed information-architecture decision before moving settings controls or
merging the two surfaces.

## Next pass proposal (2026-09-29)

The populated route repeats the same LinkedIn channel and its connection badge
in two full-width lists. Project membership is reached from the project selector,
workspace membership from the workspace selector, and provider applications
from instance settings; these scopes already have distinct destinations.
Keep those destinations and the current permissions. Render each project channel
once, with its identity, readiness, direct connection or repair action, and
management menu in the same row. Manual channels need no publisher controls.
An on-demand detail panel would save space but add a click before the main repair
action; a separate connection list keeps the current duplicated identity.
The unified row is a reversible presentation candidate, pending owner visual
review across wide and narrow states. No domain, route, or provider contract
changes are proposed.

## Implementation and review

The route now renders one list in channel order. Manual channels keep their
management controls; publisher-backed channels place identity, readiness,
connection or repair, and the same management menu in one row. The second
full-width connection list and heading are gone. The callback target and
channel-specific anchors remain available. On narrow screens the direct action
stacks below the identity, while the optional LinkedIn page form stacks its
field and button instead of truncating the field. The advanced path remains
collapsed until requested.

Rendered checks at wide, 820 px, and 390 px showed no horizontal overflow and
kept the primary connection action visible. The isolated revoked-connection
journey now asserts one channel identity plus both management and reconnection
actions in the same row. Targeted accessibility and profile-creation journeys
also passed. This visual candidate still needs owner review; do not promote
its exact row composition into the accepted design contract yet.

The second pass changed `channel-row.tsx`, `channel-management-page.tsx`,
`publisher-connection-panel.tsx`, the connection story, and the focused
connection/accessibility browser scenarios.

Project access is reached from the project selector, workspace membership from
the workspace selector, and instance-wide users and OAuth applications from
administration. Their existing routes communicate the scope, but the latter
pages still repeat heading descriptions, zero counts, and empty notices. This
is tracked as UX-254 rather than folded into the channel presentation change.

The full `bun run check` passed after the unified-list change: 40 browser
scenarios, two password-recovery scenarios, repository checks, and production
build. The next implementation pass is UX-254; the channel composition remains
available for owner review in the running application.
