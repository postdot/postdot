# UX-250 — Shared delivery composition

## Finding and scope

Publication detail already collapses destination customization and scheduling.
However, its delivery settings and promotion action were nested inside the source
editor column, while the accepted new-publication composition provides explicit
full-width settings and action slots. The detail page therefore used a narrower,
different arrangement for the same operator task.

## Changes

Split the existing delivery component into delivery settings and promotion action
components. Render them through PublicationComposer's settings/footer slots.
Keep source and destination customization in the editor slot. Read-only detail
continues to use its post presentation and does not gain editing controls.

No scheduling, validation, promotion, role or lifecycle semantics changed. Review
warnings and changed-draft feedback remain beside the promotion action. Native
disclosures and the date/time picker keep their labels and behavior. Narrow layout
uses the already accepted composer order, including actions before the preview.

## Verification

Extended the existing detail lifecycle journey to assert settings/action placement
and absence of nested scheduling in the source column. The full repository gate
passed: format, spelling/lint, typing, unit tests, 50 browser journeys, two password
recovery journeys and 17 build tasks. Inspected fresh manual-due desktop and failed
mobile captures: settings span the composer and the action is aligned separately.
Existing conflict/recovery and keyboard checks pass. Evidence uses isolated test
fixtures, not live external accounts.

## Handoff

Changed publication-editor.tsx, publication-editor-promotion-section.tsx and the
detail-action browser journey. UX-250 remains in progress for expanded destination
customization and read-only hierarchy review. Existing composer and hierarchy
contracts cover the change; AGENT.md is unchanged.
