# DEPLOY-586 — Offline administrator bootstrap and release identification

Implemented `account bootstrap --database <path> --input <private-json-file>` in
production maintenance dispatch. It runs without server secrets or an HTTP
listener, using the existing runtime lock and Better Auth first-account claim.
A new database receives committed migrations; an existing database is not
silently migrated by this command. Claimed/blocked installations and occupied
locks refuse. The input is a bounded regular JSON file; final symbolic links are
refused. Passwords are neither arguments nor output, auth logging is disabled,
and the temporary signup session is signed out. Repeating provisioning cannot
reset an account. Existing interactive password recovery remains separate.

The image now embeds optional version and full source revision in release.json,
independent of runtime environment overrides. `--version [--json]`, public
`GET /api/version`, and installation settings share that identity. Missing build
metadata is reported as unknown, not inferred from the API schema version.
Liveness/readiness and the OpenAPI schema version retain their existing meanings.
Release and native candidate workflows pass matching version/revision build
arguments. Native candidate acceptance checks offline provisioning and agreement
between CLI, API and OCI labels before publication.

Public installation guidance covers provisioning and release identification,
explicitly identifying these as source-build features unavailable in alpha.2.
No release image was published and no deployed instance was changed. GitHub #8
remains open for release/deployed acceptance; #10 is a separate data-lifecycle
scope, not part of this implementation.
