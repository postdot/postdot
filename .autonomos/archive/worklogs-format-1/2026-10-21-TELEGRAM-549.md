Parent owns everything else, the canonical checkout, integration, browser/E2E runs, tracking and cleanup. No shared services, network calls, credentials, nested workers, merge/push or bypassed hooks. Local deterministic package tests/typecheck/lint/format are permitted only with dependencies that do not write through shared node_modules links. Stop after a bounded candidate/report, or report an exact blocker.

Protocol send accepts album?: readonly TelegramMedia[], mutually exclusive with media and poll. Published album returns mediaIds in input order, and externalId containing every chat/message identity (chatId followed by colon and comma-separated message IDs); the public externalUrl points to the first message when a public username is confirmed. Album acknowledgements must match requested count, chat, unique message IDs, common nonblank media_group_id and each media kind/file identity. Partial or malformed acknowledgement stays ambiguous and never triggers an internal retry. Existing mediaId semantics are preserved for single media. Parent persists each media file identity through the existing per-execution-media delivery ledger; the publication receipt retains all message IDs without a schema migration.
