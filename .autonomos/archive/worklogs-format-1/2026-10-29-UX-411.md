# UX-411 — Keep selected media in publication creation

Status: complete
Related: UX-410 upload recovery; SPEC-010 JRN-01; DESIGN.md recovery and failure feedback

## Reproduced behaviour

Holding a real raw upload left Create draft enabled. The baseline failed on the enabled button. Creation used the ready source attachments only, so the still-selected pending file was absent from that payload.

A second browser fixture retained two recovery records but removed one stored blob. Resuming the available file removed the missing-file placeholder as well and re-enabled creation. That baseline also failed on the enabled Create draft control after only one file resumed. No lost-byte placeholder needed an explicit choice.

A queued-submit race was also reproduced: Create waited for a held autosave, a newly chosen image finished during the wait, and the eventual successful POST still carried an empty media array. The handler had captured the earlier creation callback.

## Changes

- The picker reports unsettled preparation to the composer. This includes every retained upload entry, failed/recovered/missing files, and active URL imports or edited-image saves. The hold includes completed upload entries until their verified assets have been attached and their queue entries removed.
- Create draft and Schedule remain disabled while preparation is unsettled. A localized status explains the next action and is associated with both controls. Picker actions and text editing remain available.
- Submission uses the latest creation callback after waiting for autosave, so an attachment that finished during the wait is included. The submit handler also checks the live preparation flag before and after draining queued autosaves. A direct form submission cannot bypass the disabled controls, and a new file selected while a save drains cannot be silently omitted.
- Mixed recovery resumes available blobs without dropping missing ones. Cancelling file reselection preserves the missing choices. An actual selection resolves only matching name/size placeholders and starts its selected bytes normally; Dismiss remains an explicit alternative. This preserves the existing ownership distinction between a new selection and an automatic retry of a known reservation.
- Shared browser upload fixtures now supply the pixel file and storage-read helper to both media suites. The affected selector covers the shared fixture and pending-media journey; its exact authoring count is updated. Web guidance records preparation and missing-file resolution lifetimes.

The backend, delivery scheduling, media ownership, upload protocol and session configuration are unchanged. An action rejected while media is pending requires a new creation action after resolution. An action already waiting for autosave uses the latest fully prepared composition when that wait ends.

## Validation

- Initial pending-media baseline: Create draft remained enabled during the held PUT.
- First fixed pass: one chosen image finishes attachment, then the creation request contains it.
- Grouped browser pass: 19/19, including six new creation cases, six upload-recovery cases, four narrow composer/navigation cases and the three existing publication/library media journeys.
- Missing-byte baseline: resuming the available file incorrectly released creation. The corrected case then passed; it was expanded to cover both explicit dismissal and actual reselection.
- Media-boundary pass: 14/14 (eight creation cases and six upload recovery cases). The queued-submit baseline then reproduced a successful POST with an empty media array despite a finished attachment. After using the current creation callback, the final nine creation cases pass 9/9. Across all passes, 22 distinct journeys were exercised. The seven unchanged adjacent journeys were not repeated after the missing-file refinement.
- English/dark and French/light cases cover held raw transport and held finalization, both disabled creation modes, live explanations, a direct SubmitEvent bypass attempt with no POST, and the one eventual POST. A fresh GET verifies persisted source media against the submitted attachment IDs. Mobile Axe and horizontal-overflow checks pass in both locales.
- Web unit tests: 299 pass. Script tests: 117 pass. The final quick gate passes all 21 tasks and the final production web build passes. French/light mobile explanation was visually inspected; the API and development web return HTTP 200 on ports 3002 and 5173. The spelling gate required a file-local allowance for Playwright's literal file-selection event name. The installed React input helper declares an event intersection that neither a React event nor its native event satisfies. The wrapper uses the public typed Uppy addFiles operation with the selected File objects, preserving the existing input reset.

## Limits and next scope

The hold covers preparation known to the mounted picker. Browser storage recovery retains the best-effort and missing-byte limits recorded in UX-410; this pass does not provide remote access to files whose browser data is unavailable. No full default matrix, live provider, real-device or screen-reader acceptance is claimed. Browser writes use the isolated Playwright API, database and media roots.

Recommended next task: verify the sign-in recovery path when a media upload receives a session refusal while creation is held, preserving the queued file through reconnection.
