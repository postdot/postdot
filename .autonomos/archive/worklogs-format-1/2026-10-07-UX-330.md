- Base: `4b47f2d09`.
- Status: complete; full gate passed on the final executable state.

## Operator outcome

A malformed or semantically invalid profile draft now shows the affected definition
field and a localized correction beside the JSON. The dialog preserves edited
text, metadata and the saved revision. Editing clears stale feedback; successful
save removes the error and restores the existing preview workflow. Validation
rejection never activates a profile or changes a publication.

The new browser journey proves missing capabilities return 400 rather than 500,
a missing binding identifies `/capabilities/textFields/0/bindingId`, and arbitrary
submitted sentinel values do not appear in the error. It verifies unchanged active
state and absent draft before a valid save, then unchanged saved draft after a
later refusal. English, French, a 390 px layout and unknown-code fallback are
covered. No generated form, automatic repair, line-navigation tool or new visual
system was introduced.

## Implementation boundaries

- Core structural guards run before nested field access, then the existing semantic
  validators run unchanged. Missing objects/arrays and incorrect primitive types
  become normalized issues. Sparse array entries are visited, not skipped. Guards
  also validate the structure returned by trusted preparation adapters; those
  failures retain module attribution rather than being exposed as operator detail.
- Structural validation does not expand the accepted execution modes, schema policy
  or business limits. Existing semantic checks, compiler collisions, fingerprint
  derivation and version ownership remain in place.
- Custom schema-policy issue pointers are normalized at their production site to
  the complete definition (`/contentSchema/...`). Already rooted compiler and
  binding pointers are not prefixed again.
- `ChannelProfileValidationError` extends the existing DomainInvariantError and
  preserves immutable copies of normalized issues. Its existing internal joined
  message remains compatible for other call sites. The store still rejects inside
  its transaction; it does not save a partial invalid definition.
- Only the profile-draft save route projects authoring feedback. It returns a fixed
  summary, known local issue codes and bounded JSON Pointer paths. At most 20 issues
  are returned, paths are limited to 512 characters, and issueCount communicates
  omitted detail. Unsupported/internal/module diagnostics become a fixed general
  code with no path. Raw messages, exception text, provider text and field values
  are not included in this response. Other routes and the global error handler
  remain unchanged.
- Web ApiError preserves optional authoring details. Only the profile dialog's
  400 invalid-content branch renders them, using fixed EN/FR catalog messages.
  Unknown codes use fixed general copy; generic errors, access failures and stale
  revision conflicts keep their existing behavior. One alert holds the summary
  and field list, without nested cards or a duplicate generic failure message.
- The affected-scenario selector maps both new feedback helpers and the new browser
  spec into the existing channels-and-connections domain. No gate, retry, timeout
  or worker configuration was changed.

## Limits and next task

Known local errors receive specific corrections; unrecognized, schema-compiler and
module failures intentionally retain a safe general message. The structural guard
prevents the demonstrated nested-access crashes; this task is not an exhaustive
new semantic audit of every execution tag or capability combination. It does not
migrate old definitions or replace provider-owned validation.

Custom channel creation remains a separate authoring surface with editable full
metadata and its existing error contract. UX-331 should diagnose that surface's
consistency with draft editing: supplied fingerprints, identity/version ownership,
repeat template use and invalid-definition feedback. Do not silently transfer the
accepted draft-save ownership policy to creation without demonstrating the need
and deciding the identity contract.

UX-330 is complete; UX-331 remains proposed for the next owner decision. No operating or global
design rule changes; AGENT.md and DESIGN.md remain unchanged. The specific error
contract belongs in ADR-081; evidence and incidental preflight corrections remain
in this worklog.
