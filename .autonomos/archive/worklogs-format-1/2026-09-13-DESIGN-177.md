# DESIGN-177 — Define the contextual multi-channel draft preview contract

- Status: Done
- Branch: `codex/reui-calendar-spike`
- Owner: orchestrator
- Scope: Authenticated `/dashboard/projects/$projectId/publications/new`
  preview relationship to the active publication target.
- Related issue: ISSUE-100
- Predecessor: DESIGN-175, WEB-176

## Problem

The authoring hierarchy now answers what to write and where it will go, but it
does not show the operator the effective output for the selected channel. The
operator must infer whether a channel override or media selection changed the
result.

## Accepted direction

- Keep one preview associated with the active channel tab in the `Publish to`
  column, after the channel controls. The editor remains the dominant writing
  surface.
- Resolve the displayed body using the same precedence as authoring:
  non-blank channel-specific content first, then shared content.
- Show the source title only where the known profile shape uses one (DEV.to).
  Other profiles show their effective body and selected media without inventing
  a title field that their current publication contract does not use.
- Identify the selected channel with the existing channel avatar and name.
  Custom and manual channels use the same generic body/media treatment.
- Treat the preview as a useful approximation of content hierarchy, not as a
  provider renderer. Provider constraints and compliance feedback remain a
  separate follow-up.
- Use explicit `raised`, `field`, and `inset` surfaces without shadow-only
  boundaries, universal card decoration, or additional explanatory prose.
- Empty drafts show one concise empty state; media-only drafts show the media
  without fake text.

## Out of scope

- Server-side preview APIs or provider-specific rendering engines.
- Rich-text/markdown rendering, character counters, compliance validation, and
  publication scheduling changes.
- Persisting preview preferences or creating another authoring route.

## Verification plan

- Add pure tests for effective shared/override content and DEV.to title
  behavior.
- Add browser assertions for live content, target switching, override
  precedence, media presence, and narrow/no-channel layouts.
- Run localization coverage, focused browser tests, the full repository gate,
  and inspect the authenticated local route.

## Resolution

WEB-178 implements the accepted contract. The preview is contextual to the
active channel tab, content-led, explicit about the known DEV.to title shape,
and deliberately generic for custom/manual channels. Provider-perfect rendering
and compliance feedback remain separate decisions.

## Verification

- The authenticated local route was inspected in light and dark themes.
- The empty preview uses one concise localized state; media-only drafts do not
  invent body copy.
- The full repository gate passes, including localization coverage, unit tests,
  17 Playwright scenarios, and the production build.
