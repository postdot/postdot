# AGENT: apps/web/src/lib

- **Composer recovery:** Preserve the tab-local recovery copy alongside the shared fallback. A known draft generation and revision must guard both autosave and cleanup; a conflict pauses automatic writes until an explicit version choice. Do not erase that known base while the composer reloads across channel setup. Browser recovery keys include the author (`publicationRecoveryKey(projectId, userId)`); unscoped legacy entries are never read, removed or attributed. Draft reads, writes, discards and post creation send `expectedUserId`, and a session-ended or `account_changed` refusal (including one from a media upload) pauses the composer with a reload alert instead of the conflict comparison. An expired-session refusal also pauses creation and autosave, and offers sign-in with the current composer path as its continuation. Pausing must preserve a pending recovery snapshot even when the form itself is still empty.
- **Upload recovery:** Scope browser file recovery and intent checkpoints to the authenticated author and picker scope. A retry reuses its known reservation; cancellation stops client work without deleting already shared project media. Unmounting preserves recovery and must not apply late results to the old picker. Keep persistence installation in effects so discarded React renders do not install orphan listeners. Composer creation waits for queued files (including failed or recovered files) and active imports/edits. Release that hold only after successful attachment or an explicit file removal; keep picker controls available so the operator can resolve it. Resuming available recovered blobs must retain missing-file choices; cancelling reselection does not discard those placeholders. After awaiting autosave, submit the current composition rather than the callback snapshot captured before that wait.
- **Live project access:** Feature mutations use the project action guard; control-stream access signals request verification rather than establishing revocation. Keep technical failure retryable, remove project UI only after confirmed denial, and leave unrelated caches alone. Direct async composer work captures the access epoch and checks it before starting another write, applying an acknowledgement or clearing author-scoped recovery. A response to a creation accepted before access loss must not erase that local copy afterward. Preserve the existing editor reconciliation boundary.
- **Unknown promotion outcome:** Defer incoming editor snapshots while promotion reconciliation is required. Only the explicit server-status read resolves that uncertainty; a background refresh must not replace local schedule/content or manufacture a local-edit conflict before that choice.

- **Delivery analytics:** Eden converts ISO civil-date strings to `Date` by default; reads keyed by civil dates must retain JSON strings (`parseDate: false`). Keep report invalidation within project feature keys. Historical delivery outcomes can overlap after a retry or review; they are not current queue inventory. Delivery filters and engagement tags/CSV have separate scopes.
- **Saved engagement history:** Compare adjacent measured snapshots only when their provider/content identity, revision, metric, unit, aggregation and reporting window match. Missing observations break chart segments rather than becoming zero; preserve negative changes. Timestamp and freshness metadata describe the saved observation. Keep history reads lazy, paginated and free of provider collection effects; native collection remains explicit.
