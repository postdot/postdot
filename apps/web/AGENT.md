# AGENT: apps/web

- **Stack:** React 19, Vite, TanStack Router, Tailwind CSS, shadcn/ui `base-nova`, Base UI, Host Grotesk, Solar Icons React v2 Linear, TypeScript
- **Conventions:** Use TanStack Router file-based routes under `src/routes/`; the Vite plugin owns `src/routeTree.gen.ts`.
- **Conventions:** Add shared shadcn components through `packages/ui/components.json`; use Base UI's `render` prop rather than Radix's `asChild`; import icons from `@solar-icons/react/linear/<icon>`.
- **UI boundary:** Use shared primitives from `@postdot/ui` and keep page composition and product-specific components in this app. `src/styles.css` is the app's Tailwind entrypoint and source-registration layer; shared tokens and base styles live in `@postdot/ui`.
- **Development integration:** Browser requests remain same-origin; Vite proxies `/api` and `/oauth` to `POSTDOT_API_ORIGIN`, defaulting to `http://localhost:3000`. Keep alternate local API ports in the ignored `apps/web/.env` file. When using a temporary HTTPS tunnel, set `POSTDOT_VITE_ALLOWED_HOST` to that tunnel's hostname instead of disabling Vite host checks globally.
- **Motion:** Follow [ADR-024](../../.autonomos/decisions/ADR-024-adopt-a-native-first-motion-policy.md); prefer targeted native CSS transitions, never use `transition-all`, and keep state understandable with reduced motion enabled.
- **Constraints:** Keep this app client-first and browser-focused. Do not introduce a second server architecture, use Radix UI primitives, or use React hooks inside TanStack Router loaders or guards.
- **Browser gate stability:** Freeze files under this app during isolated Vite browser tests. Unit pretest, typecheck and build scripts regenerate Paraglide output, so run them before or after browser validation. Keep Docker container start/stop outside browser runs to avoid host network-change interruptions. Even an AGENT.md update can reload the active page and legitimately reopen draft recovery, invalidating an in-progress authoring scenario.
- **Browser-test translation graph:** For `NODE_ENV=test`, Vite optimizes the generated messages entry, runtime and catalog store together. Keep their import identities shared to preserve locale state, and rebuild that cache at startup because generated catalogs can change without a lockfile change. This keeps development routes available without fetching thousands of message modules per reload; ordinary development retains translation hot reload.
- **Vite runtime:** Launch development and production web builds explicitly with `bun run --bun vite --configLoader native`. The bundled configuration loader in Vite 8.3.1 currently fails under Bun 1.4.2; native loading uses Bun's TypeScript support and preserves the established plugins. Do not add Node to the production image to work around this.
- **Scoped web guidance:** See [src/routes/AGENT.md](src/routes/AGENT.md) for route/layout width (`SPEC-010`), scope navigation, settings return controls, status presentation, form copy, and Query/Suspense feature data; [src/lib/AGENT.md](src/lib/AGENT.md) for composer recovery, upload recovery, live project access, and promotion reconciliation; and [src/providers/AGENT.md](src/providers/AGENT.md) for destination definitions, preview icons, native authoring, and channel connection readiness.
