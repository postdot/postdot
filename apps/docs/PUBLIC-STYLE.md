# Public-site narrative candidate

Scope: homepage, not-found and route error surfaces. Documentation layout is not
part of this pass. The owner approved agents as the thread from the opening,
followed by drafting, adaptation, planning/results and open-source ownership.
The exact words and visual compositions remain candidates until reviewed.

## Reference method

Prisma (https://www.prisma.io/) names concrete tasks, interfaces and outcomes for
agents. Twenty (https://twenty.com/) pairs its product argument with specific
working scenes rather than relying on adjectives alone. Borrow that method,
not their copy, customer claims, scale or features.

## Voice

Address the person using Postbot. Name what they or their agent can do, then show
what appears in the workspace. Use a short heading and at most two explanatory
sentences per scene. Prefer review, draft, destination, schedule and result over
vague productivity language. Avoid internal launch status, superlatives, fake
customer proof and claims that imply an embedded content-generating AI.

An agent acts through the existing CLI/API. Postbot does not currently ship a MCP
server; do not illustrate a working MCP connection. Draft creation is distinct
from promotion and delivery. Demo data must be visibly labeled as an example.
Open source is a product characteristic, not a license sales pitch.

## Visual grammar

Host Grotesk, accepted neutral surfaces, blue fields, three-pixel corners.
One normal-sized owner symbol in navigation; no giant logo ornaments. The
lowercase split-weight, two-tone wordmark is an experiment, not an adopted mark.
Theme control: one icon, close-corner button, transition on explicit activation.
Lenis on public routes with native touch and nested scrolling; reduced motion
keeps native scrolling. Motion supplements the scenes without hiding content.
Use distinct compositions for each part of the narrative, not identical feature
cards. Do not generate illustration images or replace the owner's logo geometry.

## Owner correction: chapter rhythm

The short alternating-background feature blocks and improvised calendar were
rejected. Keep long product chapters on a continuous surface; change the field
for a substantial narrative turn, not every heading. Prefer real interface
captures and concrete example content over generic miniatures. The same fictional
studio event should connect the hero, source, adaptations and schedule. Keep
panels stable when switching views. Screenshots can open for closer inspection,
with keyboard dismissal and native nested scrolling.

Use the existing tools for agents without implying an embedded AI writer or a
working MCP server. Do not add unsupported comparisons, customer counts, prices
or provider guarantees. No publication or repository visibility change is implied
by an autonomous local design pass.

Fresh visits start in the light theme, following the owner's Prisma/Twenty
references. Saved theme choices are respected; dark remains a manual choice.
The public theme control's initial fallback must match this provider default.
