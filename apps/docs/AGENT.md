# Postdot public site

Keep this workspace statically exportable. It has no production Node server,
authentication, or access to the application database. Search uses the exported
Fumadocs index. Motion is optional presentation and respects reduced motion.

`content/docs/(self-hosting)/(deployment)/installation.mdx` is generated from the canonical
`docs/deployment/self-hosting.md`; edit that guide instead. Run `sync:content`
before developing, typechecking, or building.

The landing page is a design candidate, not an accepted replacement for the
application design system. Do not publish the site or invent release claims.

The owner rejected the SITE-403 landing sections and copy as filler. They are
not approved public messaging. Never use Unicode arrows instead of Solar icons.
Continue visual work without treating the existing sections as editorial direction.

For local review of the actual static output, run `bun run build` then
`bun run preview` in this workspace. The preview binds to 127.0.0.1:5174 and
serves the exported not-found page with a 404 status. It is a development helper,
not a production server or a deployment change.

Section headings use a title and, when useful, one short description. Do not add
eyebrows, kickers or other pre-title labels (owner direction, 2026-10-15).

Capability illustrations should communicate an idea rather than imitate a simplified
product interface. Use actual product screenshots when interface fidelity matters.
Keep advanced configuration subordinate to the main built-in publishing path.

Documentation is organized with native Fumadocs root folders and grouped content
folders. Read `DOCUMENTATION.md` before adding navigation, changing layouts or
integrating OpenAPI. Parenthesized groups preserve existing public URLs; do not
create colliding slugs. Keep authored guidance separate from generated reference.

OpenAPI pages, operation fragments and the downloadable schema are generated by
`sync:content`; do not edit them. The exporter uses an in-memory isolated app,
never the production entry point or live instance. Keep the static reference's
request playground disabled unless its target and execution UX are explicitly
redesigned. See `DOCUMENTATION.md` for generation and validation boundaries.
