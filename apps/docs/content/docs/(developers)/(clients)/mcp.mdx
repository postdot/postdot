---
title: Connect an agent with MCP
description: Let an MCP-compatible assistant read and prepare your Postdot work with a scoped API key.
---

Postdot serves the Model Context Protocol itself, at `/mcp` on your instance. An
agent connects to that URL with an API key. There is nothing to install beside the
agent, so it works against a remote instance. MCP is available from `0.1.0-alpha.5`.

The agent acts as the key's owner, inside the projects and actions you gave the key.
It cannot do anything the same key could not do through the [API](/docs/automation/).

## Connect

Create a key in Studio under **Settings**, then **API keys**. Limit it to the
projects the agent needs, and grant only the actions it should have. A key limited
to `project:read` and `publication:manage` can read and prepare drafts but cannot
schedule or publish. See [authentication](/docs/reference/authentication/) for every
action.

Add the server to your assistant. The endpoint uses HTTP, and the key travels as a
Bearer header:

```bash
claude mcp add --transport http postdot https://postdot.example.com/mcp \
  --header "Authorization: Bearer $POSTDOT_API_KEY"
```

Assistants configured with a JSON file use the same two values:

```json
{
    "mcpServers": {
        "postdot": {
            "url": "https://postdot.example.com/mcp",
            "headers": { "Authorization": "Bearer postdot_pat_…" }
        }
    }
}
```

Keep the key out of shared configuration files. Revoke it in Studio when the agent
no longer needs it; the next call fails immediately.

## What the agent can do

The tool list follows the key. An agent only sees the tools permitted by the
key's capabilities and its owner's live roles; project-scoped keys never see
workspace or instance administration tools.

| Area                   | Examples                                                                                                                    |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| Workspaces             | List, inspect, create, archive/restore/delete workspaces, manage workspace teams and workspace invitations                  |
| Projects and access    | List and create projects, update timezone, archive or restore, manage project members, user/team grants, and invitations    |
| Channels & connections | List channels and connections, attach non-OAuth credentials (`custom-http`, `devto`, `discord`, `telegram`), share, cadence |
| Posts and publications | Create posts and drafts, edit drafts, adopt profile changes, move pending work, cancel, reschedule, approve or reject       |
| Delivery               | Promote drafts, publish or retry, reconcile an ambiguous outcome                                                            |
| Tags and media         | Tags, media library, import from a URL, request deletion, restore                                                           |
| Analytics              | Read stored analytics, refresh provider analytics                                                                           |
| API keys & instance    | List, mint, update, and revoke your API keys; manage instance members, invitations, SMTP email, recovery, and OAuth apps    |

Every tool declares whether it only reads, whether it can destroy data, and whether
it reaches an external service.

### Confirmation and secret handling

Calls that can change what is published, when or where, as well as administrative,
access, API-key, workspace, connection, approval, and instance-settings mutations
require `confirm: true`. Without it Postdot executes nothing and tells the agent
to ask you first. Creating a post with automatic delivery or a scheduled time
counts; creating unscheduled drafts does not.

<Callout title="Minted tokens appear in tool output" type="warn">
    Tools that mint or invite credentials (`create_user_api_key`, `create_access_member`,
    `create_access_invitation`, and `create_workspace_invitation`) return the generated secret or
    invitation token once in the MCP response inside the assistant's conversation context. Grant
    `api_key:manage` and `instance:admin` only to trusted operators and rotate or revoke issued
    credentials if a transcript is shared.
</Callout>

## What is not offered

- Files cannot be sent through MCP. Import media from a public URL, or upload it
  in Studio or with the [CLI](/docs/cli-reference/).
- Interactive third-party OAuth browser connections (such as LinkedIn, Bluesky, X,
  Facebook, Instagram, or Mastodon) stay in Studio. MCP can configure runtime
  OAuth application credentials (`create_provider_application_configuration`) and
  connect non-OAuth credential channels (`custom-http`, `devto`, `discord`,
  `telegram`).
- The audit log (`GET /api/audit`) and session-only browser routes (password
  change, invitation acceptance, and SSE streams) are not exposed on `/mcp`.
- Hosted assistants that only connect through OAuth cannot use this endpoint yet.
  The server accepts API keys only, never a browser session.

## Operate it

The endpoint is on by default. Set `POSTDOT_MCP_ENABLED=false` to turn it off. It
holds no session or state, so any number of instances can serve it behind a proxy.
Browser origins other than your Postdot address are refused. Requests, and
responses beyond 100,000 characters, are bounded.
