The API and CLI work with the same projects and publications as Studio. Choose
the CLI to run commands from a script or an agent, or use HTTP for an integration
that makes its own requests.

## Build an integration

<Cards>
    <Card title="Start with the CLI" href="/docs/automation/#create-a-draft-for-review">
        Create an unscheduled draft with a limited API key, then review it in Studio. Run the
        walkthrough from a source checkout with Bun.
    </Card>
    <Card title="Call the HTTP API" href="/docs/reference/authentication/">
        Choose an authentication method and key permissions, then look up request and response
        contracts in the API reference.
    </Card>
</Cards>

A dedicated MCP server, packaged agent skills, a supported n8n integration and a
mobile client are planned. They are not available yet. An agent that can run shell
commands can already use the CLI walkthrough.

## Work on Postbot

Start with [architecture](/docs/architecture/) for the server and client boundaries.
Use [apps and packages](/docs/packages/) to locate the code responsible for a feature.
The typed HTTP client lives in `packages/client`; the CLI entry point is
`scripts/postbot.ts`.

For running an instance, go to [Self-hosting](/docs/self-hosting/). For preparing
and reviewing publications, use [Guides](/docs/).
