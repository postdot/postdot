Use the CLI, API and integrations with a running Postdot instance.
You need a source checkout only when working on Postdot itself.

## Connect a tool or agent

<Cards>
    <Card title="CLI" href="/docs/automation/#create-a-draft-for-review">
        Install the public CLI and create your first draft with a scoped API key.
    </Card>
    <Card title="MCP" href="/docs/mcp/">
        Connect an MCP-compatible agent to your instance.
    </Card>
    <Card title="n8n" href="/docs/n8n/">
        Create publication drafts from your self-hosted n8n workflows.
    </Card>
    <Card title="HTTP API" href="/docs/reference/authentication/">
        Authenticate requests and choose permissions for your integration.
    </Card>
</Cards>

The [agent skills](https://github.com/postdot/postdot/tree/main/skills) include
instructions for self-hosting, publishing workflows and troubleshooting.
For command details, see the [CLI reference](/docs/cli-reference/).

API keys follow project scope, action permissions and server roles. Connect social
accounts and manage installation access in Studio. See
[authentication](/docs/reference/authentication/) for the supported access methods.

## Contribute to Postdot

Start with [development setup](/docs/contributing/) to run the project locally.
[Architecture](/docs/architecture/) explains the server and client boundaries;
[apps and packages](/docs/packages/) helps you find the code for a feature.

For running an instance, use [Self-hosting](/docs/self-hosting/).
For writing and reviewing publications, use [Guides](/docs/).
