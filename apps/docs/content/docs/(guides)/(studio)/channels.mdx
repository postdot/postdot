---
title: Channel profiles
description: Define destination requirements and review changes without rewriting existing publications.
---

A channel describes what a destination accepts. Its publisher connection is a
separate responsibility: a valid content profile does not establish connection
readiness or delivery success. Manual channels need no publisher.

## Edit represented requirements

Use Channels to create or edit a destination. Built-in providers own their native
constraints. Custom content forms expose supported text, title and attachment
controls, with a local composer preview. The preview sends nothing and does not
change existing publication content.

Read required/optional states, units and limit explanations before saving. An
absent title is different from an empty required title. A count shown without a
known maximum is not a promise of unlimited provider content.

A form represents part of a profile; it is not an arbitrary schema editor.
Preserved/read-only controls and validation explain requirements the current
form cannot safely change. Do not assume a successful save converted or removed
unrepresented rules. Server validation remains authoritative.

## Review, assess and activate

For an existing channel, save a draft and review the changes against the active
profile. Run the impact assessment before activation. Editing the proposal can
invalidate an earlier assessment; reread affected publications and current
validation results. Activation does not silently rewrite immutable execution
targets. Adopting a changed profile in a publication remains an explicit action.

A failed refresh after a successful activation does not prove activation failed.
Inspect the current active version before submitting another change.

## Update built-in requirements

After upgrading Postdot, open the channel's profile editor and choose **Load
shipped template** to compare the installed provider template with your channel.
Loading prepares a draft; save it, review the impact and activate explicitly.
Postdot does not monitor provider changes or replace active profiles automatically.

New work uses the activated profile. Existing draft text and selected target
revisions remain intact. A shorter limit can leave one publication compatible
while putting a longer one into review. Postdot does not truncate either content.

Pending work is checked before a new external operation starts, including work
claimed just before activation. Automatic and manual retries must also satisfy
the active requirements. Compatible retained targets can continue when their
execution contract is unchanged and supported. Incompatible work needs review;
use **Adapt to current profile**, preserve or edit the content, then schedule or
approve it explicitly. Retrying alone does not override a failed assessment.

An operation already sent to a provider can finish under its pinned execution
revision. Its result and historical content remain tied to that revision. If it
fails, a new attempt must satisfy current requirements. Activation neither
rewrites history nor proves that the remote provider will accept a request.

## Adapt a saved draft

Open **Adapt to current profile** from the publication. Review the previous
values beside their reuse actions. A matching binding can move to a new path;
choose **Reuse previous** for each value you want to carry over. Postdot flags
removed fields and changed field types. Enter a changed value in the adapted
content rather than relying on a type conversion.

If you have unsaved destination edits, choose whether to use them as the previous
copy. **Complete previous draft** includes advanced structured content for fields
that the form cannot represent. Cancel leaves saved and local work unchanged.

Validate the adapted content, then choose **Save adapted draft**. Editing the
candidate invalidates its earlier validation. If another edit or profile change
causes a conflict, review the latest draft and profile, then validate again; the
candidate stays available. Saving preserves the replaced draft and creates an
adapted working revision. It does not select a scheduled target, approve or send
a publication.

## Confirm a changed destination

Destination confirmation is available in current source builds. The published
`0.1.0-alpha.2` image does not include this check or its controls.

Reconnecting the same account or refreshing its credentials does not require a
new confirmation. Changing the connected account, selected destination or custom
HTTP endpoint holds existing automatic work until you review the change.

Open the publication and check **Current destination** against the selected
content. Choose **Confirm current destination** to accept it. The content and
requested schedule stay unchanged; already scheduled delivery can resume,
including overdue work. Drafts remain drafts. A failed publication still needs
its separate retry action. Confirmation does not approve a pending proposal or
replace its selected content.

If the destination or selected target changes while you review it, refresh and
confirm the new state. Saving a draft, changing its time or pressing Retry does
not silently accept a different account.

**Destinations recorded at execution** preserves the account or destination
captured for an execution. Old executions without that record show **Destination
not recorded**; Postdot does not infer their destination from today's connection.
No access token or connection secret is copied into this history.

## Custom HTTP destinations

Content rules, request mapping and connection authentication are distinct.
Structured request controls appear for supported mapped contracts. Preserve
locked dynamic/secret fields and examine the active/proposed comparison; the
presence of a form does not mean every expression is represented.

Connection credentials belong to the connection, not to profile JSON. Enter them
through the connection UI and keep them out of logs/examples. A local preview or
schema validation makes no test request and does not prove that an external
endpoint accepts the mapping. An actual delivery has external effects and needs
the same intentional scheduling and outcome review as another automatic channel.
