---
title: Provider connections
description: Connect destinations without mixing them with your Postbot login.
---

Postbot supports connected channels for Bluesky, Discord, LinkedIn, Mastodon, X and
DEV.to, alongside manual and custom HTTP destinations. Content and media support
vary by provider and profile.

Connect an account from its channel. Some providers require an application, scopes
or account eligibility; others use a token. Postbot account login is separate from
these publisher connections.

OAuth providers need callback configuration that matches their authorization flow.
Bluesky supports two deployment modes:

- **Local loopback:** the browser and API run on the same machine. Use the same
  loopback host consistently and leave the client metadata URL empty. No public
  metadata document or tunnel is required.
- **Public HTTPS:** remote browser access uses a stable HTTPS client metadata URL
  and a reachable callback that matches the deployed origin.

Other providers have their own application and callback requirements. A local
Bluesky connection does not imply that every provider supports the same setup.

Keep tokens on the server. Do not place provider credentials in shared post content
or commit them to the repository. A successful connection confirms authorization,
not unrestricted access to every provider feature.

The deployment-specific provider requirements remain documented in the source
checkout at `docs/deployment/provider-requirements.md`. Full provider setup guides
will be added before the public launch.
