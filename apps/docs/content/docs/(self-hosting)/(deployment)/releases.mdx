## 0.1.0-alpha.4

- Image: `ghcr.io/postdot/postdot:0.1.0-alpha.4`
- Manifest digest: `sha256:c345e86ab7995417b2a789e083fe262044c6132d5bb87edadd80337994e49ba3`
- Platforms: Linux AMD64 and ARM64.
- [Matching source](https://github.com/postdot/postdot/tree/ae117c125b5645ce7b49d147c24042bb690ea9a5).
- [Publication and native acceptance](https://github.com/postdot/postdot/actions/runs/40659873803).
- [Source integration CI](https://github.com/postdot/postdot/actions/runs/40656698593).

### Changes

- Postdot is the only product name: deployment variables use `POSTDOT_`, the default
  database is `postdot.sqlite`, the Compose service and volume are `postdot` and
  `postdot-data`, metrics start with `postdot_`, and Custom HTTP webhooks send
  `x-postdot-*` headers.
- Product screenshots on the site show the Postdot name.

### Upgrade from 0.1.0-alpha.3

Existing installations keep working: `POSTBOT_*` variables and `postbot.sqlite` are
still accepted (deprecated, with a warning), API keys and saved webhook profiles
continue to work, and migration 0026 updates stored identities. Native checks on both
platforms upgraded an alpha.3 data set that used the old names, then restored the
pre-update backup with the previous executable. Follow
[Move from the Postbot names](/docs/installation/#move-from-the-postbot-names), and
back up the database and media first.

## 0.1.0-alpha.3

- Image: `ghcr.io/postdot/postdot:0.1.0-alpha.3`
- Manifest digest: `sha256:9b309cf147d6490e20758914c5e3dc6d824589a2ac9e4c5903c1cc549bb35974`
- Platforms: Linux AMD64 and ARM64.
- [Matching source](https://github.com/postdot/postdot/tree/cf7d7e9465add97c7ac4e3bc57a7e141dd2c2977).
- [Publication and native acceptance](https://github.com/postdot/postdot/actions/runs/40586044797).
- [Source integration CI](https://github.com/postdot/postdot/actions/runs/40578516559).

### Changes

- Channels, profiles, connections and credentials belong to a workspace. Projects use
  them through explicit attachments, with a single managing project that can be
  transferred. See [sharing a channel](/docs/shared-channels/).
- See other projects' use of a shared channel on the calendar, anonymously when you
  cannot read them.
- Set optional daily, weekly and minimum-interval cadence limits, confirm a changed
  destination, and move pending publications between channels.
- Manage sharing from Studio, the API (`channel:share` key capability) and the CLI.
- Retire projects and workspaces, including their derived media, safely.
- Provision the first administrator offline and read the release identity from the
  CLI and API.

### Upgrade from 0.1.0-alpha.2

Migration 0023 assigns every project to a workspace and converts project-owned
channels to workspace ownership. Native checks on both platforms upgraded an
alpha.2 data set with a live connection and queued work, verified rollback of stale
writes, and restored the pre-update backup with the previous executable. Back up the
database and media first; image rollback alone does not reverse the migration.

## 0.1.0-alpha.2

- Image: `ghcr.io/postdot/postdot:0.1.0-alpha.2`
- Manifest digest: `sha256:eceecc8898aa1d1b27c4e5b91fe53b8d78afebf74be410bd4b8f7d4751d5ee9e`
- Platforms: Linux AMD64 and ARM64.
- [Matching source](https://github.com/postdot/postdot/tree/e7af5550ffa446f9264ec13159e0ed9e263e1495).
- [Publication and native acceptance](https://github.com/postdot/postdot/actions/runs/40209200573).
- [Source integration CI](https://github.com/postdot/postdot/actions/runs/40207971158).

### Changes

- Choose a destination explicitly when creating a channel. Manual channels explain
  human delivery and offer ready-to-use defaults with optional content configuration.
- Inspect missing provider setup from its status and open the configuration path
  appropriate to your installation permissions.
- Understand the first account's administrator role before creating it.
- Read maintenance command help without loading configuration or opening storage.
- Use consistent language detection in development and production builds.
- Download release-matched installation files and configure S3 from a complete example.

### Upgrade from 0.1.0-alpha.1

Native checks on both platforms upgraded a previous-release data set and verified
sign-in, project/channel identities, draft state and byte-identical local media. They
also restored the pre-update backup with the previous executable, verified the
original data and confirmed recovery hold blocks writes. No new database migration
is included in this release.

Follow the [update procedure](/docs/installation/#update-and-rollback), back up
database/media and retain deployment secrets separately. Restore with the matching
previous image if needed; changing the image alone does not reverse migrations or
remote publication effects. Anonymous image retrieval is verified. Version tags
remain immutable, with no `latest` alias.

## 0.1.0-alpha.1

This first public alpha provides Studio, the HTTP API and a source-checkout CLI.
It supports project-owned channels, media, drafts, scheduling, review and durable
publication tracking. Provider-native formats, analytics and conversations have
[different coverage](/docs/providers/provider-capabilities/). MCP and mobile clients are not
shipped. Configuration, contracts and migrations may change.

- Image: `ghcr.io/postdot/postdot:0.1.0-alpha.1`
- Manifest digest: `sha256:690778f5d1af8f4a363406b989e17da8672fc764c6e62f9cca8e1a09c483638e`
- Platforms: Linux AMD64 and ARM64.
- [Matching source](https://github.com/postdot/postdot/tree/99badfb431b95a817c645e716267815925c1f6cc).
- [Publication and native acceptance](https://github.com/postdot/postdot/actions/runs/40126611747).
- [Source integration CI](https://github.com/postdot/postdot/actions/runs/40110416940).

Anonymous manifest retrieval verified the same digest and both platform entries.
No `latest` alias exists. Version tags are immutable; pin the digest when exact
content matters. Use the [installation guide](/docs/installation/) for Compose.

There is no earlier public image, so no previous-release upgrade has been
validated. Back up database/media and preserve deployment secrets separately
before replacing an installation. Image rollback alone cannot reverse migrations.

The image includes the project license, retained third-party notices, exact
FFmpeg decoder source/build settings and base package inventory under
`/app/licenses`. See the repository's
[distribution notices](https://github.com/postdot/postdot/tree/main/licenses).
This is not a claim of exhaustive transitive-license certification.
