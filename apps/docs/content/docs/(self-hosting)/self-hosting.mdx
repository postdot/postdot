title: Self-hosting
description: Install Postdot, choose your storage and manage your instance.
---

Run Studio, the API, scheduler and publication worker from one Docker image.
Use SQLite and local media for a self-contained installation, or connect PostgreSQL
and S3-compatible storage. You can [transfer an existing installation](/docs/transfer/)
between these backends.

## Install Postdot

Start with the [Docker Compose guide](/docs/installation/). It covers the published
image, secrets, persistent storage and your first account. A source build is also
available. Postdot is in alpha; check the [release notes](/docs/releases/) for changes
and upgrade instructions.

Before connecting accounts, check the [platform setup requirements](/docs/providers/setup-effort/).
Some platforms require a developer application or paid API access.

## Choose your setup

<Cards>
    <Card title="SQLite and local media" href="/docs/installation/#first-installation">
        Keep the database and media in a persistent volume, with no separate database or queue
        service.
    </Card>
    <Card title="PostgreSQL and S3" href="/docs/postgresql/">
        Use your existing database and object storage, or run coordinated Postdot instances.
    </Card>
    <Card title="HTTPS and reverse proxy" href="/docs/reverse-proxy/">
        Configure a public origin, streaming and upload limits with Caddy, Nginx or Traefik.
    </Card>
</Cards>

For orchestrated deployments, see [Kubernetes](/docs/kubernetes/) and
[Docker Swarm](/docs/docker-swarm/), including their storage and replica requirements.

## Maintain your instance

Preserve the database, media and deployment secrets. Keep backups outside the
machine running Postdot. Use the backup procedure for your storage setup:
[SQLite](/docs/installation/#backup-and-restoration) or [PostgreSQL](/docs/postgresql/).

- [Operations](/docs/operations/): routine maintenance and recovery.
- [Storage transfer](/docs/transfer/): move the database and media between backends.
- [Release notes](/docs/releases/): changes and upgrade evidence.

Once Studio is running, follow [your first publication](/docs/first-publication/).
