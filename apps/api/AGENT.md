# AGENT: apps/api

- **Stack:** Bun, Elysia 2 beta, Better Auth, Drizzle ORM, TypeScript
- **Conventions:** Keep transport concerns in feature modules under `src/modules`; delegate business operations to `packages/core` and persistence to `@postbot/db`.
- **Composition:** `src/app.ts` is a composition root. Authentication, error handling, health, and feature routes are separate plugins/modules. Preserve Elysia's chained inference when adding routes.
- **Contracts:** Use native Elysia `typebox` schemas for route contracts. The current Drizzle release requires a small `drizzle-typebox` compatibility bridge in the project models until Drizzle's native TypeBox integration is available.
- **Tooling:** Keep OpenAPI enabled at `/openapi` and `/openapi/json`. `@postbot/client` consumes the typed Elysia application with Eden Treaty for domain routes.
- **Runtime:** Elysia JIT is the default execution mode. Keep Better Auth's base URL, secret, and trusted web origin explicit through validated environment configuration. Realtime shutdown must close both project and notification SSE streams and release their waiters before graceful server stop; waking a stopped hub without ending its streams can strand the drain. Graceful shutdown must await the worker, optional video-poster decoder, and media-maintenance drain before closing SQLite or releasing the runtime quiescence lock, then exit explicitly: the dashboard static-asset cache owns a TTL sweep interval that is never cleared, so natural event-loop exit cannot be relied on after serving static files. Exit 0 marks an orderly shutdown, 1 a drain failure, and 2 an incomplete final cleanup; shutdown diagnostics use the redacted `{step, name, message}` shape from `src/shutdown.ts`. The shutdown path itself lives in `createShutdownHandler` so exit codes and drain-before-cleanup ordering stay covered by behavioral tests; keep that orchestration thin and side-effect free apart from the injected dependencies.
- **Configuration:** Declare API environment variables in `src/config.ts` through the TypeBox-backed helpers in `src/environment.ts`, and consume the resulting `PostbotConfig` object instead of reading environment variables throughout the application. Installation SMTP is mutable through the email-settings service, shared by authentication and publication alerts. Deployment SMTP is only the initial fallback; a saved database configuration, including explicit disablement, takes precedence. Keep its encrypted persistence and current human instance-admin routes separate from recipient-owned alert preferences.
- **Logging:** Keep request logging in `src/plugins/logger.ts` and use Elysia 2 lifecycle names. Production defaults to the `error` threshold: unexpected server failures are logged, while successful-request records stay below the threshold. Do not log raw exception messages or request secrets. Do not add an Elysia 1 logger plugin without proving compatibility with the current Elysia version.
- **Production serving:** The production entrypoint serves the built SPA through the Elysia 2-compatible `@elysia/static` plugin and keeps migration and asset directories configurable for compiled or containerized deployments. Development continues to use the separate Vite server.
- **Auth integration upgrades:** Keep Better Auth mounting in `src/plugins/auth.ts` through Elysia's `.mount(auth.handler)` and preserve the chained application composition in `src/app.ts`. After a Better Auth or Elysia upgrade, run the API typecheck and tests, including the mounted sign-up/session-cookie contract. Also verify the authenticated macro still supports both session and API-key requests and that dynamic Better Auth routes remain outside the Eden domain-client contract. Do not replace either framework without a reproduced compatibility failure.
- **Authorization boundary:** Session and API-key requests must resolve project access through the single shared `authorizeProjectAccess` callback in `src/plugins/auth.ts`; machine access inherits the key owner's live project access, is further narrowed by the stored scope, and stays bounded by the action ceilings. Never reintroduce a key-only project check, and keep the hidden 404 masking identical for both methods.
- **Recovery:** Keep SQLite backup, restore, and offline account-recovery logic in `@postbot/db`; expose maintenance commands through the production bundle, and require the server to be stopped before any account recovery or restoration.
- **Media transport:** Keep upload and download routes under `src/modules/media`; finalization remains server-authoritative, and raw media downloads use a native `Response` with explicit OpenAPI documentation rather than response JSON validation.
