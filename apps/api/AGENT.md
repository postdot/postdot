# AGENT: apps/api

- **Stack:** Bun, Elysia 2 beta, Better Auth, TypeScript
- **Conventions:** Keep transport concerns in feature modules under `src/modules`; delegate business operations to `packages/core` and persistence to `@postdot/db`.
- **Composition:** `src/app.ts` is a composition root. Authentication, error handling, health, and feature routes are separate plugins/modules. Preserve Elysia's chained inference when adding routes.
- **Contracts:** Use native Elysia `typebox` schemas for route contracts. Persisted-row schemas live in `src/modules/projects/persistence-schemas.ts` and must follow `packages/db/migrations`.
- **Tooling:** Keep OpenAPI enabled at `/openapi` and `/openapi/json`. `@postdot/client` consumes the typed Elysia application with Eden Treaty for domain routes.
- **Topology:** Background runtimes (worker, media maintenance, previews, notification projection, email) start only on the elected leader; every server serves HTTP and a follower is ready when its database answers. Wakeups (`projects`, `work`, `media`, `email-settings`, `draft`) are published through the coordination, never called directly, so they reach every server. A lost topology lock drains and exits 1 for a supervisor restart.
- **Configuration:** Declare API environment variables in `src/config.ts` through the TypeBox-backed helpers in `src/environment.ts`, and consume the resulting `PostdotConfig` object instead of reading environment variables throughout the application. Installation SMTP is mutable through the email-settings service, shared by authentication and publication alerts. Deployment SMTP is only the initial fallback; a saved database configuration, including explicit disablement, takes precedence. Keep its encrypted persistence and current human instance-admin routes separate from recipient-owned alert preferences.
- **Database selection:** `POSTDOT_DATABASE_URL` selects PostgreSQL and takes precedence over `DB_FILE_NAME`, which the image and `compose.yaml` always set for SQLite; do not reintroduce a refusal when both are present. Transfer commands (`export`, `import`, `media transfer`) live in `src/transfer.ts` and read their media source from `SOURCE_POSTDOT_MEDIA_*` variables.
- **Production serving:** The production entrypoint serves the built SPA through the Elysia 2-compatible `@elysia/static` plugin and keeps migration and asset directories configurable for compiled or containerized deployments. Development continues to use the separate Vite server. The production image carries the bundle, the migrations and the dashboard assets only, never `node_modules`: a runtime dependency that escapes the bundle breaks every route in the image while a checkout keeps working. Elysia's TypeBox namespaces are wired statically with `setupTypebox` for that reason; keep that wiring, and check the built bundle for external requires whenever a new runtime dependency is added.
- **Recovery:** Keep SQLite backup, restore, and offline account-recovery logic in `@postdot/db`; expose maintenance commands through the production bundle, and require the server to be stopped before any account recovery or restoration.
- **Scoped API guidance:** See [src/plugins/AGENT.md](src/plugins/AGENT.md) for request logging, Better Auth mounting, and `authorizeProjectAccess`; [src/modules/AGENT.md](src/modules/AGENT.md) for runtime/shutdown drain, channel management, media transport, project effect admission, and workflow conflict recovery; and [src/providers/AGENT.md](src/providers/AGENT.md) for destination provider ownership.
