# AGENT: apps/api/src/plugins

- **Logging:** Keep request logging in `src/plugins/logger.ts` and use Elysia 2 lifecycle names. Production defaults to the `error` threshold: unexpected server failures are logged, while successful-request records stay below the threshold. Do not log raw exception messages or request secrets. Do not add an Elysia 1 logger plugin without proving compatibility with the current Elysia version.
- **Auth integration upgrades:** Keep Better Auth mounting in `src/plugins/auth.ts` through Elysia's `.mount(auth.handler)` and preserve the chained application composition in `src/app.ts`. After a Better Auth or Elysia upgrade, run the API typecheck and tests, including the mounted sign-up/session-cookie contract. Also verify the authenticated macro still supports both session and API-key requests and that dynamic Better Auth routes remain outside the Eden domain-client contract. Do not replace either framework without a reproduced compatibility failure.
- **Authorization boundary:** Session and API-key requests must resolve project access through the single shared `authorizeProjectAccess` callback in `src/plugins/auth.ts`; machine access inherits the key owner's live project access, is further narrowed by the stored scope, and stays bounded by the action ceilings. Never reintroduce a key-only project check, and keep the hidden 404 masking identical for both methods.
