# AGENT: apps/api/src/modules

- **Runtime:** Elysia JIT is the default execution mode. Keep Better Auth's base URL, secret, and trusted web origin explicit through validated environment configuration. Realtime shutdown must close both project and notification SSE streams and release their waiters before graceful server stop; waking a stopped hub without ending its streams can strand the drain. Handle the process signals before the runtime marker exists, so a termination during startup runs the same drain instead of the platform default disposition, which leaves the marker behind and blocks the next start: in a container the API can be PID 1, where the kernel ignores a signal that has no installed handler, so the stop would be ignored entirely and the marker would survive the forced kill. Assign each drain step as its resource is created, so a step for a resource that does not exist yet stays a no-op. Graceful shutdown must await the worker, optional video-poster decoder, and media-maintenance drain before closing SQLite or releasing the runtime quiescence lock, then exit explicitly: the dashboard static-asset cache owns a TTL sweep interval that is never cleared, so natural event-loop exit cannot be relied on after serving static files. Exit 0 marks an orderly shutdown, 1 a drain failure, and 2 an incomplete final cleanup; shutdown diagnostics use the redacted `{step, name, message}` shape from `src/shutdown.ts`. The shutdown path itself lives in `createShutdownHandler` so exit codes and drain-before-cleanup ordering stay covered by behavioral tests; keep that orchestration thin and side-effect free apart from the injected dependencies.
- **Channel management:** Authenticated project requests carry method, authentication method and API-key scope into the shared authorization callback. Channel mutations and provider connection flows require the live managing-project/workspace policy as well as ordinary project access; an editor role on another attachment is insufficient. Keep project-channel `canManage` metadata aligned with that decision. OAuth completion uses the same live management port, including checks after asynchronous provider/application work before final connection persistence. Workspace channel routes use an authenticated workspace attribution context and filter every channel/project usage through the same policy; workspace administration grants no project-content access.
- **Media transport:** Keep upload and download routes under `src/modules/media`; finalization remains server-authoritative, and raw media downloads use a native `Response` with explicit OpenAPI documentation rather than response JSON validation.
- **Project effect admission:** Publications, replies and first comments share two internal slots, at most one per project ([ADR-090](../../../../.autonomos/decisions/ADR-090-bounded-project-effects-and-renewal.md)). Keep new project/work discovery active while another effect waits. Provider fetch wrappers must combine request and effect cancellation and preserve outbound network controls; credential/media mutations must check active ownership.
- **Workflow conflict recovery:** Exhausted PostgreSQL serialization/deadlock conflicts enter scheduler recovery with a 1–30 second backoff. Drain the active batch first, suppress hints during the wait, and reread durable jobs and leases; never replay a provider call directly. Other errors remain terminal. Stop cancels recovery and drains active work.
