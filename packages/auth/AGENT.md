# AGENT: packages/auth

- **Stack:** Better Auth on Postdot's persistence port, Elysia integration at the API boundary
- **Conventions:** Export factories that receive their database dependency. Keep Better Auth configuration here and keep HTTP mounting in `apps/api`.
- **Constraints:** Use `postdotSqlAdapter` (`src/sql-adapter.ts`) on `database.sql`; it must stay engine-neutral. Better Auth authenticates people into Postdot through email/password; do not add social providers or store publisher-channel credentials here. Keep secrets and deployment URLs in environment variables; never commit credentials or generated local database files.
- **Persistence isolation:** Every Better Auth adapter operation and transaction is a port transaction (SQLite writer gate, PostgreSQL serializable retries). Hooks call async stores inside that context. Never give Better Auth a raw connection: it would bypass that isolation.
- **Password hashing:** Expose the Better Auth password-hash operation through this package for trusted offline maintenance callers; do not duplicate the hash algorithm or import auth internals from other packages.
- **Origin-check acceptance:** Better Auth skips origin validation by default in its test environment. Verify origin refusals through production HTTPS acceptance; a passing in-process session test does not qualify that browser boundary. Preserve the production origin/CSRF policy.
- **Dependency upgrades:** Upgrade `better-auth` and `@better-auth/api-key` together. Keep the explicit `PostdotAuth` API additions and the `as unknown as PostdotAuth` conversion inside `createAuth`; do not widen this boundary with `any`. After an upgrade, run this package's typecheck and tests, then the API typecheck and tests. Confirm the Better Auth endpoints used by Postdot's plugin APIs still behave as expected before changing the local contract.
