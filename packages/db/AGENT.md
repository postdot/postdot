# AGENT: packages/db

- **Stack:** Drizzle ORM, Bun SQLite, Drizzle Kit
- **Conventions:** Keep database connection and schema definitions in this package. Expose explicit database factories instead of reading process state during module import.
- **Constraints:** Use Bun's native `bun:sqlite` driver for the local SQLite runtime. Keep application schema changes migration-driven once the first domain tables are introduced.
- **Migration safety:** Keep migration application fail-closed. Do not add idempotent SQL or automatic database resets merely to hide a schema/history mismatch; unreleased local databases may be archived and recreated explicitly, while databases with data must be investigated and preserved.
- **SQLite policy:** Main file connections require WAL, FULL durability and a 5-second busy timeout (ADR-089). Strictly close prepared statements before releasing the runtime lock. Restore must retire the old WAL through SQLite before pathname replacement; never unlink sidecars to bypass contention.
- **Runtime quiescence:** The server/restore/recovery lock is fail-closed and never reclaimed automatically. `release()` reports whether the marker is gone, memoized across repeated calls without retrying removal or closing twice; callers must surface a retained marker instead of inferring success from the absence of an exception.
- **Event journal:** `audit_events` is Postdot's single append-only, versioned fact journal. Preserve its non-reusable monotonic sequence and transactional relationship with state changes. Current-state tables remain authoritative, and every notification, delivery, or analytics consumer must own separate cursor, projection, deduplication, and retry state.
- **Notification projection:** Keep recipient-owned inbox state separate from the fact journal. Project only explicitly supported event names and versions, resolve current project human actors independently from event attribution, advance each projection cursor atomically with deduplicated writes, and keep complete history reachable through stable keyset pagination.
- **External notification delivery:** Keep destinations, per-kind subscriptions, projection cursors, immutable delivery snapshots, leases, and ambiguity state separate from the in-app inbox. External projection and cursor advancement must be atomic and replay-safe; only the executor may cross the durable effect boundary.
- **External notification secrets:** Keep provider credentials in versioned encrypted destination-secret rows, separate from public configuration and delivery history. Capture the secret version at projection time and resolve it only for a claimed delivery; never log, return, or snapshot plaintext material.
- **Publisher secrets:** Keep publisher credential encryption behind an explicit internal boundary. Metadata APIs must never expose token material, and persisted publisher credentials must never reference Better Auth users or accounts. Mechanical renewal uses `withPublisherCredentialRefresh`: reload inside the credential queue, use its live clock and persist through its revision-fenced context. Separate store facades share the SQLite connection queue; unrelated credentials remain independent.
- **Media lifecycle:** Keep project-owned asset, representation, upload-intent, inspection, retention, and reconciliation state in this package. Use `@postdot/media` only through its storage contract, and keep opaque object keys out of public API responses. Persist a provider-reported remote-media expiry alongside a delivery checkpoint when one is available; consumers must still apply their own conservative reuse bound.
- **Media previews:** Internal thumbnails are versioned derived representations, not library assets or publication defaults. Preserve original bytes; track storage ownership before writes and finish preview writes before physical asset deletion. Video posters are optional background work: decoding failure must preserve a ready original, and shutdown cancellation must remain eligible for startup recovery.
- **Media recovery:** Treat SQLite-only backup as a low-level primitive. Complete media recovery must use the manifest-and-bytes bundle, verify every checksum, and fence physical media deletion while the bundle is being copied.
- **Account recovery:** Offline password recovery must acquire the database runtime lock, validate and protect a pre-change backup, update only the selected Better Auth credential, revoke that user's sessions and reset links, and preserve project data, API keys, publisher credentials, and historical actors.

- **Personal avatars:** Keep person-owned image lifecycle in `user_avatars`, separate from project media assets. Use the shared storage port and complete-backup deletion fence; complete recovery includes avatar bytes as well as project representations.
