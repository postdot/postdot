# AGENT: packages/db

- **Stack:** Postdot persistence port (`src/sql`), Bun SQLite, Bun.SQL for PostgreSQL, portable SQL migrations (`migrations/`)
- **Conventions:** Keep database connections and migrations in this package; the schema is the SQL in `migrations/`, identical on both engines (`schema-parity.test.ts`). Expose explicit database factories instead of reading process state during module import.
- **Constraints:** Use Bun's native `bun:sqlite` driver for the local SQLite runtime. Keep application schema changes migration-driven once the first domain tables are introduced.
- **Asynchronous persistence:** Runtime stores use `database.sql` and await every statement. Multi-query reads need one deferred snapshot; mutations keep their validation and writes in an explicit transaction. `defineTransaction` joins the ambient async context through savepoints. Never bypass the SQLite gate through `$client` at runtime. Native connection access is reserved for quiesced startup, maintenance and fixture setup. Keep external I/O outside transactions, including credential-refresh callbacks and media transfers.
- **Migrations are expand/contract:** a release only adds (tables, nullable or defaulted columns, indexes) so the previous release keeps running during a rolling update; removal of what it still uses waits for a later release. Never edit an applied migration.
- **Event journal:** `audit_events` is Postdot's single append-only, versioned fact journal. Each fact belongs to exactly one project or workspace and references an actor of that same scope. Preserve its non-reusable monotonic sequence, including the SQLite high-water mark across table rebuilds, and its transactional relationship with state changes. Project consumers must skip workspace facts without losing cursor progress. Current-state tables remain authoritative, and every notification, delivery, or analytics consumer must own separate cursor, projection, deduplication, and retry state.
- **Test fixtures:** New projects require a workspace. Use `@postdot/db/testing` (`seedTestWorkspace`, `seedWorkspaceChannel`, `seedWorkspaceMember`, `workspaceOf`) for current-schema fixtures; historical-schema tests seed project-owned columns by raw SQL on a chain truncated with `migrationsThrough`, then upgrade through the real chain.
- **Scoped persistence guidance:** See [src/transfer/AGENT.md](src/transfer/AGENT.md) for profile transfer (`ADR-097 §8`); [ADR-097](../../.autonomos/decisions/ADR-097-selectable-storage-profiles.md) for migration safety, instance topology, and missed wakeups; [ADR-089](../../.autonomos/decisions/ADR-089-explicit-sqlite-wal-policy.md) for SQLite WAL durability and sidecar retirement; [ADR-068](../../.autonomos/decisions/ADR-068-runtime-quiescence-sidecar-lock.md) for runtime quiescence; [ADR-095](../../.autonomos/decisions/ADR-095-workspace-channels-and-project-attachments.md) for workspace attribution, project/common-resource ownership, shared-channel blockers, authorization boundary, and channel cadence; [ADR-038](../../.autonomos/decisions/ADR-038-project-durable-facts-into-recipient-owned-notifications.md), [ADR-039](../../.autonomos/decisions/ADR-039-fence-external-notification-deliveries-behind-a-durable-outbox.md), and [ADR-040](../../.autonomos/decisions/ADR-040-version-external-notification-secrets.md) for notification projection, outbox delivery, and destination secrets; [ADR-019](../../.autonomos/decisions/ADR-019-separate-media-assets-representations-and-deliveries.md) for media lifecycle, previews, recovery, and personal avatars; [ADR-094](../../.autonomos/decisions/ADR-094-project-and-workspace-lifecycle.md) for resource retirement and account recovery; and [ADR-090](../../.autonomos/decisions/ADR-090-bounded-project-effects-and-renewal.md) for publisher secrets and owner pre-effect release.
