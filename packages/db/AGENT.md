# AGENT: packages/db

- **Stack:** Drizzle ORM, Bun SQLite, Drizzle Kit
- **Conventions:** Keep database connection and schema definitions in this package. Expose explicit database factories instead of reading process state during module import.
- **Constraints:** Use Bun's native `bun:sqlite` driver for the local SQLite runtime. Keep application schema changes migration-driven once the first domain tables are introduced.
- **Migration safety:** Keep migration application fail-closed. Validate foreign keys and domain preservation inside the migration transaction, before committing schema, data and Drizzle history together. Preserve and restore affected triggers when rebuilding referenced tables. Rehearsals use the same runtime quiescence boundary and roll back SQL/history; they do not authorize operating a live database. Do not add idempotent SQL or automatic database resets merely to hide a schema/history mismatch; unreleased local databases may be archived and recreated explicitly, while databases with data must be investigated and preserved.
- **SQLite policy:** Main file connections require WAL, FULL durability and a 5-second busy timeout (ADR-089). Strictly close prepared statements before releasing the runtime lock. Restore must retire the old WAL through SQLite before pathname replacement; never unlink sidecars to bypass contention.
- **Runtime quiescence:** The server/restore/recovery lock is fail-closed and never reclaimed automatically. `release()` reports whether the marker is gone, memoized across repeated calls without retrying removal or closing twice; callers must surface a retained marker instead of inferring success from the absence of an exception.
- **Event journal:** `audit_events` is Postdot's single append-only, versioned fact journal. Each fact belongs to exactly one project or workspace and references an actor of that same scope. Preserve its non-reusable monotonic sequence, including the SQLite high-water mark across table rebuilds, and its transactional relationship with state changes. Project consumers must skip workspace facts without losing cursor progress. Current-state tables remain authoritative, and every notification, delivery, or analytics consumer must own separate cursor, projection, deduplication, and retry state.
- **Workspace attribution:** Workspace actors grant no access. Authenticated workspace requests may use a subject snapshot with no originating project actor; do not fabricate an editorial grant or project identity for workspace administration. Their originating project-actor ID is provenance, not a foreign key or a source of authorization; snapshots survive source-project deletion. Scope cleanup triggers retire actors after the owning scope's dependent rows have cascaded, avoiding sibling-cascade ordering failures. Actor-table rebuilds must drop and recreate those triggers around the rebuild.
- **Project ownership boundary:** Every new project belongs to a workspace (`createProject` requires it); a null `projects.workspace_id` exists only for historical rows that the ownership preflight refuses. Tests needing such data null the column explicitly after creation, and fixtures use `seedTestWorkspace` from `@postdot/db/testing`.
- **Common-resource ownership:** Channels, profile versions, publishers, connections and credentials belong to a workspace (migration 0023, ADR-095). A project uses them through `project_channel_attachments`; `project_channel_profiles` / `project_channel_publishers` are derived bindings that let project-scoped rows keep their composite foreign keys, and `channel_managers` names one stable managing project. Write common resources only through a live attachment (`state = 'active'`); `project_*_contexts` views identify an editorial context for reads, not ownership or authorization, and historical context stays readable after detach without granting new admission. Writers verify visibility through those views rather than a `project_id` column. Attribution on common rows is a workspace actor snapshot (`ensureFromProjectActor`), not a project actor. Credential refresh may use the historical context so an admitted effect can finish after detach; revocation and management use the active context. A credential not yet connected to any destination is addressable only by the project whose flow staged it.
- **Shared-channel blockers:** Channel archive, delete and publisher disconnect consider work and attachments of every attached project, not only the caller's. Deleting a channel that other projects still use is refused (`shared`). Connecting a publisher queues scheduled automatic work for all attached projects.
- **Authorization boundary:** `createWorkspaceChannelStore` (exposed as `manualStore.sharedChannels`) takes a request-bound policy port and is the only creation/attach/detach/transfer path; `contextFor` resolves the workspace attribution actor from a live project actor and grants nothing. The project-scoped `createChannel` delegates to it with a policy admitting only that project, after the caller has authenticated. The API builds the real policy (`createChannelAccessPolicy`: live role, key capability and project scope) for channel sharing and cadence configuration. Cadence management uses `channel:manage`, independently of `channel:share`; publication spacing overrides use `publication:dispatch`.
- **Channel cadence:** Planning guards run inside the publication writer's immediate transaction, including creation, promotion/approval, bulk rescheduling and explicit failed-work retry. Confirmations bind current rules, publication revisions, occupancy and requested times; never accept a bare bypass flag. Preserve requested schedules. Runtime discovery and claim use the same channel eligibility expression, with a transactional recheck at the effect boundary; persist admission timing and consume an attributed spacing override once. Credential refresh remains keyed by credential, pacing by channel. Manual outcomes contribute their recorded publication time. Keep the SQL expression index in migration 0024 as SQL: Drizzle Kit incorrectly quotes its comma-separated expression when generating SQLite DDL.
- **Test fixtures:** New projects require a workspace. Use `@postdot/db/testing` (`seedTestWorkspace`, `seedWorkspaceChannel`, `seedWorkspaceMember`, `workspaceOf`) for current-schema fixtures; historical-schema tests seed project-owned columns by raw SQL on a chain truncated with `migrationsThrough`, then upgrade through the real chain.
- **Notification projection:** Keep recipient-owned inbox state separate from the fact journal. Project only explicitly supported event names and versions, resolve current project human actors independently from event attribution, advance each projection cursor atomically with deduplicated writes, and keep complete history reachable through stable keyset pagination.
- **External notification delivery:** Keep destinations, per-kind subscriptions, projection cursors, immutable delivery snapshots, leases, and ambiguity state separate from the in-app inbox. External projection and cursor advancement must be atomic and replay-safe; only the executor may cross the durable effect boundary.
- **External notification secrets:** Keep provider credentials in versioned encrypted destination-secret rows, separate from public configuration and delivery history. Capture the secret version at projection time and resolve it only for a claimed delivery; never log, return, or snapshot plaintext material.
- **Publisher secrets:** Keep publisher credential encryption behind an explicit internal boundary. Metadata APIs must never expose token material, and persisted publisher credentials must never reference Better Auth users or accounts. Mechanical renewal uses `withPublisherCredentialRefresh`: reload inside the credential queue, use its live clock and persist through its revision-fenced context. Separate store facades share the SQLite connection queue; unrelated credentials remain independent.
- **Media lifecycle:** Keep project-owned asset, representation, upload-intent, inspection, retention, and reconciliation state in this package. Use `@postdot/media` only through its storage contract, and keep opaque object keys out of public API responses. Persist a provider-reported remote-media expiry alongside a delivery checkpoint when one is available; consumers must still apply their own conservative reuse bound.
- **Media previews:** Internal thumbnails are versioned derived representations, not library assets or publication defaults. Preserve original bytes; track storage ownership before writes and finish preview writes before physical asset deletion. Video posters are optional background work: decoding failure must preserve a ready original, and shutdown cancellation must remain eligible for startup recovery.
- **Media recovery:** Treat SQLite-only backup as a low-level primitive. Complete media recovery must use the manifest-and-bytes bundle, verify every checksum, and fence physical media deletion while the bundle is being copied.
- **Resource retirement:** Delete the SQL graph inside the existing transaction with FK enforcement enabled and checks deferred until commit. Original/derived media have self-referential RESTRICT edges whose cascade order is not stable. Queue storage locators before dropping SQL ownership; a dependency outside the deleted graph must still roll back the transaction.
- **Account recovery:** Offline password recovery must acquire the database runtime lock, validate and protect a pre-change backup, update only the selected Better Auth credential, revoke that user's sessions and reset links, and preserve project data, API keys, publisher credentials, and historical actors.

- **Personal avatars:** Keep person-owned image lifecycle in `user_avatars`, separate from project media assets. Use the shared storage port and complete-backup deletion fence; complete recovery includes avatar bytes as well as project representations.
