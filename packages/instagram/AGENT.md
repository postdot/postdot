# Instagram single-image protocol

- Own the direct Instagram Login single-image protocol and its native profile only. OAuth setup, application configuration, encrypted credentials, inspected media, durable effects, the worker and Studio belong to their existing application boundaries.
- Pin the direct-login host `graph.instagram.com` and version `v26.0`. Never follow a provider redirect or a provider-supplied URL; requests use `redirect: 'error'`, `credentials: 'omit'`, a bearer token in the authorization header and a bounded timeout with an optional caller abort.
- Container creation is not a publication. Keep the container identity for the caller, read its status separately and publish only with the provider's own published media identity. A `PUBLISHED` container status is a status, not a media receipt, and a container identity is never a published identity.
- Expose the three operations separately. There is no internal polling, retry or republish: a lost write acknowledgement is ambiguous and requires reconciliation, not a second write. Only a structured 4xx rejection proves that no write occurred; a malformed body, a non-JSON body, a 5xx response, a network failure or a timeout stays ambiguous for a write and retryable for a read.
- Never return raw provider errors, caught exceptions, tokens or signed image URLs. Diagnostics stay sanitized and provider codes are mapped to local codes.
- Image inputs are public HTTPS URLs minted at execution from inspected Postbot-owned media, never arbitrary user content from a profile. Reject insecure, credentialed, fragmented, malformed and private or literal private-network URLs. Send a signed query string verbatim and never dereference the image from this package.
- The first format is exactly one JPEG with an optional caption and optional accessibility text. No text-only post, video, reel, carousel, story, poll, comment, moderation, analytics or OAuth flow belongs to this package.
- The `8,000,000`-byte ceiling is a conservative application envelope below the documented 8 MB provider maximum, not a restatement of it. The 320-1440 pixel width band is provider rescaling and is not grounds to invent a rejection. Caption and accessibility text ceilings use the documented 2200 and 1000 character maxima; the caption hashtag and mention rules stay provider-enforced because they cannot be counted safely. Provider daily-limit prose is inconsistent, so no universal quota constant is encoded here.
- Synthetic tests establish local behavior only. Live acceptance requires an explicitly authorized Instagram professional account, a correctly configured application with eligible access and an operator-approved media URL. Development access does not establish App Review approval.
